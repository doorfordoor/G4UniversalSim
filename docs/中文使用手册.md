# G4UniversalSim 中文使用手册

**实验性后处理扩展（M3/M5 原型）：**GUI Results 的 **JSON Exports (M5 prototype)** 标签可异步导出 Dose/Fluence JSON，选择目标新文件，运行中可取消；已存在目标不得覆盖，完成后显示路径和警告。命令行可执行 `python -B scripts/run_output_extension.py --list` 查看可用扩展，或用 `--run dose_json|fluence_json --input-dir <模拟输出目录> --output <新JSON路径>` 汇总已发现的 worker CSV。必须检查 `warnings` 及上游 `run_summary.txt` 的运行状态、事件数和 worker 文件清单；输出成功不等于 Geant4 成功或物理 benchmark 通过。此接口不修改 Geant4 内核，完整参数与可信 Python 模块加载限制见 `docs/输出扩展原型说明.md`。

整理日期：2026-07-11。本手册依据当前代码整理，主要覆盖 C++ 后端命令行程序、INI 配置、macro 命令、输出文件和常见问题。GUI 的使用说明见 `gui/docs/中文快速使用说明.md`，几何配置细节见 `docs/中文几何配置说明.md`。

## 1. 项目定位

G4UniversalSim 是一个基于 C++17 和 Geant4 的配置驱动仿真框架。当前可用能力包括：

- 通过 `config/main.ini` 组织运行参数、材料、几何、物理、源、计分和 biasing。
- 通过 Geant4 macro 执行 `/run/initialize`、`/run/beamOn` 以及 `/AIHL/...` 项目命令。
- 构建模板几何和层级几何，支持敏感体、计分输出和部分布尔实体操作。
- 使用 GPS 作为粒子源基础，提供若干轻量源预设。
- 使用 Geant4 参考物理列表，支持 process-level 截面 biasing 钩子。
- 输出 hits、event edep、edep 直方图、edep 分体积/分粒子汇总和 `run_summary.txt`。

当前程序不是完整的 Geant4 图形前端。`--ui` 只启动 Geant4 交互 UI 会话；项目 GUI 是另一个 Python/PySide6 外部运行器。

## 2. 快速运行

推荐从仓库根目录运行，并让所有配置路径相对仓库根目录解析。

```powershell
.\build_vs2026\Release\G4UniversalSim.exe --config config/main.ini --macro macros/run_simple.mac
```

也可以只执行一个自包含 macro：

```powershell
.\build_vs2026\Release\G4UniversalSim.exe --macro macros/run_hit_smoke.mac --threads 1 --output output/hit_smoke
```

常用 smoke 示例：

```powershell
# 敏感探测器、hits、event_edep、edep 直方图
.\build_vs2026\Release\G4UniversalSim.exe --macro macros/run_hit_smoke.mac --threads 1 --output test/output/hit_smoke_st

# 多线程输出，文件会带 _tN 后缀
.\build_vs2026\Release\G4UniversalSim.exe --macro macros/run_hit_smoke.mac --threads 2 --output test/output/hit_smoke_mt

# process-level XS biasing 初始化与挂接 smoke
.\build_vs2026\Release\G4UniversalSim.exe --macro macros/run_biasing_process_level_smoke.mac --threads 1 --output test/output/biasing_process_level_smoke

# volume_fraction 材料构建 smoke
.\build_vs2026\Release\G4UniversalSim.exe --macro macros/run_volume_fraction_test.mac --threads 1 --output test/output/volume_fraction_test
```

程序会先读取主配置并生成最终上下文；只有最终既不是 `dry_run`、也不是 `interactive`、且没有 macro 时，才打印帮助并退出。传入 `--dry-run` 或在主配置中设置 `dry_run = true` 时，会执行配置和 Geant4 对象注册，但跳过 macro/UI 执行。

配置优先级回归测试可从仓库根目录运行：

```powershell
python scripts\test_config_precedence.py
```

## 3. 命令行参数

| 参数 | 作用 |
| --- | --- |
| `--config <file>` 或 `-c <file>` | 指定主配置文件，通常是 `config/main.ini`。空路径会被拒绝。 |
| `--macro <file>` 或 `-m <file>` | 初始化对象创建完成后执行的 Geant4 macro。也支持把 macro 作为第一个位置参数传入；空路径会被拒绝。显式 CLI macro 优先于主配置中的 `[run]/macro`。 |
| `--output <dir>` 或 `-o <dir>` | 覆盖输出目录。优先级高于 `[output]/dir` 和 macro 的输出目录命令；空路径会被拒绝。 |
| `--run-name <name>` | 覆盖运行名称，优先级高于主配置和运行时上下文；空名称会被拒绝。 |
| `--ui` | 启动交互 UI，会初始化 `G4VisExecutive`。 |
| `--threads <N>` 或 `-t <N>` | 多线程构建下设置 worker 线程数，`N` 必须大于 0；优先级高于主配置和项目 macro 命令。 |
| `--seed <N>` | 设置随机种子，同时写入 `SimulationContext` 并设置 CLHEP；优先级高于主配置和项目 macro 命令。 |
| `--check-overlaps <true\|false>` | 覆盖几何重叠检查开关，并阻止低优先级项目命令改写。 |
| `--dry-run` | 创建并注册 Geant4 对象，但跳过 macro 和 UI 执行。 |
| `--help` 或 `-h` | 打印帮助。 |

当前没有 `--version` 参数。

### 配置优先级

当前已实现的启动字段优先级为：

`默认值 < 主配置文件 < macro 运行时命令 < 显式 CLI 参数`

主配置由 `SimulationManager::Configure()` 读取。显式 CLI 参数会在配置读取后重新应用；没有对应 CLI 参数时，项目自有 `/AIHL/app/*`、`/AIHL/output/setDir` 和 `/AIHL/geometry/checkOverlaps` 命令可以修改运行上下文。显式 `--macro` 也会覆盖主配置中的 `[run]/macro`。

主配置中的字段在各 Manager 完成读取后会进行消费追踪。拼写错误、未知 section 或已知 section 中没有被后端读取的 key 会输出 `[ConfigWarning]`，消息包含配置文件、行号、section、key 和原始值，接近拼写时会给出建议。warning 不会阻止 dry-run 或正常运行；摘要中的 `config_warning_count` 和 `[Warnings]` 会保留同一明细。材料文件和几何文件使用独立解析器，本机制不改变它们的未知字段规则。

`run_summary.txt` 在 dry-run、正常 macro、交互会话结束或失败收尾时写入最终状态。`[Values]` 中保留启动时的计划字段，并增加 `status`、`planned_event_count`、`actual_completed_event_count`、`run_count`、`actual_threads`、`configured_seed`、`initial_engine_seed`、`macro_seed_modified`、`actual_output_dir`、`macro_execution_status` 和失败命令位置等事实字段；`[Runs]` 记录每次 `beamOn`，`[GeneratedFiles]` 记录本次明确写入或实际修改的输出文件，即使文件在运行前已经存在。已知会改变随机状态的命令仅包括项目 `/AIHL/app/setSeed`、当前安装 Geant4 示例使用的 `/random/setSeeds` 和 `/random/resetEngineFrom`，且只有命令成功后才标记 `macro_seed_modified`。preflight 失败的 `macro_execution_status` 为 `preflight_failed`，并记录 `macro_failure_phase = preflight`；此时 `macro_failure_code = 0` 且 `macro_failure_code_available = false`，表示没有执行 `ApplyCommand()`。无法执行模拟时事件数为 0，无法可靠取得的值标记为 `unknown` 或 `not_executed`。

macro 执行前会递归检查静态 `/control/execute`，并使用同一份规范化命令序列执行。嵌套 macro 的相对路径按发出命令的当前 macro 文件目录解析，支持 Windows 反斜杠、带空格路径和 `../`；行尾 `#` 注释会在引号外移除。遇到首个 Geant4 命令失败时立即停止并返回非零退出码。当 CLI 锁定对应字段时，项目命令以及已知的 `/run/numberOfThreads`、`/random/...` 冲突命令会直接失败，并报告 macro 文件和行号。`/control/alias`、`/control/loop`、`/control/foreach` 等无法可靠静态分析的动态场景不支持；未被识别的任意 Geant4 命令不应被视为已受保护。

重复 CLI 参数采用最后一次出现的值；这是兼容行为，测试和文档均按此约定。字符串参数的空值会被拒绝。

当前未完整支持的能力会在启动或 macro 执行前明确拒绝：`placement=assembly`、材料 `temperature`/`pressure`，以及在不带 GDML 的 Geant4 上使用 GDML（GDML 自路线图 A5、LET 自 A2、`[physics.region.*]` 自 A6 起支持）。几何 placement 可用 `normal`，或路线图 A5 新增的实验性 `replica`/`parameterised`（见《中文几何配置说明》）；region cuts 可用 geometry volume 的 `cut.*` 或 `[physics.region.<名称>]`（见 8.2）；材料只使用 density、state 和 composition。计分可使用 hits、Edep，或启用实验性的敏感体 Dose 与 Track-Length Fluence（需要默认 scorer 和符合范围的敏感体）。相关未支持字段为 false 或缺失时不影响现有配置。

## 4. 主配置文件结构

`main.ini` 是 `SimulationManager` 的主入口。典型文件如下：

```ini
[run]
name = simple_test
threads = 1
seed = 12345
interactive = false
verbose = 1
check_overlaps = true
dry_run = false

[output]
dir = output/simple_test

[materials]
file = config/materials/material.ini

[geometry]
template = simple_box
config = config/geometry/simple_box.ini
check_overlaps = true
default_world_material = G4_AIR

[physics]
reference = FTFP_BERT_EMZ
default_cut = 1 mm
biasing = false
verbose = 1

[source]
preset = proton_beam
particle = proton
energy = 10 MeV
position_type = point
position = 0,0,-1 mm
direction = 0,0,1

[scoring]
enabled = true
hits = true
event_edep = true
edep = true
let = false
dose = false
fluence = false
auto_create_default_scorers = true
verbose = 1

[scoring.edep]
raw_histogram = true
weighted_histogram = true
bins = 200
min = 0 eV
max = 10 MeV
volume_summary = true
particle_summary = true

[biasing]
enabled = false
```

主配置中的路径按进程工作目录解析。GUI 生成包会写入绝对路径，命令行手写配置则建议使用仓库根目录下的相对路径。

## 5. 材料配置

材料文件由 `[materials]/file` 指向，默认示例是 `config/materials/material.ini`。

材料独立配置文件采用闭合 schema，不是宽松的键值存储。允许 `[NIST]` 的 `materials`、`[isotope.<name>]`、`[element.<name>]`、`[material.<name>]` 及 legacy `[Alias] material = G4_*`。旧 GUI run package 在 `[material.<name>]` 中生成的 `type = material` 已弃用但仍兼容，读取时忽略大小写和首尾空白且不改变材料定义；新 GUI 不再写出该字段，其他值、空值或其他 section 中的 `type` 会直接失败。隐式 `global` 不得有字段；未知 section、空的动态名称后缀和多余 key 会在 Geant4 初始化前直接失败，并报告文件、行号、section、key 和 value，接近拼写时会给出建议。`temperature` 和 `pressure` 仍使用专用的未支持错误；请改用 density、state 和 composition。该规则与主配置的 warning 不同，材料 schema 错误会导致非零退出。

旧式 NIST 别名仍然可用：

```ini
[World]
material = G4_AIR

[Silicon]
material = G4_Si
```

新版材料段支持 `[nist]`、`[isotope.<name>]`、`[element.<name>]` 和 `[material.<name>]`。

```ini
[nist]
materials = G4_AIR, G4_WATER, G4_Si

[material.Epoxy]
mode = mass_fraction
density = 1.20 g/cm3
components = G4_C:0.60, G4_H:0.08, G4_O:0.32
state = solid

[material.WaterLike]
mode = atom_count
density = 1.0 g/cm3
components = G4_H:2, G4_O:1

[material.Composite]
mode = volume_fraction
density = auto
components = G4_SILICON_DIOXIDE:0.85, Epoxy:0.15
```

材料规则：

- `mass_fraction` 的组分数值必须加和为 1.0。
- `atom_count` 的组分必须引用元素，数值表示原子数。
- `volume_fraction` 的组分数值必须加和为 1.0，并且组分必须是材料。不要直接用裸元素做体积分数组分；如果需要元素，先定义成有密度的材料再引用。
- `density = auto` 只支持 `volume_fraction`，会按组分密度计算理想加和密度。
- `volume_fraction` 也可以写显式密度；程序会用体积分数和组分密度转换质量分数，最终 `G4Material` 使用显式密度。

## 6. 几何入口

几何入口在主配置中设置：

```ini
[geometry]
template = simple_box
config = config/geometry/simple_box.ini
check_overlaps = true

```

可选模板为 `simple_box`、`layered_device`、`hierarchical`、`array` 和 `shielding`。`gdml` 配置入口为兼容保留项，但当前后端和 GUI validator 会在运行前明确拒绝，不能当作可运行 GDML 导入功能使用。

几何详细写法见 `docs/中文几何配置说明.md`。

## 7. 源配置

`[source]` 会配置 GPS 的当前源。常用字段：

| 字段 | 说明 |
| --- | --- |
| `preset` | 支持 `proton_beam`、`mono_proton`、`neutron_beam`、`gamma_beam`、`isotropic_neutron`、`plane_proton_beam`。 |
| `particle` | Geant4 粒子名，例如 `proton`、`neutron`、`gamma`、`e-`。 |
| `energy` | 单能源，例如 `10 MeV`。 |
| `position_type` | `point`、`plane`，以及路线图 A4 新增的 `volume`、`beam`（见 7.1）。 |
| `position` | 点源坐标，例如 `0,0,-1 mm`。 |
| `shape` | 平面源可选 `circle`（默认）、`rectangle`，以及 A4 新增的 `annulus`、`ellipse`、`square`；体源与束斑见 7.1。 |
| `center` | 平面源三轴中心，格式如 `1 mm, -2 mm, 0 mm`。 |
| `direction` | 方向向量或 `+x`、`-x`、`+y`、`-y`、`+z`、`-z`。 |
| `radius` | `plane` + `circle` 时的圆形平面源半径。 |
| `halfx`、`halfy` | `plane` + `rectangle` 时必须设置的 X/Y 正半宽，需带合法长度单位；不能同时写 `radius`。 |
| `isotropic` | 为 `true` 时使用各向同性角分布。 |
| `verbose` | 源模块输出级别。 |

高级源调整仍可使用 Geant4 原生 `/gps/...` 命令。

矩形平面源实验性示例：

```ini
[source]
preset = proton_beam
particle = proton
energy = 1 MeV
position_type = plane
shape = rectangle
center = 1 mm, -2 mm, 0 mm
halfx = 1 mm
halfy = 2 mm
direction = 0,0,1
```

该矩形位于 XY 平面，源采样位置的 X/Y 理论区间分别为 `[0, 2] mm`、`[-4, 0] mm`；`direction` 控制发射方向，不会旋转矩形平面。`isotropic=true` 时须移除显式 `direction`。旋转平面、环形、体源、能谱、角分布、多源、离子和相空间见 7.1。

### 7.1 高级源（路线图 A4，实验性）

以下字段可写在 `[source]`，或写在多个 `[source.<名称>]` 节中（每节一个 GPS 源）。所有长度、能量、角度都必须带单位。验证见 `scripts/test_gps_sources.py`（统一用例 `gps_sources`）：每种分布都用真实 Geant4 的初级粒子首步（位置、方向、动能）与解析期望比对，容差为 5 倍统计标准误差。

**能谱**：`energy_type`

| `energy_type` | 必需字段 | 含义 |
| --- | --- | --- |
| `mono`（默认） | `energy` | 单能。 |
| `gauss` | `energy`（均值）、`energy_sigma` | 高斯能谱。 |
| `uniform` | `energy_min`、`energy_max` | 区间内均匀。 |
| `power` | `energy_min`（> 0）、`energy_max`、`alpha` | dN/dE ∝ E^alpha。 |
| `exp` | `energy_min`、`energy_max`、`ezero` | dN/dE ∝ exp(−E/ezero)。 |
| `histogram` | `spectrum_file` | 分箱能谱；CSV 表头 `e_low_MeV,e_high_MeV,weight`（或 `_keV`），各箱首尾相接、权重 ≥ 0，箱内均匀抽样。 |
| `points` | `spectrum_file` | 逐点能谱；CSV 表头 `energy_MeV,density`（或 `_keV`），能量严格递增，点间线性插值。 |

`spectrum_file` 的相对路径按主 INI 所在目录解析；`#` 之后为注释。不属于所选类型的能谱字段会报错。

**位置**：`position_type`

| 类型 | `shape` 与字段 |
| --- | --- |
| `point` | `position`。 |
| `plane` | `circle`（`radius`）、`rectangle`（`halfx`、`halfy`）、`annulus`（`radius`、`inner_radius`）、`ellipse`（`halfx`、`halfy`）、`square`（`halfx`）；中心为 `center`。 |
| `volume` | `sphere`（`radius`）、`cylinder`（`radius`、`halfz`）、`box`（`halfx`、`halfy`、`halfz`）、`ellipsoid`（`halfx`、`halfy`、`halfz`）；中心为 `center`，体内均匀。 |
| `beam` | 高斯束斑：`shape = circle` + `beam_sigma`（x、y 各为该 σ，不截断），或 `shape = ellipse` + `beam_sigma_x`、`beam_sigma_y`。 |

- `rot1`、`rot2`（成对出现，不能平行）旋转 plane/volume/beam：平面由 `rot1` 和正交化后的 `rot2` 张成。例如 `rot1 = 1,0,0`、`rot2 = 0,0,1` 得到 XZ 平面。
- `confine = <物理体名>`（需 `position_type = volume`）：只保留落在该物理体内的采样点（Geant4 GPS 拒绝采样），采样形状必须包住该物理体。物理体名通常为 `<名称>_PV`，可用 `/AIHL/geometry/listUserVolumes` 查看；名称不存在时在第一轮开始前报错并非零退出（GPS 原本会静默忽略）。

**角分布**：`angular`

| `angular` | 字段 | 含义 |
| --- | --- | --- |
| `fixed` | `direction` | 固定方向（与旧写法 `direction` 相同）。 |
| `isotropic` | 可选 `min_theta`、`max_theta` + `direction` | 全空间各向同性；给出 `max_theta` 时为以 `direction` 为轴的圆锥（锥内各向同性）。 |
| `cos` | `direction`，可选 `min_theta`、`max_theta`（≤ 90 deg） | 余弦律（Lambert），以 `direction` 为轴。 |
| `beam1d` | `direction`、`angular_sigma` | 极角 θ 取自 Gauss(0, σ)（Geant4 GPS 约定：⟨θ²⟩ = σ²），方位角均匀。 |
| `beam2d` | `direction`、`angular_sigma_x`、`angular_sigma_y` | 两个正交方向的高斯发散；x′ 轴为全局 x 在垂直于 `direction` 平面上的投影（`direction` 平行于 x 时用 y）。 |
| `focused` | `focus = x,y,z` | 每个粒子从产生点指向焦点。 |

`angular` 不能与旧字段 `isotropic` 同时出现；无 `max_theta` 的 `isotropic` 不能带 `direction`。

**多个加权源**：使用 `[source.<名称>]` 时，`[source]` 只能保留 `verbose`。每个命名源必须给出粒子、能量（或 `energy_type`）、位置以及方向/角分布，`intensity`（正数，默认 1）决定该源每个事件被选中的概率 intensity/Σintensity；未知字段直接报错。此时 `/AIHL/source/*` 单字段命令会被拒绝（无法确定作用于哪个源），可改用 INI 或原生 `/gps/source/...`。

```ini
[source.low]
particle = proton
energy = 5 MeV
position_type = point
position = -50,0,0 mm
direction = +z
intensity = 1

[source.high]
particle = proton
energy_type = gauss
energy = 15 MeV
energy_sigma = 0.5 MeV
position_type = volume
shape = sphere
center = 50,0,0 mm
radius = 5 mm
angular = isotropic
intensity = 3
```

**离子与放射源**：`particle = ion` 与 `ion = Z A [电荷 [激发能]]`（电荷默认 Z，激发能带单位，如 `ion = 27 60 27 0 keV`）。`energy` 为离子总动能；`energy = 0 keV` 表示静止衰变源，需要 `[physics] extra_modules = radioactive_decay`。实测 Na-24 静止源：2000 次衰变中 1998 次到达 Mg-24 的 4122.9 keV 能级（NNDC 99.86%），β⁻ 平均能量 551 keV（NNDC 554 keV）；12C 离子束初级粒子为 C12。注意：Geant4 ≥ 11.2 默认不模拟寿命超过 1 年时间阈值的核素衰变（例如 Co-60 会直接被终止），调整阈值属于路线图 A6 物理配置。

**相空间读写**：

- 写：在主 INI 加 `[phase_space]`，`volume = <物理体名>`（必需），`particles = all|<粒子列表>`，`kill = false|true`。每个 worker 写 `phase_space_tN[_rR].csv`（schema `phase_space_csv_v1`），记录**穿入**该物理体的粒子在边界处的状态（体内任何相互作用之前）。`kill = true` 时记录后终止该粒子，可用于两阶段模拟。
- 读：`[source] phase_space_file = a.csv, b.csv`（逗号分隔，按顺序拼接；同一轮的各 worker 文件可直接一起列出），可选 `phase_space_recycle = true`。`[source]` 中不能再有其他源字段。连续且 `(runID, eventID)` 相同的行构成一个历史；第 k 个事件重放第 k 个历史（循环时取模），与 worker 分配无关、可复现。每一轮都从第一个历史开始；不循环时若 `beamOn` 大于历史数，在该轮开始前报错。
- 实测：600 个 50 MeV 质子历史写出后重放，每个初级粒子的入射位置、方向、动能与记录值一致（最大相对差 5e-12），水中平均沉积能 49.48 MeV 与 49.49 MeV 一致（±0.19 MeV）；`kill = true` 后体内无质子沉积；手写的双粒子、权重 0.5 历史按一个事件重放并保持权重。

限制：上述分布均为 Geant4 GPS 的抽样，本项目只验证配置映射与抽样统计；尚未提供 GUI 编辑器（GUI 仍阻止生成这些字段，可手写主 INI），也未验证偏置权重下的相空间以及 GPS 的能量/角度偏置抽样。

## 8. 物理配置

推荐使用 Geant4 参考物理列表：

```ini
[physics]
reference = FTFP_BERT_EMZ
default_cut = 1 mm
biasing = false
```

当前代码列出的参考列表包括 `FTFP_BERT`、`FTFP_BERT_HP`、`FTFP_BERT_EMZ`、`FTFP_BERT_LIV`、`FTFP_BERT_PEN`、`QGSP_BERT`、`QGSP_BIC` 和 `Shielding`。

可选字段：

- `em`：对参考列表应用 EM 后缀，例如 `option4`、`livermore`、`penelope`。
- `modules`：手动模式下的模块列表；参考模式下会被兼容处理为 `extra_modules`。
- `extra_modules`：参考模式下额外注册的模块。
- `default_cut`：默认 production cut。
- `biasing`：启用 generic biasing physics 钩子。真正的 biasing 规则还要在 `[biasing]` 中配置。
- `[physics.cuts]`：按粒子设置 cut，例如 `e- = 1 um`。
- `[physics.region.<RegionName>]`：区域 production cut、步长限制与用户特殊截断（路线图 A6），见 8.2。
- `[physics.microelec]`：可启用区域级 MicroElec 扩展和电子捕获辅助过程；该能力仍属于高级/实验路径。

### 8.1 EM 选项预设（路线图 A6）

reference 模式下 `[physics] em = <预设>` 把 EM 后缀加到参考物理列表名上（例如 `reference = FTFP_BERT` + `em = option4` 即 `FTFP_BERT_EMZ`）：

| `em` | 后缀 | EM 构造器 | 典型模型（`/AIHL/physics/dumpProcesses` 实测） |
| --- | --- | --- | --- |
| `standard`（默认） | 无 | `G4EmStandard` | Klein-Nishina Compton、Urban msc |
| `option1` / `option2` / `option3` | `_EMV` / `_EMX` / `_EMY` | `G4EmStandard_opt1/2/3` | option3：Urban msc |
| `option4` | `_EMZ` | `G4EmStandard_opt4` | LowEP Compton、Goudsmit-Saunderson msc、5D 电子对 |
| `livermore` | `_LIV` | `G4EmLivermore` | Livermore Compton/光电/5D 电子对 |
| `penelope` | `_PEN` | `G4EmPenelope` | Penelope Compton/光电/电子对/Rayleigh |

验证（`scripts/test_physics_a6.py`）：1 MeV 光子窄束穿过 10 cm 水的未散射透射率，五种预设均与 NIST XCOM（μ/ρ = 0.07072 cm²/g，T = 0.4930）在 1σ 内一致（0.4930–0.5005，σ = 0.0079）。

### 8.2 区域物理：production cut、步长限制与用户特殊截断（路线图 A6）

`[physics.region.<区域名>]`（区域名区分大小写）作用于 Geant4 `G4Region`：

| 字段 | 含义 |
| --- | --- |
| `gamma`、`e-`、`e+`、`proton` | 该区域的 production range cut；未写的粒子使用 `[physics]/default_cut`。 |
| `max_step` | 每步最大长度（`G4StepLimiter`，对带电粒子）。 |
| `max_track_length` | 径迹**自产生起**的总长度上限，超过即终止（因此在真空中飞行的距离也计入）。 |
| `max_time` | 全局时间上限。 |
| `min_kinetic_energy` | 每一步开始时动能低于该值即以零长度 `UserSpecialCut` 步终止并就地沉积。 |
| `volumes` | 可选：逗号分隔的逻辑体名（或几何体积名，自动补 `_LV`），把它们设为该区域的根逻辑体；区域不存在时据此新建（适用于 GDML 几何）。 |

区域必须由几何的 `region = <名称>` 定义或通过 `volumes` 创建，否则 INI 几何在配置阶段、GDML 几何在构建时报错并列出现有区域。同一区域的 cut 只能在一处设置：几何体积已用 `cut.*` 时再写 `[physics.region]` 的 cut 会报错。`DefaultRegionForTheWorld` 不能写在这里（使用 `default_cut` 与 `[physics.cuts]`）。任一区域设置了限制时自动注册 `G4StepLimiterPhysics`。宏命令 `/AIHL/physics/setRegionCut <区域> <粒子> <长度>` 也可用（初始化前）。

实测：区域 e⁻ cut 1 µm 在水中换算为 990 eV（Geant4 下限），100 MeV 质子产生约 135 万个 δ 电子，而 1 mm 默认 cut 时为 0；`max_step = 0.2 mm` 时初级质子最长步 0.197 mm（无限制时 15.7 mm）；`min_kinetic_energy = 50 MeV` 时所有初级质子在降到 50 MeV 以下的下一步被终止，没有在阈值下继续输运的步；`max_track_length = 30 mm` 时径迹长度为 30.00 mm。

### 8.3 放射性衰变（路线图 A6）

```ini
[physics.radioactive_decay]
enabled = true            # 列表中没有时注册 G4RadioactiveDecayPhysics（已有时不重复注册）
time_threshold = 1000 y   # 可选；时间单位 ps、ns、us、ms、s、min、h、d、y
```

Geant4 ≥ 11.2 默认的时间阈值为 1 年：平均寿命更长的核素（如 Co-60，τ = 7.6 y）不会衰变而是直接终止。需要长寿命源时请设置 `time_threshold`。实测：默认阈值下 1000 个静止 Co-60 无一衰变；`time_threshold = 1000 y` 时 99.8% 衰变至 Ni-60 的 2505.7 keV 能级，β⁻ 平均能量 95.3 keV（NNDC 95.8 keV）。没有放射性衰变物理时设置 `time_threshold` 会报错。

### 8.4 活动过程导出（路线图 A6）

`/run/initialize` 之后执行 `/AIHL/physics/dumpProcesses <文件.json> [粒子,粒子,...]`（只读，默认粒子为 gamma、e-、e+、proton、neutron、alpha、GenericIon、mu±、pi±），写出 `g4usim_process_dump_v1`：物理列表构造器、放射性衰变时间阈值、各粒子的过程（类型、子类型、是否激活）与其 EM 模型或强子相互作用模型及能量范围（Geant4 11 的 `GammaGeneralProc` 会展开为 phot/compt/conv/Rayl 子过程）、各区域的根逻辑体、range cut 与用户限制，以及每个材料-cut 组合换算后的能量阈值。用它可以确认所选预设、cut 和限制确实被 Geant4 采用。

### 8.5 电磁场（路线图 A7，实验性）

`[field]` 定义整个世界的全局场，`[field.<名称>]` 定义作用于指定逻辑体（及其没有自己场的子体积）的局部场；局部场在其体积内取代全局场。

| 字段 | 说明 |
| --- | --- |
| `magnetic` | 均匀磁场 `Bx, By, Bz 单位`，单位 `T`、`mT`、`uT`、`G`、`kG`（也可每个分量各写单位）。 |
| `electric` | 均匀电场，单位 `V/m`、`kV/m`、`MV/m`、`V/cm`、`kV/cm`、`MV/cm`、`V/mm`、`kV/mm`。可与 `magnetic` 同时给出（电磁场）。 |
| `magnetic_map` / `electric_map` | 场图 CSV（相对路径按主 INI 目录解析），与对应的均匀值二选一。 |
| `volumes` | 仅局部场：逗号分隔的逻辑体名或几何体积名（自动补 `_LV`）。 |
| `min_step`、`delta_chord`、`delta_one_step`、`delta_intersection` | 积分精度，默认 0.01 mm、0.25 mm、0.01 mm、0.001 mm；高精度轨迹可调小。 |

场图格式：表头 `x_<mm|cm|m>,y_..,z_..,Bx_<单位>,By_<单位>,Bz_<单位>`（电场为 `Ex_`…），每行一个规则网格节点，所有不同的 x、y、z 组合必须恰好各出现一次（每轴至少 2 个值）。在**全局坐标**中三线性插值，网格外场为零。

```ini
[field]
magnetic = 0, 0, 2 T

[field.Separator]
volumes = Gap
electric = 0, 1.383, 0 MV/m
magnetic = 0, 0, 0.1 T
```

实现：纯磁场使用 `G4Mag_UsualEqRhs`，含电场时使用 `G4EqMagElectricField`，二者均用 `G4DormandPrince745` 积分；场对象在每个线程的 `ConstructSDandField` 中创建，场图数据各线程共享只读。

验证（`scripts/test_fields_a7.py`，与解析轨迹比较，均在给定容差内）：
- 2 T 均匀磁场中 100 MeV 质子在 x = 0.5 m 处的 y 坐标与圆轨迹相差 1e-5 mm，方向与能量不变。
- 1 MV/m 纵向电场使能量增加 0.5 MeV；横向电场下能量增量等于 qE·y。
- 交叉电磁场（E = vB 的 Wien 速度选择器）使质子直线通过（4 nm），单独磁场时偏转 89.24 mm（与解析一致）。
- 常数场图与均匀场一致。
- 线性梯度场图满足正则动量守恒的出射方向（1e-6）。
- 局部场盒内为圆弧、盒外为直线。
- 非法单位、缺分量、不完整网格、全局场带 `volumes`、局部场缺 `volumes`、未知体积和未知字段均在事件前拒绝。

限制：场图只支持规则笛卡尔网格（无柱坐标、无对称/镜像展开）；没有时间相关场；GUI 尚不能编辑场。

## 9. 计分和输出

`[scoring]` 控制是否写出 hit、event edep 和默认 scorer：

```ini
[scoring]
enabled = true
hits = true
event_edep = true
edep = true
let = false
dose = false
fluence = false
auto_create_default_scorers = true
```

当前 `edep` 已具备主要运行输出链。LET 开启时会 fail-fast；Dose 提供实验性敏感 physical touchable 累积剂量：在 `[scoring]` 设置 `dose=true`、`auto_create_default_scorers=true` 且几何中含 `sensitive=true` 体积。后端按 run、worker 和 physical touchable 输出 `dose_volume_summary_tN[_rR].csv`，列包括 `mass_kg`、`raw_edep_MeV`、`weighted_edep_MeV`、`raw_dose_Gy`、`weighted_dose_Gy`。跨 worker 合并时只对 Edep 求和，质量使用同一体积的一份数据。该结果无时间、源强、注量归一化，且尚未完成独立物理 benchmark。

实验性 Track-Length Fluence 可在相同条件下设置 `[scoring]/fluence=true`。仅支持没有 daughter volume 的敏感 solid，Geant4 在敏感体内每个 step 的长度计入 `raw_track_length_mm`，乘 track weight 后计入 `weighted_track_length_mm`，即使该 step 的 Edep 为零也计入。后端每 worker/run 写 `fluence_volume_summary_tN[_rR].csv`，以 `raw_track_length_mm / volume_mm3` 和 `weighted_track_length_mm / volume_mm3` 得到 `raw_fluence_mm-2`、`weighted_fluence_mm-2`。GUI Results / Fluence (mm^-2) 按真实 physical touchable 聚合已发现的 worker 径迹长度，每个体积只取一次；无法保证缺失文件完整。结果未按事件数、时间或源强归一化，不是 surface-crossing fluence，亦无独立物理 benchmark。可使用 `python -B scripts/run_output_extension.py --run fluence_json --input-dir <输出目录> --output <新文件.json>` 将完成的 CSV 转换成 JSON，详见 `docs/输出扩展原型说明.md`。

`[scoring.edep]` 控制 raw/weighted event edep 直方图和汇总：

```ini
raw_histogram = true
weighted_histogram = true
bins = 200
min = 0 eV
max = 10 MeV
volume_summary = true
particle_summary = true
```

### ROOT 输出（推荐用于多线程和后续分析）

在主配置中选择输出格式：

```ini
[output]
dir = output/my_run
format = root    # csv（默认）| root | both
```

或在宏中 `/run/initialize` 之前执行 `/AIHL/output/setFormat root`。`root` 模式下每个 run 只写一个 `g4usim.root`（后续 run 为 `g4usim_rR.root`），多线程结果由 Geant4 自动合并，不再需要上面的合并工具。文件包含 `edep_raw`/`edep_weighted` 直方图和 `hits`、`events`、`edep_volume`、`edep_particle`、`dose`、`fluence` 六个 ntuple，详见 [输出数据契约](输出数据契约.md)。

运行模拟不需要安装 ROOT。读取示例（`pip install uproot`）：

```python
import uproot
f = uproot.open("output/my_run/g4usim.root")
events = f["events"].arrays(library="pd")      # 需要 pandas；也可用 library="np"
counts, edges = f["edep_raw"].to_numpy()
```

迁移期可用 `format = both` 同时写 CSV，并用 `python scripts\compare_root_csv.py --dir <输出目录>` 核对两者一致。每次运行还会写出机器可读的 `run_metadata.json`。

### LET（传能线密度，实验性）

在主配置中开启（与 Dose/Fluence 相同，不能通过宏开启）：

```ini
[scoring]
let = true
auto_create_default_scorers = true

[scoring.let]
particles = proton        ; 可选：all（默认，全部带电粒子）或逗号分隔的粒子名
```

对敏感体内每个带电粒子步，后端用 `G4EmCalculator::ComputeElectronicDEDX` 计算该步平均动能处的非限制电子阻止本领 S，按步长 l 和径迹权重 w 累计，输出每个敏感 physical touchable 的径迹平均 LET_t = Σw·S·l / Σw·l 和剂量平均 LET_d = Σw·S²·l / Σw·S·l（单位 keV/µm）。CSV 为 `let_volume_summary_tN[_rR].csv`，ROOT 为 `let` ntuple；两者都给出可跨线程相加的 `sum_wl_mm`、`sum_wSl_MeV`、`sum_wS2l_MeV2_per_mm`，合并时先对各 worker 求和再相除。验证：20 µm 水层中 100 MeV / 10 MeV 质子的 LET_t 与 Bethe 公式（I=75 eV）相差 0.6% / 1.4%（Geant4 的 G4_WATER 使用 I=78 eV），与 NIST PSTAR 一致到约 1%。尚未覆盖重离子和厚靶能谱的基准。

### 位移损伤剂量（DDD，实验性，路线图 B2）

在主配置中开启（与 Dose/Fluence 相同，需要默认 scorer；不能通过宏开启）：

```ini
[scoring]
displacement = true
auto_create_default_scorers = true

[scoring.displacement]
proton = niel/si_proton.csv     ; <Geant4 粒子名（小写）> = <NIEL 表>，相对路径按主 INI 目录解析
e- = niel/si_electron.csv
neutron = niel/si_neutron.csv
```

NIEL 表为 CSV，表头 `energy_MeV,niel_MeV_cm2_g`，`#` 开头为注释，能量严格递增且 > 0，NIEL 有限且 ≥ 0，至少两行；节点之间按对数-对数插值（节点值为 0 时线性）。对没有 daughter 的敏感 solid（与 Fluence 相同的限制）内每一步（包括中子等零沉积步），若粒子有表，按该步首末动能的平均值 E 计入 DDD = Σ w·l·NIEL(E)/V（MeV/g）；没有表的粒子不计，表外能量的径迹长度计入 `out_of_range_track_length_mm` 而不计 DDD。CSV 为每 worker/run 一份的 `displacement_volume_summary_tN[_rR].csv`（每个 touchable × 粒子一行：`track_length_mm`、`out_of_range_track_length_mm`、`ddd_MeV_g`、`ddd_sum_sq_MeV2_g2`、`n_events`，可跨线程相加）；合并结果和相对误差在 `scorer_statistics[_rR].csv`（`scorer = displacement`，`quantity = ddd_total` 与 `ddd_<粒子>`），ROOT 输出暂不写单独的 ntuple，只写统计文件。

结果完全取决于所提供的 NIEL 表，仓库不附带 NIEL 数据；Geant4 自身的非电离沉积不参与计算（它只是局部反冲能，不含 Lindhard 分配且依赖 cut）。验证（`scripts/test_displacement_damage.py`）：DDD 与由 hits 独立重算的值一致（2×10⁻⁴），中子零沉积步与 NIEL·N/A 一致（0.3%），表外能量和非法表在事件前拒绝。NIEL 数据本身与位移损伤效应没有经过基准比较。用法示例见 `scenarios/shielding_coating`。

### 打分网格（Geant4 原生 `/score/` 命令）

在宏中 `/run/initialize` 之前定义网格，即可使用 Geant4 全部原生打分量（沉积能、剂量、径迹长度注量、穿越流、次级粒子数等）和过滤器（粒子、动能、带电/中性）。例如在 2 cm 硅靶上做 20 层深度剂量分布：

```
/score/create/boxMesh depthMesh
/score/mesh/boxSize 10. 10. 10. mm      # 半长
/score/mesh/nBin 1 1 20
/score/mesh/translate/xyz 0. 0. 0. mm
/score/quantity/energyDeposit eDep MeV
/score/quantity/doseDeposit dose Gy
/score/quantity/cellFlux flux
/score/quantity/energyDeposit eDepElectron MeV
/score/filter/particle electronOnly e-
/score/close
/run/initialize
/run/beamOn 1000
```

结果写入 ROOT 文件的 `mesh` ntuple 和/或 `scoring_mesh.csv`，每个格元带 `sum`、`sum_sq`、`entries` 与相对误差 `rel_error`。Python 读取：

```python
import sys; sys.path.insert(0, "scripts")
import g4usim_io
m = g4usim_io.load_mesh("output/my_run/g4usim.root", "depthMesh", "dose")
print(m.unit, m.value[0, 0, :], m.rel_error[0, 0, :])
```

也可以在主配置 INI 中定义网格（GUI 和批处理推荐此方式），后端在物理列表注册后、任何用户宏执行前把它们转换成相同的 `/score/` 命令，结果与宏定义逐格元一致：

```ini
[scoring.mesh.depthMesh]          ; 网格名区分大小写
shape = box                       ; box | cylinder
size = 10 mm, 10 mm, 10 mm        ; box：x/y/z 半长；cylinder：半径, 半高
bins = 1, 1, 20                   ; box：x,y,z；cylinder：r,z,phi
center = 0 mm, 0 mm, 0 mm         ; 可选

[scoring.mesh.depthMesh.dose]     ; 每个打分量一个小节
type = doseDeposit                ; 任意 Geant4 primitive scorer 命令名
unit = Gy                         ; 可选

[scoring.mesh.depthMesh.eDepElectron]
type = energyDeposit
unit = MeV
particles = e-                    ; 可选粒子过滤，逗号分隔
energy_min = 0.1 MeV              ; 可选动能过滤（可与 particles 组合）
energy_max = 10 MeV
```

缺少 `shape/size/bins`、未知形状、找不到对应网格的打分量小节、无效的打分器或粒子名都会在运行前报错并非零退出；`run_summary.txt` 中 `scoring_mesh_ini_command_count` 记录生成的命令数。

网格结构记录在 `run_metadata.json`（`scoring_mesh_<名称>_*`）。圆柱网格的格元索引顺序以其中的 `_axes` 为准。字段与验证见 [输出数据契约](输出数据契约.md)。

## 10. 进程级截面偏置

推荐使用 process-level 配置：

```ini
[physics]
reference = FTFP_BERT_EMZ
biasing = true

[biasing]
enabled = true

[biasing.xs.proton.hIoni]
enabled = true
factor = 10
only_primary = true
apply_to_secondaries = false
min_weight = 0.05
max_interactions = 5
volumes = Target
```

规则说明：

- `[biasing]/enabled = true` 才会加载 biasing 规则。
- `[physics]/biasing = true` 会注册 generic biasing physics 钩子。若 biasing 规则存在，`SimulationManager` 也会自动打开该物理钩子。
- section 名必须是 `[biasing.xs.<particle>.<process>]`。当前不支持名称中带 `.` 的 process。
- `volumes` 为空时，会尝试使用几何中标记 `bias = true` 的 logical volume。
- 旧式 `[biasing.xs]` 粒子级写法仍兼容，但会打印 legacy 警告，不建议新配置继续使用。

## 12. 常见问题

### 运行后没有 hits 文件

确认几何体设置了 `sensitive = true`，`[scoring]/hits = true`，并且粒子确实在敏感体内沉积了能量。`macros/test_simple_min.mac` 可能只验证初始化，不一定产生 hit。验证 hit 链路请优先用 `macros/run_hit_smoke.mac`。

### 修改几何后结果没有变化

几何、材料、物理大多应在 `/run/initialize` 前配置。初始化后改几何，需要 `/run/reinitializeGeometry` 或重启进程；改物理通常需要 `/run/physicsModified` 或重启。

### 材料找不到

几何中的 `material` 必须是已加载材料、NIST 材料，或材料配置里定义的别名。GUI 生成包会把材料文件复制或生成到包内，不会覆盖原始材料文件。

### 几何根节点为空

检查几何模板和几何文件是否匹配。`hierarchical` 模板必须有 `[world]`；非 world 体积必须有有效 `parent`。

### M0-3B2B1 几何安全校验

几何文件中的 production cut、固定模板 shape、hierarchical shape 参数、boolean tool 参数、`copyNo` 和 placement 会在首个 Geant4 geometry object 创建前校验。cut 仅允许 `cut.gamma`、`cut.e-`、`cut.e+`、`cut.proton`，并要求同 section 存在非空 `region`。M0-3B2B2 进一步提供来源诊断、legacy metadata 和 boolean ignored-key warning；严格 `version=2`、自动迁移和完整无损 round-trip 留给 M0-3B3。

### GDML 初始化失败

当前 GDML 尚未实现，配置会在后端校验阶段被拒绝。不要把它当作可运行的 GDML world replacement。

### 多线程输出不是一个总 CSV

CSV 格式下这是当前设计：每个 worker 写 `_tN` 文件，合并需要显式运行 `scripts/merge_outputs.py` 或 `mergeHistograms.exe`。改用 `[output]/format = root` 可直接得到一个已合并的 `g4usim.root`。

## 13. 当前边界

- STL 导入为实验性 `shape = tessellated`（路线图 A5，见《中文几何配置说明》）；STEP/IGES 等其他 CAD 格式需先导出为 STL。
- GDML 导入未实现，配置会 fail-fast。
- importance、weight-window、splitting、Russian roulette 等高级 biasing 未实现。
- LET 未支持，开启会 fail-fast；Dose 和 Track-Length Fluence 仅提供敏感体实验性体积输出，使用前须阅读计分章节的质量、体积及归一化限制。
- 后端支持的几何能力和 GUI 可编辑能力不完全相同；GUI 说明中会单独列出 GUI 限制。
