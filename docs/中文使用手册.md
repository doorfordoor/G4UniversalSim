## 1. 项目简介

G4UniversalSim 是一个 C++17 + Geant4 的通用仿真框架，目标是把常见 Geant4 仿真流程拆成可配置、可扩展的模块：

- 配置驱动：通过 `config/main.ini`、几何 ini、材料 ini 和 macro 控制运行。
- 模板几何：支持 `simple_box`、`layered_device`、`hierarchical`、`array`、`shielding`、`gdml` 等模板入口。
- GPS 粒子源：底层使用 `G4GeneralParticleSource`，保留 Geant4 原生 `/gps/...` 命令。
- 可配置物理：支持 Geant4 reference physics list，也支持手动组装 EM 和其他 physics constructor。
- Hits 与 Scoring：`SensitiveDetector` 把 `ParticleHit` 转为 `HitRecord`，交给 `ScoringManager` 输出 hits、event edep 和 edep histogram。
- XS Biasing：`BiasingManager` 保存截面偏置规则，通过 physics hook 和 geometry post-build callback 挂接 operator。
- 后处理：提供独立 C++ histogram 合并工具和 Python 绘图、CSV 合并、参数扫描脚本。

### 当前可用功能

- `main.cc` 已形成可启动 Geant4 executable workflow。
- `SimulationManager` 负责创建并持有各 manager 和 messenger。
- `DetectorConstruction`、`PhysicsList`、`ActionInitialization` 通过 `unique_ptr` 创建后交给 `G4RunManager`。
- `run_simple.mac` 可自举加载材料、几何、physics、source、scoring 并执行 `/run/beamOn 100`。
- `EdepScorer` 可输出 raw / weighted event edep histogram。
- `mergeHistograms` 不依赖 Geant4，可独立构建。

### 实验性或暂未完整实现功能

- `MicroElecPhysics` / `ElectronCapture` 是高级可选功能，当前主要提供 atomic deexcitation 设置和低能电子捕获辅助过程，不替换完整 EM 物理模型。
- `LETScorer`、`DoseScorer`、`FluenceScorer` 当前是轻量 stub 或最小接口，尚未实现完整物理计算。
- `GDMLTemplate` 当前是 placeholder 配置入口，`VolumeBuilder` 未真正调用 `G4GDMLParser` 导入 GDML。
- 多线程输出当前依赖 per-thread 文件，合并需要后处理工具或脚本。

## 2. 环境要求

### 基本要求

- CMake 3.10 或更高。
- 支持 C++17 的编译器。
- Geant4，当前工程通过 `find_package(Geant4 REQUIRED ui_all vis_all)` 查找。
- 如果使用可视化 UI，需要 Geant4 构建时启用相应 UI / Vis 支持，如 Qt/OpenGL。
- Python 脚本需要 Python 3；`plot_hist.py` 额外需要 `matplotlib`。

### Windows 工具链要求

如果你的 Geant4、Qt、CLHEP 是用 MSVC 编译的，本项目也必须用 MSVC 编译。不要用 MinGW/UCRT 的 `g++` 去链接 MSVC 生成的 Geant4 `.lib`，否则会出现大量 unresolved symbol。

推荐在 “Developer PowerShell for Visual Studio” 或已加载 MSVC 环境变量的终端中构建。

### Visual Studio 2022 构建

```powershell
cmake -S . -B build_vs -G "Visual Studio 17 2022" -A x64 -DGeant4_DIR="D:/ProgramFiles/Geant4/lib/cmake/Geant4"
cmake --build build_vs --config Release
```

如果 Geant4 已经在 `CMAKE_PREFIX_PATH` 或系统环境中可被找到，可以省略 `-DGeant4_DIR=...`。

也可以使用仓库中的 preset：

```powershell
cmake --preset vs2022-x64
cmake --build --preset vs2022-release
```

### Visual Studio 2026 说明

如果你的 CMake 版本支持 VS 2026 generator，可以尝试：

```powershell
cmake -S . -B build_vs2026 -G "Visual Studio 18 2026" -A x64 -DGeant4_DIR="D:/ProgramFiles/Geant4/lib/cmake/Geant4"
cmake --build build_vs2026 --config Release
```

但当前检查过的本机 CMake 不支持 `Visual Studio 18 2026`，可用列表只有 `Visual Studio 17 2022`、`Visual Studio 16 2019` 等。遇到：

```text
CMake Error: Could not create named generator Visual Studio 18 2026
```

说明需要更新 CMake，或改用 VS2022 generator，或使用 Ninja + `cl.exe`。

### Ninja + cl.exe 替代方案

先打开 VS Developer PowerShell，确保 `cl.exe` 在 PATH 中，然后：

```powershell
cmake -S . -B build_ninja_cl -G Ninja -DCMAKE_BUILD_TYPE=Release -DGeant4_DIR="D:/ProgramFiles/Geant4/lib/cmake/Geant4"
cmake --build build_ninja_cl
```

重点是 Ninja 使用的编译器必须是 MSVC `cl.exe`，而不是 MinGW/UCRT `g++.exe`。

## 3. 快速开始

### 3.1 使用 main.ini + macro 运行

```powershell
.\build_vs\Release\G4UniversalSim.exe --config config/main.ini --macro macros/run_simple.mac
```

这会先由 `SimulationManager` 读取 `config/main.ini`，再执行 `macros/run_simple.mac` 中的 Geant4 和 `/AIHL/...` 命令。

### 3.2 只使用 macro 运行

```powershell
.\build_vs\Release\G4UniversalSim.exe --macro macros/run_simple.mac
```

当前 `run_simple.mac` 是自举 macro，包含材料、几何、physics、source、scoring 的最小配置以及：

```text
/run/initialize
/run/beamOn 100
```

因此可以不传 `--config` 直接运行最小 simple box 示例。

### 3.3 进入交互模式

```powershell
.\build_vs\Release\G4UniversalSim.exe --config config/main.ini --ui
```

交互模式会创建 `G4VisExecutive` 并启动 `G4UIExecutive`。如果 Qt 或可视化库不可用，请先使用 batch macro 模式验证。

### 3.4 最小运行后输出文件

默认 `config/main.ini` 输出目录为：

```text
output/simple_test
```

常见输出：

| 文件 | 作用 |
|---|---|
| `hits_t0.csv` | 每个敏感体积 step/hit 的详细记录。只有 sensitive volume 中有非零能量沉积时才会有有效行。 |
| `event_edep_t0.csv` | 每个 event 的 `raw_edep` 和 `weighted_edep`。 |
| `hist_edep_raw_t0.csv` | event-level raw edep 直方图。 |
| `hist_edep_weighted_t0.csv` | event-level weighted edep 直方图。 |
| `edep_volume_summary_t0.csv` | 按 volume 汇总的 raw/weighted edep。 |
| `edep_particle_summary_t0.csv` | 按 particle 汇总的 raw/weighted edep。 |
| `run_summary.txt` | 运行配置和状态摘要。 |

## 4. 命令行参数说明

命令行参数来自 `main.cc`：

| 参数 | 含义 | 示例 |
|---|---|---|
| positional macro | 位置参数形式的 macro 文件 | `G4UniversalSim.exe macros/run_simple.mac` |
| `--config`, `-c` | 主配置文件 | `--config config/main.ini` |
| `--macro`, `-m` | 执行 macro 文件 | `--macro macros/run_simple.mac` |
| `--output`, `-o` | 覆盖输出目录 | `--output output/run01` |
| `--run-name` | 覆盖 run 名称 | `--run-name beam_10MeV` |
| `--ui` | 启动交互 UI | `--ui` |
| `--threads`, `-t` | 设置线程数，MT Geant4 下传给 `G4MTRunManager` | `--threads 4` |
| `--seed` | 设置随机数种子，并写入 CLHEP | `--seed 12345` |
| `--check-overlaps` | 覆盖几何 overlap 检查开关 | `--check-overlaps true` |
| `--dry-run` | 创建 managers 和 Geant4 user initialization objects，但不执行 macro/UI | `--dry-run` |
| `--help`, `-h` | 打印帮助 | `--help` |

如果既没有 `--macro` 也没有 `--ui`，程序只打印 usage，不会自动 `/run/beamOn`。

## 5. 配置文件 main.ini 写法

标准主配置见 `config/main.ini`。`SimulationManager::Configure()` 也兼容部分旧 key，例如 `randomSeed`、`outputDir`、`configFile`、`materialFile`，但新配置建议使用下表中的 key。

### `[run]`

| key | 含义 | 默认值 | 单位 | 示例 | 必需 |
|---|---|---|---|---|---|
| `name` | run 名称，写入 summary | context 默认 | 无 | `simple_test` | 否 |
| `threads` | 线程数 | `1` | 无 | `1` | 否 |
| `seed` | 随机种子 | unset | 无 | `12345` | 否 |
| `interactive` | 是否交互模式 | `false` | 无 | `false` | 否 |
| `verbose` | 框架 verbose | `0` | 无 | `1` | 否 |
| `check_overlaps` | overlap 检查 | context 默认 | 无 | `true` | 否 |
| `dry_run` | 是否 dry-run | `false` | 无 | `false` | 否 |
| `macro` | macro 文件 | 空 | 路径 | `macros/run_simple.mac` | 否 |

### `[output]`

| key | 含义 | 默认值 | 单位 | 示例 | 必需 |
|---|---|---|---|---|---|
| `dir` | 输出目录 | `output` | 路径 | `output/simple_test` | 否 |

### `[materials]`

| key | 含义 | 默认值 | 单位 | 示例 | 必需 |
|---|---|---|---|---|---|
| `file` | 材料配置文件 | 空 | 路径 | `config/materials/material.ini` | 几何需要材料时建议填写 |

### `[geometry]`

| key | 含义 | 默认值 | 单位 | 示例 | 必需 |
|---|---|---|---|---|---|
| `template` | 几何模板名 | `simple_box` | 无 | `simple_box` | `/run/initialize` 前必须有有效模板 |
| `config` | 几何配置文件 | 空 | 路径 | `config/geometry/simple_box.ini` | `/run/initialize` 前必须有 root/world |
| `check_overlaps` | placement overlap 检查 | context 默认 | 无 | `true` | 否 |
| `default_world_material` | world 默认材料 | `G4_AIR` | 无 | `G4_AIR` | 否 |

### `[physics]`

| key | 含义 | 默认值 | 单位 | 示例 | 必需 |
|---|---|---|---|---|---|
| `reference` | Geant4 reference physics list；非空时进入 Reference 模式 | 空，Manual 模式 | 无 | `FTFP_BERT_EMZ` | 否 |
| `em` | Manual EM option；Reference 模式下尝试变成 EM suffix | `G4EmStandardPhysics_option4` | 无 | `option4` | 否 |
| `list` | 旧兼容 key，等价设置 EM option | 空 | 无 | `option4` | 否 |
| `modules` | Manual 模块列表；Reference 模式下作为 extra module 兼容处理 | `G4DecayPhysics` | 无 | `decay, ion` | 否 |
| `extra_modules` | Reference 模式追加模块 | 空 | 无 | `optical` | 否 |
| `default_cut` | 全局 production cut | `1 mm` | 长度 | `1 mm` | 否 |
| `biasing` | 是否启用 generic biasing physics hook | `false` | 无 | `false` | 否 |
| `verbose` | physics verbose | `0` | 无 | `1` | 否 |

### `[physics.cuts]`

该 section 的所有 key 都会作为 particle name 读取，value 用长度单位解析：

```ini
[physics.cuts]
gamma = 1 mm
e- = 1 um
e+ = 1 um
proton = 1 um
```

### `[physics.region.<RegionName>]`

保存 region cut 配置，当前第一版主要保存到 `PhysicsManager`，实际 region production cuts 也可由 geometry 的 `region` + `cut.*` 创建：

```ini
[physics.region.SV]
gamma = 100 nm
e- = 100 nm
e+ = 100 nm
proton = 100 nm
```

### `[physics.microelec]`

| key | 含义 | 默认值 | 单位 | 示例 | 必需 |
|---|---|---|---|---|---|
| `enabled` | 是否注册可选 MicroElec 扩展 | `false` | 无 | `true` | 否 |
| `region` | 目标 region | `SV` | 无 | `SV` | 否 |
| `electron_capture` | 是否启用低能电子捕获辅助过程 | `false` | 无 | `true` | 否 |
| `electron_capture_threshold` | 捕获阈值 | `16.7 eV` | 能量 | `16.7 eV` | 否 |

### `[source]`

| key | 含义 | 默认值 | 单位 | 示例 | 必需 |
|---|---|---|---|---|---|
| `preset` | 源 preset | GPS 默认 | 无 | `proton_beam` | 否 |
| `particle` | 粒子名 | preset/GPS 默认 | 无 | `proton` | 否 |
| `energy` | 单能能量 | preset/GPS 默认 | 能量 | `10 MeV` | 否 |
| `position_type` | `point` 或 `plane` | preset/GPS 默认 | 无 | `point` | 否 |

| `direction` | 方向向量或 `+z` 等轴向 token | preset/GPS 默认 | 无 | `0,0,1` | 否 |
| `isotropic` | 是否各向同性 | `false` | 无 | `false` | 否 |
| `radius` | plane source 半径 | `1 mm` | 长度 | `1 mm` | plane 模式可选 |
| `center` | plane source 中心，当前使用 z 分量 | `0,0,-1 mm` | 长度 | `0,0,-1 mm` | plane 模式可选 |
| `verbose` | source verbose | `0` | 无 | `0` | 否 |

## 6. 材料文件 material.ini 写法

当前 `config/materials/material.ini` 使用 legacy alias 格式：

```ini
[World]
material = G4_AIR

[Silicon]
material = G4_Si
```

这表示注册一个别名 section，底层材料来自 NIST。

### 6.1 NIST 材料列表格式

`MaterialIniReader` 支持：

```ini
[Nist]
materials = G4_AIR, G4_Si, G4_WATER
```

### 6.2 同位素

```ini
[isotope.U235]
symbol = U
z = 92
n = 235
a = 235.0439 g/mole
```

### 6.3 元素

简单元素：

```ini
[element.Si]
symbol = Si
z = 14
a = 28.0855 g/mole
```

同位素组成元素：

```ini
[element.Uranium]
symbol = U
isotopes = U235:0.05,U238:0.95
```

同位素丰度必须加和为 1.0。百分数格式如 `5%` 也可被 fraction parser 解析。

### 6.4 自定义材料

按原子数：

```ini
[material.Si3N4]
density = 3.17 g/cm3
mode = atom_count
components = Si:3,N:4
state = solid
```

按质量分数：

```ini
[material.BEOLmix]
density = 3.0 g/cm3
mode = mass_fraction
components = G4_Cu:0.4,Si3N4:0.6
state = solid
```

支持密度单位：`g/cm3`、`g/cm^3`、`kg/m3`、`kg/m^3`、`mg/cm3`、`mg/cm^3`。

支持摩尔质量单位：`g/mole`、`g/mol`、`kg/mole`、`kg/mol`。

### 6.5 预留但未实现

`mode = volume_fraction` 可以被 parser 识别，但 `MaterialFactory` 当前会抛出：

```text
volume_fraction mode is reserved but not implemented
```

所以体积分数混合材料目前属于预留功能，不能作为可运行配置使用。

## 7. 几何配置写法

几何命令和 `main.ini` 中的 `[geometry]` 会调用 `GeometryManager`，再通过 `TemplateFactory` 选择模板。

支持模板名：

| 模板名 | 别名 | 状态 |
|---|---|---|
| `simple_box` | `simple` | 可用 |
| `layered_device` | `layered` | 可用 |
| `hierarchical` | 无 | 可用，基于 generic `[volume.*]` |
| `array` | 无 | 可用 |
| `shielding` | 无 | 可用 |
| `gdml` | 无 | placeholder，未真正导入 GDML |

### 7.1 simple_box 示例

来自 `config/geometry/simple_box.ini`：

```ini
[world]
size = 10 cm, 10 cm, 10 cm
material = G4_AIR

[target]
name = Target
shape = box
size = 1 cm, 1 cm, 1 mm
material = G4_Si
position = 0 mm, 0 mm, 0 mm
rotation = 0 deg, 0 deg, 0 deg
sensitive = true
bias = false
region = SV
cut.gamma = 1 um
cut.e- = 1 um
cut.e+ = 1 um
cut.proton = 1 um
```

必需 key：

- `[world]/size`
- `[world]/material`
- `[target]/size`
- `[target]/material`

### 7.2 layered_device 示例

来自 `config/geometry/layered_device.ini`：

```ini
[layers]
count = 3
names = Substrate, Oxide, Metal
auto_stack = true
axis = z
gap = 0 um

[layer.Oxide]
thickness = 1 um
xy = 10 mm, 10 mm
material = G4_WATER
sensitive = true
bias = false
region = OxideRegion
cut.e- = 100 nm
```

### 7.7 VolumeNode 常用字段

Generic `[volume.*]` 支持的常用字段包括：

- `name`：体积名，通常 section 名也可作为 name。
- `parent`：母体积名。
- `shape`：`box`、`tubs`/`cylinder`、`sphere`、`orb`、`cone`。
- `material`：材料名。
- `size`：box 全长，格式如 `1 cm, 1 cm, 1 mm`。
- `parameters`：非 box shape 参数。
- `position`：相对母体积位置。
- `rotation`：欧拉角。
- `sensitive`：是否标记 sensitive。
- `bias`：是否标记 bias volume。
- `region`：region 名。
- `cut.gamma`、`cut.e-`、`cut.e+`、`cut.proton`：region production cuts。

## 9. Source 粒子源用法

`SourceManager` 底层使用 `G4GeneralParticleSource`，并保留 Geant4 原生 `/gps/...` 命令。为了避免 `G4ParticleTable::CheckReadiness`，GPS 是 lazy 创建的：manager 构造时不创建 GPS，physics list 注册后再初始化或在 `PrimaryGeneratorAction` 生成事件时获取。

### 支持的 preset

当前 `SourceManager::ApplyPreset()` 支持：

| preset | 粒子 | 能量 | 位置 | 方向 |
|---|---|---|---|---|
| `mono_proton` | proton | `10 MeV` | `(0,0,-1 mm)` | `+z` |
| `proton_beam` | proton | `10 MeV` | `(0,0,-1 mm)` | `+z` |
| `neutron_beam` | neutron | `1 MeV` | `(0,0,-1 mm)` | `+z` |
| `gamma_beam` | gamma | `1 MeV` | `(0,0,-1 mm)` | `+z` |
| `isotropic_neutron` | neutron | `1 MeV` | `(0,0,0)` | isotropic |
| `plane_proton_beam` | proton | `10 MeV` | 半径 `1 mm`、z=`-1 mm` 的圆形面源 | `+z` |

### `/AIHL/source/...` 示例

```text
/AIHL/source/preset proton_beam
/AIHL/source/particle proton
/AIHL/source/energy 10 MeV
/AIHL/source/point 0 0 -1 mm
/AIHL/source/direction 0 0 1
```

面源示例：

```text
/AIHL/source/planeBeam radius=1 mm z=-1 mm direction=+z
```

### 原生 GPS 示例

高级源配置可以继续使用 Geant4 原生命令：

```text
/gps/particle proton
/gps/energy 10 MeV
/gps/pos/type Point
/gps/pos/centre 0 0 -1 mm
/gps/direction 0 0 1
```

注意不要和 `/AIHL/source/...` 在同一次初始化前反复覆盖同一 GPS 状态，除非你明确知道最后生效的命令顺序。

## 10. Physics 物理列表用法

Physics 模块支持 Reference 和 Manual 两种模式。

### 10.1 Reference 模式

```text
/AIHL/physics/setReferenceList FTFP_BERT_EMZ
/AIHL/physics/setDefaultCut 1 mm
```

Reference 模式使用 `G4PhysListFactory` 创建 Geant4 reference physics list，例如：

- `FTFP_BERT`
- `FTFP_BERT_HP`
- `FTFP_BERT_EMZ`
- `FTFP_BERT_LIV`
- `FTFP_BERT_PEN`
- `QGSP_BERT`
- `QGSP_BIC`
- `Shielding`

可用列表依赖你的 Geant4 版本，可以用：

```text
/AIHL/physics/listAvailableReferences
```

追加模块：

```text
/AIHL/physics/addExtraModule optical
```

Reference 模式下，`setEM` 不直接 `ReplacePhysics`，而是尝试修改 reference list 的 EM suffix，例如 `option4` 对应 `_EMZ`。

### 10.2 Manual 模式

```text
/AIHL/physics/clearReferenceList
/AIHL/physics/setEM option4
/AIHL/physics/addOther decay
/AIHL/physics/addHadronic bert
```

常见 alias 由 `PhysicsFactory` 统一处理，避免在各处复制 if/else。

### 10.3 Cuts

全局 cut：

```text
/AIHL/physics/setDefaultCut 1 mm
```

粒子 cut：

```text
/AIHL/physics/setCut e- 1 um
/AIHL/physics/setCut proton 1 um
```

Region cut：

```text
/AIHL/physics/setRegionCut SV e- 100 nm
```

当前分工：

- PhysicsList 处理全局 default cut 和 particle cut。
- Geometry/VolumeBuilder 在创建 `G4Region` 时可根据 geometry 配置里的 `cut.*` 设置 region production cuts。
- `PhysicsManager` 也保存 region cuts，用于后续策略统一和诊断。

### 10.4 MicroElec / ElectronCapture

MicroElec 是实验性高级可选模块：

```text
/AIHL/physics/enableMicroElec true
/AIHL/physics/setMicroElecRegion SV
/AIHL/physics/enableElectronCapture true
/AIHL/physics/setElectronCaptureThreshold 16.7 eV
```

`ElectronCapture` 只对电子适用，只在指定 region 内且电子动能低于阈值时触发。触发时通过 Geant4 particle change 产生 local energy deposit 并 kill track，不直接写 `ScoringManager`。

## 11. Scoring 输出用法

### 11.1 核心链路

```text
SensitiveDetector::ProcessHits
-> ParticleHit::ToHitRecord
-> ScoringManager::ScoreHit
-> EdepScorer
-> OutputManager
```

`SteppingAction` 默认不调用 `ScoreHit()`，避免和 `SensitiveDetector` 重复计分。

### 11.2 命令示例

```text
/AIHL/scoring/enable true
/AIHL/scoring/hits true
/AIHL/scoring/eventEdep true
/AIHL/scoring/edep true
/AIHL/scoring/autoCreateScorers true
/AIHL/scoring/setEdepHistogram 200 0 eV 10 MeV
/AIHL/scoring/setWeightedEdepHistogram bins=200 min=0 eV max=10 MeV
```

### 11.3 raw_edep 与 weighted_edep

- `raw_edep`：原始能量沉积，直接累加 `hit.edep`。
- `weighted_edep`：带权能量沉积，累加 `hit.edep * hit.weight`。

Biasing 启用后，应优先关注 weighted 结果。

### 11.4 输出文件字段

`hits_t0.csv`：

```text
eventID,trackID,parentID,particle,edep,ndep,stepLength,x0,y0,z0,x1,y1,z1,px,py,pz,kineticEnergy,process,volume,weight,LETcalc,LETstep
```

`event_edep_t0.csv`：

```text
eventID,raw_edep,weighted_edep
```

`hist_edep_raw_t0.csv` / `hist_edep_weighted_t0.csv`：

```text
bin_low,bin_high,count
```

具体 header 由 `Histogram1D::WriteCSV()` 决定；后处理工具按前三个数值列读取。

### 11.5 LET / Dose / Fluence 状态

当前：

- `LETScorer`：可注册，读取 hit 中预留 LET 字段，但不负责真实 LET 计算。
- `DoseScorer`：stub，Dose = edep / mass 需要体积质量信息，当前未实现。
- `FluenceScorer`：stub，fluence 需要面积或 track-length 定义，当前未实现。

## 12. Biasing 用法

### 12.1 工作原理

XS biasing 链路：

```text
BiasingMessenger 或 biasing.ini
-> BiasingManager 保存 XSBiasRule
-> PhysicsList / Reference list 注册 G4GenericBiasingPhysics
-> DetectorConstruction 构建 geometry
-> GeometryRegistry 提供 logical volumes
-> BiasingManager::AttachOperators
-> BiasingMultiParticleXS / BiasingXS
-> track weight
-> ScoringManager weighted scoring
```

### 12.2 Macro 示例

```text
/AIHL/biasing/enable true
/AIHL/biasing/xs/addParticle proton
/AIHL/biasing/xs/addProcessForParticle proton protonInelastic
/AIHL/biasing/xs/setFactor proton 100
/AIHL/biasing/xs/onlyPrimary proton true
/AIHL/biasing/xs/setMinWeight proton 0.05
/AIHL/biasing/xs/setMaxInteractions proton 5
/AIHL/biasing/xs/addVolume Target
/AIHL/physics/enableBiasing true
```

### 12.3 常见注意点

- 只执行 `/AIHL/biasing/enable true` 不够，还必须让 Physics 模块注册 generic biasing physics hook。
- volume 名称必须能在 `GeometryRegistry` 中找到。
- process 名称必须匹配 Geant4 实际 process 名称，如 `protonInelastic`。
- 带 biasing 的物理统计应看 `weighted_edep`。
- 动态修改 biasing 后建议重新初始化 geometry/physics，而不是运行中直接改。

## 15. 常见错误排查

### 15.1 MinGW 链接 MSVC Geant4 `.lib` 出现 unresolved symbol

现象：链接时报大量 `undefined reference to G4...`、`CLHEP...`、Qt/OpenGL 相关符号。

原因：工具链 ABI 不匹配。

解决：使用和 Geant4 一致的编译器。若 Geant4 是 MSVC 编译，使用 VS generator 或 Ninja + `cl.exe`。

### 15.2 找不到 `Geant4Config.cmake`

显式传入：

```powershell
-DGeant4_DIR="D:/ProgramFiles/Geant4/lib/cmake/Geant4"
```

### 15.3 找不到 `config/main.ini`

从项目根目录运行，或传绝对路径：

```powershell
.\build_vs\Release\G4UniversalSim.exe --config D:\Geant4\G4UniversalSim\config\main.ini --macro macros/run_simple.mac
```

### 15.4 `Material not found`

先加载材料：

```text
/AIHL/material/load config/materials/material.ini
```

并确认几何配置使用的是 Geant4 NIST 名称或已注册别名。

### 15.5 `root node is not set`

说明 geometry config 没加载成功。检查：

```text
/AIHL/geometry/setTemplate simple_box
/AIHL/geometry/loadConfig config/geometry/simple_box.ini
/AIHL/geometry/printTree
```

`simple_box` 必须有 `[world]/size`、`[world]/material`、`[target]/size`、`[target]/material`。

### 15.6 `/run/initialize` 失败

常见原因：

- 材料未加载。
- geometry root 为空。
- physics reference list 名称不可用。
- source 粒子名错误。
- Geant4 库/运行时环境不完整。

先使用 `macros/test_simple_min.mac` 或 `macros/run_simple.mac` 验证基础链路。

### 15.7 `hits_t0.csv` 没生成

可能原因：

- 没有 sensitive volume。
- 粒子没有打到 sensitive volume。
- step 中 `edep` 和 `ndep` 都为 0，`SensitiveDetector` 默认跳过 zero-edep hits。
- scoring hits 输出被关闭。

确认：

```text
/AIHL/scoring/hits true
```

### 15.8 `event_edep_t0.csv` 没生成

确认：

```text
/AIHL/scoring/enable true
/AIHL/scoring/eventEdep true
```

该文件在 event 结束时懒创建。

### 15.9 bias operator 没 attach

检查：

- `/AIHL/biasing/enable true`
- `/AIHL/physics/enableBiasing true`
- bias volume 名称是否存在于 `GeometryRegistry`
- 是否在 geometry build 后触发 post-build callback

### 15.10 physics reference list 找不到

使用：

```text
/AIHL/physics/listAvailableReferences
```

不同 Geant4 版本可用 reference list 不完全一致。

### 15.11 Qt / visualization 问题

先用 batch macro 不带 `--ui` 验证：

```powershell
.\build_vs\Release\G4UniversalSim.exe --macro macros/run_simple.mac
```

Qt/OpenGL 问题通常与 Geant4 可视化构建选项和运行时 PATH 有关。

### 15.12 CMake 不支持 Visual Studio 18 2026 generator

当前检查过的 CMake 输出显示不支持：

```text
Could not create named generator Visual Studio 18 2026
```

解决：

- 更新 CMake 到支持该 generator 的版本。
- 改用 `Visual Studio 17 2022`。
- 使用 Ninja + `cl.exe`。

## 16. 当前限制与后续计划

### 已可用

- simple_box、layered_device、array、shielding、hierarchical 模板。
- Reference/Manual physics。
- GPS source presets。
- SensitiveDetector + ParticleHit + HitRecord。
- raw/weighted event edep。
- Edep histogram。
- XS biasing 基础闭环。
- 后处理合并和绘图脚本。

### 实验性

- MicroElecPhysics / ElectronCapture。
- GDML placeholder。
- Biasing 的多粒子、多 process 场景需要结合具体 physics list 验证。

### Stub 或暂未完整实现

- LETScorer、DoseScorer、FluenceScorer 的真实物理计算。
- ParticleAggregator / 粒子分组高级分析。
- 多线程输出自动 merge。
- GDML 真导入。
- 复杂 phase-space / 多源系统。

### 多线程输出限制

`OutputManager` 不保证线程安全。当前设计倾向每个 worker 独立输出文件，例如 `_t0`、`_t1`，后续用 `merge_outputs.py` 或 `mergeHistograms` 合并。

## 17. 文档差异与待确认项

1. `AppMessenger` 和 `DetectorMessenger` 源码中有 `/AIHL/app/...`、`/AIHL/detector/...` 命令，但当前默认 executable 没有在 `SimulationManager` 或 `main.cc` 中实例化它们，因此运行时不一定注册。英文文档若暗示默认可用，需要修正或后续接入。
2. `GDMLTemplate` 当前只是 placeholder，不会真正用 `G4GDMLParser` 导入几何。
3. `volume_fraction` 材料模式 parser 可识别，但 `MaterialFactory` 明确未实现。
4. `CONFIG_REFERENCE.md` 中对 histogram 默认 max 的描述较简略；源码中建议用户显式写 `max = 10 MeV`，避免默认内部单位造成误解。
5. VS 2026 generator 命令仅适用于支持 `Visual Studio 18 2026` 的未来/对应 CMake；当前本机 CMake 不支持。
