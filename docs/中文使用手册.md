# G4UniversalSim 中文使用手册

整理日期：2026-07-11。本手册依据当前代码整理，主要覆盖 C++ 后端命令行程序、INI 配置、macro 命令、输出文件和常见问题。GUI 的使用说明见 `gui/docs/中文快速使用说明.md`，几何配置细节见 `docs/中文几何配置说明.md`。

## 1. 项目定位

G4UniversalSim 是一个基于 C++17 和 Geant4 的配置驱动仿真框架。当前可用能力包括：

- 通过 `config/main.ini` 组织运行参数、材料、几何、物理、源、计分和 biasing。
- 通过 Geant4 macro 执行 `/run/initialize`、`/run/beamOn` 以及 `/AIHL/...` 项目命令。
- 构建模板几何和层级几何，支持敏感体、计分输出和部分布尔实体操作。
- 使用 GPS 作为粒子源基础，提供若干轻量源预设。
- 使用 Geant4 参考物理列表，支持 process-level 截面 biasing 钩子。
- 输出 hits、event edep、edep 直方图、edep 分体积/分粒子汇总和 `run_summary.txt`。

当前程序不是完整的 Geant4 图形前端。`--ui` 只启动 Geant4 交互 UI 会话；项目 GUI 是另一个 Python/PySide6 外部运行器。

## 2. 快速运行

推荐从仓库根目录运行，并让所有配置路径相对仓库根目录解析。

```powershell
.\build_vs2026\Release\G4UniversalSim.exe --config config/main.ini --macro macros/run_simple.mac
```

也可以只执行一个自包含 macro：

```powershell
.\build_vs2026\Release\G4UniversalSim.exe --macro macros/run_hit_smoke.mac --threads 1 --output output/hit_smoke
```

常用 smoke 示例：

```powershell
# 敏感探测器、hits、event_edep、edep 直方图
.\build_vs2026\Release\G4UniversalSim.exe --macro macros/run_hit_smoke.mac --threads 1 --output test/output/hit_smoke_st

# 多线程输出，文件会带 _tN 后缀
.\build_vs2026\Release\G4UniversalSim.exe --macro macros/run_hit_smoke.mac --threads 2 --output test/output/hit_smoke_mt

# process-level XS biasing 初始化与挂接 smoke
.\build_vs2026\Release\G4UniversalSim.exe --macro macros/run_biasing_process_level_smoke.mac --threads 1 --output test/output/biasing_process_level_smoke

# volume_fraction 材料构建 smoke
.\build_vs2026\Release\G4UniversalSim.exe --macro macros/run_volume_fraction_test.mac --threads 1 --output test/output/volume_fraction_test
```

程序会先读取主配置并生成最终上下文；只有最终既不是 `dry_run`、也不是 `interactive`、且没有 macro 时，才打印帮助并退出。传入 `--dry-run` 或在主配置中设置 `dry_run = true` 时，会执行配置和 Geant4 对象注册，但跳过 macro/UI 执行。

配置优先级回归测试可从仓库根目录运行：

```powershell
python scripts\test_config_precedence.py
```

## 3. 命令行参数

| 参数 | 作用 |
| --- | --- |
| `--config <file>` 或 `-c <file>` | 指定主配置文件，通常是 `config/main.ini`。空路径会被拒绝。 |
| `--macro <file>` 或 `-m <file>` | 初始化对象创建完成后执行的 Geant4 macro。也支持把 macro 作为第一个位置参数传入；空路径会被拒绝。显式 CLI macro 优先于主配置中的 `[run]/macro`。 |
| `--output <dir>` 或 `-o <dir>` | 覆盖输出目录。优先级高于 `[output]/dir` 和 macro 的输出目录命令；空路径会被拒绝。 |
| `--run-name <name>` | 覆盖运行名称，优先级高于主配置和运行时上下文；空名称会被拒绝。 |
| `--ui` | 启动交互 UI，会初始化 `G4VisExecutive`。 |
| `--threads <N>` 或 `-t <N>` | 多线程构建下设置 worker 线程数，`N` 必须大于 0；优先级高于主配置和项目 macro 命令。 |
| `--seed <N>` | 设置随机种子，同时写入 `SimulationContext` 并设置 CLHEP；优先级高于主配置和项目 macro 命令。 |
| `--check-overlaps <true\|false>` | 覆盖几何重叠检查开关，并阻止低优先级项目命令改写。 |
| `--dry-run` | 创建并注册 Geant4 对象，但跳过 macro 和 UI 执行。 |
| `--help` 或 `-h` | 打印帮助。 |

当前没有 `--version` 参数。

### 配置优先级

当前已实现的启动字段优先级为：

`默认值 < 主配置文件 < macro 运行时命令 < 显式 CLI 参数`

主配置由 `SimulationManager::Configure()` 读取。显式 CLI 参数会在配置读取后重新应用；没有对应 CLI 参数时，项目自有 `/AIHL/app/*`、`/AIHL/output/setDir` 和 `/AIHL/geometry/checkOverlaps` 命令可以修改运行上下文。显式 `--macro` 也会覆盖主配置中的 `[run]/macro`。

主配置中的字段在各 Manager 完成读取后会进行消费追踪。拼写错误、未知 section 或已知 section 中没有被后端读取的 key 会输出 `[ConfigWarning]`，消息包含配置文件、行号、section、key 和原始值，接近拼写时会给出建议。warning 不会阻止 dry-run 或正常运行；摘要中的 `config_warning_count` 和 `[Warnings]` 会保留同一明细。材料文件和几何文件使用独立解析器，本机制不改变它们的未知字段规则。

`run_summary.txt` 在 dry-run、正常 macro、交互会话结束或失败收尾时写入最终状态。`[Values]` 中保留启动时的计划字段，并增加 `status`、`planned_event_count`、`actual_completed_event_count`、`run_count`、`actual_threads`、`configured_seed`、`initial_engine_seed`、`macro_seed_modified`、`actual_output_dir`、`macro_execution_status` 和失败命令位置等事实字段；`[Runs]` 记录每次 `beamOn`，`[GeneratedFiles]` 记录本次明确写入或实际修改的输出文件，即使文件在运行前已经存在。已知会改变随机状态的命令仅包括项目 `/AIHL/app/setSeed`、当前安装 Geant4 示例使用的 `/random/setSeeds` 和 `/random/resetEngineFrom`，且只有命令成功后才标记 `macro_seed_modified`。preflight 失败的 `macro_execution_status` 为 `preflight_failed`，并记录 `macro_failure_phase = preflight`；此时 `macro_failure_code = 0` 且 `macro_failure_code_available = false`，表示没有执行 `ApplyCommand()`。无法执行模拟时事件数为 0，无法可靠取得的值标记为 `unknown` 或 `not_executed`。

macro 执行前会递归检查静态 `/control/execute`，并使用同一份规范化命令序列执行。嵌套 macro 的相对路径按发出命令的当前 macro 文件目录解析，支持 Windows 反斜杠、带空格路径和 `../`；行尾 `#` 注释会在引号外移除。遇到首个 Geant4 命令失败时立即停止并返回非零退出码。当 CLI 锁定对应字段时，项目命令以及已知的 `/run/numberOfThreads`、`/random/...` 冲突命令会直接失败，并报告 macro 文件和行号。`/control/alias`、`/control/loop`、`/control/foreach` 等无法可靠静态分析的动态场景不支持；未被识别的任意 Geant4 命令不应被视为已受保护。

重复 CLI 参数采用最后一次出现的值；这是兼容行为，测试和文档均按此约定。字符串参数的空值会被拒绝。

当前未完整支持的能力会在启动或 macro 执行前明确拒绝：`placement=replica`、`placement=parameterised`、`placement=assembly`、GDML、材料 `temperature`/`pressure`、`[physics.region.*]` 以及 LET/Dose/Fluence 开启。几何 placement 暂时使用 `placement=normal` 并显式定义子 volume；region cuts 暂时使用 geometry volume 的 `cut.*`；材料只使用 density、state 和 composition；计分暂时使用 hits 或 Edep。相关字段为 false 或缺失时不影响现有配置。

## 4. 主配置文件结构

`main.ini` 是 `SimulationManager` 的主入口。典型文件如下：

```ini
[run]
name = simple_test
threads = 1
seed = 12345
interactive = false
verbose = 1
check_overlaps = true
dry_run = false

[output]
dir = output/simple_test

[materials]
file = config/materials/material.ini

[geometry]
template = simple_box
config = config/geometry/simple_box.ini
check_overlaps = true
default_world_material = G4_AIR

[physics]
reference = FTFP_BERT_EMZ
default_cut = 1 mm
biasing = false
verbose = 1

[source]
preset = proton_beam
particle = proton
energy = 10 MeV
position_type = point
position = 0,0,-1 mm
direction = 0,0,1

[scoring]
enabled = true
hits = true
event_edep = true
edep = true
let = false
dose = false
fluence = false
auto_create_default_scorers = true
verbose = 1

[scoring.edep]
raw_histogram = true
weighted_histogram = true
bins = 200
min = 0 eV
max = 10 MeV
volume_summary = true
particle_summary = true

[biasing]
enabled = false
```

主配置中的路径按进程工作目录解析。GUI 生成包会写入绝对路径，命令行手写配置则建议使用仓库根目录下的相对路径。

## 5. 材料配置

材料文件由 `[materials]/file` 指向，默认示例是 `config/materials/material.ini`。

材料独立配置文件采用闭合 schema，不是宽松的键值存储。允许 `[NIST]` 的 `materials`、`[isotope.<name>]`、`[element.<name>]`、`[material.<name>]` 及 legacy `[Alias] material = G4_*`。旧 GUI run package 在 `[material.<name>]` 中生成的 `type = material` 已弃用但仍兼容，读取时忽略大小写和首尾空白且不改变材料定义；新 GUI 不再写出该字段，其他值、空值或其他 section 中的 `type` 会直接失败。隐式 `global` 不得有字段；未知 section、空的动态名称后缀和多余 key 会在 Geant4 初始化前直接失败，并报告文件、行号、section、key 和 value，接近拼写时会给出建议。`temperature` 和 `pressure` 仍使用专用的未支持错误；请改用 density、state 和 composition。该规则与主配置的 warning 不同，材料 schema 错误会导致非零退出。

旧式 NIST 别名仍然可用：

```ini
[World]
material = G4_AIR

[Silicon]
material = G4_Si
```

新版材料段支持 `[nist]`、`[isotope.<name>]`、`[element.<name>]` 和 `[material.<name>]`。

```ini
[nist]
materials = G4_AIR, G4_WATER, G4_Si

[material.Epoxy]
mode = mass_fraction
density = 1.20 g/cm3
components = G4_C:0.60, G4_H:0.08, G4_O:0.32
state = solid

[material.WaterLike]
mode = atom_count
density = 1.0 g/cm3
components = G4_H:2, G4_O:1

[material.Composite]
mode = volume_fraction
density = auto
components = G4_SILICON_DIOXIDE:0.85, Epoxy:0.15
```

材料规则：

- `mass_fraction` 的组分数值必须加和为 1.0。
- `atom_count` 的组分必须引用元素，数值表示原子数。
- `volume_fraction` 的组分数值必须加和为 1.0，并且组分必须是材料。不要直接用裸元素做体积分数组分；如果需要元素，先定义成有密度的材料再引用。
- `density = auto` 只支持 `volume_fraction`，会按组分密度计算理想加和密度。
- `volume_fraction` 也可以写显式密度；程序会用体积分数和组分密度转换质量分数，最终 `G4Material` 使用显式密度。

## 6. 几何入口

几何入口在主配置中设置：

```ini
[geometry]
template = simple_box
config = config/geometry/simple_box.ini
check_overlaps = true
default_world_material = G4_AIR
```

可选模板为 `simple_box`、`layered_device`、`hierarchical`、`array` 和 `shielding`。`gdml` 配置入口为兼容保留项，但当前后端和 GUI validator 会在运行前明确拒绝，不能当作可运行 GDML 导入功能使用。

几何详细写法见 `docs/中文几何配置说明.md`。

## 7. 源配置

`[source]` 会配置 GPS 的当前源。常用字段：

| 字段 | 说明 |
| --- | --- |
| `preset` | 支持 `proton_beam`、`mono_proton`、`neutron_beam`、`gamma_beam`、`isotropic_neutron`、`plane_proton_beam`。 |
| `particle` | Geant4 粒子名，例如 `proton`、`neutron`、`gamma`、`e-`。 |
| `energy` | 单能源，例如 `10 MeV`。 |
| `position_type` | 当前后端支持 `point` 和 `plane`。 |
| `position` | 点源坐标，例如 `0,0,-1 mm`。 |
| `direction` | 方向向量或 `+x`、`-x`、`+y`、`-y`、`+z`、`-z`。 |
| `radius` | `position_type = plane` 时的圆形平面源半径。 |
| `isotropic` | 为 `true` 时使用各向同性角分布。 |
| `verbose` | 源模块输出级别。 |

高级源调整仍可使用 Geant4 原生 `/gps/...` 命令。

## 8. 物理配置

推荐使用 Geant4 参考物理列表：

```ini
[physics]
reference = FTFP_BERT_EMZ
default_cut = 1 mm
biasing = false
```

当前代码列出的参考列表包括 `FTFP_BERT`、`FTFP_BERT_HP`、`FTFP_BERT_EMZ`、`FTFP_BERT_LIV`、`FTFP_BERT_PEN`、`QGSP_BERT`、`QGSP_BIC` 和 `Shielding`。

可选字段：

- `em`：对参考列表应用 EM 后缀，例如 `option4`、`livermore`、`penelope`。
- `modules`：手动模式下的模块列表；参考模式下会被兼容处理为 `extra_modules`。
- `extra_modules`：参考模式下额外注册的模块。
- `default_cut`：默认 production cut。
- `biasing`：启用 generic biasing physics 钩子。真正的 biasing 规则还要在 `[biasing]` 中配置。
- `[physics.cuts]`：按粒子设置 cut，例如 `e- = 1 um`。
- `[physics.region.<RegionName>]`：兼容入口仍可被识别，但当前会 fail-fast；请改用 geometry volume 的 `cut.*`。
- `[physics.microelec]`：可启用区域级 MicroElec 扩展和电子捕获辅助过程；该能力仍属于高级/实验路径。

## 9. 计分和输出

`[scoring]` 控制是否写出 hit、event edep 和默认 scorer：

```ini
[scoring]
enabled = true
hits = true
event_edep = true
edep = true
let = false
dose = false
fluence = false
auto_create_default_scorers = true
```

当前最可靠的 scorer 是 `edep`。LET、Dose、Fluence 尚未具备完整运行时计算和输出契约，开启时会 fail-fast；暂时使用 hits 或 Edep。

`[scoring.edep]` 控制 raw/weighted event edep 直方图和汇总：

```ini
[scoring.edep]
raw_histogram = true
weighted_histogram = true
bins = 200
min = 0 eV
max = 10 MeV
volume_summary = true
particle_summary = true
```

常见输出文件：

- `run_summary.txt`
- `hits_t0.csv`
- `event_edep_t0.csv`
- `hist_edep_raw_t0.csv`
- `hist_edep_weighted_t0.csv`
- `edep_volume_summary_t0.csv`
- `edep_particle_summary_t0.csv`

多线程运行时，每个 worker 会写自己的 `_tN` 文件。后端不会自动合并 CSV 或直方图。需要显式运行合并工具：

同一进程连续执行多次 `/run/beamOn` 时，首轮保留 `_tN` 文件名，后续 run 使用 `_tN_rR`（`R` 为 run ID），不会再覆盖前一次数据。hits/event CSV 的首列 `runID` 用于区分各次 run。详细的列、单位、文件生成条件和旧版兼容边界见 [输出数据契约](输出数据契约.md)；这些输出不等于物理结果已经验证。

```powershell
python scripts\merge_outputs.py --input test\output\hit_smoke_mt --pattern "hits_t*.csv" --output test\output\hit_smoke_mt\hits_merged.csv
python scripts\merge_outputs.py --input test\output\hit_smoke_mt --pattern "event_edep_t*.csv" --output test\output\hit_smoke_mt\event_edep_merged.csv
.\build_vs2026\Release\mergeHistograms.exe --input test\output\hit_smoke_mt --pattern hist_edep_raw_t*.csv --output test\output\hit_smoke_mt\hist_edep_raw_merged.csv
.\build_vs2026\Release\mergeHistograms.exe --input test\output\hit_smoke_mt --pattern hist_edep_weighted_t*.csv --output test\output\hit_smoke_mt\hist_edep_weighted_merged.csv
```

## 10. 进程级截面偏置

推荐使用 process-level 配置：

```ini
[physics]
reference = FTFP_BERT_EMZ
biasing = true

[biasing]
enabled = true

[biasing.xs.proton.hIoni]
enabled = true
factor = 10
only_primary = true
apply_to_secondaries = false
min_weight = 0.05
max_interactions = 5
volumes = Target
```

规则说明：

- `[biasing]/enabled = true` 才会加载 biasing 规则。
- `[physics]/biasing = true` 会注册 generic biasing physics 钩子。若 biasing 规则存在，`SimulationManager` 也会自动打开该物理钩子。
- section 名必须是 `[biasing.xs.<particle>.<process>]`。当前不支持名称中带 `.` 的 process。
- `volumes` 为空时，会尝试使用几何中标记 `bias = true` 的 logical volume。
- 旧式 `[biasing.xs]` 粒子级写法仍兼容，但会打印 legacy 警告，不建议新配置继续使用。

## 12. 常见问题

### 运行后没有 hits 文件

确认几何体设置了 `sensitive = true`，`[scoring]/hits = true`，并且粒子确实在敏感体内沉积了能量。`macros/test_simple_min.mac` 可能只验证初始化，不一定产生 hit。验证 hit 链路请优先用 `macros/run_hit_smoke.mac`。

### 修改几何后结果没有变化

几何、材料、物理大多应在 `/run/initialize` 前配置。初始化后改几何，需要 `/run/reinitializeGeometry` 或重启进程；改物理通常需要 `/run/physicsModified` 或重启。

### 材料找不到

几何中的 `material` 必须是已加载材料、NIST 材料，或材料配置里定义的别名。GUI 生成包会把材料文件复制或生成到包内，不会覆盖原始材料文件。

### 几何根节点为空

检查几何模板和几何文件是否匹配。`hierarchical` 模板必须有 `[world]`；非 world 体积必须有有效 `parent`。

### M0-3B2B1 几何安全校验

几何文件中的 production cut、固定模板 shape、hierarchical shape 参数、boolean tool 参数、`copyNo` 和 placement 会在首个 Geant4 geometry object 创建前校验。cut 仅允许 `cut.gamma`、`cut.e-`、`cut.e+`、`cut.proton`，并要求同 section 存在非空 `region`。M0-3B2B2 进一步提供来源诊断、legacy metadata 和 boolean ignored-key warning；严格 `version=2`、自动迁移和完整无损 round-trip 留给 M0-3B3。

### GDML 初始化失败

当前 GDML 尚未实现，配置会在后端校验阶段被拒绝。不要把它当作可运行的 GDML world replacement。

### 多线程输出不是一个总 CSV

这是当前设计。每个 worker 写 `_tN` 文件，合并需要显式运行 `scripts/merge_outputs.py` 或 `mergeHistograms.exe`。

## 13. 当前边界

- STL 导入未实现。
- GDML 导入未实现，配置会 fail-fast。
- importance、weight-window、splitting、Russian roulette 等高级 biasing 未实现。
- LET、Dose、Fluence 当前未支持，开启会 fail-fast。
- 后端支持的几何能力和 GUI 可编辑能力不完全相同；GUI 说明中会单独列出 GUI 限制。
