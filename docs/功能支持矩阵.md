# G4UniversalSim 功能支持矩阵

基线日期：2026-07-11。判定依据是当前后端实际实现和仓库中的可运行测试，不依据旧文档、GUI 控件名称或类名。

## 1. 支持等级定义

| 等级 | 判定规则 |
| --- | --- |
| 完整支持 | 后端完成配置/命令解析、校验和运行时行为，结果或状态有明确输出，并有相应测试或 smoke 证据。 |
| 部分支持 | 只完成部分入口或运行路径，存在实验性限制、未闭合依赖、有限形状/分布、手工后处理或物理结果尚未验证。 |
| 未支持 | 后端没有运行时实现，或者只是占位/空实现；解析成功、GUI 显示或类已注册不改变此等级。 |

GUI 的“可编辑”不提升后端支持等级；GUI 只支持后端已经实现且 writer/validator 能正确闭环的子集。

## 2. 核心后端

| 领域 | 功能 | 等级 | 当前事实和边界 |
| --- | --- | --- | --- |
| 配置 | INI section/key 读取、注释、基本类型和单位解析 | 完整支持 | 由 IniReader、ConfigManager、UnitParser 等实现；不同模块仍有各自校验。 |
| 配置 | 主 INI 字段消费追踪和未消费字段 warning | 部分支持 | M0-3B1 保留主配置字段的文件、行号、原始值和消费状态；配置完成后报告未知 section 和未消费 key，并写入 `run_summary.txt`。材料文件和几何文件仍使用独立解析器。 |
| 配置 | CLI、主 INI、macro 的统一优先级和来源追踪 | 部分支持 | M0-1/M0-1b 已将启动流程统一为“默认值 < 主配置文件 < macro 运行时命令 < 显式 CLI 参数”，并对已知项目命令、`/run/numberOfThreads` 和 `/random/...` 做递归 preflight；动态 alias/loop/foreach 不支持。仍没有完整 EffectiveConfig 和来源追踪，任意未识别的 Geant4 命令也不应视为已保护。 |
| 材料 | NIST 材料和旧式 [Alias] material = G4_* | 完整支持 | 通过 G4NistManager 构建或查找。 |
| 材料 | 自定义元素、同位素、质量分数、原子计数 | 完整支持 | MaterialIniReader 和 MaterialFactory 有实际构建与依赖校验。 |
| 材料 | 材料体积分数混合 | 完整支持 | 仅接受材料组分；支持 density = auto 或显式密度，并转换为质量分数。 |
| 材料 | 材料 temperature、pressure | 未支持 | 配置和 Messenger 明确拒绝；暂时使用 density、state 和 composition。 |
| 几何 | simple_box、layered_device、hierarchical、shielding 模板 | 完整支持 | 后端可构建；layered_device 和 shielding 当前只沿 z 轴工作。 |
| 几何 | array 模板 | 部分支持 | 可生成规则阵列，但模板逻辑和参数主要围绕盒状阵元；其他 shape 组合需单独验证。 |
| 几何 | box、tubs、sphere、orb、cone、trd、trap | 完整支持 | VolumeBuilder 有对应 Geant4 solid 创建器；各实体参数契约不同。 |
| 几何 | 层级树、位置、旋转、敏感体、bias 体、copy number、可视化属性 | 完整支持 | 普通层级体积走 G4PVPlacement，并注册到 GeometryRegistry。 |
| 几何 | placement = replica/parameterised/assembly | 未支持 | 后端在几何校验阶段拒绝，不能退化为 G4PVPlacement；暂时使用 `placement=normal` 和显式子 volume。 |
| 几何 | subtraction、union、intersection 布尔实体 | 部分支持 | 后端实际创建 CSG solid；union/intersection 会警告，仍需 overlap 和场景级结果验证。 |
| 几何/物理 | production cut | 部分支持 | geometry volume 的 `cut.*` 可应用；`[physics.region.*]` 在统一实现前明确拒绝，暂时使用 geometry volume 的 `cut.*`。 |
| 几何 | GDML 导入 | 未支持 | 后端在配置校验阶段拒绝，GUI validator 也阻断；暂时使用受支持的几何模板。 |
| 几何 | STL/CAD 导入 | 未支持 | 当前没有导入实现。 |
| 物理 | Geant4 reference physics list | 完整支持 | 通过 G4PhysListFactory 创建，并可应用 EM 后缀和额外模块。 |
| 物理 | 手动物理模块、默认 cut、粒子 cut | 完整支持 | PhysicsList、PhysicsFactory 和 PhysicsManager 有运行时路径。 |
| 物理 | MicroElec 和 ElectronCapture | 部分支持 | 有构造、区域和阈值配置；依赖 Geant4 构建能力，仍属于实验路径，需场景基准。 |
| 源 | GPS 粒子、单能、点位置、固定方向、各向同性 | 完整支持 | SourceManager 配置后驱动 G4GeneralParticleSource。 |
| 源 | 平面圆形源 | 完整支持 | 后端生成 Plane + Circle；方向和位置参数有有限语义。 |
| 源 | 高级矩形/环形/锥形/余弦/聚焦分布 | 未支持 | GUI 中部分字段只是预览模型，C++ 配置 writer 不生成这些 GPS 设置。 |
| 探测 | sensitive logical volume 到 SensitiveDetector 的绑定 | 完整支持 | DetectorConstruction 根据 GeometryRegistry 绑定 hit 链路。 |
| 计分 | hits、raw/weighted event edep、Edep 直方图和分体积/分粒子汇总 | 完整支持 | EdepScorer、OutputManager 和线程本地 context 有实际输出。 |
| 计分 | LET | 未支持 | 没有可靠运行时 LET 计算链，开启时 fail-fast；暂时使用 hits 或 Edep。 |
| 计分 | Dose、Fluence | 未支持 | 没有完整物理和输出契约，开启时 fail-fast；暂时使用 Edep 或 hits。 |
| 偏置 | process-level 截面 biasing | 部分支持 | 可解析、校验、挂接和运行 smoke；现有测试不证明 biased/analog 物理结果等价。 |
| 偏置 | legacy particle-level XS 兼容语法 | 部分支持 | 有兼容展开和警告；新代码应优先使用 process-level 规则。 |
| 偏置 | importance、weight window、splitting、Russian roulette | 未支持 | 当前没有对应运行时实现。 |
| 输出 | hits/event edep/直方图/汇总/run_summary.txt | 完整支持 | 文件按需创建；多线程 worker 产生 _tN 文件。M0-2 后摘要在最终生命周期阶段写入，并记录每次 run、实际事件数、状态、失败命令和生成文件；输出文件清单不等于物理结果验证。 |
| 输出 | /AIHL/output/setDir、线程后缀、flush、close、print | 完整支持 | OutputMessenger 已注册；无显式 CLI `--output` 时可由 macro 改目录，显式 CLI `--output` 会锁定输出目录；改变目录仍应在初始化和文件打开前完成。 |
| 输出 | 多线程自动合并 | 未支持 | 后端只写每线程文件，需要 scripts/merge_outputs.py 或 mergeHistograms 手工/GUI 触发。 |
| 输出 | CSV 单位和版本化数据契约 | 部分支持 | 列名存在，但当前 header 未携带单位和 schema 版本。 |

## 3. GUI 和工具

| 功能 | 等级 | 当前事实和边界 |
| --- | --- | --- |
| PySide6 项目、运行包、QProcess 运行、日志和历史 | 完整支持 | gui/g4usim_gui/core、widgets 和 smoke tests 覆盖主要流程。 |
| 项目 JSON 读写和旧字段兼容 | 部分支持 | 当前 schema 为 G4UniversalSimProject version 5，已有兼容逻辑，但仍需版本化迁移测试。 |
| 材料编辑器 | 部分支持 | 支持 NIST、质量分数、体积分数、原子计数的有限 writer；自定义元素/同位素、温压等字段不能完整 round-trip。 |
| 几何编辑器 | 部分支持 | 可生成 simple box、layered device、hierarchical/boolean 子集；trd/trap、高级模板和复杂预览不是完整 GUI 编辑能力。 |
| 源编辑器 | 部分支持 | 可生成 point/fixed、point/isotropic、plane circle 的子集；其他分布会被校验阻止。 |
| 物理编辑器 | 部分支持 | 可生成 reference list、default cut 和 biasing hook；手动物理模块与 biasing 规则没有完整编辑器。 |
| 计分编辑器 | 部分支持 | 开放 hits、event edep、Edep 和直方图；LET/Dose/Fluence 被阻止，不应开放为有效功能。 |
| 3D 预览 | 部分支持 | 预览不是后端几何真值；能力取决于 PyVista/3D 依赖，对未支持实体应显示近似或不可用。 |
| GUI 国际化 | 未支持 | 当前界面主要是硬编码英文字符串，未建立 QTranslator/翻译资源闭环。 |
| GUI 主题和配置持久化 | 未支持 | 当前没有统一浅色/深色/系统主题与持久化策略；零散样式不能当作主题系统。 |
| 输出合并工具和历史扫描 | 完整支持 | GUI 可发现线程文件并调用 Python/C++ 合并工具；合并仍是后处理，不是后端自动行为。 |

## 4. 状态变更门槛

把一项能力从“部分支持”改为“完整支持”至少需要：后端解析、校验、运行时、输出契约、单线程/必要时多线程测试、GUI 生成或明确“不适用”、中文文档和 Agent 文档全部同步。把“未支持”改为“部分支持”也必须先有真实运行时行为，不能只增加开关、枚举、空类或预览控件。
