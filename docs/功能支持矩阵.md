## 1. 支持等级定义

| 等级 | 判定规则 |
| --- | --- |
| 完整支持 | 后端完成配置/命令解析、校验和运行时行为，结果或状态有明确输出，并有相应测试或 smoke 证据。 |
| 部分支持 | 只完成部分入口或运行路径，存在实验性限制、未闭合依赖、有限形状/分布、手工后处理或物理结果尚未验证。 |
| 未支持 | 后端没有运行时实现，或者只是占位/空实现；解析成功、GUI 显示或类已注册不改变此等级。 |

GUI 的“可编辑”不提升后端支持等级；GUI 只支持后端已经实现且 writer/validator 能正确闭环的子集。

2026-10-19 M0 交互错误审计增量：`csh` 的直接 Geant4 UI 命令现由派生终端执行并逐条取得 `ApplyCommand()` 数值返回码，已有错误文本分类继续保留，其他非零返回码以 `geant4_command_status` 报告。真实 `/gps/pos/type InvalidCandidate` 的状态码 500 可被记录，摘要中的多行诊断已归一化；新增受控 shell 在已识别失败后立即停止读取后续命令。仍仅**部分支持**，未覆盖 Qt UI、动态嵌套执行和所有未被明确识别的失败，M0 未验收。证据见 `scripts/test_interactive_commands.py`、`docs/测试平台说明.md`。

2026-10-19 源应用回归增量：真实 Geant4 的单线程双 run 通过敏感体首步记录验证同一进程由 `e-`/1 MeV 切换到 `proton`/3 MeV，并与最终来源摘要比对。该观测只覆盖这一点源、单能、硅敏感目标的受控路径；`effective_config_geant4_applied=unknown` 的整体判定不变，其他 GPS 分布和物理正确性仍未验证。

2026-10-03 状态补充：Git HEAD 为 `018345c`，B2B2 已提交；GUI 展示和 C0A 为尚未提交的工作区实现。下表明确区分 Git 基线与工作区验证，未跟踪源码的全新检出验证仍未完成。阶段证据见 `docs/开发审计与阶段目标.md`。

## 4. 状态变更门槛

把一项能力从“部分支持”改为“完整支持”至少需要：后端解析、校验、运行时、输出契约、单线程/必要时多线程测试、GUI 生成或明确“不适用”、中文文档和 Agent 文档全部同步。把“未支持”改为“部分支持”也必须先有真实运行时行为，不能只增加开关、枚举、空类或预览控件。
