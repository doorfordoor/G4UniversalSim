# G4UniversalSim 功能支持矩阵

基线日期：2026-07-11。判定依据是当前后端实际实现和仓库中的可运行测试，不依据旧文档、GUI 控件名称或类名。

## 1. 支持等级定义

| 等级 | 判定规则 |
| --- | --- |
| 完整支持 | 后端完成配置/命令解析、校验和运行时行为，结果或状态有明确输出，并有相应测试或 smoke 证据。 |
| 部分支持 | 只完成部分入口或运行路径，存在实验性限制、未闭合依赖、有限形状/分布、手工后处理或物理结果尚未验证。 |
| 未支持 | 后端没有运行时实现，或者只是占位/空实现；解析成功、GUI 显示或类已注册不改变此等级。 |

GUI 的“可编辑”不提升后端支持等级；GUI 只支持后端已经实现且 writer/validator 能正确闭环的子集。

2026-10-03 状态补充：Git HEAD 为 `018345c`，B2B2 已提交；GUI 展示和 C0A 为尚未提交的工作区实现。下表明确区分 Git 基线与工作区验证，未跟踪源码的全新检出验证仍未完成。阶段证据见 `docs/开发审计与阶段目标.md`。

| 输出 | /AIHL/output/setDir、线程后缀、flush、close、print | 部分支持 | OutputMessenger 已注册；无显式 CLI `--output` 时可由 macro 改目录，显式 CLI `--output` 会锁定输出目录。batch 命令处理器或 OutputManager setter 抛异常时，即使 `ApplyCommand()` 返回 0，也已验证中断 macro、失败摘要、原目录及来源不误变更。交互 `csh` 会话的材料/输出 Messenger 失败现于会话结束时判定为失败并记录类别和消息；逐条即时中止及其他命令未闭合。改变目录仍应在初始化和文件打开前完成。 |

| 输出 | CSV 单位和版本化数据契约 | 部分支持 | M0-4 工作区候选在摘要和 `--capabilities` 中标记 CSV 契约 v3，当前已验证的能量/长度列带 `_MeV`/`_mm`，hits 不再输出未计算的 LET 零值列；摘要按实际表头标记 v2/v3/`unknown`。hits/event 保留 `runID`、后续 run 文件使用 `_rR`，单线程与双线程两次 `beamOn` 已验证不覆盖；关闭总计分时不再写全零 event CSV。Windows 中文主配置、macro、输出目录的摘要路径可按 UTF-8 读取。共享 worker 错误登记、batch 非零退出/失败摘要、真实双线程事件行及汇总关闭两类故障注入已验证；已知目录冲突拦截、合并发布失败注入也已补充。字段语义与迁移见 `docs/输出数据契约.md`；通用直方图单位、自由文本/CSV 内容编码、真实设备故障及交互 UI 路径尚未闭合。 |
| 测试 | M0-5 统一入口与构建身份 | 部分支持 | 工作区 `scripts/run_m0_tests.py` 与 CTest 按 static/GUI/backend/integration 分层，JSON 报告区分 pass/fail/skip；主后端 `--capabilities.source_fingerprint` 与合并工具 `--source-fingerprint` 防止旧二进制冒充当前源码，报告另列编译器、配置、Geant4 版本及 MT 状态。严格门槛列出未纳入 Git 的源文件。Windows/Linux 无 Geant4 CI workflow 候选仅通过本地 YAML 结构检查，未在 GitHub 运行；当前严格门槛会因 24 个未纳入 index 的源文件失败。干净检出、完整构建选项、跨平台及 Geant4 CI、可选依赖和物理基准仍未闭合。 |

交互命令 M0 增量（2026-10-19）：`csh` 模式现识别不存在的命令以及已验证的参数类型拒绝（例如 `/run/beamOn wrong`），并在结束后写 `status=failed` 和非零退出码。仅覆盖明确匹配的 Geant4 诊断，不具备逐条命令返回码保证；支持等级仍为“部分支持”。

## 4. 状态变更门槛

把一项能力从“部分支持”改为“完整支持”至少需要：后端解析、校验、运行时、输出契约、单线程/必要时多线程测试、GUI 生成或明确“不适用”、中文文档和 Agent 文档全部同步。把“未支持”改为“部分支持”也必须先有真实运行时行为，不能只增加开关、枚举、空类或预览控件。
