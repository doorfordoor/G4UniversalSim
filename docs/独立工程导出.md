# 独立 Geant4 工程导出

本页说明 K2-2 新增的“导出 Geant4 工程”功能：从当前项目（或向导生成的单目标项目）写出一个**可独立审阅、可独立构建**的 C++/CMake 工程。导出的工程不包含图形界面、后端可执行文件、Geant4 SDK 与物理数据，也不承诺物理结果、可复现性签名或完整工具链。

支持等级与验收状态以 `功能支持矩阵.md`、`ROADMAP.md` 与 [K2 合同](collab/outbox/20261107-k2-contract.md) 为准；本页只说明入口、产物和限制。

## 1. 支持的两个子集

| 子集 | 来源 | 内容 |
| --- | --- | --- |
| S-A 外部项目 | 已打开的外部项目（例如 `examples/07_parallel_world_box/`） | 主 INI、材料/几何/并行世界 INI、宏、资源文件，按白名单重写路径键 |
| S-B 生成项目 | 向导“单目标”生成的当前配置 | 先用现有 writer 在隔离 staging 生成运行包，再对同一组白名单键重写路径 |

两个子集都只支持单进程工作目录（cwd）语义、单 run 宏、`hits=false` 的输出子集；其他功能（多 run、GUI、任意物理列表、任意源/计分组合）不在 K2-2 范围。

## 2. 入口

- GUI：菜单 **Project → Export Geant4 project...**。项目不可导出时动作禁用，悬停提示给出原因（无几何、外部配置缺失、输出目录冲突等）。
- 命令行：

  ```text
  python -m g4usim_gui.experiment_cli --project <项目目录或项目 JSON> export-project --destination <导出目录>
  ```

  仅接受新目录（不含 `export-manifest.json`）或同一父目录下的新名称；已存在、位于源项目或模板树内、含链接/重解析点的目标均拒绝。
- 导出前请确认项目自身可运行：导出的工程只重写输入路径，不修复非法配置。

## 3. 导出目录布局

```text
<导出目录>/
  CMakeLists.txt              独立 CMake 工程（Geant4 REQUIRED）
  CMakePresets.json           Visual Studio presets（Linux 不使用）
  cmake/                      构建身份与运行时辅助
  main.cc include/ src/ tools/ schema/   后端源码（含工具与 schema）
  config/ macros/             模板默认配置与宏（未被项目引用时不参与运行）
  docs/                       4 份中文文档
  README.md                   仓库 README（原样）
  licenses/                   3 份第三方许可文本
  scenarios/semiconductor/niel/si_proton.csv
                              h2 组件测试所需的 SR-NIEL 输入（模板唯一数据成员）
  THIRD_PARTY_NOTICES.md      宿主依赖与项目自身许可证状态说明
  export-template-manifest.json  模板身份清单（复制自安装模板）
  project/
    README.md                 外部项目保留源字节；生成项目由导出器写说明
    main.ini                  已按白名单重写路径键的主配置
    config/materials.ini      材料配置（外部）或生成材料配置
    config/geometry.ini       几何配置
    config/parallel.ini       并行世界配置（仅 S-A）
    macros/run.mac            运行宏
    resources/                资源闭包（相位空间、场图、STL 等，如有）
  README-EXPORT.md            导出说明与冻结运行命令
  export-manifest.json        导出身份清单（不含自身哈希）
```

## 4. 路径语义（重要）

后端按**进程工作目录（cwd）**解析主 INI 中的相对路径，不按配置文件所在目录解析；`--working-directory` 是唯一会显式 `chdir` 的参数，导出命令不使用它。因此：

- 所有命令必须在**导出根**执行，不要 `cd project/`。
- 主 INI 中只重写已存在的白名单键：`[output] dir`、`[materials] file`、`[geometry] config`、`[parallel_world] geometry_config`，以及已存在的 `[run] macro`；材料与主几何值写成 `project/config/...`，输出写成 `runs/default/output` 等相对导出根的路径。
- `[parallel_world] geometry_config` 例外：后端 `ParallelWorldConfig` 按主 INI 所在目录解析该值，因此导出时写 `config/parallel.ini`（文件本身仍在 `project/config/parallel.ini`）；这是真实消费者语义，不是相对导出根的路径。
- 不插入原本不存在的键（例如 S-A 的 `[run] macro` 与 `[output] format`），以免改变原始运行语义；`[run] macro` 是 S-A 已有内容时的唯一位置来源。
- `rewrite_main_ini` 只替换值跨度，保留缩进、CRLF/LF、BOM、行内注释与无末尾换行。

## 5. 导出命令（冻结）

Windows（在导出根执行）：

```text
build_vs2026\Release\G4UniversalSim.exe --config project/main.ini --macro project/macros/run.mac --output runs/default/output
```

Linux（在导出根执行）：

```text
build_linux/G4UniversalSim --config project/main.ini --macro project/macros/run.mac --output runs/default/output
```

只检查配置而不运行物理时追加 `--dry-run`。

## 6. 构建

依赖（宿主自备，不随包分发）：

- CMake ≥ 3.21、C++17 编译器；
- Geant4 11.3.2 或 11.4.3（同一 ABI；含数据变量/G4 数据目录）；
- 可视化所需的 Qt5；GDML 所需的 Xerces-C（本机 Geant4 前缀内可自动推导 `XercesC_ROOT`）；
- 导出工程不需要 Python、PySide6 或图形界面。

Windows（单行，在导出根）：

```text
cmake --preset vs2026-x64 -DCMAKE_PREFIX_PATH=<Geant4 前缀> -G "Visual Studio 18 2026" -A x64
```

```text
cmake --build build_vs2026 --config Release
```

```text
ctest --test-dir build_vs2026 -C Release -L "^component$"
```

Linux（单行，在导出根）：

```text
cmake -S . -B build_linux -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=<Geant4 前缀>
```

```text
cmake --build build_linux -j
```

```text
ctest --test-dir build_linux -L "^component$"
```

组件测试应恰好命中 `h2_volume_scoring_check` 与 `parallel_scoring_component` 两项；`-L "^component$"` 使用标签精确匹配，不能用 `-R component` 代替。导出工程默认 `G4USIM_STANDALONE_EXPORT=ON` 的等价行为通过 CMake 选项控制：独立工程不注册 `m0_*` 测试与 `scripts` 运行时目录。

构建完成后可执行：

```text
--config project/main.ini --macro project/macros/run.mac --output runs/default/output --dry-run
```

## 7. 模板与身份

- 安装包内的模板来自 `export-template/`（由 `packaging/build_export_template.py` 从仓库单一来源生成），导出根中的 `export-template-manifest.json` 是模板成员与身份的唯一来源。
- 模板身份的算法为冻结的 `sha256_sorted_sha256_path_lines_v1`：按相对路径排序后以 `<sha256><两个空格><相对路径>` 行拼接再取 SHA-256；`algorithm` 与 `file_count` 一并记录。
- 导出的 `export-manifest.json` 记录工具版本、源码身份（Git head / source fingerprint）、模板身份、项目选择、文件表、输入审计、构建命令与测试信息；`identity.digest` 对除自身外的全部文件按同一算法计算。
- 模板是受控文本闭包：成员按统一换行（CRLF/CR → LF）归一后的规范字节计算 `sha256`、`bytes` 与 `identity`，且与最终复制到导出树的字节一致；checkout 的换行检出差异与安装模板因此得到同一身份。
- `tools/` 只包含其顶层直接成员；`tools/<子目录>/`（例如本地协作脚本）不属于模板，不得进入清单或随导出携带。
- 模板只额外携带一个数据文件 `scenarios/semiconductor/niel/si_proton.csv`（role = `example`），它是 `h2_volume_scoring_check` 的真实输入；其余 `scenarios/` 与 `examples/` 不进入闭包，`not_included` 明确说明这一唯一例外。
- checkout 与安装包必须使用同一稳定候选的模板清单；开发态身份与打包态身份不一致即拒绝导出（不得硬编码历史 digest）。
- `verify_export` 始终按导出树的真实原始字节校验，不做任何换行规范化；模板规范化仅用于模板成员的身份与复制。

## 8. 校验与证据

- `scripts/test_k2_project_export.py`：S-A/S-B 正例、双目的地一致性、模板身份、路径注入/链接/越界/额外文件等反例（P1–P8、R1–R12），并核对源项目与示例文件字节未被修改。
- `gui/smoke_tests/smoke_export_project.py`：Project 菜单动作、禁用原因、S-A/S-B 导出到临时目录、`R#` 错误码显示、中英文。
- 导出后可用 `verify_export(<导出根>)` 复核：实际文件闭包必须与 manifest 完全一致，链接、额外文件、缺失文件都拒绝。
- 这些是静态/界面与导出链测试，不是独立工程的构建验证；独立构建与受控修改的证据由 K2-3 单独给出。

## 9. 错误码

| 代码 | 含义 |
| --- | --- |
| R1 | 目标已存在或已被导出 |
| R2 | 目标父目录不存在 |
| R3 | 路径含链接/重解析点、盘符、UNC 或语义歧义（输入或输出） |
| R4 | 项目选择不可用（模式/路径不支持的组合） |
| R5 | 引用的外部输入缺失或越出项目根 |
| R6 | 配置不受支持（实体、物理、源、计分、宏顺序/重复等） |
| R7 | 导出后发现绝对路径残留 |
| R8 | 导出模板不可用（安装/检出均找不到清单） |
| R9 | 目标位于源项目或模板树内 |
| R10 | 导出源在导出过程中被修改 |
| R11 | 模板身份不匹配 |
| R12 | 写入失败（事务失败，staging 清理） |

## 10. 已知限制

- 仅支持两个子集；不支持多 run、任意几何/材料/物理组合、GUI 输入、宏参数化、输出格式 Root/CSV 之外的能力。
- 不捆绑 Geant4、数据集、Qt、编译器、Python；不保证可复现的字节级构建，不提供签名。
- 导出工程只重写路径，不改变任何物理语义；物理结果仍需在目标平台单独验证。
- 仓库自身没有项目许可证文件；`THIRD_PARTY_NOTICES.md` 与 `licenses/` 只覆盖第三方组件，不能替代项目许可。
- 模板默认 `config/` 与项目 `project/config/` 并存；运行只引用 `project/config/`（毒化模板测试保证不会误读）。
