本阶段保留 `run_metadata_json_v1`、CSV v3、ROOT v4，增加独立版本的 `g4usim_provenance_v1` 扩展。阶段验收以 [ROADMAP](ROADMAP.md)、[STATUS](../STATUS.md) 为准；本文描述接口，不代表完整阶段已经通过。

产品f176d0e的Windows全量、真实Linux双版本与M0双平台自动矩阵已通过，见[自动验收归档](verification/f1-automated-20261030/README.md)。实窗待验，F1尚未关闭；后续文档提交与该已测产品的构建身份分开。

## 三种不同结论

| 问题 | 判据 | 不代表 |
| --- | --- | --- |
| 程序是否完成本次运行 | 退出状态、新摘要、逐 run 的计划/完成事件等既有运行判据 | 输出从未被修改 |
| 当前输出是否与记录相符 | 在当前结果根目录重新读取已登记文件，比较 SHA-256 与字节数 | 物理正确、来源签名或防恶意共同修改 |
| 配置是否被接受、在内核应用 | [完整 2C](EffectiveConfig.md) 的独立配置和运行收据 | 仅因输入文件读过就已经生效 |

失败运行可以留下字节相符的诊断文件；完成运行的文件也可能后来被修改。GUI 分别显示运行状态与文件身份，不能用其中之一覆盖另一结论。

## 身份层次

`run_metadata.json` 的 `provenance` 对象包含：

- `schema = g4usim_provenance_v1`。
- `execution_id`：每进程一次、master/worker 共享的 128-bit 随机标识，以 32 个小写十六进制字符表示。不使用或改变 Geant4 随机引擎，不与 run ID、seed、revision 混用。
- `build`：构建时的 `git_commit`、`git_source_state`、`source_fingerprint`、编译器、构建配置与 Geant4 版本。`git_state_scope = cpp_build_inputs`，clean 仅表示实际编译输入的原始字节与 HEAD 清单一致。未提交、忽略但参与构建或被 assume-unchanged 隐藏的不同字节仍为 dirty；Git 缺失/源码归档/无法核对时为 unknown。运行目录的 Git 不参与该判定。
- `inputs`：实际文件读取与明确未观测引用的账本。`sequence` 从 1 连续递增，只表示线程安全的账本追加顺序，不承诺多个并发读取的开始/结束时间顺序；同路径多次读取保留多条，不能以最后版本覆盖先前读取。
- `input_coverage = project_readers_observed`，`input_observation = bytes_read_not_semantic_acceptance` 与 `input_exclusions`：明确覆盖项目读入器，而非整个操作系统/Geant4 的所有文件访问。

`source_fingerprint` 是实际 C++ 源、头、构建模板、CMakeLists 与 cmake 模块的排序清单原字节 SHA-256；不等于编译出的可执行文件 SHA。发布/验证工具另外记录实际可执行文件 SHA。HEAD/ref/index 变化会使下一次增量构建重新生成构建身份，文档提交也更新 commit。

## 输入记录

每条包含 `path/kind/role/capture_method/status/sha256/size_bytes/reason`。`recorded` 的 hash 与长度来自交给该次读入器的实际原始字节（含 BOM、换行、NUL），不是最终化时重新打开路径取得。解析失败但已完整读入的输入仍可留在账本；这不是接受记录。

已覆盖主 INI、独立几何/材料、递归 macro、spectrum、phase-space、NIEL、field map、copies table、STL、GDML 实际依赖和受支持随机状态恢复。STL 的验证与构造可先后读两次，二者分别记录。GDML 来自 Xerces 实际文件/流捕获：未完整读取的网络流、stdin 或无法捕获的跨线程打开保持 unobserved。RNG 原快照在完整读取关闭后、解析与引擎提交前登记；拒绝的文件不伪装为成功恢复。

`unobserved` 必须给原因，hash/size 为 JSON null。Geant4 内部数据集、未覆盖的原生 IO 不伪造 hash。已识别的 `/gps/hist/file` 与 `/run/particle/retrievePhysicsTable` 只记录成功命令引用；后者可能仅安排未来读取，OFF 不产生输入记录。该清单不是任意原生命令读文件的完整拦截器。

原输入后来改变、删除或来自其他机器时，历史读取身份仍保留。读取输出时不要求原输入路径可访问，也不把历史 hash 显示成对当前源文件重新验证。完整配置的最终快照作为已登记输出独立哈希，主配置原字节由 main_ini 输入记录定位。

## 输出文件记录

`generated_files` 原有 `path/schema` 继续存在，扩展字段如下：

| 字段 | 语义 |
| --- | --- |
| execution_id | 与 provenance 的进程标识一致 |
| scope | process、run 或 thread |
| run_id / thread_id | process 均 null；run 只有非负 run；thread 有非负 run 和 worker/sequential thread |
| sha256 / size_bytes | 对已关闭产物实际读取的字节身份 |
| integrity_status | hashed、unavailable、self_reference_excluded |

关联由产物生成点传入，不以文件名推测全部归属。CSV/ROOT 及有效配置快照维持既有文件名；消费者对已知命名做冗余一致性检查。有效配置的负 thread 表示主线程，其产物属于 run，不能伪装成 worker。

普通产物关闭后先进行流式哈希，再写文本摘要；摘要成功关闭后单独哈希，最后写 JSON。元数据自身必须登记，但唯一使用 `self_reference_excluded`，hash/size 均 null，避免自哈希循环。该排除不适用于其他产物。

已登记文件丢失、读取失败不会从清单悄悄消失：锁存 `artifact_integrity` 首因、最终失败、非零退出；可写诊断中保留 unavailable。metadata 打开/写入/关闭失败沿用 R02，纠正文本摘要并不登记失败 JSON；`summary_write_status=completed` 只指文本成功关闭。没有跨文件原子事务或外部并发修改下的不可变快照保证。

## 消费与兼容

GUI、绘图、扫描、场景分析、自动合并及扩展共用 `output/provenance.py`。新扩展存在时检查类型、重复 JSON key、有限值、schema、身份归属以及每个已登记文件的实际 hash/size。未知版本、缺失、损坏或不一致必须阻止自动可信消费，不能降级到 glob。合并计划执行前重新校验内容；mtime/size 不能代替 SHA。

没有 metadata 时仍走原 legacy/unverified 行为；旧 v1 metadata 有清单但无 provenance 时仍读取并明确缺少内容校验。显式单文件/list 的离线分析保留，但不伪称来自可验证运行。

复制/搬移结果目录时只按清单原根映射到当前根，不读取旧根。未登记的额外文件不自动加入本轮输入，不因额外文件存在就认定篡改。后处理不会重写后端原始清单以把衍生产物混入本轮输出。

## 性能与验收入口

`scripts/measure_output_performance.py` 在独立目录交替测量指定基线/候选程序的 hits、event、mesh 工作负载和 csv/root/both。报告保存实际 exe SHA、输入/log/输出 SHA、事件完成、墙钟、字节数及独立 Python 流式复核耗时。后者不是后端哈希 CPU 时间；结果不外推所有模型的性能。

当前 CSV writer 已使用标准流缓冲。54次格式对照与18次缓冲对照没有证明256KiB候选有稳定整体收益，因此撤回该候选，保留现有缓冲。测量条件、结果与边界见[格式与缓冲决策](collab/inbox/20261030-1500-astra-f1-format-decision.md)，不声称“从无缓冲升级”。

仅显式设置 `[output] format=auto` 或初始化前的 `/AIHL/output/setFormat auto` 才启用自动选择：最终 scoring 已启用，且 hits 或 event_edep 至少一项启用时使用 ROOT；其余使用 CSV。该策略不启用计分项目，也不依据事件数猜测数据量。省略 format 仍是 CSV，csv/root/both 及旧别名不变。

摘要中的 `output_format_requested` 记录所选策略，`output_format` 记录实际格式，`output_format_selection_reason` 解释选择；2C `/output/format` 分别记录 requested/resolved 与来源。初始化前调整计分依赖会改变 auto 的实际选择，初始化后格式与计分修改继续拒绝。该能力不扩大 GUI 的配置编辑白名单。

身份校验和历史扫描在后台执行；新请求与页面关闭会取消旧请求并拒绝过期结果。一次操作内复用同一验证结果以避免重复读盘，下一次操作仍重新计算 SHA，合并执行前再次校验。该机制不是跨操作缓存，也不承诺所有既有数据解析和绘图均在后台。历史包打开动作锚定当前目录，快照原路径仅作历史记录。

定向入口：`test_build_identity.py`、`test_f1_input_provenance.py`、`test_f1_input_resources_backend.py`、`test_f1_output_identity.py`、`test_output_auto.py`、`smoke_f1_output_identity.py`、`smoke_f1_async_identity.py`，同时保留原输出、随机恢复、GDML、ROOT/CSV、后处理及全量平台回归。实际结果与未验范围必须来自阶段证据归档。
