## 5. 已确认的开放问题

### 5.1 默认层级几何的 GUI 诊断

`test/geometry/hierarchical_test.ini` 曾产生 91 个 error 和 2 个 warning：

- 60 个 `vis.*` round-trip blocker。
- 24 个 `cut.*` round-trip blocker。
- 5 个 `trd` 参数 blocker。
- 1 个汇总 blocker。
- 1 个错误口径：GUI 将 `trd` 描述为后端不支持，但后端实际支持 `trd`。
- 完整 `sphere` 被笼统标记为近似预览。
- 几何有 `bias=true` 而物理 hook 未启用时产生有效 warning。

界面顶部曾显示 201 个 error，而明细附件只有 91 个，说明 parser、editor、validator 或页面汇总之间可能重复计数。修复归入 M0-3B3 和 GUI 诊断降噪，不应通过删除源字段解决。

### 5.2 Run Console 和配置来源

当前设计要求“当前运行默认值”中存在 config/macro 才能运行，但目标设计是两种明确模式：

- `generated`：默认，由“配置”页校验并生成 run package，用户无需手选 config/macro。
- `external`：高级模式，使用外部 config、macro 或后端允许的有效组合。

generated 模式必须生成 package 内的 `main.ini` 和短 `run.mac`。生成 macro 只负责初始化和 `beamOn`，不能重复加载材料、几何、物理、源和计分配置。配置变化必须使旧 package 变为 stale；外部路径变化必须重新构建命令预览。

原始几何 source-copy 模式仍必须由用户显式选择，不能因为存在 round-trip blocker 就自动开启。

### 5.3 已审计运行日志

一份层级几何日志确认：

- test macro 显式加载 `test/materials/test_materials.ini` 和 `test/geometry/hierarchical_test.ini`，覆盖了主配置中的路径；这符合“macro 高于主配置”的既定优先级，但与 GUI 预期不一致。
- 日志没有 `/run/beamOn`、Run 开始、Run 结束或完成事件证据，执行停在 `/vis/open OGLSQt`。
- `exit code=0` 不能单独代表模拟成功；GUI 还需要读取 run summary 的 run 数、事件数和 macro 状态。
- `cooling_pipe` 被 Geant4 检测为超出 `main_chamber`，最大突出约 `4.55 cm`。
- XS biasing operator 虽然挂接，但 `protonInelastic` 和 `neutronInelastic` 不在实际进程列表中，规则不会产生预期偏置。
- legacy biasing、Messenger 状态变化和 worker warning 大量重复。
- `aqua`、`brown`、`darkgray`、`lime` 被后端回退为 gray。
- 测试/批处理 macro 与可视化 macro 应分离，不能让 `OGLSQt` 阻止 batch `beamOn`。

## 6. 总体路线

### M0：可信运行基础

- 已完成提交：M0-1、M0-2、M0-3A、M0-3B1、M0-3B2A、M0-3B2B1。
- 当前收尾：M0-3B2B2。
- 后续：M0-3B3 几何 `version=2` 和完整 round-trip。
- 后续：M0-3C generated/external 运行来源、macro 冲突、有效配置清单和成功语义。
- 后续：M0-3D 默认示例 overlap、颜色和运行质量。
- 后续：M0-3E biasing 目标进程 fail-fast。
- 后续：M0-4 输出格式、单位、版本和生成条件。
- 后续：M0-5 统一测试入口、构建、多线程和平台验证。

### M1：Geant4 后端能力

- 扩展经过测试的原生 solid，例如 `cons`、`trd`、`trap`、`torus`、`polycone`、`polyhedra`。
- 实现 `replica`、`parameterised`、`assembly`。
- 实现真实 GDML 导入。
- 完善材料温度、压力、状态和后续光学属性。
- 统一 geometry region cuts 与 physics region 配置。
- 固化 sensitive、bias、copy number 和 reinitialize 生命周期。

### M2：物理计分和验证

- 定义并实现 LET、Dose、Fluence。
- 明确单位、权重、统计量、多线程合并和输出 schema。
- 建立固定种子参考场景和误差标准。
- 比较 analog 与 biased 结果，不能只以 operator 挂接作为物理验证。

### M3：GUI 产品化

- schema 驱动编辑器和完整 round-trip。
- 简单/高级 Profile、模块开关和运行前清单。
- 后端能力清单驱动的 shape/source 控件。
- 完成国际化、主题、3D 近似提示、日志分级和问题导航。

当前工作区中的主题、国际化和预览是提前实现，不代表 M3 已完成。

### M4：测试、发布和生态

- CTest、GUI/backend 统一入口和 CI。
- Windows/Linux、Geant4 和可选依赖兼容矩阵。
- 安装包、schema 迁移、示例库、物理 benchmark 和发布文档。
