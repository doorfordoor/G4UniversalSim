# 并行计分世界（Roadmap H3-2 后端）

本文说明 Geant4 11.3.2 后端里可选的「并行计分世界」。它让用户在一个只用于计分的
Geant4 平行世界里定义参考体积，用与质量世界相同（或更细）的盒形区域计分剂量与注量，
而不改变质量世界的几何、命中集合和逐事件能量。

- 状态：**实验性功能**。后端 H3-2 运行时已通过主审验收；H3-3 提供只读的 GUI
  入口、状态与诊断、K1 资源闭包、两套可复现示例与本文档更新。主 INI 的
  `[parallel_world]` 与独立平行几何文件均登记为 `experimental`、
  `gui.editable = external_only`：GUI 不编辑这两处，只显示状态并拒绝不支持的组合。
- 范围：box 体积与规则 box 网格；dose/fluence 默认计分器；CSV 输出；单线程与多线程。
  统计基准（Case A/A2/B/C）属于 H3-4，本阶段不运行、不声称物理正确性已验证。

## 1. 机制

启用后：

1. 后端按主 INI 的 `[parallel_world]` 读取一个独立的几何文件，在 master 线程构造
   `G4VUserParallelWorld`（`ScoringParallelWorld`）。
2. `G4ParallelWorldPhysics` 注册 `G4ParallelWorldProcess`；该过程在跨越平行世界体积
   边界处限制步长，并把 ghost（平行世界）步交给 `ParallelScoringDetector`。
3. 计分器从 ghost 步构造 `HitRecord`：体积路径以 `/<parallel_world.name>#0` 为根，
   `processName = parallel_world_step`，沉积能量、步长、动能、权重均取 ghost 步；
   `doseMass` 使用配置阶段解析并复核过的**声明材料参考质量**（按材料密度 × 盒体积，
   用 Geant4 单位换算），`fluenceVolume` 使用同一个盒体积。
4. `ScoringManager::ScoreParallelHit` 是专用入口：只把命中转发给已启用的 `dose` 与/或
   `fluence` 计分器；**不**写 hits、不累加逐事件 `event_edep`、不广播 LET/位移损伤/直方图。
5. 因为存在平行世界时 Geant4 会强制 coupled transportation，输运与随机数序列会改变；
   合同明确不承诺与未启用时逐位一致。

## 2. 配置

主 INI（默认关闭）：

```ini
[parallel_world]
enabled = true                 ; 缺省 false，保持旧行为
name = ScoringWorld            ; 可选，缺省 ScoringWorld
geometry_config = parallel.ini ; 启用时必填，路径相对主 INI
```

并行几何文件是**闭合** schema，只允许以下 section/key：

```ini
[world]
material = G4_Galactic         ; 只允许这一项；ghost 世界尺寸由质量世界决定

[volume.Slab]
parent = world
shape = box                    ; v1 只支持 box
size = 20, 20, 2               ; mm，三个正有限值
position = 0, 0, 0             ; mm，缺省 0
material = G4_WATER            ; 主材料文件中存在的材料名，允许别名
sensitive = true               ; 必须显式 true

[grid.SlabGrid]                ; 规则网格：自动生成 nx*ny*nz 个计分单元
parent = world
size = 20, 20, 2               ; 网格区域总尺寸（mm）
position = 0, 0, 0             ; 区域中心（mm）
material = G4_WATER
bins = 2, 2, 1                 ; 每轴 >=1 的整数，乘积 <= 4096
sensitive = true
```

网格单元名为 `<grid>_<ix>_<iy>_<iz>`（ix 最快），单元尺寸 `dx = size.x / nx` 等，
中心为 `区域中心 + (i + 0.5) * d - size / 2`，体积 `dx * dy * dz`。物理体 copy 号按
创建顺序分配，因此体积路径形如 `/ScoringWorld#0/SlabGrid_1_0_0#2`；比较时用
`volume_name` 或路径前缀 `#` 之前的部分。

未启用时 `[parallel_world]` 不得声明 `name`/`geometry_config`；启用但缺少几何文件、
未知 section/key、重复声明、空 section 均在配置阶段拒绝。

## 4. 两阶段校验

- **Stage A（配置阶段，未创建任何 Geant4 几何对象）**：键与几何文件结构；名字合法且
  不与世界/体积重名；声明质量世界为 box 且包含每个计分盒；材料存在且密度为正；计分器
  开启情况与不支持组合。
- **Stage B（内核几何构建后、事件前）**：取实际 ghost 世界与各体积逻辑体，核对实际
  盒尺寸、实际质量 `G4LogicalVolume::GetMass(true, false)` 与配置参考质量相对差
  ≤ 1e-12，以及 8 个角点与中心落在 ghost 世界 solid 内（`G4VSolid::Inside`）。失败时
  在 `run_summary.txt` 记录 `output_failure_stage = parallel_world_geometry|sd|physics`
  并以非零退出，不静默降级。

## 5. 输出与身份

启用时 `run_summary.txt` 增加：

```text
parallel_world_enabled = true
parallel_world_name = ScoringWorld
parallel_world_geometry_config = parallel.ini
parallel_world_geometry_sha256 = <64 位 sha256>
parallel_world_volume_count = 1
parallel_world_total_mass_kg = 0.000800
parallel_world_physics_constructor = G4ParallelWorldPhysics
parallel_world_process = G4ParallelWorldProcess
parallel_world_step_source = ghost_step
parallel_world_dose_normalization = declared_material_reference_mass
```

有效配置新增 `/parallel_world/{enabled,name,geometry_config,geometry_sha256,volume_count,total_mass_kg}`
与逐体积 `/parallel_world/objects/volume:<name>/{material,density_kg_m3,volume_mm3,mass_kg,sensitive,material_matches_mass_world}`；
`material_matches_mass_world` 只有在声明质量世界里有同材质 box 完整包含该计分盒时才为
true（中心点或同名不算证明）。收据等级：`manager_accepted`（配置接受）、
`kernel_constructed`（Stage B 通过）、`run_validated`（本轮完成事件数 > 0 且有输出）。

启用平行计分世界、`[scoring] hits=true` 且 CSV 输出启用的真实 worker 上，即使只有平行世界
命中（质量世界敏感体关闭，因而没有 mass hit），`hits_tN.csv` 也会由真实 `OutputManager`
写出表头，并在 run 收尾关闭、登记为 `hits_csv_v3`；数据行为 0，平行世界 ghost 步绝不写入
hits。该文件存在只证明 writer 生命周期与登记，不代表发生了质量世界 hit；平行结果仍在
dose/fluence CSV 中。

## 7. 已知限制

- 只实现后端；GUI 仍把 `[parallel_world]` 视为不可编辑的外部配置（H3-3）。
- 未做统计基准与云 CI（H3-4/H3-5）。本阶段的「正例通过」只证明接线、单位、
  归一化与隔离路由，不证明物理正确性。
- Stage B 的不一致状态无法通过受支持的输入构造（声明与内核几何同源），因此没有
  注入式负例；Stage B 正例在每次启用运行中执行。该点需主审裁定。
- Case M 的线程分配由 Geant4 调度决定：小事件数下两轮可能落在同一 worker；测试
  只要求两轮事件数合计正确、逐 worker 文件存在，不把调度视为失败。
- 只在本机 Windows/MSVC/Geant4 11.3.2 验证；Linux、ROOT、偏置、电磁场未验证。

## 10. 生命周期重绑与浮点交叠界限（2026-11-07，r3）

首审（r2）之后仍有两个已实证缺陷，本节的实现是对它们的冻结范围内最小修复。

### 10.1 证明与当前质量几何绑定

`Configure()` 阶段的材料一致性证明只对当时的质量世界树有效。PreInit 宏可以执行
`/AIHL/geometry/loadConfig <file>` 替换质量几何（这是一个已支持的入口），因此证明不能在之后
的 run 里继续沿用：

- `ParallelWorldConfig::RebindToCurrentGeometry(geometry, materials)` 重新做声明包含检查、
  材料解析、密度/参考质量计算，并**重新推导**每个体积的整盒材料证明；`ResolveMaterials`
  先清空旧证明再重算，无法重复证明的退化为 `unknown`，不会继承 Configure 时的 `true`。
  重绑入口先复用既有 `ValidateMainName(name, geometry)`：PreInit 换几何可能换掉 world 名，
  原 Load 时的“并行世界名不得与质量世界名冲突”约束必须继续成立；该检查只针对 parallel world
  自身的 `name`，不新增任何规则。
- 接线点：`RefreshParallelWorldForCurrentGeometry()` 在
  (a) `ConfirmEffectiveCommand()` 处理 `/AIHL/geometry/*` 后立即调用；
  (b) `ValidateParallelWorldForRun()` 在 `/run/initialize` 与每次运行前调用。
  两处都同时刷新有效配置视图（`RefreshEffectiveConfig()`），所以 `effective_config_run_*.json`、
  `effective_config_finalization.json` 与运行摘要看到的是同一份当前证明。
- 当前几何无法容纳声明体积、或材料表无法解析声明材料时抛错，按既有失败通道锁存并拒绝运行；
  不静默降级。

回归输入来自主审的原始字节（`out/collab/h3-independent-r3/lifecycle-geometry-switch/`）：
质量几何在 PreInit 从 water 换成 copper，`/run/beamOn 20` 完成 20 事件；要求最终
`/geometry/objects/Slab/material = copper`、并行 `/parallel_world/objects/volume:Slab/material = water`，
而 `material_matches_mass_world` 为 `unknown`（不同材料、不同树，无法证明）。

### 10.2 内部交叠的浮点误差界限

原实现对内部交叠使用 `1e-9 × max(1, |low|, |high|)` 的相对容差。它在世界坐标绝对值很大时
（例如 1,000,000 mm）会达到约 0.001 mm，把可表示的真实交叠（0.0005 mm）当成接触吞掉，
构造因此被接受。现在改为对被比较的坐标差使用可解释的绝对误差界：

```
CoordinateBound(a, b) = 64 * DBL_EPSILON * (|a| + |b| + 1)
```

64 ulp 覆盖十进制解析、单位换算与 ±半长算术的误差累积；在 1,000,000 mm 处约为 2.8e-8 mm，
小于 0.0005 mm 的真实交叠，而精确贴面仍然是接触。判据用在四个位置：展开体积的内部交叠、
声明包含、整盒包含、异材质后代与候选盒的内部相交。面/边/点接触与合法规则网格不受影响。

回归输入来自主审原始字节（`out/collab/h3-independent-r3/overlap-precision-repro/`）：
根世界 2100000×100×100 mm，world 直属 A/B 各 2×2×2 mm，中心相距 1.9995 mm，实际交集
0.0005×2×2 mm。要求 `--dry-run` 在构造前以 `overlap in their interior` 拒绝。

`scripts/test_parallel_world.py` 内嵌上述两组输入的原始字节与 SHA-256，写盘前逐个核对，

## 11. GUI/schema 入口与示例（H3-3，2026-11-07）

### 11.1 用户入口

平行世界计分只通过**外部主 INI** 配置。GUI 不提供 `[parallel_world]` 或平行几何的
编辑器，这是 `gui.editable = external_only` 的既有策略，不是缺失。

- Project 页把 `Current Run Defaults → Run input mode` 设为 `Use external files`，
  选择外部主 INI 与 macro。状态摘要追加一行：
  `Parallel world: enabled, name ScoringWorld; ghost geometry <解析后的路径>`；
  未配置、无法读取、已禁用也各有明确文本。

## 12. 网格计分归属恢复（H3-4 前置修复 r1，2026-11-07）

### 12.1 现象与根因

- H3-4 Case A2 的 20 事件预跑发现：4×4×1 网格（束流沿 z 通过，格面经过 x=0/y=0）
  平行剂量只合计到质量侧的约 71.5%，径迹长度同比例缺失；1×1×1、z 向切分、
  以及束流位于单元内部时结果正确。
- round125 步级 trace 证明**能量没有丢**：丢失的是「ghost 预步点被定位在世界根
  `/ScoringWorld#0`、而世界根当时没有敏感探测器」的步。Geant4 的
  `G4ParallelWorldProcess` 只在预步点 touchable 的逻辑体积挂有 SD 时才分发 Hit；
  预步点恰好位于单元共享面（容差内）时导航器返回根体积，这些步被静默跳过——
  既不报错也不产生记录。
- 这是计分归属覆盖问题，不是物理输运差异；不能靠移动/膨胀/重叠几何或按质量侧
  比例补齐来掩盖。

### 12.2 修复

- `ScoringParallelWorld::ConstructSD()` 在每个工作线程给 ghost world 根挂
  `ParallelScoringWorldSD_<world>`（`Scope::WorldRoot`）；叶体积仍用原来的
  `ParallelScoringDetector`（`Scope::Leaf`），正常叶步路径与语义不变。
- 根步由 `ProcessWorldRootStep` 处理：
  - 预步点先按声明盒 AABB 预筛，再用真实已构造的 `G4Box` 与 `G4PVPlacement`
    变换做 `LocalPoint` 判定；归属只来自真实 PV/变换，不复制质量世界；
  - `probe = pre + dir × 1e-6 mm`：probe 严格在盒内 → 该盒归属（进入或内部步）；
    probe 仍在闭盒边界 → 沿共享面/棱/角的滑行步，按单元名字典序确定性归属一次；
    两者皆无 → 跳过（外表面出射进入真空、外部或 gap），不计入任何计分体；
  - 结构不一致（非盒几何、变换缺失等）→ 锁存失败并 `AbortRun`，不静默吞掉。
- 物理量来源不变：剂量与注量仍取 ghost 步（`ParticleHit::FromStep`）与声明的
  材料参考质量/体积；归一化口径不变；不按比例补齐、不复制质量世界贡献。

## 14. 网格导航包络（H3-4 前置修复 r3，2026-11-07）

### 14.1 根因（内核直接证据）

- 主审用冻结 f656 候选 + 原始 thin-grid 输入、只开 `/tracking/verbose 1` 复现：光子
  只有一步 `z=-20 mm → 50 mm`、`StepLeng=70 mm`、世界输运（CoupledTransportation）。
  说明共享面沿轨迹时，grid 边界不会被内核切步，预步点始终在网格外——不存在
  「把预步点在目标内的步补分发」的修补空间。
- 因此改为最小导航几何：每个声明的 grid 构造一个**全局边界完全相同**的内部导航
  `G4Box` 包络（尺寸/中心/材料 `G4_Galactic` 与声明 grid 一致），原 cells 变成其子体，
  全局大小/位置/材料完全不变。包络不是新的计分体积，不计入 `parallel_world_volume_count`
  与参考质量总和；包络 SD 只恢复内部真实 cell 的预步归属，外部/gap 明确跳过，叶体积
  仍走原专用计分路由；不剪切、不按比例分摊 70 mm 整步的 Edep。

### 14.2 实现要点

- `ParallelWorldConfig`：grid 解析时生成 `EnvelopeSpec`（名字=grid 名、材料、声明
  size/centre、cell 索引表）；`ResolveMaterials` 解析包络材料。
- `ScoringParallelWorld`：`Construct()` 为每个包络建 `G4Box`/`G4LogicalVolume`/`G4PVPlacement`，
  cells 以包络为 mother（位置=cell 中心−包络中心）；`ConstructSD()` 为包络挂
  `Scope::Envelope` 探测器（每线程），世界根 SD 仍保留给单盒体积。
- `ParallelScoringDetector`：`ProcessHits` 分派 Leaf/WorldRoot/Envelope；包络归属用真实
  父子变换合成（`G4Transform3D(parent) * G4Transform3D(cell)`）计算局部预步点与局部
  方向，按「严格内部/进入 → Owner（唯一或字典序）」「沿共享面滑行 → 字典序归属一次」
  「域外/出射 → Skip」判定，不使用固定 probe 距离；输出路径为
  `/ScoringWorld#0/<grid>#0/<cell>#0`。
- `SimulationManager::ValidateParallelWorldForRun()`：新增 Stage B 包络校验（数量、
  母体、copy 0、无旋转、盒尺寸 1e-12 相对一致；cell 为包络直接子体、无旋转，且
  包络+cell 平移和与声明中心 1e-12 相对一致）。

## 12. 空 hits 表头修复（2026-11-07，H3-4 R-RUNTIME 字面产物）

冻结合同 §8.5/R-RUNTIME 要求启用平行计分、质量层不敏感、`hits=true` 时 hits CSV 存在且为
0 行。旧候选因为 `ScoringManager::ScoreHit` 从未被调用（平行步走 `ScoreParallelHit`），
`OutputManager` 的 hits writer 从不打开，`Close()` 也就不会登记文件，导致旧 72 项正式输出
中 R-RUNTIME 缺少该文件。

修复位置只有 `ParallelScoringDetector::Initialize(G4HCofThisEvent*)`（实现
`src/ParallelWorld/ParallelScoringDetector.cc`，声明在对应头文件）：仅 `Scope::WorldRoot`
在真实 worker 上取线程本地 `ScoringManager` 与它真正的 `OutputManager`；当 scoring 启用、
`IsHitOutputEnabled()` 为真、输出为 CSV 且 writer 尚未打开时，调用既有
`OpenHitFile()` 写表头。异常走既有 `ReportScoringFailure("parallel_world_hits", ...)`；
不使用 master 输出指针，不写任何 ghost 行，不改变计分、输运、RNG、量定义或默认未启用
平行世界的行为。run 收尾仍由既有 `OutputManager::Close()` 关闭并登记文件。

验证：新候选（exe `802ad812…`，源码指纹 `879f00c3…`）用冻结的 R-RUNTIME 输入重跑
