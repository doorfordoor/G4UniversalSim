## 4. E2：完成约定模块的配置 schema 迁移

### 现有单源字段与组合约束

- 盘点 `SourceManager` 当前真正消费的字段、别名、默认值、空值语义、单位和路径基准。
- 将现有单源字段迁入 schema，覆盖 preset 覆盖关系、point/plane、circle/rectangle、fixed/isotropic 及冲突约束。
- 生成已迁移部分的 C++ 已知键表、Python 数据和文档表；沿用后端运行校验，不能让 schema 擅自改变接受范围。
- 让当前 GUI 已可生成的源字段复用 schema；不借此开放高级源编辑器。
- 对暂不能表达的跨字段规则保留显式校验和专项测试，并列出缺口；存在缺口时不得把整个 source section 标为完全迁移。部分迁移需先设计生成器与已知键表的兼容方式，避免同一 section 重复登记。

验收：合法/非法/缺省/显式空值/别名优先级与字段消费测试一致；旧配置保持行为；用真实初级粒子的位置、方向和能量检查 writer 到输运的链路，不能只测生成字符串。

### 高级源、动态 section 与相空间

- 覆盖 `[source.<名称>]`、能谱、beam/volume、旋转、confine、离子、多源权重，以及关联 `[phase_space]` 配置。
- 区分配置阶段可验证的条件与 `PrepareForRun()` 才能确认的条件；`--inspect-run` 成功不能代替运行时接受。
- 保留多源单字段命令拒绝、缺失 confine 体失败、相空间事件索引与 worker 分配无关等既有契约。
- 文件引用、带中文路径及错误来源纳入差异测试。默认不增加 GUI 编辑能力。

验收：源字段清单有明确覆盖；差异测试与 `test_gps_sources.py` 等真实回归通过，无静默忽略或新增兼容性变化。

### 物理配置

迁移 `[physics]`、区域物理和放射性衰变字段，保留区域名称大小写、参考列表/手动模式依赖、cut/limit 单位、衰变阈值及重复注册保护。若字段依赖编译能力或真实物理初始化，分别标记验证阶段。

验收：schema 差异测试、A6 专项与实际过程清单相符；不能仅检查物理列表名称或 Manager 缓存。

### 计分与输出关联

迁移 `[scoring]` 及其子 section：Edep、Dose、Fluence、LET、displacement、网格配置及相关依赖。梳理动态 section、过滤条件和 NIEL 文件契约，不重新定义物理量。

验收：保留零沉积步参与 track-length 计分、无 daughter 限制、默认 scorer 依赖；覆盖 CSV/ROOT、多 worker、多 run、统计和单位契约。选用既有计分专项，不以全零文件作为支持证据。

### 几何与材料独立配置

先迁移几何，再迁移材料；分别使用文件级 schema，不把主 INI 规则套用到独立文件。

- 几何：模板与 shape-specific 参数、动态体积名、放置、布尔工具、版本 1/2、重复定义、metadata 和来源诊断。
- 材料：NIST、自定义元素/同位素、组分及密度规则、循环依赖、大小写和保留 section。
- 保留 GUI 的不可无损回写阻断、原始文件复制模式及不覆盖源文件的行为。

验收：E1 差异测试、几何/材料解析测试、GUI 往返及真实构建回归一致；未知字段的 warning/error 等级不得因迁移悄然变化。

### E2 总验收

建立“文件/section/字段 → 后端解析 → 校验阶段 → GUI 可编辑状态 → 测试”的覆盖清单。确认原 E2 约定模块无未登记缺口，再标 E2 完成。其他 section（例如 field、biasing）必须显式登记覆盖状态，另排迁移批次；不得称为全仓库配置已统一。

生成文件只由 [generate_config_schema.py](../scripts/generate_config_schema.py) 生成；新增 schema 表达能力保持版本兼容。schema 描述后端事实，发现后端缺陷时单列行为修复与兼容说明。

## 5. F6：实时运行进度

先定义版本化进度消息，再接 GUI。消息应区分 run、计划/完成事件、阶段、耗时与速率；ETA 无法可靠计算时显示未知。多 worker 计数要正确汇总并限制输出频率。

- 后端：明确开始、运行、结束、中止；零事件和初始化阶段不得伪造百分比。
- GUI：异步解析，支持一行被分块读取、噪声日志、消息格式不兼容和进程突然退出。
- 进度条只反映过程，不替代 `run_result.py` 的最终成功判定。
- 本批不提供未经定义的“实时部分剂量”。

验收：真实单/多线程、多 run、失败和取消；完成计数与最终摘要一致，进度按 run 正确重置；记录性能开销，不能为了显示进度改变物理结果或写出规则。

## 6. F2：两轮运行之间调整参数

### F2-A：能力与协议设计

先列候选字段并实测 Geant4 生命周期。旧路线图提到的 source shape、run name、输出开关等仅是候选，不能直接作为安全白名单。保持当前输出目录、线程、几何、物理和计分修改守卫。

提供协议方案、错误传播、取消/关闭、会话失联及重放设计后，再由用户决定采用受控 `csh` 管道还是新增版本化协议。协议确定前可做只读调查和隔离验证，不更改生产入口。

### F2-B：后端会话与可复现证据

在最小安全白名单上支持三轮运行；逐轮保存已实际应用的配置、来源、事件数、随机状态策略和输出身份。拒绝的命令不得修改缓存后假装生效；危险修改必须明确要求新进程/新运行包。

原路线图的逐位重放目标保留，但需限定：相同构建、数据集、线程数、初始随机状态及执行顺序；比较去除时间/路径等非确定元数据后的物理记录。先验证单线程，再验证多线程事件映射；不能把统计相符当作逐位重现，无法达标时登记缺口并讨论，不静默降低标准。

### F2-C：GUI 下一轮面板

仅暴露已验证字段，区分“当前已生效”和“下一轮待应用”。使用会话状态驱动按钮；运行中禁止编辑不安全字段，失败可诊断，关闭时清理子进程。需重启的改动生成新包，不覆盖历史结果。

验收：真实三轮 GUI → 后端 → 摘要 → 重放闭环，外加非法状态、取消、崩溃、失败命令和旧结果保留。
