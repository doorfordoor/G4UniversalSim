# 环境发现与诊断（I1）

I1 提供独立的只读环境探测服务和异步选择对话框。没有 Geant4、SDK、编译器或后端时，仍可加载诊断服务；对话框本身需要 GUI 已有的 PySide6。它不安装软件，不激活 shell，不更改系统或当前进程的环境变量，不初始化 Geant4，不拥有模拟运行状态。

## 服务接口

`gui/g4usim_gui/core/environment_discovery.py` 仅依赖 Python 标准库和已有的纯 Python 能力协议校验器。

```python
facts = discover_environments(candidates=[
    "/opt/one/G4UniversalSim",
    {"executable": "/opt/two/G4UniversalSim", "label": "另一环境",
     "env": {"LD_LIBRARY_PATH": "/opt/two/lib", "GEANT4_DATA_DIR": "/data/two"},
     "sdk_roots": ["/opt/two"]},
], timeout=5.0)
single = probe_environment("/opt/one/G4UniversalSim", timeout=5.0)
execution_facts = probe_environment("/opt/one/G4UniversalSim", cwd="/work/experiment", timeout=5.0)
```

返回值是可直接交给 `json.dumps(..., allow_nan=False)` 的字典。集合使用 `g4usim_environment_discovery_v1`，单环境使用 `g4usim_environment_v1`。集合包含 `environments`、主机 `host` 和 SDK 候选 `sdk`；顺序保留输入顺序，相同路径与相同环境覆盖去重。相同二进制的不同子进程环境覆盖保持为不同候选。环境变量值不回显到事实集合，不保存完整环境变量或用户设置。

`candidates=None` 仅搜索 `G4USIM_EXE` 和 PATH 上的 `G4UniversalSim`/`G4UniversalSim.exe`；`candidates=[]` 明确关闭自动后端搜索。可传单一路径或候选字典。不会递归扫描磁盘、安装目录或注册表。相对路径按调用进程当前目录解析；裸文件名按子进程 PATH 查找；中文和空格路径作为独立参数传递，不经过 shell。

`env` 是子进程环境覆盖；值为 `None` 表示只从该子进程移除变量。候选的覆盖优先于集合覆盖。每条命令独立使用 `timeout` 秒预算，超时后结束并回收该直接子进程；集合总耗时随候选和工具数量增长，不是整个集合只允许一个 timeout。探测不执行用户 shell 脚本，也不终止其他运行任务。

单环境 `probe_environment(..., cwd=...)` 可明确指定查询子进程的工作目录，命令收据记录 `working_directory`；未指定时沿用可执行文件所在目录。K1 执行前后的探测使用实际执行输入目录，数据报告中的相对路径按该子进程目录解释，不能按桌面 Python 的当前目录推算。目录选择与存在性仍不是数据内容校验。

深 Windows 目录通过共用 `backend_launch` 计划从短祖先启动，由后端在数据发现前恢复真实 cwd；收据另记 `launch_working_directory` 和 `launch_route`，不能以启动祖先冒充查询环境。旧后端明确拒绝 `--working-directory` 或未声明 `launch.working_directory=true` 时报告不支持，不重试成假就绪。通用 SDK/编译器探测不接收此后端专属参数。环境覆盖字典使用 `None` 显式移除继承变量；省略键继续继承。

去重先按实际子进程 PATH 解析裸名称，再使用与探测相同的规范路径身份。裸名称解析到 PATH 的后端与显式当前目录路径不同，即使后者不存在，也分别保留诊断；两种输入顺序都遵守此规则。解析失败不以猜测路径吞掉后续候选；同一规范路径的别名可以去重，同一文件的不同环境覆盖继续保留。

## 事实层级

| 字段 | 能够说明 | 不能说明 |
| --- | --- | --- |
| `candidate`、路径 | 候选来源、标签和解析后的路径 | 后端能够加载或模拟 |
| `identity` | 实际二进制 SHA-256、探测前后字节是否一致 | 运行时依赖或数据内容身份；全程不可变保证 |
| `architecture` | PE/ELF 文件头中机器类型和位数；未知保持 unknown/null | 不用主机位数猜目标，不把跨架构一律当作不能运行 |
| `capabilities` | 实际执行该文件的 `--capabilities`，经既有 v1 协议校验的声明 | 初始化成功、GUI 能编辑全部能力、物理基准通过 |
| `build` | 该后端返回的 Geant4 数字版本及构建编译器 | 当前主机已安装相同编译器或 SDK |
| `data` | `--check-geant4-data` 返回的目录发现结果、逐项必需/可选状态 | 数据文件内容完整、具体物理列表需要的全部数据已验证 |
| `sdk` | 显式根、Geant4 环境线索和 CMake 前缀中配置/头文件是否存在 | 已运行 CMake 配置、编译、链接或版本兼容检查 |
| `host.tools` | 主机 PATH 中 CMake/编译器路径及实际版本命令的返回事实 | 编译环境已激活、能构建当前项目 |
| `host.optional_components` | 当前 Python 能找到的模块及发行版本 | 模块实际导入、原生依赖加载或渲染功能通过 |

SDK 只检查提供的根及有限固定子路径（含版本化 share 目录）；找不到不等于整台机器没有 SDK。CMake 和编译器未找到不会把现有可运行后端标记为失败。GDML 等可选后端能力保持能力原始协议值，不从 SDK 文件或 Python 模块反推。Geant4 11.3.2/11.4.3 的数据集清单由各自后端给出，前端不维护另一份版本表。

## 状态和错误

单环境的 `ready` 仅表示能力协议可读、必需数据目录发现完整且探测前后二进制 SHA 一致。`data_incomplete` 表示能力可读而必需数据目录不完整；可选数据缺失不会伪造必需失败。`partial` 表示能力可读但数据探测失败或协议不可确认。`unavailable`、`not_found`、`error`、`changed_during_probe` 分别保留失败含义。

每个命令记录参数、实际退出码（无法取得为 null）、耗时和有限长度 stderr。超时、无法启动、缺库、加载器拒绝、输出过大、编码错误、协议错误分别记录。Windows 缺 DLL 状态码与错误映像状态码分开，后者不能单凭状态码断定架构错误。Linux/macOS 缺动态库根据原始加载器诊断归类。未知失败保留原始状态和消息。

只在数据报告结构正确、逐项状态自洽且退出码与 `required_complete` 对应时接受数据事实。能力命令非零退出不会因 stdout 看似 JSON 而被接受；数据缺失专用退出码 1 与合法不完整报告一起解释。重复 JSON 键、非有限数值、错误协议或相互矛盾的数据报告均拒绝。二进制变化使结果不可作为选择依据，需要刷新。

严格 JSON 边界也拒绝合法数字语法在浮点转换后溢出的 `1e999`/`-1e999`，包括顶层附加字段、dataset 附加字段和嵌套对象/数组。数据路径保持 `protocol_error`，不产生完整数据或 ready 的事实；能力可读时总状态为 `partial`，GUI 显示数据可用性未知，仍只允许选择能力可读的路径。数值字符串 `"1e999"` 不被当成数字处理。

## GUI 使用与集成边界

`EnvironmentDialog(candidates=..., timeout=5.0)` 在后台线程池探测，调用方使用 `open()` 或 `show()`。表格显示路径、诊断状态、文件架构、Geant4 版本和构建编译器；详情区显示当前候选、主机工具及 SDK 原始事实。刷新期间旧行不可选择，重复刷新不排队。关闭窗口立即返回，后台直接子进程依各自超时结束，迟到结果不会发布到已关闭或已删除窗口。

用户可添加后端文件并显式选择。只有能力协议可读且二进制探测前后稳定的候选可被接受；数据不完整时仍允许选路径并保留警示。选中表格行不等于接受。确认后 `environment_selected(dict)` 发出独立副本，`selected_environment()` 与 `selected_executable()` 返回接受结果。调用方负责把选择传给已有入口并继续现有运行前校验；对话框不会更改项目、启动模拟或安装依赖。主窗口接线由 K1 集成负责人完成。

所有新界面文本经统一 `ui_text`/`ui_format`，原始协议字段及后端诊断保留原文。新增词条在本次独立交付报告列出，由 i18n 写者集中合入。本任务不修改主词典。

## 验证入口和范围

```text
python -B tools/test_assert_probe.py scripts/test_i1_environment.py --report out/collab/k1-i1-contract.json
python -B tools/test_assert_probe.py gui/smoke_tests/smoke_i1_environment.py
```

两个脚本均支持 `--component`：即使统一 runner 注入 `G4USIM_EXE`，component 模式仍只跑独立组件专项。统一登记对应 static/gui component 与 backend/integration 真实后端四组；不带该开关时保留环境变量指定的真实后端探测。

设置 `G4USIM_EXE` 或向首个脚本传 `--executable` 后，额外探测真实后端；不提供时只验证合成协议与真实 Python 子进程行为，输出明确说明未请求真实后端。专项覆盖中文/空格路径、多候选和独立环境覆盖、无 Geant4、SDK 候选、缺库、超时、协议损坏、二进制变化、异步响应、选择和窗口生命周期。合成协议、错误码注入、真实子进程、真实后端查询和实窗观察应分别计证。具体本次结果见 `out/collab/k1-i1-delivery.md`；专项通过不等于 K1 整体验收、模拟或物理验证通过。
