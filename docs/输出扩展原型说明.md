# M5 输出后处理扩展原型

更新：2026-10-21。当前提供一个**显式装载的 Python 后处理接口**，用于将已完成的 Geant4 输出转换为其他格式。该原型不改变正在运行的 Geant4 内核，不能注册 C++ sensitive detector、scorer、geometry builder 或 physics process，也不能作为 M5 整体验收通过的证据。

## 使用方法

GUI 使用：在 Results 页面选定已有模拟输出目录，切换到 **JSON Exports (M5 prototype)** 标签，点击 **Export Dose JSON...** 或 **Export Fluence JSON...** 并选择尚不存在的 `.json` 目标文件。执行期间按钮被禁用，**Cancel export** 可取消子进程；日志显示 CLI 输出，成功后显示结果路径和 `warnings`、刷新文件列表。GUI 会核对 JSON 的 schema、API 结果版本、extension ID、扩展版本、data 对象和 warnings 列表，发现无效 JSON 常量（`NaN`/`Infinity`）时不报告成功。该流程只聚合已发现的 CSV；**不自动核实模拟是否完整**，需要独立检查 `run_summary.txt` 的状态、事件数、worker 文件及警告。当前 GUI 只提供两个内置导出按钮，不提供第三方插件管理。

在仓库根目录执行，需使用可导入项目 Python 包的 Python 3.10+：

```powershell
python -B scripts/run_output_extension.py --list
python -B scripts/run_output_extension.py --run dose_json --input-dir "D:\simulations\case01" --output "D:\simulations\case01-dose.json"
python -B scripts/run_output_extension.py --run fluence_json --input-dir "D:\simulations\case01" --output "D:\simulations\case01-fluence.json"
```

`--input-dir` 必须指向**已完成**的模拟输出目录，其中包含 `dose_volume_summary_tN.csv`，多 run 后缀为 `_tN_rR.csv`。`--output` 的父目录必须存在，目标文件必须尚不存在。成功时打印 JSON 的绝对路径；失败返回非零，不覆盖已有文件。在支持硬链接的文件系统上，先在目标目录写完整临时文件，再通过硬链接独占发布，随后清理临时文件；不保证在所有文件系统、网络盘或权限策略下都可用。

外部扩展由可信 `.py` 文件显式指定，可重复使用 `--module`：

```powershell
python -B scripts/run_output_extension.py --module "D:\trusted\my_extension.py" --list
python -B scripts/run_output_extension.py --module "D:\trusted\my_extension.py" --run my_extension --input-dir "D:\simulations\case01" --output "D:\simulations\my-result.json"
```

不会自动扫描或执行第三方插件。`--module` 使用 Python 导入机制执行文件中的代码，**没有沙箱或最小权限隔离**；仅能加载已经人工审核并信任的代码。当前不提供插件签名、运行超时、资源配额或故障进程隔离。

## API v1 与扩展实现

扩展模块需声明 `EXTENSION` 字典和 `process(input_dir: pathlib.Path) -> dict`。例如：

```python
from pathlib import Path

EXTENSION = {
    "id": "my_extension",
    "version": "0.1.0",
    "api_version": 1,
    "description": "A trusted output postprocessor",
}

def process(input_dir: Path) -> dict:
    return {"kind": "example", "source": input_dir.name}
```

注册表 `scripts/output_extension_registry.py` 负责检查扩展 ID（小写字母开头，后续数字或下划线）、`major.minor.patch` 三段数字版本、API 版本 1、非空描述和可调用的 `process`。重复 ID 或 API 版本不匹配会拒绝注册。当前版本号仅检查格式，尚无跨 API 自动迁移、依赖解析或持久化扩展清单。

成功 JSON 顶层结构固定为：

```json
{
  "schema": "G4UniversalSimOutputExtensionResult",
  "version": 1,
  "extension_id": "dose_json",
  "extension_version": "0.1.0",
  "data": {}
}
```

扩展的 `data` 必须为可以严格 JSON 序列化的对象；不接受 `NaN`/`Infinity`。扩展内部异常导致执行失败。当前的错误隔离范围限于独立 CLI 进程与独占结果文件，并非安全沙箱。

## 内置 dose_json 的契约

实现位于 `scripts/extensions/dose_json_extension.py`，复用 GUI 的 `read_dose_summaries()` 读取器。输入是 Dose MVP 的逐 worker CSV，而不是 hits CSV。以 `(runID, volume_path)` 聚合多个 worker：`raw_edep_MeV`、`weighted_edep_MeV` 相加，`mass_kg` 作为物理体积共享分母只保留一次，然后以 `energy_MeV × 1.602176634e-13 / mass_kg` 得到 Gy。JSON 记录 `thread_ids`、单位及读取警告。

CSV 名称、列名和单位依赖 `docs/输出数据契约.md`。读取器会跳过格式损坏或数值不自洽的文件并在 `warnings` 中报告；输出 JSON **不能据此保证所有预期 worker 文件均完整**。若没有任何有效 Dose 行，则返回失败且不输出 JSON。使用结果前应检查 `warnings` 和上游 `run_summary.txt` 的状态、事件数及实际生成文件登记。

`physical_validation=not_established` 是固定的显式限制：数据仅对应模拟历史累计的敏感体吸收剂量，没有源强、时间、注量的归一化，没有独立物理 benchmark，也不涵盖复杂几何质量语义的完整验证。后处理结果不提升底层 Dose 的物理可信等级。

## 测试及后续工作

内置 `fluence_json`（`scripts/extensions/fluence_json_extension.py`）复用 GUI 的 `read_fluence_summaries()`：输入 `fluence_volume_summary_tN[_rR].csv`，对每个 `(runID, volume_path)` 仅累加 raw/weighted `track_length_mm`，每个体积仅取一次 `volume_mm3`，最后重新计算 `fluence_mm-2`。JSON 包含 `thread_ids`、单位、warnings 和 `physical_validation=not_established`。没有有效记录则拒绝生成；损坏文件只跳过并留下警告，**不能保证缺失线程完整**。适用范围限于无 daughter 的敏感 solid，属于 track-length fluence，没有事件数、照射时间、源强归一化或独立物理 benchmark；不代表表面穿越注量。CLI 的独占发布和可信模块限制同 `dose_json`。

```powershell
python -B scripts/test_output_extensions.py
python -B scripts/test_dose_scoring.py
python -B scripts/run_m0_tests.py --profile all --case output_extensions --case dose_scoring
```

`test_output_extensions.py` 使用受控 CSV 检查注册、聚合、版本拒绝及目标文件保护；`test_dose_scoring.py` 使用真正的 Geant4 ST/MT、双 run 输出，再通过 CLI 扩展为 JSON，对照每个 worker CSV 核对 run、线程、质量、能量和 Gy。后者要求当前构建的 Release 后端及其运行环境，不应在缺失二进制时标记通过。统一测试会记录源码指纹、PASS/FAIL/SKIP 和报告路径。

GUI 专项 `gui/smoke_tests/smoke_output_extensions_gui.py` 已覆盖真实 Qt 异步 CLI 导出、两种 JSON 数值、重复运行/覆盖拒绝、进程取消、启动失败、损坏 JSON 和页面关闭；尚未进行真实 GUI 人工视觉验收或在同一 GUI 专项内从 Geant4 运行到 JSON 的连贯操作。下一步设计统一扩展发现、兼容协商、C++ 插件生命周期与隔离；这些均尚未实现。
