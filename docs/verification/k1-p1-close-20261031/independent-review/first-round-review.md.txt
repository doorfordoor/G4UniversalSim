## 范围与结论

1. **P1 r3 拒绝顺序正确，未发现确定阻断缺陷。** experiment_bundle.py:741–748 对每个 source receipt 在 resolve 之前先调用 _no_links(path)，并对 staging 同样检查。_no_links:111–122 遍历词法路径及全部祖先，在 abspath 折叠之前拒绝 symlink / junction / st_file_attributes 的 reparse 位。历史“外部源父目录在 inspect 后变为指向 staging 的 junction”会在 745 左侧拒绝，不再因 canonical containment 直接 continue。父路径已有链接的正常读取由 _read:125–136 / _Closure.add:177–192 同样约束。
2. **8.3 与长拼写不应再触发中间文件误重读。** package_writer.py:149–159 使用 resolve 写入收据，export_bundle:721 有意清除 writer；745 在无链接前提下比较规范身份，Path.resolve 默认 strict=False 可处理已删除的 writer 尾部。需要当前平台运行证明具体路径表现。普通外部收据在 747 仍由 _read 检查单硬链接普通文件并比较最初 SHA；未把原始读取 SHA 替换成重定位后的成员 SHA。
3. **异常传播与失败清理结构未因 r3 改变。** export_bundle:749–755 在拒绝或发布失败时 committed 仍为 false，清理 staging；成功 exclusive rename 后才 committed=true。Windows os.rename 与 Linux renameat2(RENAME_NOREPLACE) 的发布差异在 655–670。被拒异常不会走 return 成功。外部源从不由 exporter 写入；恢复测试源是夹具自己的责任。清理本身抛错可覆盖原异常，这是原有行为，最小 P1 动态证据须确认这次实际清理完成。
4. **搬移草稿身份未放宽。** _snapshot_paths:393/459–472 仅 loading 时、原模型值与 raw.strip() 经同一 _resolve 后相等才改草稿；非法/空白/不同草稿保留，保留首尾空白。真实 GUI 下一动作回归在 smoke_k1_relocation:121–177；backend 选择在 144–152/178–183。组件、真实后端、实窗各自计证。
5. **测试缺口明确。** test_k1_staging_alias:46–73 测真实 exporter 的等价词法拼写；74–115 为导出前已存在的静态 junction/symlink 拒绝；116–122 的真实 Windows 8.3 在不可用时只记录缺失。它本身不覆盖 post-capture 改变。smoke_k1_relocation 也不覆盖该时间边界。旧 late-reparse-base 与 candidate receipt 已读：base error+published=false；r2 error=null+published=true。两个脚本 exit=0 是反例观察成功，绝非 r2 行为通过。
