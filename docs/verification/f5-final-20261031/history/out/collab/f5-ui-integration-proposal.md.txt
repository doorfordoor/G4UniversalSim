# F5 GUI 编辑、撤销与恢复集成提案

审查基线：`676ffb2b27a56d636a2c984012c9442a6091337b`，2026-10-30。此文件为只读勘察的设计输出，未修改产品文件，未进行桌面验收。下面“建议”均待主设计师与 core/recovery 接口裁决；不将现有缺口说成已实现。

## 1. 必须闭合的实际边界

1. **确定为缺陷（F5 接续需修）**：普通项目对象只有 geometry/source/physics/scoring editor，没有材料文档；`ConfigBuilderPage.update_project()` 也未复制材料草稿。材料只留在页面对象，重新发布项目会 `reload_materials()` 从源重建。因此不可仅给 `G4USimProject` 套 undo/autosave 就声称完整覆盖材料编辑。证据：`gui/g4usim_gui/core/project.py:35`、`:60`；`widgets/config_builder_page.py:245`、`:249`、`:261`；`widgets/config/materials.py:129`。这里及下文 `widgets/`、`window/`、`core/` 路径均相对 `gui/g4usim_gui/`。
2. **确定为缺口**：当前没有项目级 Undo/Redo、保存标记或关闭时草稿提示。菜单只有 File/View；`closeEvent` 直接停止作业并关闭。材料/几何 `is_dirty` 是“不同于源文件”的 writer 选择标记，不能充当项目“是否保存”的 dirty。证据：`window/shell.py:240`；`main_window.py:120`；`widgets/config/geometry.py:521`。
3. **确定为风险，须回归实验覆盖**：Setup 的 quick signals 先连 `_emit_changed`，再连 SPS 同步槽；一次键入可能先发旧模型、后发同步模型，不能把每次 `settingsChanged` 当独立命令。证据：`widgets/config_builder_page.py:195`；`widgets/config/setup_panel.py:204`；`widgets/config/run_config.py:436`。材料逐字输入还会重建表格/详情，恢复时必须避开递归写入与光标跳动。
4. **确定为缺口**：表格正在编辑但未提交的文字只存在 delegate editor；F4 只监听文字失效诊断，没有草稿保存。Setup 无效 seed 会变成模型 None，向导各页还有尚未写入 spec 的控件数据。只保存 dataclass 会丢这些文本。证据：`widgets/diagnostic_navigation.py:163`；`widgets/config/setup_panel.py:261`；`widgets/new_simulation_wizard.py:167`、`:206`、`:294`。
5. **确定为边界不齐，F5 统一门禁**：运行时仅禁 Project 的部分控件，Config 仍可改，菜单 Open/Wizard 仍可调；Project browse 按钮也不在禁用清单。扫描仅禁创建/打开/运行按钮，场景仅禁生成/校验/运行按钮，其草稿输入仍活动。证据：`window/run.py:258`；`widgets/project_page.py:170`、`:220`；`widgets/scan_page.py:444`；`widgets/scenario_page.py:248`。建议 F5 在拥有者任务执行期间冻结会影响该任务的编辑、Undo/Redo、替换入口；按钮禁用与方法守卫两层都做。不能仅靠 UI disabled。
6. **无问题，须保持**：F4 generation/epoch 不属于可撤销快照；每次 edit/undo/redo/reload/recovery 都递增，旧报告即使值恢复相同仍不可复活。证据：`widgets/config_builder_page.py:341`；`widgets/form_diagnostics.py:66`；`docs/agent-history.md:499`。

## 2. 推荐事务接口（尽早冻结）

推荐无 Qt core 接受显式命令；Qt 层只采集/投影，不让 core 依赖控件：

```python
history = WorkspaceHistory(initial_snapshot, limit=...)
history.execute(label_key, mutate_candidate, merge_key=None, merge_epoch=None)
# 或对已有槽的适配：history.record(before, after, label_key, merge_key, merge_epoch)
history.undo() -> WorkspaceSnapshot | None
history.redo() -> WorkspaceSnapshot | None
history.current() -> WorkspaceSnapshot   # detached/deep-copy
history.mark_saved(snapshot)             # 成功落盘后，不能仅靠当前游标猜
history.reset(snapshot, saved=True)      # 成功 Open/Recent/Snapshot 切换文档
```

`WorkspaceSnapshot` 至少包含：严格项目数据、完整 `MaterialDocument`、完整 `GeometryDocument` 与源绑定/源错误/blocker、Source/Physics/Scoring 模型、可编辑 raw drafts、scan 草稿与 deep-copy base、scenario 字段和目标目录、可恢复 wizard 草稿。具体存储 schema 由 core/recovery agent 决定；GUI 不能自造第二个业务快照协议。

**GUI 必需 hooks**：`capture_workspace()`、`apply_workspace(snapshot, reason)`、`commit_edit(label, operation, merge_key)`、`flush_pending_edit()`、`can_mutate_workspace(reason)`、`history_changed`。恢复文件调用同一 capture/apply，不能通过“保存→重新打开源文件”模拟恢复；历史命令 replay 不调用源读取、生成包或后端运行。

**原子范围**：一次用户动作以最外层 `begin/end` 包住完整 signal cascade；内层 `_emit_changed` 仅标记需要刷新，退出最外层后 capture 一次。可采用 core `record(before, after)` 命令对象；不要仅用延迟 timer 对比掩盖多次独立按钮点击，也不要在每个现有槽之后单独 push。前一已提交快照加 raw draft overlay 可作为输入事件前状态，但 explicit button/reload/wizard 操作必须显式 transaction。

**投影**：`apply_workspace` 在恢复 guard + `QSignalBlocker` 下赋全模型，再刷新所有镜像，最后一次性失效 diagnostics/package/preview。不要调用当前 `_set_project` 作为普通 Undo 的恢复器，它会读磁盘且刷新结果视图 (`window/project.py:77`、`widgets/config_builder_page.py:249`)。Open 使用独立 reset 路径；Undo 不改变 project_file，也不把历史 outputDir 当已运行事实重新发布。

## 4. 历史合并与未提交草稿

- 主窗口维护一条带 scope 标签的会话配置历史，Project/Config/scan/scenario 按真实编辑先后撤销；不要因为切页而把 Undo 静默路由到另一堆栈。菜单例如“撤销：扫描 · 参数值”。向导为 modal 子历史，主窗口堆栈在向导内暂停。
- 同一编辑会话+同一字段+同一行稳定定位，连续键入可合并；建议静默 800ms 或焦点转移、Enter、选行/切页、选择另一控件、保存、Undo/Redo、结构命令、读源后终止合并。长按 spinbox 在一次 press/release 合并；离散 combo/checkbox/button 一次一命令。不得跨 save marker 合并，也不得跨对象删除重建后凭同名合并。
- 插入行、删除行、拖动不存在；现有 move 按钮每次一命令，不与字段编辑合并。duplicate 必须深拷贝内嵌 dict/list；修改副本不改变原件/历史。
- 文本草稿需保存原始字符串（含空、非法单位、未完成整数、Unicode 空白），业务投影仍遵守现行 trim/解析规则。不可为了 autosave 强制通过 validator，也不可把非法 seed None 当已经保存原输入。
- 表格 edit delegate 管理 pending cell `(collection,row identity,column,before text,raw text)`；Autosave 可采集未 commit 的 raw draft。按 Undo 时先结束当前编辑组，再撤销该组；Escape 取消该 cell 草稿且不创建业务命令；Enter/Tab/失焦提交一次。需专测菜单点击导致 focus-out 后再触发 Undo 的双重执行。
- `QLineEdit/QPlainTextEdit/QAbstractSpinBox.lineEdit()` 的原生 Ctrl+Z/Redo 与右键菜单不能另起一套编辑历史。配置可编辑控件统一接入快捷键/上下文菜单路由，保留 copy/cut/paste/select all 与 IME；只读日志/原文使用自身普通复制菜单。单纯 QAction shortcut 会被 QLineEdit ShortcutOverride 吞掉，必须测试 keyboard 和 menu 两个入口。
- Undo 后新增编辑清掉 redo；失败/no-op/rejected command 不占历史。历史容量/清理只裁掉最旧命令，不冒充变为已保存；清理后仍按保存指纹判 dirty。

## 5. 菜单、工具条、状态与生命周期

建议 File 保留已有项，补标准 `Ctrl+O`、`Ctrl+S`、`Ctrl+Shift+S`，增加“恢复未保存工作…”；Edit 菜单提供 `撤销 <动作>` Ctrl+Z、`重做 <动作>` Ctrl+Shift+Z（Windows 同时 Ctrl+Y），空栈显示灰色。主框架标题区小工具条放两个撤销/重做按钮，复用同一 QAction，不新造快捷键或重复回调。所有 label/tooltip/action reason 走 i18n，主题用既有 token。

标题 `项目名 *` 表示普通项目/工作草稿未保存，状态栏独立显示“恢复副本已更新 HH:mm / 自动保存失败：原因 / 本轮未创建恢复副本”。材料源 dirty 仍用现有材料标记，不因保存项目错误清为源 clean。主报告不得将“已写恢复文件”称作“项目已保存”或“配置已验证”。

在 **Open/Recent/Load snapshot/Close** 之前先 `flush_pending_edit`，如 dirty 给“保存 / 放弃修改 / 取消”。只有真正保存成功才继续；取消保存对话框或写入失败视为取消切换。完成候选解析和投影预检后才发布并 reset 历史；候选错误保持旧项目、栈、原路径、恢复条目。迁移创建副本不修改历史；显式打开副本才走同一替换流程。Wizard Finish、例子套用保留同文档 undo；外部 Open 作为文档边界清栈。

运行门禁建议：main run/Inspect pending 时冻结主 Project/Config 与相关主历史；scan run 冻结 scan 草稿/base与替换manifest操作；scenario run 冻结 scenario草稿/directory；跨 scope 全局 Undo 若顶项涉及忙 scope 则明确禁用并说明原因，不越过它去撤销更旧项。项目替换/恢复在任一 owned run/Inspect 使用 workspace 时禁止。只读查看、日志、Stop/Kill 保持可用。后端 geometry 导出不是 run，修改时取消/失效旧请求并保持“最后请求”发布规则。

**关闭次序**：先处理未保存选择，再停止 owned jobs、最后可靠 flush recovery/清理自身会话租约并关窗。当前 closeEvent 一开始停全部 timer；若用户取消或进程仍未停止导致 event.ignore，应恢复自动保存 timer，不得把取消关闭变成之后不再自动保存。不得关闭其他实例任务，保留 Q1 bounded wait 行为。

## 6. 自动保存与恢复对话框

建议编辑后 debounce 2 秒、持续输入最多 30 秒有一次落盘；间隔/上限归 recovery 核心配置。UI timer 只采 snapshot，文件写入由 recovery 服务负责，上一写入未完成时仅保留最新 revision；旧异步成功不能把新草稿显示为已保存。路径用系统用户数据/恢复目录，不写原 `.json`，原件不覆盖，不生成或运行 Geant4。

启动发现非活跃会话的有效恢复项时，展示可比较列表：项目名/原项目绝对路径或“未命名”、最后恢复时间、来源会话、原件是否改变/缺失、所含草稿（材料/几何/扫描/场景/向导）、校验状态。选择项目后摘要明确“恢复的是未验证编辑草稿，不恢复运行成功状态或后台进程”。

三个明确按钮：**恢复草稿**（载入内存、标未保存、生成包 stale，建议后续 Save As；若含 wizard 重新打开草稿）/**暂不恢复**（保留条目，不删除）/**丢弃所选恢复副本**（明确确认后只删除所选本应用恢复条目）。关闭对话框等于暂不恢复。损坏/超限/未知schema 条目显示原因且不能恢复，保留原文件供诊断；原项目磁盘改变展示双方时间/哈希信息，禁止自动覆盖或拼接。

多实例只能读取自己的 active session，其他 live lease 条目显示“另一窗口正在编辑”不可接管；恢复在新会话持有独立条目，旧条目只在恢复成功且新恢复写入可靠后按协议消费。恢复失败保持当前工作、原恢复文件与 project_file 不变。退出明确放弃可清理该会话恢复；正常成功保存时清理匹配 revision 的恢复，不能删另一实例或更新的 revision。

## 7. 外部动作不可撤销

- 写普通项目/另存、创建迁移副本、生成运行包、创建扫描目录/场景文件、复制历史包、导出日志/结果/图片：Undo 不回滚磁盘，不删除新产物、不覆盖旧文件。
- Run/Scan/Scenario 的启动/停止/kill、既有进程结果、统计合并、扩展执行、读取或删除外部文件：不可放进配置命令回放。复原配置不会重跑，不会恢复已停止进程或抹掉真实日志。
- 当前 `_generate_current_package` 写 configPath/macroPath/outputDir（`window/run.py:226`），需要从编辑历史的“运行包状态”分离或作为不可重放派生元信息；任何 Undo 后包标 stale，不能恢复“可运行旧包”标记。结果页仍绑定产生结果的实际目录，不随配置 history 偷换。扫描 `create_scan` 的 manifest、场景 `_generated/_outcome` 同理（`widgets/scan_page.py:228`；`widgets/scenario_page.py:295`）。
- 语言/主题、导航、窗口布局、相机、只读日志和诊断定位不是配置命令。F5 不扩 J1/K1/L1，不增加任意自动工具执行。
