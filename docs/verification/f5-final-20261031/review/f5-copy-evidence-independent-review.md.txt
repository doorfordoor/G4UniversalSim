`f5-copy-evidence.py:21–26` 只拒绝首部盘符、反斜杠和字面 `.`/`..`，不拒绝成员内冒号；`:85` 只对完整第一段做保留名比较。因此合法结构的 manifest 目标 `copy-receipt.json:stream` 被 `make_plan` 接受。

- 真实结果：`make_plan` 接受；`execute` 抛 `ValueError: Copied member set differs from explicit manifest`。
- `copy-receipt.json` 存在，默认流 **0 字节**；`:stream` 为本测试的 **28 字节**证据；`copy-incomplete.json.copy_status=incomplete`。
- **没有**声称返回了有效成功 JSON；helper 的 execute 仍失败。问题是文件命名协议可被突破，不能仅靠完成文件名存在判断归档成功。
- 原始收据：`out/collab/f5-copy-evidence-independent-path-probe.json` 的 `copy-receipt.json:stream` 项及保留夹具。源 SHA 未变。

相邻输入 `nested/file:stream` 同样 plan 接受，执行到写盘后才在 exact-files 检查失败；`NUL` plan 接受，访问设备后以 Bad file descriptor 失败。两种尾部带空格/点的 `.. ` 路径在 execute 的 resolve 检查中被拒绝，**本次没有复现目录逃逸或外部写入**，不得把这两项说成已逃逸。
