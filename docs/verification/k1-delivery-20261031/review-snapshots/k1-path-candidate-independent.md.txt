## 两处测试覆盖缺口

### [P2] probe 的 cwd 断言只是请求回显，不能守住“数据发现前切换”

位置：候选 test_backend_working_directory.py:92-95；关联冻结 environment_discovery.py:53-54、:60。

probe[working_directory] 在 Python 发起子进程前直接写入请求 cwd。它即使在后端先从短祖先解析了相对 GEANT4_DATA_DIR、然后才 chdir，也会是正确值。CLI inspect 的 :58 能证明写 plan 时已经切换，不能证明更早的数据发现顺序。当前专项依赖机器已配置数据，因此这种错误顺序可同时通过这些断言；本候选实际源码顺序是对的，但回归尚不能保护该点。

具体负对照：在真实深 cwd 放置可指向现有数据根的相对资源路径，在短 launch cwd 同名位置放缺失/错误数据；通过 probe_environment 的 env 参数传相对 GEANT4_DATA_DIR（清理会抢占优先级的 G4*DATA），核对后端 data.report discovery 的实际 dataset 路径/required_complete，并对调路径做失败对照。无需复制数据集或改系统设置。能力只读返回和 data 两条命令都必须经 helper，后端数据事实由 report 验，不只看 probe 请求字段。

### [P2] 新能力位尚无真实协议断言

位置：候选 BackendCapabilities.hh:16 与 test_backend_working_directory.py:92-95。

专项仅要求环境 ready；删除 launch.working_directory 字段，仍可通过当前断言。这会遗漏 Python 兼容协商所依赖的公开协议。应从真实 capabilities.data 校验 launch.working_directory **is True**，不能用 truthy 的 1 或字符串替代；Python helper 的旧后端/不支持 flag 错误分类由其交付测试覆盖，不能把该错误归成 Geant4 数据缺失。

以上两项是具体证据覆盖缺口，不是声称候选后端已经复现错误行为。
