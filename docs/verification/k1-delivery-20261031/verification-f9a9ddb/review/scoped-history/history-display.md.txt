## 身份与资格边界

- window/run.py 在已有 runner 的 Starting 信号处绑定；window/experiment.py 从公共 records 中只接受唯一 pending run/initialization 的 record_id、run_id、整数revision，绑定元组来自服务记录，不解析 label、输出路径、事件数或 telemetry run index。缺失/不唯一时显示 unverified，不猜身份。
- 显示范围来自同一 state.history/revision/qualification 与 busy：record缺失→unverified；stale/revision不符→changed；存在更新运行/初始化动作→historical；实际进程活动→running；pending/busy/checking→checking；之后才允许该记录 passed→current。runner finished 与 F1/后台持久化核验之间，不会直接用 RunResult.success 晋升当前通过。
- shell 将 changed/historical/unverified/checking 统一去掉 success 颜色，结果与进度用相同范围文案；run_id等显示在 tooltip。旧结果快照不是重新读取的历史机器事实，也不用于 core资格。
- run_page 保存显示用深拷贝，在原 F5 restore 清空 _result_state/_progress_data 后仍能展示“上次运行”、旧3/3/100%。没有修改 transactions.py、原恢复哨兵、RunResult、record/status、实际摘要、原始输入身份或持久化资格。新 runner Starting 清掉显示快照，避免把旧100%冒成本次新进度。
- 原始 raw draft、Undo/Redo/恢复和外部字节变化通过原 service/history_changed 刷新传播；没有只监听seed控件。语言刷新会重画范围文案和header，不靠缓存翻译后的成功字符串。
