# F3-2 噪声修订 R3｜测量方案（N=2000，保守备选）

2026-11-07。本轮只收敛方案与无 Geant4 自测，不启动后端、不改旧证据、不改产品、不提交 Git。
主审已依据实测内存证据与设计二审选定 **N=2000、2 线程、seed 4242、36 次启动预算、5% MAD 门与原科学标准不变**；
不开发 N=4000 的 eventID 分区比较器，不新建通用比较框架。

## 1. 为什么是这个方案

- 旧两批各 36 次启动全部 exit 0，科学/哈希/PID 检查通过，但计时噪声跨过 5% 门：
  - 批1 `hits/csv` MAD 5.15539%，批2 `hits/root` MAD 5.52623%；其余组合合格。
- 两批的已知缺陷：每轮内组合顺序固定（`hits/csv → hits/root → mesh/csv → mesh/root`），
  组合身份与执行位置完全混杂；跨批中位漂移 +11.5%～+15.6% 且无代码变化，说明存在机器状态漂移，
  但既有快照无法归因到具体后台进程，也不能把漂移写成因果诊断。
- 1000 事件单次离线科学比较实测 Python 进程 OS 峰值 **2,550,013,952 B（约 2.55 GB）**，
  身份绑定的 PID observer 采样 295 次、exit 0，见 `out/collab/f3-noise-r3/analysis-memory-probe/`。
  按事件数线性放大只是**假设场景**：N=2000 约 5.1 GB，N=4000 约 10.2 GB；后者超过旧批执行时
  报告的约 6.8 GB 空闲内存，因此不再作为本轮方案，也不据此声称任何"必然通过"。
- 结论：采用最小改动备选 **N=2000 + 原比较算法**，在运行时以真实可用内存作为执行准备边界。

## 2. 测量设计（36 次启动，全部真实单进程 beamOn 2000）

每个样本是一个后端进程：2 线程、seed 4242、同一几何/物理/源与输出模板，只把事件数从
1000 改为 2000；`total_elapsed_s` 仍为全进程 elapsed，Python 哈希校验仍在计时之外。

| 阶段 | 轮数 | 组合 | 启动数 | 用途 |
| --- | --- | --- | --- | --- |
| warmup | 1 | 4 | 4 | 独立预热，不进入统计 |
| timing | 5 | 4 | 20 | 5 个完整交错区组，MAD/中位与 5% 门 |
| memory | 3 | 4 | 12 | PID 绑定的独立 RSS 样本 |
| **合计** | | | **36** | 不拼接、不剔除、不补跑 |

**顺序**：只增加一个可选的 `--order blocked`。默认仍为 `legacy`（旧脚本行为与报告形状不变）。
blocked 规则：第 r 轮把组合列表左旋 r 位；4 组合 × 5 轮使每个组合在位置 0–3 各出现至少一次。
报告逐样本记录两个字段，名称与实际含义一致：

- `execution_position`：该组合在本轮调度中的实际执行位置；
- `base_combo_index`：该组合在 CLI 固定列表中的编号。

不再把固定组合编号写成 `order_index` 冒充执行顺序。blocked 是本轮唯一的顺序选项，
不做伪随机化，也不声称旋转本身能降低 MAD；它只是让位置效应可被检查。

## 3. 离线科学复验（独立子进程，任务级绑定 N）

- 比较器仍是冻结的 `out/collab/20261107-f3-baseline/preflight/science_compare.py`
  （SHA-256 `c8195197b9bd7278f74d689edff83dda247af1b4c686f41b3bcd0e7fc982bd82`），文件不改。
- `compare_n.py` 在任务级 import 该模块并设置 `module.EVENTS = 2000`：真实运行要求
  planned/completed=2000、事件 0..1999 完整且唯一；旧文件保持 1000 的默认值不受影响。
- 每个组合在**独立 Python 子进程**中比较，子进程退出即释放缓存。正式样本共 **32 个**，
  每个样本都与**同组合的 timing 第 0 次**比较，结论写入 `measurement/science/`：
  - 4 个 timing 第 0 次自身资格核：元数据、角色、注册文件与回执 SHA 全部核对；
  - 16 个 timing 第 1..4 次对第 0 次；
  - 12 个独立 memory 样本（第 0..2 次）对同组合 timing 第 0 次。
- 32 个正式样本的 SHA/输入渲染/注册文件仍逐样本独立核对；不得用 16 个计时配对替代
  32 个正式样本，也不得漏掉 4 个 r0 资格核或 12 个 memory 样本。
- 旧比较算法、元组多重集、12 位有效数字、1e-9/0 容差、mesh 全 run N 只取一次等语义全部保留。

## 4. 资源就绪观察（执行准备边界，不放宽科学断言）

- N=2000 的线性内存投影约 5.1 GB；旧批执行时报告空闲约 6.8 GB，余量不足 2 GB。
- 离线比较启动前读取**执行时真实可用物理内存**；低于 **6 GiB** 时输出
  `status=resource_not_ready`、记录观测值与所需值、**不启动任何比较**，计划保留为未完成，
  等待资源满足后再继续。不得关闭用户进程，不得为通过检查而放宽 6 GiB 边界。
- 该边界是执行准备条件，不是科学判据；5% MAD、科学等价与全部负控都不因内存状态改变。

## 5. 验收与停止条件

- 36 次启动全部成功；每样本 exit 0、注册文件/哈希/PID 身份检查通过。
- 噪声门：四个组合**各自**的 relative MAD ≤ 5%（等号通过）。这是冻结测量唯一的噪声判据；
  不得改成只看 `hits` 两点或把其余三个组合写成"回归"。任一组合超门时，本轮结论为
  `inconclusive`（资源/噪声），保留全部样本，不称产品失败、不称阶段通过。
  未来的候选优化比较另按预注册规则（≥5% 收益在 5 对中至少 4 对、其余组合 ≤5%）评定，
  该规则不适用于本轮冻结基线。
- 32 个正式样本的离线比较全部 `status=pass`；旧比较器 SHA 不变；资源门记录真实可用内存。
- 任一科学比较失败：保留输出与子进程日志，停止，不重跑、不改模板/种子/容差/事件数。
- 任一计时组合超门：本轮结论为 `inconclusive`，保留全部样本，不剔除异常点、不增加重复次数。
- 本轮自测不启动 Geant4、不创建测量输出目录、不改旧批报告；回执后停写等最终静态复验与冻结。
