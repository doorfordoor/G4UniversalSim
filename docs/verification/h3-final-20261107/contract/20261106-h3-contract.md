状态：`draft`，`implementation_authorized=false`。依据 2026-11-06 派工（m20617）、固定清单 `docs/collab/decisions/20261106-h3-closeout.md`，并按 `docs/collab/reviews/20261106-h3-contract-review-r1.md` 的 8 点逐项修订。本文件只做语义与架构合同，不实施产品、不运行正式基准、不扩展工具。若独审冻结，本文件即 H3-2..H3-5 验收基线；冲突以冻结决定为准。

## 0 判定边界（必须先读）

1. 平行世界一旦注册，`G4RunManagerKernel::InitializePhysics()` 会对 `numberOfParallelWorld > 0` 调用 `physicsList->UseCoupledTransportation()`（Geant4 11.3.2 `source/run/src/G4RunManagerKernel.cc:577`）。**输运机制因此改变，不能承诺与质量世界运行逐事件、逐步长或 RNG 序列一致。**
2. 本阶段只承诺两类限定基准：同一次运行内质量世界计分薄层与平行世界复制层的**聚合能量/长度归属一致**（接线与归一化检查）；独立批次间**等效剂量在预注册区间判据内兼容**（统计兼容，不是无偏性证明）。
3. 计分几何不改变质量世界材料与输运定义；`G4ParallelWorldPhysics(name, false)` 的 `layeredMass=false` 不切换质量世界材料。平行体积与质量世界体积空间重叠是允许的，不因此判错。
4. 边界归属沿用项目既有语义：一个计分步的全部 `edep`/`stepLength` 归入其**步前**体积，不按步内穿越比例拆分，不把边界步计入两个体积。
5. 任何“与质量世界剂量相同”的结论只在 §8 的病例、输入、种子与判据内成立；不得外推到其他几何、粒子、能量或偏置配置。
6. 本阶段**不修改** `ScoringManager::ScoreHit` 的既有自动路由语义；平行世界使用专用入口（§4.6），从结构上避免污染质量世界事件累计/hits/默认直方图。

## 3 最小配置接口

### 3.1 主 INI（可选，默认关闭）

```ini
[parallel_world]
enabled = true
name = ScoringWorld
geometry_config = parallel_world.ini
```

- `enabled`：布尔，缺省 `false`。语义统一如下：
  - `enabled` 缺省或 `false`，且**没有任何**其他 `[parallel_world*]` 键、没有并行几何文件引用：并行世界禁用，完全保持旧行为（无新文件、无旧行为字段变化、无有效配置条目）。
  - `enabled=false` 但存在 `name`/`geometry_config` 等其他平行配置：**配置期拒绝**（避免显式关闭却残留配置造成误解；诊断给出文件/行/section/key）。
  - `enabled=true`：`geometry_config` 必填；随后进入 §6 Stage A。
- `name`：非空；`[A-Za-z0-9_]` 开头，可含 `-`；不得与质量世界名或其物理体积名重复；不得含 `/`、`#`、空白；缺省 `ScoringWorld`。
- `geometry_config`：启用时必填，路径按主 INI 目录解析（与 `[geometry]/config` 同约定）；必须是存在的普通文件。
- 只允许前置静态配置；不新增 `/AIHL/...` 运行时修改命令；初始化后修改一律按既有 PreInit 门禁拒绝。

### 3.2 并行几何文件语法（层次几何受限子集 + 规则网格）

独立文件，使用现有 `IniReader` 与单位约定，但只实现下列子集；未知 section/key、重复声明、空 section 在构建任何几何对象前拒绝。

```ini
[world]
material = G4_Galactic

[volume.Slab]
parent = world
shape = box
size = 20, 20, 2 mm
position = 0, 0, 0 mm
material = water
sensitive = true

[grid.SlabGrid]
parent = world
size = 20, 20, 2 mm
position = 0, 0, 0 mm
material = water
bins = 4, 4, 1
sensitive = true
```

- `[world]`：只作声明；唯一允许键 `material = G4_Galactic`。**不写 `size`、不用于构造**；ghost 世界 solid 由 Geant4 从质量世界复制。体积/网格的包含校验用实际质量世界 solid 的包围盒（§6 Stage B），不拿声明值代替。
- `[volume.<name>]`：`parent=world`、`shape=box`、`size`（三个正有限长度）、`position`（三个有限长度，缺省 0）、`material`（主材料文件中可解析、密度有限且 >0）、`sensitive=true`。
- `[grid.<name>]`（规则网格，正式支持“网格与计分体积”要求，见 §3.4）：`parent=world`、`size`（网格区域总尺寸，三个正有限长度）、`position`（区域中心，缺省 0）、`material`、`bins = nx, ny, nz`（三个整数，均 ≥1，`nx·ny·nz ≤ 4096`）、`sensitive=true`。
  - 派生：`dx = size.x/nx` 等，每个 `d > 0`；单元 `(ix,iy,iz)` 的 `volume_name = <grid>_<ix>_<iy>_<iz>`（ix 变化最快，其次 iy，再 iz），`doseVolumePath = /<parallel_world.name>#0/<grid>_<ix>_<iy>_<iz>`；单元中心 = 区域中心 + 每轴 `(i+0.5)·d − size/2`；单元体积 = `dx·dy·dz`（mm³），参考质量 = 声明材料密度 × 体积。
  - 单元之间在构造上解析不重叠（规则分割），无需再跑重叠检测；网格整体以及单个单元必须位于质量世界 solid 内部（Stage B）。
  - H3-4 Case A2 使用 `bins = 4, 4, 1` 的 16 单元网格，不手写 16 个 `[volume.*]`。
- 拒绝：嵌套体积（`parent != world`）、非 box 形状、旋转/placement/replica/parameterised/布尔/装配/GDML/STL/tessellated、region/cuts/visual/bias 等键；重复体积/网格名；`bins` 非整数或 ≤0、单元尺寸非正；与 `[world]` 之外未经校验的包含关系。
- 本阶段只支持“单 box 体积 + 规则 box 网格”两类计分体；任意形状、重叠网格、非均匀网格属后续阶段，不在 H3 范围。

### 3.3 与原生 mesh 的关系（原范围说明）

- ROADMAP/清单要求“parallel world 内网格与计分体积”。本合同的规则网格是**项目自有的解析 box 网格**：它由 `[grid.<name>]` 生成 N 个真实 `G4Box` 计分体，逐个进入 Dose/Fluence scorer 与 H2 过滤/谱，满足“网格与计分体积”的最小可用形态；不是 Geant4 原生 `/score` mesh 的复用。
- 不复用原生 mesh 的依据（真实机制，不是泛泛拒绝）：原生 mesh 由 `G4ScoringManager` 在自己的内部平行世界中建立并依赖 `G4ParallelWorldScoringProcess`（`src/Scoring/ScoringMeshConfig.cc` 观察 `mesh->GetParallelWorldProcess()`）；再叠加用户 `G4VUserParallelWorld` 会形成两套并行世界/两套计分过程，现有产品代码、输出身份与测试均未覆盖该组合。H3-5 之前不把原生 mesh + 用户平行世界列为支持组合；H3-3 文档与 GUI 必须写明替代路径（规则网格）。
- 后续若需任意形状/非均匀网格，另立合同扩展 `[grid]` 或复用原生 mesh，不在本阶段。

### 3.4 不支持组合（v1 显式拒绝及依据）

- `[output] format = root`：ROOT 输出来自 `G4AnalysisManager` 的合并文件（`include/Output/OutputManager.hh:19`），现有 ROOT writer 只为既有 scorer/直方图登记；平行世界计分体未登记进 ROOT 输出，开启会得到缺失平行体积的文件（静默不完整），故拒绝并在 H3-5 后再评估扩展。
- `[biasing] enabled = true`：H4 之前不组合通用偏置与平行世界；权重语义叠加与 `G4ParallelWorldProcess` 过程顺序均未验收，故拒绝。
- `[field]` 非空：`G4FieldManager` 挂接在质量世界 logical volume 的 per-thread 槽（`G4LogicalVolume.hh` 的 `G4MT_fmanager` 宏与 `G4LVData`），ghost 体积无对应 field manager；平行体积在含场输运中的边界/能量沉积没有契约或测试覆盖，故拒绝。
- `[scoring.mesh.*]`：见 §3.3 的依据。
- `[scoring]` 中 LET 或 displacement 启用：两者依赖质量世界电子阻止本领/NIEL 表上下文；ghost 步 `CopyStep` 的 `meanKineticEnergy`/材料上下文不足，v1 只做 dose/fluence。
- 其余组合（ROOT、场、偏置、mesh）在 H3-5 交班中列后续条目，不得悄悄打开。

## 4 计分语义

### 4.1 计分步来源与字段

`ParallelScoringDetector` 的输入是 `G4ParallelWorldProcess` 提供的 ghost `G4Step`（`CopyStep` 语义见 §2）。`HitRecord` 填充：

- `eventID`/`trackID`/`parentID`：ghost 步 track（与质量步一致）。
- `particleName`：track 粒子定义名（精确 Geant4 名，供 H2 过滤）。
- `edep`/`ndep`：ghost 步的质量步拷贝值（MeV；本阶段不用 `ndep` 计分）。
- `stepLength`：ghost 步长（mm；含零沉积步）。
- `kineticEnergy`：ghost **步前**点动能（MeV；与质量世界 hits 的 `kineticEnergy_MeV` 同源语义）。
- `weight`：ghost 步 track 权重（平行世界不重复乘权重）。
- `doseVolumePath`/`volumeName`：由 ghost touchable history 生成，根为 `/<parallel_world.name>#0`。
- `processName`：固定 `parallel_world_step`（诊断可区分，不参与物理判断）。

### 4.2 权重与累积

- 每个 ghost 步只调用一次专用入口（§4.6）；dose 贡献 `w·edep[J]/m_kg`，fluence 贡献 `w·stepLength/V_mm3`。权重恰乘一次。
- 零沉积步仍进入 fluence（与质量世界 SD 的零沉积分支一致）；平行世界**不写 hits 行**。
- `n_events`：本线程本轮完成的全部事件数（含零贡献事件）；沿用 scorer 现有 `EndEvent` 计数口径。无命中体积时 CSV 只写表头（header-only 合法）。
- 统计矩：沿用 `HistoryStatistics` 事件矩与 `uncertainty_estimator=uncorrected_event_moments_v1`；不新增每 bin 不确定度。

### 4.3 质量/体积归一化与“参考剂量”命名

- `m_ref_kg = density_kg_per_m3 × volume_mm3 × 1e-9`，`volume_mm3` 由 box/网格单元尺寸精确计算；`density` 来自声明材料的 `G4Material::GetDensity()`，必须有限且 >0。
- 内核对象就绪后核对：ghost 逻辑体积 `GetMass(true,false)`（自身材料，不传质量步材料）与配置参考质量相对差 ≤1e-12。
- 计量名称：本阶段 CSV 列名保持 `weighted_dose_Gy`（不改 schema），但文档/身份必须写明它表示**按声明材料参考质量归一的能量沉积剂量**（`reference dose`）；因 `layeredMass=false`，实际能量沉积来自质量世界同一位置的输运材料。**仅当声明材料与该位置质量世界材料一致时**，才可把它称为该材料的近似吸收剂量；材料不一致的病例不在 H3-4 验收域，不得展示为“任意材料中的真实吸收剂量”。
- `run_summary`/有效配置增加 `parallel_world_dose_normalization = declared_material_reference_mass`；逐体积记录 `material_matches_mass_world`（由配置与质量几何材料解析比较，无法确定时记 `unknown`，不推测）。H3-4 只使用材料匹配病例（水/水）。

### 4.4 事件 N、零贡献、边界归属

- 边界归属：每步全部 `edep`/`stepLength` 归入**步前**体积；网格内部边界步归入步前单元；同一步不进入两个单元，不按穿越比例拆分。
- 网格总量守恒：Σ 全部单元能量 = 同一批步的总能量（每步恰好一次），与质量世界计分薄层的总量在 §8.2 判据内比较。
- 质量世界 SD 与平行 SD 可同时启用：同一物理步分别进入两个世界的计分路径，`volume_path` 不同，代表不同体积，不构成重复计分。
- 边界相关观测（平行步数、零沉积步数、每单元步数）只作诊断记录，不设通过门槛。

### 4.5 H2 过滤/谱复用边界

- 过滤器/谱 section 按 scorer 配置，不按世界配置；启用平行世界后同时作用于质量世界与平行世界全部命中。合同**不新增** `world=` 选择键（H2 已冻结，不在本阶段扩展）；文档与 GUI 必须明示。
- 平行体积路径带世界名前缀，谱/汇总 CSV 可逐体积区分；`spectrum_<scorer>_tN.csv` 表头与 `spectrum_kinetic_energy_csv_v1` 不变。
- 谱分桶用 `kineticEnergy`（步前）与 `alreadyWeightedAmount`（加权量），与 H2 完全一致；LET/displacement 不参与（§3.4）。

### 4.6 专用计分入口与不重复计数反例（对应独审第 1 点）

**实际调用链（H3-2 必须实现）**：

1. `ParallelScoringWorld::ConstructSD()`（每线程）→ `ParallelScoringDetector::ProcessHits(G4Step*)`。
2. `ParallelScoringDetector::ProcessHits`：走 ghost 步；构造 `HitRecord`（§4.1）；`ScoringManager* manager = AIHL::GetCurrentThreadScoringManager()`（回退到绑定 manager 时给既有警告）；`if (!manager) 记录失败并终止本轮`；调用 `manager->ScoreParallelHit(record)`，**每个 ghost 步恰好一次**（正沉积与零沉积同一入口）。
3. `ScoringManager::ScoreParallelHit(const HitRecord&)` 新方法（`ScoringManager.cc`，紧邻 `ScoreFluenceStep`）：
   - `if (!enabled_) return;`；`if (outputManager_ && outputManager_->HasOutputFailure()) return;`（沿用 fail-closed）。
   - 只取显式体积 scorer：
     - `if (doseScoringEnabled_) { scorer = GetScorer("dose"); if (scorer && scorer->IsEnabled()) scorer->ScoreHit(hit); }`（Dose scorer 自身跳过 `edep==0`）；
     - `if (fluenceScoringEnabled_) { scorer = GetScorer("fluence"); if (scorer && scorer->IsEnabled()) scorer->ScoreHit(hit); }`（Fluence scorer 自身跳过 `stepLength==0`）。
   - 不调用 `ScoreHit`、不累加 `currentEventRawEdep_/currentEventWeightedEdep_`、不 `WriteHit`、不填 `edepScoring_` 直方图、不广播 LET/DDD/edep scorer。
   - 异常处理与既有 scoring 路径一致：`RecordOutputFailure("scoring_"+name, ...)` + `AbortRun(true)`；失败保留证据。
4. 零沉积步：同一入口进入，Fluence scorer 计一次，Dose scorer 跳过；不得再调用 `ScoreFluenceStep`/`ScoreDisplacementStep`（避免同一长度被计两次）。

**不重复计数反例（H3-4 必须包含）**：

- **R-COMP**（组件级）：真实 `ScoringManager` 启用 dose+fluence+hits+event_edep；一个合成事件内调用 `ScoreParallelHit`（含一个正沉积步与一个零沉积步）；断言 hits 收集/`event_edep` 累计为 0、dose/fluence 各增加一次、零沉积步只增加一次 fluence。若实现误走 `ScoreHit`，hits 行数与事件 edep 将非零，此反例必须失败。
- **R-RUNTIME**（真实运行）：质量世界薄层 `sensitive=false`、平行世界启用；`[scoring] hits=true event_edep=true dose=true fluence=true`；运行 2000 事件。断言：hits CSV 存在但 0 数据行；`event_edep_t0.csv` 2000 行且 `raw_edep_MeV=weighted_edep_MeV=0`；dose/fluence CSV 有平行体积行且非零；`scorer_statistics` 的 `n_events=2000`。若平行计分污染旧累计，event_edep/hits 会非零，此检查必须失败。
- **R-SAME**（同运行双世界）：质量薄层与平行复制层同时启用（Case A）；断言质量薄层的 `event_edep` 累计读取自 `event_edep` CSV 与 mass-only 对照口径一致（不把平行贡献加入）；本反例只验证路由分离，不要求两世界物理数值相同。

## 5 世界注册、构造、物理注册与线程生命周期（对应独审第 2 点）

1. **配置加载**：`SimulationManager` 在 `Configure()` 阶段读取 `[parallel_world]`，执行 §6 的 Stage A 结构预检（文件/键/单位/形状/网格算术/重叠/声明包含/禁用组合），失败在任何 Geant4 对象创建前。
2. **注册**：`SimulationManager::CreateDetectorConstruction` 在返回 detector 前调用 `detector->SetParallelWorldConfig(...)`；该函数构造 `ScoringParallelWorld` 并 `RegisterParallelWorld`。注册早于 `main.cc:816-820` 的 `SetUserInitialization(detector)`。
3. **master 构造**：`ScoringParallelWorld::Construct()` 在 `InitializeGeometry()` 的 `ConstructParallelGeometries()`（master）执行：`GetWorld()` 取 ghost 世界；为 `[volume]`/`[grid]` 建 `G4Box`/`G4PVPlacement` 到 ghost 世界（独立 builder，不写质量世界 registry）；执行 §6 Stage B 的实际 solid 包围盒包含、实际质量核对。构造出的 ghost 逻辑体积/物理体积指针与网格单元表只读保存（master 构建、worker 复用，无需 worker 重建几何）。
4. **每线程 SD**：`ScoringParallelWorld::ConstructSD()` 在 `ConstructParallelSD()` 中**每个线程都会被调用**（worker 路径见 `G4WorkerRunManager.cc:164-165`）。每次调用都创建**本线程自己的** `ParallelScoringDetector`，并对 ghost 逻辑体积逐个 `SetSensitiveDetector(sd)`。依据：`G4LogicalVolume::SetSensitiveDetector()` 写 `G4MT_sdetector = subInstanceManager.offset[instanceID].fSensitiveDetector`，即 per-thread sub-instance 槽（`source/geometry/management/src/G4LogicalVolume.cc:475-482` 与头文件宏），不会把别的 worker 的对象写坏；`G4SDManager` 本身是 `G4ThreadLocal`（`G4SDManager.cc:37`）。因此 **不能假设 master-only，也不能假设 sequential**：`threads=1` 若走 MT 单 worker，同样经过 worker 的 `ConstructParallelSD()`。
5. **Hit 时线程本地 manager**：`ParallelScoringDetector::ProcessHits` 用 `AIHL::GetCurrentThreadScoringManager()` 取本线程的 `ScoringManager` 克隆（由 `ActionInitialization::Build()` 在线程内设置，见 `src/Actions/ActionInitialization.cc:91-99`）；取不到时按既有 `SensitiveDetector` 行为警告并失败，不静默落到 master manager。
6. **物理**：`SimulationManager::CreatePhysicsList` 在 reference 与非 reference 两条分支都注册 `G4ParallelWorldPhysics(name,false)`，位于 reference/extra 模块之后、`ApplyCuts` 之前；不改其余过程列表。
7. **默认**：未启用时不注册并行世界/物理构造器/SD，不增加输出/摘要/有效配置条目；默认回归比较**科学输出 CSV 与摘要字段语义**（schema、列、值），**不要求**输入身份 SHA、时间戳或绝对路径相同（这些随环境/构建变化）。
8. **多线程与合并规则（v1 支持范围）**：支持 `threads ≥ 1`（含 MT 单 worker）。每个 worker 各自写线程后缀 CSV（现有 `MakeThreadFilename`/`Thread` scope 语义），**不新增产品级合并文件**。消费/验收侧合并规则固定为：同一 run、同一 `volume_path` 的 `raw_edep_MeV`、`weighted_edep_MeV`、`raw_track_length_mm`、`weighted_track_length_mm`、各自的 `*_sum_sq_*` 按文件跨 worker **相加**；`n_events` 为各文件本线程事件数（run 级 N 取 run_summary 的完成事件数）；质量列各 worker 相对差 ≤1e-12；禁止对 worker 值取平均/中位，禁止把同一事件计两次。`scorer_statistics.csv` 走既有 master 合并（`HistoryStatistics`）。
9. **Case M 成功判定**：退出码 0、同一进程两次运行 `completed` 分别为 200、50（§8.6）、每 worker 文件存在且可相加、连续两 run 的文件互不覆盖（`_rR` 后缀）、重复同一 MT 配置时逐 worker 文件字节一致（可重复性证据；调度差异导致的 event 分配不同则记录逐文件 SHA 差异并判 inconclusive，而不是判失败）。
10. **生命周期**：并行几何/SD 只在初始化阶段构造；`ClearParallelWorlds` 只在整几何重建时由 RunManager 调用，本项目仍禁止初始化后改几何，H3 不新增热重建路径。

## 6 错误路径与拒绝清单（对应独审第 7 点）

### 6.1 Stage A：配置结构预检（`Configure()`，无 Geant4 几何对象）

1. `[parallel_world]` 存在但 `enabled` 非 `true` 且携带 `name`/`geometry_config` 等其他键或引用并行几何文件：拒绝（禁止“关闭但残留配置”）。只有单独的 `enabled=false`/缺省（无其他键）表示禁用并保持旧行为。
2. `enabled=true` 但缺 `geometry_config`、文件不存在/不可读/非普通文件。
3. `name` 空、非法字符、与质量世界/其物理体积/其他 section 名冲突。
4. 并行几何文件：未知 section/key、重复声明、`[world]` 缺失、`world.material != G4_Galactic`、`[volume]/[grid]` 的 parent/shape/size/position/material/sensitive 非法、`bins` 非整数/≤0/单元尺寸非正/单元数 >4096、重复名称、声明尺寸无法解析。
5. 质量世界若为箱形以外模板（GDML/tessellated 等）且无法在 Stage A 取得可校验的包围盒声明：拒绝并说明 v1 只支持箱形质量世界（Stage B 仍用实际 solid 复核）。
6. 体积/网格声明包围盒超出质量世界声明的世界盒（箱形时可用质量几何配置的 `[world]` 尺寸；这是**预检**，不替代 §6.2）。
7. `[scoring]` 缺失或 dose/fluence 均未启用，但配置了平行计分体。
8. §3.4 的禁用组合。
9. `[parallel_world]` 未知键。

### 6.2 Stage B：内核对象就绪、事件前

1. 材料名在 `MaterialManager` 中不存在或 `density` 非有限/≤0。
2. 实际 ghost 世界 solid 的包围盒包含校验失败（用 `G4VSolid::GetBoundingLimits`/`Inside` 对每个 box/网格单元复核；**不依赖**声明值）；单元尺寸与实际构造不一致。
3. 实际 `G4LogicalVolume::GetMass(true,false)` 与配置参考质量相对差 >1e-12。
4. SD 创建/挂接失败（含线程本地 SDManager 注册失败）。
5. 物理构造器注册失败（重复注册、物理列表状态非法）。

统一策略：锁存输出失败（stage：`parallel_world_config`、`parallel_world_geometry`、`parallel_world_sd`、`parallel_world_physics`），写失败摘要并非零退出；不得静默退化为仅质量世界计分，不得产生“看似成功”的平行世界科学输出。失败证据保留，不自动重试。

## 8 H3-4 预注册基准（冻结后不得改参；对应独审第 4/5/8 点）

### 8.0 公共几何/源/物理

- 质量世界：`G4_Galactic` 箱形世界，**全长** 100×100×100 mm（即各轴 ±50 mm）；水薄层 20×20×2 mm，位于原点，`sensitive=true`（Case A/A2/A2f 与 Case B 的质量侧）。
- 源：质子 10 MeV，点源 `(0, 0, -20) mm`，方向 `(0, 0, 1)`，单能。
- 物理：`[physics] reference = FTFP_BERT`，`default_cut = 0.1 mm`；不用偏置/场/ROOT。
- 参考质量：水 `1.0 g/cm³ × 20×20×2 mm³ = 0.8 g`；逻辑体积实测质量与配置相对差 ≤1e-12。
- 种子核查（2026-11-06 精确检索本仓库脚本/文档/示例/配置）：`20261400`、`20261401–20261464`、`20261465`、`20261466` 均未被使用。冻结后不换种、不加批、不丢批。
- 所有区间比较用 Decimal 十二位有效数字半单位区间：`h = 0.5×10^(floor(log10|d|)−11)`（精确零=0），**求和按各加数区间相加**（不是总量单个半单位）。

### 8.1 Case A：同运行复制薄层聚合等价（接线/归一化检查，非统计检验）

- 输入：质量世界水层 `sensitive=true`；并行几何含同样 20×20×2 mm 水层副本（同位置/材料/`sensitive=true`）；`[scoring] dose=true fluence=true hits=false`；`threads=1`；2000 事件；`seed=20261400`。
- 四个端点（两个体积各 4 个值，均来自 CSV 精确列名）：
  - `dose_volume_summary_t0.csv`：`raw_edep_MeV`、`weighted_edep_MeV`；
  - `fluence_volume_summary_t0.csv`：`raw_track_length_mm`、`weighted_track_length_mm`。
- 判据：对上述 4 个物理量，质量体积与平行体积的区间相交；`n_events=2000`。此判据验证 ghost 步字段、质量/长度归一化与路由分离；同运行内两体积共享同一物理步，**不是**独立统计证据。
- 失败：任一量不相交即 `fail`，保留全部输出并停止后续 Case（先修接线，不问物理）。

### 8.2 Case A2：规则网格总量与 H2 谱和（对应第 3/8 点）

- 输入：同公共几何；并行几何为 `[grid.SlabGrid]`（`size=20,20,2 mm`、`position=0,0,0`、`bins=4,4,1`、`material=water`、`sensitive=true`，共 16 个 5×5×2 mm 单元）；质量水层 `sensitive=true`；`[scoring] dose=true fluence=true`；`[scoring.spectrum.dose] bins=10 min=0 max=20`（MeV）；`threads=1`；2000 事件；`seed=20261465`。
- 端点：16 个平行单元的 `weighted_edep_MeV`/`raw_edep_MeV`（dose CSV）与 `raw_track_length_mm`/`weighted_track_length_mm`（fluence CSV）之和；质量水层对应值；每单元谱文件行（10 bin + underflow + overflow）。
- 判据：Σ 平行单元 `raw_edep_MeV` 区间 = 质量体积 `raw_edep_MeV` 区间；weighted edep 同理；Σ 单元 `raw_track_length_mm` = 质量体积值；`weighted_track_length_mm` 同理（区间按 16 个加数先相加再与质量体积区间比较）；每单元谱的 `Σ(bin+underflow+overflow)` 与该单元 `weighted_dose_Gy` 区间相交；`n_events=2000`、16 个 `volume_path`、`spectrum_csv_schema_version=1`。
- 边界所有权：内部单元边界上的步归入**步前**单元；每步恰计一次，故总量守恒；不设逐单元剂量分布判据（份额由边界归属决定，属观察项）。

### 8.3 Case A2f：过滤在平行体积上的独立复算

- 输入：同 Case A2 几何/种子 `20261465`，另加 `[scoring.filter.dose] particles = proton`，并 `hits=true`。
- 前置断言（对应第 8 点）：质量世界 hits 只含质量体积行；`hits_t0.csv` 中**没有**任何平行世界 `volume`/`volume_path` 行（专用入口不写 hits，先证明再复算）。
- 端点：过滤后质量体积与平行体积的 `weighted_edep_MeV`；质量 hits 中 `particle==proton` 的 `Σ(edep·weight)` 独立复算值。
- 判据：平行过滤值 = 质量过滤值 = 独立复算值（三者两两区间相交）；过滤后总量 ≤ 不过滤总量（Case A2 同种子）；`n_events=2000`。此检查验证 H2 过滤器经 ghost 步正确路由；不外推为过滤物理正确。

### 8.4 Case B：独立批次等效剂量检验（对应第 5 点）

- 输入：两套几何，除敏感标记外相同：`geometry_mass.ini`（水层 `sensitive=true`，不启用平行世界）；`geometry_parallel.ini`（水层 `sensitive=false`，启用平行世界与单个 20×20×2 mm 水层副本 `sensitive=true`）。源/物理/世界同 §8.0。每批 2000 事件、`threads=1`。
- 种子：质量侧 `20261401–20261416`，平行侧 `20261417–20261432`；同对批次交替执行（质量→平行），顺序固定写入计划。
- 端点：每批 `weighted_dose_Gy / n_events`（Gy/event）的批均值；两组各 16 个批均值 `m_mass`、`m_parallel`；差值 `Δ = m_parallel − m_mass`；标准化分母 `m̄ = (m_mass + m_parallel)/2`。
- 判据（整个区间判据，不用点估计+半宽分别判）：计算 Welch 99% 双侧区间 `CI99(Δ) = Δ ± t·SE`；等价边界 `δ = 0.01·m̄`。
  - `CI99(Δ) ⊂ [−δ, +δ]` → **pass**（在本分辨率内兼容；不是无偏性证明）；
  - `CI99(Δ)` 完全落在 `[−δ,+δ]` 之外 → **fail / 调查**，保留全部原始输出，不改参重跑；
  - 其他（区间跨边界，精度不足）→ **inconclusive**，报告区间、`Δ/m̄`、SE 与批次数；预注册**不允许**加批/换种，也不自动标为“limited 通过”。判定不写入“不是产品缺陷”的预授权结论；若需要调查，由主审另行决定。
- 报出：`m_mass`、`m_parallel`、每批值、组内 sd、Δ、SE、df、`δ`、`Δ/m̄`、CI99 上下界与相对化 (`CI/ m̄`)。

### 8.5 Case C：无扰动对照（对应第 4 点）

- 输入：质量侧同 Case B；平行侧启用平行世界但只放一个 **1×1×1 mm `G4_Galactic` 探针**，中心 `(30, 30, 0) mm`（在 ±50 mm 世界内、远离束流轴）；探针 `sensitive=true`（满足“至少一个平行计分体”的最小配置）。源/物理同 §8.0；每批 2000 事件、`threads=1`。
- 边界描述：只保证**初级笔形束不直穿探针**；不承诺次级粒子绝不命中探针。探针剂量作为诊断报告，不设通过/失败门槛。
- 种子：`20261433–20261448`（启用平行世界）与 `20261449–20261464`（禁用平行世界），各 16 批。
- 端点：同 Case B 的批均值（质量水层），`Δ` 与 `m̄`。
- 判据：同 Case B 的整个 CI 判据，`δ = 0.005·m̄`：`CI99(Δ) ⊂ [−δ,+δ]` → pass（0.5% 分辨率内无质量世界剂量扰动证据）；完全在界外 → fail/调查；跨边界 → inconclusive。不得把 inconclusive 预授权为“机制预期内、不是缺陷”；由主审决定是否另立解释。
- 该对照只说明本病例、本分辨率；不外推其他几何/粒子/能量。

### 8.6 Case M：多线程生命周期与合并（对应第 2 点）

  2. 每个 worker 的 dose/fluence CSV 存在（含平行体积行），文件线程后缀/`_rR` 正确，Run2 不覆盖 Run1；

  4. 重复执行同一 MT 配置一次（同种子/同线程/同事件），比较逐 worker 文件 SHA：全部相同 → 可重复性通过；若仅 worker 间事件分配不同但逐事件记录集合一致，记 **inconclusive**（调度差异），不得直接判失败；若同一 worker 文件内容不同且无可解释原因 → **fail**；
