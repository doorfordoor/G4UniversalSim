# 多模型协作约定

2026-10-27：用户授权以已完成阶段的审计试运行协作流程。项目约束以根目录及对应子目录 AGENTS.md 为准，阶段状态仍只由 [ROADMAP.md](ROADMAP.md) 维护。本文件不替代支持矩阵、测试说明或科学参考来源。

## 工作方式

- 主负责人核对当前分支、已有修改、阶段检查点及验收边界，定义一个完整阶段或审计的交付范围。内部拆分不要求用户逐项确认。
- 2026-10-28 用户确认的分工：Astra（Codex 侧）作为**总设计师与首席审查者**，负责架构/协议设计、复杂诊断、科学方法审查与验收标准；DeepSeek（本仓库的 DSH 会话）作为**前端设计负责人**（GUI 交互、视觉与信息架构）并承担实现、本机真实验证与证据工业化；Sol 用于核心实现与集成；Luna 用于边界明确的辅助任务。这是分工约定，不是模型能力或额度保证，也不改变“代理只获得必需上下文”的规则。
- 跨代理通信以仓库文件为准（见 [collab/README.md](collab/README.md)），不依赖粘贴整段对话；需要时用 `tools/dump_agent_session.py` 导出对方会话摘要到 `out/collab/`（被 git 忽略），不导出密钥或凭据。
- 按当前工具实际可调用的模型分配任务。记录请求的模型、任务标识、实际调用是否成功、输出与复核结果。不可用时明确替代情况，不把角色名称当作调用凭据。
- 代理只获得完成任务必需的上下文；禁止读取或回传密钥。外部 API 密钥仅由调用程序加载，不写入日志、文档或任务提示。
- 不使用虚构公司身份或无限额度承诺；对辅助模型要求充分分析、可验证结论与清晰边界。

## 任务交接

每项任务记录：目标、输入依据、允许修改的文件、禁止改变的行为、验收条件、实际模型及任务标识、输出证据、遗留问题。只读审查明确禁止修改生产文件。

可并行的任务必须文件互不冲突，或处于独立 worktree。共享工作区时由主负责人统一集成；只读审计可共享同一提交。不得清理、覆盖或提交用户已有修改。分支和正常推送遵守现有路线图约定，用户要求只读时不创建代码修改。

## 审查与验收

- 审查者给出具体路径/行号、触发条件、影响和最小复现，不以泛泛重构建议充当缺陷。
- 主负责人独立复现或核对证据；无法复现的意见记录为待核实，不直接宣布代码有错。实现者不独占最终验收。
- 测试判据来自需求、后端契约及可靠参考，不因模型判断而放宽。解析、运行和物理验证分别记录；固定种子回归不能替代统计或物理基准。
- 自动化报告检查 pass/fail/skip、源码跟踪门禁、后端源码指纹和实际输出。历史报告与本轮重跑明确分开。模型审查通过不能代替测试通过，测试通过也不能证明没有缺陷。
- 审计发现代码问题时，先形成可复核记录；未授权修复的审计不顺便改生产代码。改变物理假设、默认行为或扩大范围时向用户提出具体决定。

## 阶段收尾

维护简短阶段检查点，记录提交、已改文件、证据路径、运行中的任务/进程及下一步。完整日志留在忽略的 out/verification/，重要结论写入可提交文档。按整阶段交付，说明未验证范围及未调用模型。

先用实际试运行评估审查价值和额外负担。不预设必须建设 LangChain/LangGraph 调度平台；无人值守恢复、队列及成本统计如成为需求，另立工程任务。
