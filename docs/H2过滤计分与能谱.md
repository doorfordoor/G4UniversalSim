# H2 过滤计分与动能能谱

本文说明 H2 的按体积计分过滤与动能能谱：配置写法、物理量定义、单位与边界、
在 GUI 中编辑的方式、一个可复演的最小示例，以及当前实现边界。后端语义以
H2-1 冻结合同（`docs/collab/decisions/20261106-h2-contract-freeze.md`）为准；
本文只描述已实现并可复演的部分，H2-4 的完整物理基准与 H2-5 的平台验收尚未完成。

## 1. 用途

- **过滤（filter）**：只把满足粒子名与/或动能窗口的计分步交给该 scorer，
  用于按粒子种类、按能区拆分 Dose、Fluence、LET、位移损伤。
- **动能能谱（spectrum）**：把 Dose、Fluence、位移损伤按敏感体积内每个计分步的
  **步前动能** 分桶累计，得到每个体积的动能分布。

过滤器与能谱都是可选的：未配置时输出与旧版本完全一致（不新增文件、section、
`run_summary.txt` 键）。

## 2. 配置写法

```ini
[scoring]
enabled = true
dose = true
fluence = true
auto_create_default_scorers = true

[scoring.filter.dose]
particles = e-,gamma
energy_min = 1 MeV
energy_max = 10 MeV

[scoring.filter.fluence]
particles = all

[scoring.spectrum.fluence]
bins = 10
min = 0.5 MeV
max = 1.5 MeV
```

规则：

| 项目 | 说明 |
| --- | --- |
| `[scoring.filter.<scorer>]` | `scorer` 只能是 `dose`、`fluence`、`let`、`displacement` |
| `[scoring.spectrum.<scorer>]` | `scorer` 只能是 `dose`、`fluence`、`displacement`（LET 是比值，不能线性分桶） |
| `particles` | 可选。留空表示不限；`all` 表示不限；只能单独使用 `all`；否则写逗号分隔的 **Geant4 精确粒子名**（区分大小写，例如 `e-`、`gamma`、`proton`） |
| `energy_min` | 可选，缺省为 0；含下界 |
| `energy_max` | 可选，缺省为 +inf；**不含**上界 |
| `bins` | 必填整数，1 ~ 10 000 000 |
| `min` / `max` | 必填，`max > min`，`min >= 0`；单位可用 `eV`、`keV`、`MeV`、`GeV` |

过滤器与能谱要求对应 scorer 已启用、`auto_create_default_scorers = true`，
并且必须存在 `[scoring]` section；不满足时在配置阶段拒绝，不会静默运行。
多个 filter 与 spectrum 组合是 AND：粒子集合内部是 OR，粒子条件与能量窗口之间是 AND。

非法配置的典型诊断（配置阶段失败）：

- `[scoring.filter.edep]`：`Unknown scoring filter topic 'edep'; expected dose, fluence, let or displacement`；
- `[scoring.spectrum.let]`：`Spectrum for scorer 'let' is not supported; LET is a ratio and cannot be binned additively`；
- `particles = all,gamma`：`all` 只能单独使用；
- `energy_min` 为负或 `energy_max <= energy_min`；
- `bins < 1`、`min < 0`、`max <= min`、非有限值；
- scorer 未启用（消息会指出缺少的 `[scoring] <scorer> = true`）；
- 只写 filter/spectrum 而没有 `[scoring]`；
- `[output] format = root` 且启用 spectrum；
- `particles` 中出现未注册的 Geant4 粒子名：在 `BeginOfRunAction` 首事件前失败，
  输出失败阶段为 `scoring_filter_particle`（不会悄悄丢弃该粒子）。

## 3. 语义与单位

计分步判定顺序与旧版一致：先通过 scorer 自身的物理守卫（例如 Dose 只计入正沉积步），
再用 filter 判定，最后按动能进入能谱。

- **动能采样点**：`Step` 的步前动能（与 hits CSV 的 `kineticEnergy_MeV` 同源），
  不是步平均动能；DDD 的 NIEL 查表仍使用内部步平均动能，未改变。
- **权重**：每个计分步只乘一次径迹权重（与既有 CSV 的 weighted 列一致）。
- **事件数**：`n_events` 是该 worker 完成的 run 件数（含零贡献事件），与既有
  `dose_volume_summary.csv` 等文件的 `n_events` 相同口径。
- **量**：每个 bin 的 `amount` 是该体积该能区的**加权量**：
  - Dose：`sum(w * edep) / mass`，单位 `Gy`（`edep` 先换算为 J，`mass` 为 kg）；
  - Fluence：`sum(w * stepLength) / volume`，单位 `mm^-2`；
  - Displacement：`sum(w * stepLength * NIEL(E)) / volume`，单位 `MeV/g`。
- **过滤区间**：`[energy_min, energy_max)`，上界不含，便于把能区拆成互斥集合。
- **能谱桶**：宽度 `(max - min) / bins`；第 i 桶为 `[min + i*width, min + (i+1)*width)`，
  只有**最后一个桶包含 `max`**；`E < min` 进 underflow（`bin = -1`），`E > max` 进
  overflow（`bin = bins`）；每计入谱的步恰落入一个桶。
- **哪些步进谱**：Dose 谱只含正沉积步；Fluence 与 Displacement 谱沿用各自 scorer 的
  守卫（Fluence 的零沉积输运步也计入），因此 Fluence 谱可以覆盖穿过体积但不沉积能量的光子。

## 4. 输出

每个 worker 仅在实际写出时生成 `spectrum_<scorer>_t<N>.csv`，例如
`spectrum_fluence_t0.csv`，前两行（按体积分块）精确表头为：

```
runID,scorer,volume_path,volume_name,region,bin,low_edge_MeV,high_edge_MeV,amount,unit,n_events
```

- 每个命中体积先按 bin 升序写 `region=bin`（`bin` 0..N-1），再写 `region=underflow`
  （`bin=-1`，`low_edge_MeV` 为空）与 `region=overflow`（`bin=N`，`high_edge_MeV` 为空）；
  `amount` 为 0 的 bin 也照写，便于下游对账。
- 数值以 12 位有效数字打印；文件按线程登记，`run_summary.txt` 只有在实际写了谱文件时
  才设置 `spectrum_csv_schema_version = 1`；`output_csv_schema_version` 保持旧值 3。
- 只有 `[output] format = csv`（或可解析为 csv 的 `auto`）允许启用 spectrum；
  ROOT 输出与 spectrum 组合在配置阶段拒绝。
- 每 bin 目前**不提供**独立统计不确定度；跨 bin 求和与不确定度请回到
  `scorer_statistics.csv` 的加权总量与 `fluence_volume_summary.csv` 等文件。

## 5. 在 GUI 中编辑

Configuration 页面 → `Run Config` → `Scoring` 标签页新增“Volume filters”和
“Kinetic-energy spectra”两组：每个 scorer 一行（启用、粒子、能量窗 / 桶数、min、max）。
这些控件挂在既有 Scoring 编辑器上，写入既有主 INI writer、随项目保存/重载，
没有新增独立面板；未启用时不会写出新 section。 bins 的合法范围是 1..1000000（与后端一致），非整数或越界值不会被截断或写出。有效配置与运行回执沿用既有
Effective Configuration 视图：配置接受（manager_accepted）、挂接（kernel_constructed）
与实际运行验证（run_validated，只有真正有计分步时才会登记）分开显示，0 个候选步不会
被标成物理验证。运行回执以聚合路径（`scoring/filter/<scorer>`、`scoring/spectrum/<scorer>`）
记录，`observed` 含实际文件 sha256 与大小；由于字段级 `application_status` 仍按逐键
值匹配，聚合回执可能显示 `unknown`（表示“未逐键匹配”，不代表物理验证失败）。

## 6. 最小示例（V5，可复演）

示例目录 `examples/h2_volume_spectrum/`（几何、`main.ini`、`run.mac`）：

- 世界 40 mm 立方 `G4_Galactic`；10 × 10 × 0.1 mm `G4_Galactic` 片在原点，`sensitive = true`；
- 1 MeV 光子的 8 × 8 mm 方形面源，位于 `z = -2 mm`，方向 +z；
- 100 事件、单线程、随机种子 20261305；
- 10 个能谱桶，范围 `[0.5, 1.5] MeV`。

从该目录运行：

```powershell
C:\path\to\G4UniversalSim.exe --config main.ini --macro run.mac --output output
```

期望（本机 Windows、Geant4 11.3.2、后端 `fae758c4…` 实测）：

- `output/spectrum_fluence_t0.csv` 共 12 行（10 个 bin + underflow + overflow）；
- `bin = 5`（`[1.0, 1.1) MeV`，包含 1.0 MeV）的 `amount = 1`、`unit = mm^-2`；
  underflow 与 overflow 的 `amount = 0`；
- `fluence_volume_summary_t0.csv` 的 `weighted_fluence_mm-2 = 1`（100 × 0.1 mm / 10 mm^3）；
- `run_summary.txt` 含 `status = completed`、`actual_completed_event_count = 100`、
  `spectrum_csv_schema_version = 1`、`output_csv_schema_version = 3`。

复演证据（命令、日志、谱 CSV 与摘要）保存在 `out/collab/h2-config-entry/`；
后端黑盒回归 `scripts/test_h2_volume_scoring.py` 与 GUI smoke
`gui/smoke_tests/smoke_h2_volume_config.py`、`gui/smoke_tests/smoke_h2_volume_editor_ui.py`
覆盖同一组语义。

## 7. 边界与未验证项

- 本实现是计分/输出层的过滤与分桶，**不改变输运、随机数、物理列表或截面**。
- 全步 Target 能量沉积按步前权重重算与既有 Dose 一致；但零沉积步不写 hits，
  因此 hits 不是 DDD/注量全部计分步的完整路径清单。
- 过滤与谱只在 scorer 实际计分路径内生效；LET 只提供过滤，不提供谱。
- 只有 csv 输出；ROOT 输出与 spectrum 组合被拒绝。
- 完整物理基准（H2-4）与平台/CI 验收（H2-5）尚未完成；本页不构成物理正确性结论。
