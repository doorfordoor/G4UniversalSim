# F4 结构化诊断与定位

实现候选；正式阶段状态与验收以 [ROADMAP](ROADMAP.md) 为准。

## 使用方式

配置页校验后在 Messages 显示统一问题列表。选中一行后按 Enter、双击或点“定位字段”，会打开对应编辑页、选中确切对象或单元格、滚动到控件并短暂高亮；这一步不修改配置。Esc 或计时结束清除高亮。原文字报告继续保留。

项目/运行、创建模拟向导、参数扫描和屏蔽/涂层场景使用同一列表与诊断模型。配置页报告中的 executable/workspace_root/runs_root 可以跳到 Project。修改输入、重新加载或切换项目后，旧诊断失效；先重新校验再定位。扫描重新校验不创建目录或运行包。

“查看来源”只读。当前文件与诊断记录的逻辑文本 SHA256 一致时显示当前来源；文件改变或消失时，只能显示自身身份正确的历史快照，并明确提示历史。未记录内容身份、行号越界、预览超过 4 MiB 均不得宣称定位成功。源文本经过 UTF-8 解码和换行归一化，这个 SHA 不是 F1 原始输入字节 SHA。来源检查不写源文件。

## 共用数据契约

`gui/g4usim_gui/core/diagnostics.py` 提供纯数据模型、规范化身份、严格 JSON 读写与兼容投影。供后续 K1/L1 直接调用，不需要创建界面控件。

| 字段 | 含义 |
| --- | --- |
| code / severity / origin | 稳定机器代号、error/warning/info/blocker、生产模块；blocker 阻断运行 |
| location | editor、field、collection、零起始 row、entity、snapshot_id；来自规则生产处，不能解析翻译文字倒推 |
| source | 文件、一起始 line、section/key/value、text_sha256 和可选只读文本快照 |
| message / raw_message | 兼容展示文本和原始诊断；不参与稳定身份 |
| message_key / params | 展示翻译模板和不可变参数；机器 code/字段名不翻译 |
| identity_parameters | 区分同规则的不同事实，例如扫描点序号；不使用本地化消息 |
| related_locations | 相关位置，仅作上下文，不能默认作为当前编辑目标 |
| unavailable_reason | 没有可编辑位置或可靠源位置时的明确原因 |

身份为规范 JSON 的 SHA256，包含严重度、生产来源、实际位置/源内容身份与区别参数，不包含语言、展示文字或编辑器瞬态 revision。参数深层冻结，身份计算不依赖调用时工作目录。报告/定位还必须绑定当前快照，身份相同不等于旧验证仍然有效。

JSON schema 标记 `g4usim_diagnostics_v1`；含 diagnostics、snapshot_id、errors/warnings/info、can_run。严格读取拒绝重复键、不合法严重度、非有限数、身份与事实不符、计数/阻断语义不一致等。原 ValidationReport 三类字符串列表、顺序、to_text 和 can_run 保留；相同文字来自不同对象或源行时，结构化记录仍保留各自位置。

运行包继续写 `validation_report.txt`，同时写 `validation_diagnostics.json`。它是生成时的校验证据，不证明 Geant4 已运行或物理正确。项目持久格式仍为 v6；诊断 sidecar 不进入 dataclass asdict/项目快照，不新增持久 UUID。

## 覆盖与边界

| 入口 | 可定位内容 | 明确限制 |
| --- | --- | --- |
| Configuration | 已有 Setup、Run、Materials、Geometry、BooleanOps、Source、Physics、Scoring 实际编辑字段 | 不新增高级参数编辑能力；隐藏、只读、禁用、已删除或歧义对象拒绝定位 |
| 主 INI / 材料 / 几何解析 | 规则生产点真实文件、行号、section/key；重复行独立身份 | 文件读取失败没有虚构行号；不自动修复或忽略 source_errors/blockers |
| Project / Run | 路径、模式、线程数、种子等现有校验字段 | 后端自由文本 stderr 保留原文；无结构化位置时不得用正则猜字段 |
| 新建模拟向导 | 已访问步骤中的当前可编辑字段 | 跳转不重新初始化默认值、不改变 WizardSpec；不启用不适用字段 |
| 参数扫描 | 当前 values/parameter 输入错误 | 派生点的配置错误保留相关位置和扫描点身份，不能跳到不同的基础配置 |
| 屏蔽/涂层场景 | 基础和高级表单实际字段 | 仍调用原场景模型/schema；定位不重算 TID/DDD、不改变运行判定 |

高级源、材料和几何当前不支持的 GUI 字段仍可给只读来源或明确不可定位原因。无结构化位置的任意 Geant4 日志并未因此变为结构化协议。没有实现自动修改、撤销/恢复、通用 AI Agent 或物理验证；对应 F5/K1/L1/Q2 保持各自阶段边界。

## 验证入口

- `scripts/test_f4_diagnostics.py`：身份、不可变性、严格 schema 与旧文本兼容。
- `scripts/test_f4_producers.py`：主配置/源/物理/计分/聚合实际规则位置。
- `scripts/test_f4_document_diagnostics.py`：材料/几何/源行、源快照、重复行及持久格式保持。
- `gui/smoke_tests/smoke_f4_navigation.py`：真实 Qt 编辑器、行/单元格、失效、只读来源与高亮生命周期。
- `gui/smoke_tests/smoke_f4_entrypoints.py`：项目/运行、向导跨页、场景、扫描及真实运行包 JSON。
- `gui/smoke_tests/smoke_f4_inspect_protocol.py`：畸形 JSON 与陈旧回调的协议组件负例。
- `gui/smoke_tests/smoke_f4_inspect_backend.py`：真实 QProcess/Geant4 Inspect 拒绝、stderr 原文与不启动运行。
- `gui/smoke_tests/smoke_f4_layout.py`：小窗口滚动可达与诊断区域布局。

上述专项不替代全量旧用例同口径回归、真实 Linux CI、Windows 实窗和独立审查。DeepSeek 设计参与与采用/纠偏范围见 [设计收据](collab/outbox/20261030-deepseek-f4-design.md)。
