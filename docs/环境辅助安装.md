# 环境辅助安装（I2 实施候选）

2026-11-01：当前已有安装服务、命令行和 GUI 候选，I2 阶段尚未关闭。以下说明当前入口与行为，不代表 Windows/Linux、运行环境/开发环境的正式交付矩阵已经通过。

## 四种事实分别判断

| 事实 | 判断依据 | 不能据此推断 |
| --- | --- | --- |
| 文件已安装 | 安装收据记录校验、解包和发布；有警告时一并保留 | 后端和数据已经可用 |
| 环境就绪 | I1 重新检测实际后端、能力与必需数据的结果 | 配置已初始化或事件已运行 |
| 模拟完成 | K1 核验本次进程、摘要和逐轮计划/完成事件等运行证据 | 物理结果已验证 |
| 物理验证 | 指定参考、判据、输入与适用范围的独立对照 | 任意场景均正确 |

安装或选择环境都不会启动模拟。安装结束后，仍须由用户选择环境，再按通常流程校验和运行项目。

## 从界面安装

1. 打开主界面的“环境”，进入“环境发现与诊断”，选择“安装运行环境…”。已有后端路径会作为检测候选；没有指定路径时，发现过程读取环境变量和 PATH 中的候选。
2. 选择用途：运行仿真使用运行环境，不要求用户安装编译器；开发 Geant4 工程使用开发环境，后续还需实际编译验证。版本列表是发布包版本，只显示与当前平台、架构和用途匹配的条目；方案中另列该包声明的 Geant4 版本。开发所需的 CMake 和 C++ 编译器需另行检查，不能从包已安装推断它们可用。
3. 加载发布方提供的安装清单，选择安装所在目录并填写一个新文件夹名。程序会尝试读取随包提供的清单；没有清单、清单为空或没有匹配版本时，当前不能直接安装。不要把空列表理解为已自动找到可下载的版本。
4. 先“检查安装方案”，查看目标位置、文件来源、大小、许可、空间需求和拒绝原因。检查计划本身不下载、不安装、不运行后端。确认来源可信后，再执行“安装此方案”；联网下载还须显式允许。
5. 文件发布后，环境列表会重新检测新安装；原有候选继续保留。若当时已有检测正在进行，会在该轮结束后再检测。程序不会自动切换当前项目的环境；选中条目后使用“使用所选环境”。

清单必须给出确切产物、大小、SHA-256、许可及解包目标。散列用于核对字节完整性，不能代替对发布来源的判断。未知版本、平台不符、路径越界、链接或未知目录占用等会被拒绝；不覆盖已有环境。

## 取消、恢复和报告

安装过程中可请求取消。取消在服务检查点生效，界面会等待操作收尾；关闭正在安装的窗口也先请求取消，不表示系统立即终止了所有文件操作。取消或失败后的收据说明是否留下可恢复的临时文件。

重新打开安装窗口，选择原来的父目录和文件夹名，再检查方案。若发现合法的中断事务，会提供“继续上次安装”及清理临时文件的操作。恢复须与原计划和事务身份相符；旧事务缺少可核验的计划时只能清理。清理需要明确确认，仅处理该事务拥有的临时目录，保留已安装文件及其他环境。已发布后发生清理问题会保留“文件已安装但有警告”的事实，不反写成未安装。

“保存安装报告…”导出计划和执行收据，目标须为新文件，不静默覆盖旧证据。安装窗口的清理操作不是卸载。核心服务及命令行另有按安装收据校验、卸载和开发环境编译探测入口；GUI 不因此承诺完整的一键卸载或编译器自动安装。

## 命令行及实现边界

从源码环境运行 `python packaging/install_plan.py --help` 查看实际参数。当前提供 `plan`、`execute`、`verify`、`uninstall`、`recover`、`probe-sdk`；执行安装需要已形成的计划，恢复继续通过 `execute --resume`，清理通过 `recover`。开发环境编译探测要求显式指定构建目录和 CMake；编译器或生成器按入口参数选择，不将“文件已安装”当作“已编译通过”。

服务在 `gui/g4usim_gui/core/environment_install.py`，界面在 `widgets/install_dialog.py`；I1 只读发现与 K1 模拟工作流保持各自职责。安装收据不是 K1 的运行记录，也不恢复旧项目的验证资格。

## 当前验证与未闭合验收

计划、拒绝路径、受校验发布、取消/恢复、重开窗口与环境重新发现已有专项检查；相关入口为 `scripts/test_install_plan.py`、`gui/smoke_tests/smoke_i2_install.py`。本轮 Windows 冻结曾从宿主 PATH 收入不兼容的 ICU DLL；构建子环境清理和二进制来源审计的修复已独审。另修复自检在窗口尚未接受关闭时强制析构的问题，等待原有任务收尾后再释放窗口。新冻结程序实际完成九页、图表、3D 加载与正常退出，辅助 Python 实际 ROOT 读写通过；启动导入故障另验失败收据及非零退出。上述是桌面组件交付检查，不等于完整安装包或全部阶段验收通过。
