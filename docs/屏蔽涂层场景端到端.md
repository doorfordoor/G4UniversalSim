# 屏蔽与涂层场景端到端（GUI 场景页，路线图 2B）

本文说明 GUI 左侧 **Scenario** 页与命令行 `scenarios/shielding_coating/` 的同一套场景链路：字段校验 → 生成配置 → 真实后端运行 → 分析 → 带证据的结果。场景页是**一个具体场景的端到端入口**，不是通用编辑器；通用编辑仍走 Configuration / 几何 / 材料编辑器。

## 1. 场景是什么

几何沿 +z（横向尺寸由 `size` 控制，默认 10 mm）：

```
FrontPlane（真空 10 µm）| 源平面 | 涂层 0 … 涂层 n-1 | 间隙 | BackPlane（真空 10 µm）| 间隙 | Device（G4_Si，厚度 device_thickness）
```

- 涂层是「材料:厚度」列表，束流先遇到第一层（例如 `B4C:300um,G4_W:100um,G4_Al:300um`）。材料取 NIST 名（`G4_Al`、`G4_Si`、`G4_W`、`G4_Ti`、`G4_Cu`、`G4_Ta`、`G4_Galactic` 等）或自定义材料（`B4C`、`HEB`、`ZnO`、`Si3N4`）。
- 源是法向入射的方形平面源，面积由 `source_half` 决定；单能（`energy > 0`）或按积分通量谱抽样（默认 `environment/proton_integral_flux.txt`、`electron_integral_flux.txt`）。
- 两种模式：`transmission` 记录穿过涂层进入 BackPlane 的粒子（相空间，`kill = false`），在 Device 里计剂量、注量与位移损伤；`albedo` 记录从 FrontPlane 反向离开的粒子（`kill = true`），源位于 FrontPlane 与第一层之间，初级粒子不穿 FrontPlane。
- 可选界面层（`junction_density`，0 < x < 1）与某层内的球形真空孔（`pores_layer`、`pore_radius`、`pore_fraction`）复现原 CoatingSimulation 的 openJunction / openBubble 选项。

## 2. 字段（基础 7 + 高级 8）

| 字段 | 默认 | 含义与约束 |
| --- | --- | --- |
| `mode` | transmission | `transmission` / `albedo` |
| `particle` | proton | `proton` / `e-` / `mixed`；`mixed` 必须用谱，不能再给单能 |
| `energy` | 0 MeV（用谱） | 单能能量，`>= 0`，有限值 |
| `layers` | `B4C:300um,G4_W:100um,G4_Al:300um` | 「材料:厚度」逗号分隔，厚度必须 > 0 |
| `events` | 1000 | 每轮事件数，`>= 1` |
| `threads` | 4 | 后端线程数，`>= 1` |
| `seed` | 12345 | 随机种子，32 位整数范围 |
| `size`（高级） | 10mm | 横向边长 |
| `device_thickness`（高级） | 300um | 硅器件厚度 |
| `source_half`（高级） | 4mm | 源平面半边长（决定源面积与每入射注量归一化） |
| `junction_density`（高级） | 0 | 界面层密度比例，`[0, 1)` |
| `pores_layer`（高级） | -1 | 打孔层索引，`-1` 表示无孔；必须落在层栈范围内 |
| `pore_radius` / `pore_fraction`（高级） | 20um / 0.01 | 孔半径与体积分数；放不下时报错而不是静默生成 |
| `niel`（高级） | 空 | `PARTICLE=TABLE.csv`，可多项；提供后追加 `[scoring.displacement]` 并计算 DDD |

长度单位支持 `nm/um/mm/cm/m`。校验分三层：GUI 字段解析 → `ShieldingSpec.problems()` → 配置 schema（`config_schema.check_value`），三层的消息都会显示在页面「问题」面板，**有任一问题时不生成、不运行**。

## 3. 生成的文件

生成目录下写入：

| 文件 | 内容 |
| --- | --- |
| `materials.ini` | NIST 材料与自定义材料（含界面层 `_J` 变体） |
| `geometry.ini` | hierarchical 几何：FrontPlane / BackPlane / Coating 层 / Device（+ 可选孔阵列） |
| `pores.csv` | 有孔时：`x_mm,y_mm,z_mm` 孔心（同 seed 逐字节确定） |
| `spectrum_proton.csv` / `spectrum_electron.csv` | 用谱时：直方图输入 |
| `main.ini` | 主配置：`[run]`、`[output]`、`[materials]`、`[geometry]`、`[physics]`（reference + EM 预设 + 区域 cut/step）、`[scoring]`、`[source]`（或 `[source.protons]`/`[source.electrons]`）、`[phase_space]` |
| `run.mac` | `/run/initialize` + `/run/beamOn N` |
| `scenario.json` | 场景元数据：模式、粒子、事件数、源面积、抽样通量、层表、孔数、界面层密度、器件厚度、是否位移损伤、涂层体积数、**NIEL 表（particle / path / sha256）** |

`scenario.json` 是后续「证据」的来源：分析脚本用它确认这次运行确实启用/未启用位移损伤，并核对 NIEL 表的实际文件摘要。

## 4. 运行

GUI 用 `QProcess` 调用后端（与 Run Console 相同的可执行文件）：

```
G4UniversalSim.exe --config main.ini      # 工作目录 = 场景目录
```

页面显示后端日志（首行 `$ <exe> --config main.ini`）与退出码；日志同时写入场景目录的 `backend.log`。运行结束后不是只看退出码：页面读取 `run_summary.txt`，要求 `status = completed` 且 `run_0_completed_events` 等于计划事件数，否则按 `describe_failure` 显示失败原因，**不会**把失败渲染成空结果。

## 5. 结果与证据语义

结果表每行五列：`Group / Label / Value / Unit / Evidence`。

| 量 | 单位 | 定义 | 证据来源 |
| --- | --- | --- | --- |
| TID — Total | Gy | 器件内沉积能量 / 器件质量 | `scorer_statistics.csv`（run 级累计） |
| TID — Per primary | Gy / 初级 | Total / 完成事件数 | 同上 + 摘要事件数 |
| TID — Per fluence | Gy / (cm⁻²) | Total / 入射注量；注量 = 完成事件数 / 源面积 | 同上 + `source_area_cm2` |
| DDD（有 NIEL 表时） | MeV/g | Σ w·l·NIEL(E_平均) / 体积（与评分器定义一致） | `scorer_statistics.csv` + `scenario.json` 的 NIEL 表摘要 |
| 透射率 | — | 穿过 BackPlane 的粒子数 / 计划事件数 | `phase_space_t*.csv` |
| 反照率 | — | 从 FrontPlane 反向离开的粒子数 / 计划事件数 | `phase_space_t*.csv` |

证据面板列出：运行状态、完成事件数、统计文件、`run_metadata.json` 的 schema、**NIEL 表路径与 sha256（前 16 位）**、以及分析脚本给出的警告。任何一项缺证据都直接显示，不写成 0：

- 统计文件在 `run_metadata.json` 的 `generated_files` 里列出但磁盘上不存在 → 分析失败（退出码 3），不写报告；
- 统计文件既不存在也未被列出 → 报告带 `no_statistics_file_zero_deposition` 标签的零值，而不是伪装成「实测为零」；
- 运行未完成、事件数为 0、相空间文件陈旧（`eventID >= 完成事件数`）或混入其他轮次 → 分析失败。

分析脚本 `scenarios/shielding_coating/analyze.py` 与 GUI 使用**同一个** `analyze(output_dir)` 函数，命令行与页面结果一致。

## 6. 12 步端到端路径（`gui/smoke_tests/smoke_scenario_backend.py` 覆盖）

1. 打开 Scenario 页，默认字段通过校验；
2. 设 `events`、`threads`、`energy`；
3. 选择生成目录；
4. 生成 → 页面报告文件写入；
5. 检查 `main.ini` 中的线程/种子；
6. 点击 Run；
7. 后端日志逐行出现；
8. 进程结束、退出码 0；
9. 读取摘要：`status = completed`、完成事件 = 计划事件；
10. 分析报告：TID / 透射率 / 证据标签；
11. 结果表 TID 行证据 = `scorer_statistics.csv`，透射行证据 = `phase_space`；
12. 证据面板显示完成事件数与统计文件。

## 7. 与外部的验证关系

- **不是新的物理基准**：本场景的物理由已验收的基准覆盖（`scenarios/benchmarks/` 的 CSDA/射程/光子衰减用外部表 PSTAR/ESTAR/XCOM；硅器件剂量与 DDD 见 `scenarios/semiconductor/` 的 SR-NIEL 表），场景页只证明「配置→运行→分析→证据」链路一致。
- 剂量率/注量归一只对法向入射、平板几何有效；不做角度分布、非平板几何、光核/中子活化（可选 `QGSP_BERT_HP`，但未做基准）。
- DDD 只有在给 `niel` 时才有值；NIEL 表必须是有出处的表格（目前仓库内为 `scenarios/semiconductor/niel/si_*.csv` 的 SR-NIEL 硅表），界面只接受路径并记录摘要，不验证数据来源。
- 统计不确定度：结果表给的是 run 级累计值；判读显著差别仍需多次独立运行（当前页面不做误差传播）。

## 8. 复现与回归

```bash
# 命令行等价链路
python scenarios/shielding_coating/make_scenario.py --out work/shield --events 2000
G4UniversalSim.exe --config work/shield/main.ini
python scenarios/shielding_coating/analyze.py work/shield/output

# 回归
python -B scripts/test_shielding_scenario_model.py        # static：文件契约/确定性/校验/CLI 一致
python -B scripts/test_shielding_analysis.py              # static：正常值与五类证据错误
python -B scripts/test_scenario_shielding_core.py         # backend：200 事件真跑 + headless 驱动
python -B gui/smoke_tests/smoke_scenario_page.py          # Qt：字段/校验/生成/证据列/i18n
python -B gui/smoke_tests/smoke_scenario_backend.py       # integration：12 步端到端
```

未完成/已知限制：GUI 只暴露上述 15 个字段（其余 `ShieldingSpec` 字段仍可经命令行设置）；相空间只记 BackPlane/FrontPlane；页面不做参数扫描（用 Parameter Scans 页或命令行）；结果表不画图（用 Results 页读 CSV/ROOT）。
