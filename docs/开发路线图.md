# G4UniversalSim 长期开发路线图

基线日期：2026-07-11。本文依据当前 src/、include/、main.cc、gui/ 和可运行测试整理。功能当前状态以功能支持矩阵为准；本文是开发顺序和完成门槛，不是对未来功能的承诺。

## 1. 项目目标

把 G4UniversalSim 建成一个配置驱动、可复现、可验证的 Geant4 桌面工作台：同一份有效配置可以由 CLI、macro 和 PySide6 GUI 运行，后端行为、输出契约、GUI 显示和中文文档保持一致。

长期目标不等于覆盖 Geant4 全部接口。每个公开能力都必须有清楚的输入契约、运行时语义、输出契约和验证证据。

## 2. 当前基线

- 已有 C++17 后端、INI 配置、Geant4 macro、多个几何模板、材料构建、GPS 源、参考/手动物理列表、敏感探测器、hit 与 event edep 输出、Edep 计分和 process-level 截面 biasing。
- 已有 PySide6 外部运行器、项目 JSON、运行包生成、材料/几何/源/物理/计分编辑器、输出查看和多线程文件合并工具。
- M0-1/M0-1b 已为 `output`、`threads`、`seed`、`check_overlaps`、`run_name` 和 `macro` 等启动字段建立 `SimulationCommandLineOverrides` 过渡层，闭合最终上下文驱动的启动流程，并对静态 macro 做递归 preflight；实际优先级为“默认值 < 主配置文件 < macro 运行时命令 < 显式 CLI 参数”。当前仍不具备完整的 EffectiveConfig 和有效配置来源追踪。
- placement = replica/parameterised/assembly、GDML、材料温压、Physics region cuts 和 LET/Dose/Fluence 开启目前由 M0-3A fail-fast 拒绝；本阶段仍不实现这些 Geant4 功能。
- GUI 当前只生成后端已验证的子集，部分控件是预览或编辑器模型字段；2026-10-03 工作区已有集中式双语和主题实现，但尚未提交，完整 QTranslator、人工视觉及可访问性验证仍未闭合。

2026-10-03 执行位置：HEAD `018345c` 已包含 B2B2；GUI 展示整理已通过候选复审，C0A 工作区已补充启动边界并用真实 QProcess 完成 3/3 事件。后续仍按“GUI 独立提交 → C0A 独立提交 → C0B/C4 → D/E → B3 → M0-4/5 → M1 → M2 → M3 → M4 → M5”推进，具体队列见 `docs/持续开发执行规划.md`。提交前独立核对未跟踪 GUI 输出源码和测试 fixture，不能用本机测试替代全新检出验证。

目标澄清：当前必须先完成 M0 并通过阶段验收。C0B 原先的 `--inspect-macro` 只读接口仍保留，仅提供 macro 静态计划。

C0B 后续工作区已增加 `--inspect-run` 联合查询及 GUI 外部 Run 的自动预检门槛：覆盖 config-only、macro-only、CLI 覆盖、来源行号和递归命令，未执行 Geant4 run。当前可窄复审；全模块 EffectiveConfig 仍待闭合，C4 有未提交工作区候选。M0-1/M0-2 回归脚本改用临时工作区，防止失败摘要或随机引擎文件污染仓库示例。

C4 工作区候选现已让 Runner、运行页和历史页共用摘要事实判定：退出码 0 且没有新摘要或实际 run 不再视为模拟成功；逐 run 核对计划和完成事件，并拒绝各轮不一致但合计相等的摘要；dry-run、交互无 run、正常结束无 run、失败、用户终止和未证实分别呈现。反例 smoke 与 GUI 真实 3/3 事件 smoke 已通过；这尚非提交基线，也不替代完整 M0 验收。

M0-3D 工作区部分进度：复杂示例冷却管已调整为位于母体内，四种示例颜色已有明确后端 RGB，新增无可视化批处理入口，真实后端完成 3/3 事件且 overlap 检查无报警；回归还验证旧坐标会被 overlap 检测识别。B3 工作区现已让 GUI 默认复杂源无 blocker，并证明生成包 3/3 事件。旧 `test/main_hierarchical.ini` 的无效体积和 legacy 粒子/process 交叉组合已改为两条显式规则；与 batch macro 运行 3/3、与完整 macro 运行 100/100，两个 wrapped process 匹配。实际偏置发生与物理等价性仍未验证，不提升 E/M2 支持等级。

M0-3E 工作区候选已修正 macro biasing 配置未进入实际物理列表的生命周期问题，并在初始化后、事件前对实际 wrapped process 做 fail-fast。专项真实运行覆盖有效和无效目标、MT、多次 run、隐式初始化、physicsModified 后重新初始化及日志去重；摘要明示“规则已配置、operator 已挂接、process 已匹配、实际效果未知”。GUI generated 不再允许只开启无规则的 hook。biasing 挂接后几何重建现先明确拒绝以免访问违例；`--ui` 与启用 biasing 的配置或修改 biasing 的 macro 也会在会话前失败。实际 UI 命令、几何重建安全实现和偏置效果仍未完整验收，物理结果验证仍属 M2。

## 3. 开发阶段

### 阶段一：配置和生命周期契约

目标是让“最终到底运行了什么”可检查、可复现。

- 引入统一的有效配置模型，记录默认值、Profile、主 INI、CLI 和 macro 的来源以及最终值。
- M0-1/M0-1b 已完成当前启动字段的覆盖优先级、启动流程、共享规范化 macro 解析/执行和静态 preflight 回归；后续仍需把 `SimulationCommandLineOverrides` 迁移为可记录来源的完整 EffectiveConfig，同时处理未知字段、schema_version、默认值和向后兼容。
- 2026-10-16 工作区新增最终 Manager 状态子集快照及材料加载来源清单：材料文件多次加载或通过 macro 编辑材料时不再把初始主配置路径写作唯一有效来源；初始化后批处理材料修改现提前拒绝。真实摘要回归只覆盖这些可观察事实，全模块来源追踪、交互生命周期和配置应用状态仍未完成。
- 2026-10-17 工作区补充输出路径修改的状态原子性：`OutputManager::SetOutputDir()` 失败不再提前修改 `SimulationManager` 的最终输出路径与来源；批处理输出 Messenger 即使被 Geant4 转换为 warning，也由独立错误记录阻止后续 macro 执行。两个测试专用异常注入模式已在真实后端摘要专项回归中通过，尚缺交互式命令和实际存储故障覆盖；此项仍属 M0 工作区候选。
- 2026-10-18 接续阶段：新增 `--ui --ui-session csh` 的真实命令行交互回归；会话结束后检查材料和输出 Messenger 失败，并写入交互失败类别/消息、非零退出和失败摘要。无 macro 的交互失败保留 `macro_execution_status=not_run`。这关闭了两类已知 warning 被误判成功的收尾路径；逐条即时中止、其他交互命令、完整生命周期和真实设备故障仍未闭合。
- M0-2 已完成最终生命周期摘要：记录状态、每次 run、计划/完成事件、实际线程、seed 修改、最终输出目录、生成文件和失败命令位置。M0-3 审计配置被接受但运行时无效的入口；M0-4 工作区已修正 CSV/直方图合并，按 run 分文件并将当前已验证的能量/长度列升级为带单位的 CSV v3 表头，移除 hits 中未计算的 LET 占位列；真实单线程/双线程多 run 测试通过。通用直方图单位、完整逐文件数据契约与故障注入仍待完成。M0-5 工作区已有分层测试、构建身份和 Windows/Linux 无 Geant4 CI workflow 候选，但 CI 尚未实际运行，24 个未纳入 Git index 的源码仍阻断干净检出；继续补齐跨平台构建和多线程验证。
- M0-3A 已完成第一阶段 fail-fast 防护：对尚未完整支持的 placement、GDML、材料温压、Physics region cuts 和 LET/Dose/Fluence 开启统一拒绝，并同步 GUI validator 与中文文档；本阶段不实现新的 Geant4 功能。
- M0-3B1 已完成主配置字段消费追踪和未消费字段 warning：warning 按文件、行号稳定排序，写入控制台和 `run_summary.txt`；材料文件与几何文件的独立解析器留给 M0-3B2。
- M0-3B2A 已完成材料独立配置文件闭合 schema：未知 section/key、隐式 `global` 字段和空动态后缀在 Geant4 初始化前失败；temperature/pressure 继续使用 M0-3A 专用拒绝路径；旧 GUI run package 的 `[material.<name>] type = material` 作为已弃用输入保持兼容，新 writer 不再生成。
- M0-3B2B1 已完成几何安全闭环：production cut 与 region 依赖、固定模板 box 限制、hierarchical/boolean 逐 shape 参数、`copyNo` 和 placement 均在首个 geometry object 创建前校验；GUI 对无法无损保存的字段阻断 editable writer/package，并提供明确的原始文件复制模式。
- M0-3B2B2 已完成几何来源诊断与兼容 warning：保留原始 section/key/value 来源，统一输出未知 section、未消费字段、legacy metadata 和 boolean ignored key，并分开记录主配置与几何配置 warning 计数。严格 `version=2`、自动 metadata 迁移和完整无损 round-trip 留给 M0-3B3。
- M0-3B3 工作区已闭合 hierarchical 普通体积的已知 `vis.*`/`cut.*` 与 `trd` 五参数往返：GUI 保留原值和项目快照，`trd` 可在表格编辑，默认复杂源生成后再读取体积语义一致；源文件、生成文件及 GUI package 各自通过真实后端 3/3 事件。后端现有显式 `[global] version = 2` 严格诊断候选，五模板干净文件和错误字段前置拒绝已通过专项；GUI 可在当前可编辑子集保留并写回该标记，严格源/生成文件分别完成真实后端 2/2 事件。自动迁移、布尔工具扩展和完整 schema/诊断去重仍未完成。
- 增加只校验、不运行的入口，以及运行前计划和有效配置导出；输出中应包含实际启用/关闭的模块和依赖。
- 把配置校验从“各模块分别读取后才失败”提升为可组合的前置校验，但不能用 GUI 校验替代后端校验。

完成门槛：同一配置在 CLI、macro 和 GUI 生成包中的最终值可追踪；覆盖优先级有测试；错误包含文件、section、key 和依赖上下文。

### 阶段二：补齐后端已声明但未闭合的能力

先修复会让用户误以为功能已生效的灰色状态：

- 实现或明确拒绝 replica、parameterised、assembly，不能继续只解析 placement 类型。
- 统一 geometry region cuts 与 [physics.region.*] 的语义，确保保存的 region cut 真正应用到对应 G4Region。
- 让材料 temperature、pressure 要么进入 G4Material 构造/状态语义，要么在解析时明确拒绝；不能只保存字符串。
- 固化 sensitive、bias、copy number、可视化属性和几何重建的生命周期测试。
- 完善输出列单位、量纲和版本化契约，避免同一列名在不同输出路径表示不同物理量。

完成门槛：每个字段都有“解析—校验—运行—输出/日志—测试”证据；没有仅因字段存在而标记为支持的能力。

### 阶段三：完成可发表的计分链路

- 先定义 LET 的物理量、步长/材料/密度依赖、权重处理、单位和统计方式，再实现 hit 到 LET 的计算链路。
- 使用明确的体积质量或材料几何契约实现 dose；定义零质量、复合材料和权重结果的处理。
- 定义 fluence 的面/体积/track-length 语义，优先评估 Geant4 原生 primitive scorer 或 G4MultiFunctionalDetector，避免另造无契约的统计器。
- 为 analog 与 biased 运行建立同一场景、固定随机种子、误差和收敛比较；process-level biasing 的现有 smoke 只能证明挂接，不代表物理结果已验证。

完成门槛：scorer 不再是空实现；每个量有单位、参考结果或基准场景、单线程/多线程行为和输出 schema；GUI 只在这些条件满足后开放开关。

### 阶段四：几何能力和 GUI 能力对齐

- 建立后端能力清单/版本化 schema，GUI 由能力清单生成或校验控件，而不是维护独立白名单。
- 完成通用几何编辑器的 round-trip：读取后端支持的字段、编辑、写出、再次读取，未知字段不静默丢失。
- 对复杂实体、GDML、CAD/STL 和高级 GPS 采用“后端先行、GUI 后开”的顺序；预览几何必须显示近似和不可用状态。
- 完成 GUI 的中文界面、翻译切换、浅色/深色/系统主题和配置持久化；不把主题色或翻译文本散落在业务控件中。

完成门槛：GUI 生成包可被后端独立运行；后端报错能回指 GUI 字段；源配置不被覆盖；所有可编辑字段都有校验和测试。

### 阶段五：测试、发布和兼容性

- 工作区已将现有 C++ smoke、GUI smoke、输出合并测试接入分层 `scripts/run_m0_tests.py` 与 CTest，并对当前源码和后端可执行文件做指纹比对；仍需干净检出、Windows/Linux、依赖版本矩阵及持续集成，见 `docs/测试平台说明.md`。
- 建立单线程/多线程、Windows/Linux、可选 MicroElec/3D 依赖和 Geant4 工具链的兼容矩阵。
- 为配置 schema、输出 CSV、run summary、项目 JSON 和生成包建立版本迁移策略。
- 发布前只把通过后端运行测试、配置校验、GUI 生成、输出检查和中文文档审查的能力标为完整支持。

## 4. 暂不提前开放的方向

高级 GPS 分布、GDML/CAD 导入、光学材料与 digitization、重要性偏置/权重窗口/分裂/俄罗斯轮盘、参数扫描和结果数据库，都必须等到各自的数据契约、后端实现和基准测试齐备后再进入 GUI。仅增加枚举、表单或预览不能改变支持等级。

## 5. 每个开发任务的完成清单

- 后端配置解析和默认值已核对。
- 校验、依赖和错误路径已覆盖。
- 运行时对象和生命周期已验证。
- GUI 只展示并生成后端已实现的子集。
- 相关测试已运行，未运行部分已记录。
- M0-1/M0-1b 的配置优先级测试入口为 `python scripts/test_config_precedence.py`；涉及后端改动时还要运行构建、`--help`、配置 dry-run、macro preflight 和真实后端 smoke。
- docs/功能支持矩阵.md、相关中文手册和 AGENTS.md 已同步。
- git diff 未包含无关代码或覆盖工作区已有改动。
