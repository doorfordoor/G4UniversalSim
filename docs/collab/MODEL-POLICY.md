# 项目协作与模型调度规则

## 一、基本原则

主审根据任务性质、复杂度、风险和执行成本，决定是否委派子 Agent，以及使用何种模型和推理档位。

模型分配采用建议策略，不作强制绑定。优先保证任务质量、执行效率和验证可靠性。

模型能力不替代工程验证。所有工作仍须满足既定契约、证据要求和验收标准。

## 二、模型选择策略

当前可显式指定的非网页模型为 `gpt-6.1-sol`，支持 `low`、`medium`、`high` 推理档位。Astra 可在父 Agent 使用 Astra 时通过省略 `model` 继承。

建议如下：

| 任务类型 | 推荐配置 |
|---|---|
| 简单检索、信息提取、边界明确的小任务 | Sol low / medium |
| 常规代码实现、GUI、脚本、IO、文档、CMake 和测试 | Sol medium，复杂任务可提高至 high |
| Geant4 生命周期、复杂状态管理、多线程安全、疑难缺陷及高风险验证 | 优先考虑 Astra |
| 科学正确性、物理与统计口径、重要架构决策 | 优先考虑 Astra |

以上配置仅作为调度参考。

主审可以根据实际任务调整模型与推理强度，不必默认使用最高档，也不必为了使用低成本模型而强行拆分任务。

委派时不要求在子 Agent 的任务提示词中重复声明模型。通过工具参数或继承机制确定模型，并以工具回执为准。

当可用模型或工具能力变化时，可重新评估调度策略。

## 三、任务委派

1. **优先判断是否需要委派。** 紧耦合、难以拆分的关键工作由主审直接负责；具有明确边界、独立产出和验收标准的任务可以委派。
2. **合理并行。** 无冲突任务可以并行，同一文件在同一时间只允许一个写者。
3. **明确任务契约。** 每项委派应提供任务目标、已确定的接口或行为契约、允许操作的文件、证据路径及完成标准。
4. **保持任务可追踪。** 记录请求模型、推理档位、任务 ID 和工具回执。工具已接受有效的模型请求时，无须额外要求子 Agent 自报身份。
5. **优先复用已有任务。** 对运行正常的异步任务，继续跟进原会话，避免重复启动和重复消耗。

## 四、独立复验与验收

1. 作者实现和独立复验由不同执行者负责。同型号的不同执行者可以承担独立复验。
2. 独立复验必须检查候选源码、原始输入、实际执行结果、退出状态、日志和执行身份等相关证据，不能仅依据作者的总结。
3. 复验范围与深度应匹配任务风险。高风险科学计算与关键架构修改必须具有相应的验证证据。
4. 主审负责最终整合与签收。MR1、MR2、MR3 的最终签收职责不得转交子 Agent。
5. 模型或协作规则更新，不要求重新执行已经有效验收的工作。
6. 对失败、未完成或状态未知的任务如实记录，不得将其标记为通过。

工具不可用时，主审继续执行能够独立完成的工作，并报告具体限制。不得因此降低验收标准，也不得以实现者自测替代独立复验。
