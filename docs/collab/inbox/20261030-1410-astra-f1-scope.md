# F1 输出身份与来源：执行契约

基线 `20ab4f3eb34b41d4004a4e1b9d38d2f2f290f366`，分支 `roadmap/F1-output-provenance`。用户授权完整实现、审查、验收；2026-10-30 补充允许子代理使用 Astra。此文为开工范围，不是验收结论。

## 范围与兼容决策

保留 `run_metadata_json_v1`、CSV v3、ROOT v4 及默认 CSV。新增可选但完整校验的 `provenance` 对象，schema=`g4usim_provenance_v1`；旧元数据没有该对象时仍兼容、明确无内容校验。新协议存在但损坏、未知版本或文件不一致必须拒绝自动可信读取，不得退回旧目录扫描。运行完成、文件身份一致、物理验证为不同结论。

`provenance` 固定包含：

- `execution_id`：独立于 Geant4 RNG 的 32 位小写十六进制进程标识，master/worker 共享；不是 seed/run/revision。
- `build`：`git_commit`（40/64 hex 或 unknown）、`git_source_state`（clean/dirty/unknown）、`source_fingerprint`、`compiler_id`、`compiler_version`、`configuration`、`geant4_version`。Git 状态只覆盖实际 C++ 构建输入，构建时记录，不读取运行目录 Git 代替。
- `input_coverage`：固定 `project_readers_observed`；`input_observation` 固定 `bytes_read_not_semantic_acceptance`。实际读取字节不自动等于解析接受或内核应用；后两者继续看 2C。
- `input_exclusions`：至少列出 Geant4 内部数据集及未观测的原生命令输入。不得宣称全部系统文件 IO 已追踪。
- `inputs`：按实际观察次序，每条 `sequence`（从 1 单调递增）、`path`、`kind`、`role`、`capture_method`、`status`（recorded/unobserved）、`sha256`、`size_bytes`、`reason`。recorded 必须有原读取字节 SHA 和非负整数长度；unobserved 使用 null 且说明原因。重复读取同路径必须保留，包括 STL 验证与构造间变化。输入原路径当前不存在不抹掉历史身份，不在最终化重新打开输入伪装实际消费。

`generated_files` 保留 path/schema，F1 每条追加 `execution_id`、`scope`（process/run/thread）、`run_id`、`thread_id`、`sha256`、`size_bytes`、`integrity_status`（hashed/unavailable/self_reference_excluded）。process 的 run/thread 为 null；run 的 thread 为 null；thread 为明确非负 ID。run/thread 必须关联真实 run。metadata 自身条目为 process/self_reference_excluded/hash 与 size 为 null；仅此条目可自引用排除。其他已关闭文件流式 SHA-256，不以 mtime/size 代替。不一致表示相对于记录的字节不一致，不推断恶意或签名认证。

先关闭常规输出及有效配置，再核对已登记文件，写文本摘要并对实际关闭的摘要哈希，最后写 JSON。登记文件丢失/hash 失败锁存 `artifact_integrity`、非零退出并纠正摘要，不静默从名单删去；metadata 打开/写/关失败继续沿用 R02，失败 JSON 不登记。哈希只证明该次读取，不承诺外部并发修改下原子快照。

## 单写者与接口

- 输出代理：`include/Output/*`、`src/Output/*` 及显式输出登记调用点（除下面主负责人的文件）；实现共享 execution ID、显式 scope、artifact 快照与序列化；新增 `scripts/test_f1_output_identity.py`。公开 API 建议 `GetExecutionId()`、`CollectArtifactEvidence()`、`RunSummary::SetProvenance(effective_config::Value)`、`SetArtifactEvidence(...)`，接口落定立即回报。不要改 SimulationManager/EffectiveSimulation/main/CMake。
- 资源代理：`Config/InputProvenance`、各读取调用点、GDML capture、RandomCommandGuard；新读入账本 API `Snapshot()`、`RecordRead(...)`、`MarkUnobserved(...)`。账本纯 C++、互斥、仅存元数据。提供独立流式 `HashFile(path) -> FileDigest{sha256,size_bytes}`，该函数不登记输入；输出不得误入输入账本。保留 `Sha256(string_view)`/`ReadFile` 兼容 API。新增 `scripts/test_f1_input_provenance.py` 与必要工具。不要改主负责人/输出目录。
- 前端代理：GUI 输出来源统一验证器、结果/历史展示、所有 Python 自动目录消费者及相应测试；DeepSeek 设计已收据化。改动来源状态不改变运行结果判据。所有读取均从当前根重定位；执行合并前重验内容。新增 `smoke_f1_output_identity.py`；需要的跨范围改动先通知。派生输出保持原清单只读，不擅改原始身份；后处理自动消费必须验原数据。
- 主负责人：CMake/BuildInfo/BackendCapabilities、SimulationManager/EffectiveSimulation/main、测试登记、契约文档与总验收；最终化连接账本/输出；构建身份验证。独立交叉审查后关闭。

## 提交节点和验收

1. 来源与身份实现：构建时 commit/dirty、精确输入读账、流式产物 SHA、版本化增量协议与错误传播。正反例覆盖两次 run、1/2/4 workers、csv/root/both、dry-run、无 run、失败摘要、metadata 自排除、缺产物/读失败、原输入改后/消失、GDML/STL/恢复文件实际字节。不能假定 worker0 收到事件。
2. 消费者与界面：旧记录兼容，新记录严格类型/重复 key/未知版本/同长度同 mtime 篡改/缺文件/跨 run/搬移/旧根仍存在；运行失败但字节相符、运行成功但字节不符分开展示；合并计划后修改须拒绝。DeepSeek 信息架构和真实窗口观察分别计证。
3. 性能与可选格式：先测 hits/event/mesh 工作负载的 csv/root/both，包含墙钟、字节数及新增哈希成本。对现有 streambuf 基线比较，证据不足不宣称优化收益；`format=auto` 仅可显式选择，默认保持 CSV，选择原因可追踪。默认值变更留后续单独决定。
4. 冻结实现、独立审查、Windows 全量与真实 Linux 双版本 CI、逐报告严格证据门禁、实际 GUI 关键状态、更新支持矩阵/CHANGELOG/STATUS/ROADMAP/Agent 历史并归档。实现提交与阶段关闭分开；正常集成 codex，不重写历史。旧 E6 证据不可追改。

不扩大 Q2 物理验证、不修改实验几何/材料/物理定义、不声称内部 Geant4 数据集或任意原生 IO 已完整捕获。新增异常不得改变历史首因/输出失败语义。对范围或字段的新决定在本契约补记并通知所有写者。

## 首轮独立审查修订

- 输入 sequence 连续从 1 开始；包括 unobserved 在内 path 必须非空（未知位置使用明确占位）。读账表示字节读取，RNG restore 应在原快照完整读取关闭后、解析与引擎提交前登记；拒绝的已读文件仍留诊断，不代表接受。
- Git clean 不能仅凭 status：assume-unchanged/忽略的实际编译文件会漏掉。逐实际构建输入 raw blob 与 HEAD 清单比较，工具不可用则 unknown。
- 官方 Geant4 11.3.2 原生输入引用确认：[GPS histogram file](https://raw.githubusercontent.com/Geant4/geant4/v11.3.2/source/event/src/G4GeneralParticleSourceMessenger.cc)、[physics-table retrieval](https://raw.githubusercontent.com/Geant4/geant4/v11.3.2/source/run/src/G4UserPhysicsListMessenger.cc)。后者正确名称为 `/run/particle/retrievePhysicsTable`，仅设置后续可能读取，不是 `/run/retrievePhysicsTable`；OFF 不登记输入。F1 对二者只记录 unobserved 引用，不伪造实际字节。
- 已有有效配置文件 `effective_config_run_R_tT` / `effective_config_final_rR_tT` 与普通产物后缀不同，必须按实际显式归属校验；负 thread 是主线程 run 证据，不能误解为 worker 或默认 run0。
