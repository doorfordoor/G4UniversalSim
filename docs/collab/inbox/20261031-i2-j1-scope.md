# I2 / J1 接口与验收约定

基线 `72af8aa`；工作分支 `roadmap/I2-J1-desktop`，复用 effective-config 检出。用户本次要求“下一阶段先开个头”。本文件是协作范围与接口约定，不另建进度入口；当前状态由 STATUS / ROADMAP 维护。本次交付为方案与设计准备，安装器、布局与主题尚待实现。

## I2：辅助安装与双平台交付

复用 `packaging/build_package.py` 的 Windows 打包、清环境 smoke 与许可汇集，复用 `installer.iss` / `test_installer.py` 的安装与卸载基础；它们尚不是跨平台环境安装服务。I1 的 `core/environment_discovery.py` 保持只读事实来源，`widgets/environment_dialog.py` 保持异步发现/显式选择，K1继续拥有模拟动作与进程。

首个实施提交为 `feat(I2): add validated installation plans`：

- 输入：显式 runtime / sdk 方案、平台/架构、精确版本、用户选定前缀、I1事实快照、经审阅的离线产物清单。清单记录来源、实际大小/SHA256、许可与解包目标；不虚构尚不存在的发布地址或散列。散列完整性不等于来源真实性。
- 输出：`g4usim_install_plan_v1`，列出依赖、下载/暂存/发布步骤、空间需求、冲突与不可用原因；另定义执行收据契约。计划阶段只能记 planned，不能生成 downloaded/verified/published/probed 等已执行事实。空间需求未知则明确未知，不能填零假装满足。
- runtime 不强迫用户安装编译器；sdk 明确包含开发依赖及后续编译验证。未知版本、缺产物/许可依据、平台不符、路径越界或未知目录占用须拒绝形成可执行计划，并给诊断。已有环境不自动覆盖；安装后的实际能力仍由I1复探测。
- 首节点为无副作用的离线规划：无GUI、无后端、无SDK/编译器时也能导入和输出拒绝原因；不联网、不安装、不启动模拟。输出文件只由调用者显式指定。解析、字段校验、拒绝路径与输出协议均有正反例。
- 拟写入 `packaging/install_plan.py`、`packaging/manifests/`、`scripts/test_install_plan.py` 及安装说明；统一测试登记和指纹必须覆盖新增安装源码，不能让 `packaging/` 成为证据盲区。拟新增路径不表示已有实现。

后续提交依次覆盖受校验下载与可恢复发布、runtime/SDK完整流程、Windows/Linux包及干净系统安装/卸载、诊断包与实际CI。当前Windows打包写死11.3系列，Linux源码CI有11.3.2/11.4.3，不等于这些组合均有产品包。Windows11.4、原生Linux桌面、包内Python辅助工具与ROOT读写分别验收；11.2不默认纳入支持。安装成功、环境检测就绪、模拟完成和物理验证分别报告。

已有构建脚本会清理自己的 out/package，不能直接作为用户安装事务；既有安装验收会改注册表/菜单，不能用作无副作用测试。普通包smoke应升级为当前运行结果与逐run事件证据核验，不以摘要子串冒充完成。

## J1：可调整工作区与主题

前端设计由DeepSeek协作，最新[设计交付与主负责人修正](../outbox/20261031-deepseek-j1-kickoff.md)以当前代码和用户B/K/C模板CSS为输入。尚未做模板画面或产品实窗验收。

首个实施提交为 `feat(J1): add persistent dock workspace`：从现有单实例面板建立Qt原生停靠骨架，保存/恢复/复位本机布局；不销毁重建编辑器，不新增事务或运行控制器。中央视图与Dock职责分开，布局动作不提交草稿、不启停模拟。Qt布局二进制、屏幕信息与布局版本只保存在本机UI设置，不进入项目、F5事务或K1分享包；损坏设置和失联屏幕有明确回退。

完整阶段随后实现配置编辑/运行观察/结果分析三个预设、B/K/C起始色板与浅/深/系统策略、清楚的区域层级和主题稳定后的主要中文。状态仍由K1/F4生产，不因简化文案改变blocking、陈旧或四层验证含义；AI区域明确尚未接入，L1另做实际Agent能力。

J1须验证拖拽/缩放/隐藏/浮动、重启恢复/复位、草稿与运行状态不变、运行中主题/布局切换、代表性DPI及中英实窗。F8随后扩展跨页、键盘、可访问性和向导整体检查，不代替J1自身实窗验收。
