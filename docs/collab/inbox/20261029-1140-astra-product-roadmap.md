## 1. 是否必要、有什么价值

| 用户目标 | 价值判断 | 必要范围与应收缩部分 | 成本/位置 |
| --- | --- | --- | --- |
| 双平台与环境助手 | 高；决定其他人能否装上、跑起来，也支撑独立工程导出 | Windows/Linux 的明确支持矩阵、自动诊断很必要。只供本人 Windows 使用时，完整 Linux 安装器收益较低；若要分享工具则必要。安装助手只支持经过测试的环境组合，不承诺任意系统一键成功 | 诊断中等、双平台分发和安装较高；2C 后首先补诊断，SDK 安装先于独立工程编译 |
| 自由工作区与主题 | 中高；配置、3D、日志和 AI 同屏可减少来回切页 | 面板移动/缩放/隐藏、布局保存、恢复默认有实际价值。先做 3 套主题与 3 个任务布局；14 套皮肤、插件布局市场、自造窗口框架暂不值得 | 中等；工作流服务稳定后、AI 页面交付前，可与环境助手并行 |
| 验证、保存与两类导出 | 最高；是结果可信、可复现、可分享及摆脱工具依赖的基础 | 验证过的配置包应优先。独立 C++ 工程是重要长期能力，但不是配置编辑器必须马上具备的条件；它需要明确支持子集和跨平台编译验收 | 配置闭环中高，独立源码导出高；分别安排，不能因后者复杂而拖延前者 |
| AI 实际执行任务 | 高；减少配置语法、工具切换和重复排错，是有辨识度的产品能力 | 先让 AI 安全调用已有配置、校验、运行和分析能力。自动改 C++、自动选择物理模型是后续扩展，不能混在首版承诺里 | 配置 Agent 中高、代码 Agent 很高；可信配置流之后 |
| API/本地模型 Agent 工作流 | 长期高；可更换模型、长任务恢复、全过程留证据 | 这是第 4 项成熟后的编排层，不再建设一套重复系统。首版无需多 Agent 互聊，也不绑定单一云服务 | 高；配置 Agent 与独立工程导出各自稳定后整合 |

判断依据是当前产品用途与代码结构，不是对未来用户数量或商业收益的量化预测。优先级低一些不等于没有价值。

## 4. 按整阶段交付的顺序与验收

### 当前：可靠性修复 + 完整 2C

先处理上述阻断问题，随后完成实际消费者、输入哈希、对象身份、配置/运行开始/最终化三阶段证据以及 off/auto/on。代码覆盖与物理验证分别登记。每项缺陷须有修前反例、修后专项、对应既有回归；阶段收尾完整平台无 FAIL/SKIP 并通过证据门禁。阶段 2 不因这次产品规划扩大功能实现范围。

### 接续：可信配置与环境诊断（对应 F1/F4/F5、E3/D/F8 延伸）

形成一个 GUI/CLI/未来 Agent 共用的服务接口：inspect、validate、apply-config-patch、generate-package、run、evaluate、export。变更先在副本验证，原子接受配置事务；支持撤销、保存、恢复。运行用独立 run ID 和新目录；配置改变使旧验证证据失效，不改变历史结果。

环境区分两个档位：普通用户只需要应用运行时及数据集；开发用户才需要 Geant4 SDK、编译器和 CMake。启动自动检查已配置路径、受控安装目录、环境变量及常见安装前缀，不做每次全盘扫描。显示候选路径、版本、平台/架构、编译器兼容、可选组件、数据完整性和真实 smoke 结果；有多个环境时保留用户明确选择。

检测由不依赖 Geant4 的 GUI/启动器先执行，再调用候选后端能力探测；不能依赖一个已因缺 DLL/共享库而启动失败的后端去安装自身依赖。找到 `Geant4Config.cmake` 或安装目录只代表发现候选，不代表该二进制能运行或 SDK 可编译；诊断和试编译/小运行分别报告。未安装全局 Geant4 时，完整的应用自带运行时也可以是合法选择。

配置导出包含项目模型、材料/几何、macro、引用资源、版本/哈希清单、验证记录和重放入口；迁移本地绝对路径，缺资源或无分发权的依赖给出明确清单。共享包不带 API 密钥和机器布局。独立临时目录加载、修改、重跑、验证失效与重新签发均通过后交付。

验证层级必须显式：字段/依赖合法 → 后端可初始化/几何检查 → 指定输入的真实 smoke 完成 → 特定基准或实验条件下的物理比较。凭证绑定配置及全部输入字节、后端构建、环境、种子、事件数和判据；“已验证”不是永久标签，也不是通用物理正确证明。

### 接续：环境安装助手与可调整工作区（可并行）

环境助手提供经过测试的运行时/SDK安装方案、下载大小与来源、校验、安装日志和失败恢复；应用管理的独立前缀优先，不默认改全局 PATH 或替换已有 Geant4。Windows 原生与 Linux 原生分别验收；WSL 只是额外路径。离线包和未支持平台给可执行的手动说明，不能报告安装成功而缺数据或无法运行。

工作区复用 QWidget 与 Qt 原生 docks，不为外观改写物理逻辑。配置、3D/结果、日志、AI 四类区域可移动、缩放、隐藏/恢复；预置“建模/运行/分析”布局。主题和布局独立保存，支持版本迁移、屏幕拔出后的窗口回收、默认恢复、键盘操作及高 DPI。密集表格统一无衬线字体，代码/数值可用等宽字体；不照搬 HTML 阅读行距。

验收至少覆盖两平台启动和真实小运行；布局重启恢复、多屏转单屏、高 DPI、中英切换、切主题不丢配置/结果、不重复连接信号或启动任务。GUI 布局只从本机受控存储恢复，不把 Qt 二进制布局混进可分享实验包。

### 接续：配置 Agent（先交付有用的自动执行）

首个任务链：自然语言需求 → 明确目标体积/源 → 结构化配置差异 → 同一套校验 → 生成运行包 → 小运行 → 读取真实证据 → 人类确认/导出。用户授权范围内自动继续；目标不唯一或改变科学假设才澄清。任务可取消、有资源/事件/重试上限，失败保留首因与输入；运行过的进程通过 run ID 查询，恢复任务不得重复启动。

“探测器改硅，1 GeV 电子束测试”在已有支持范围通常只需修改配置，无须生成新 C++ 或重新编译。不能漏掉用户意图不明确的探测器选择、方向、事件数与比较指标；AI 的总结只解释证据，不担任唯一验收器。密钥放系统凭据存储，provider 层兼容云 API 与本地端点；不假设所有模型都支持同样的工具调用能力。

验收用固定实验任务集：正确目标和单位、歧义澄清、非法参数拒绝、后端失败/中止不报成功、配置变更可撤销、断点恢复不重复运行、日志里的文字不能变成执行权限。比较人工与 Agent 完成任务的时间/成功率，价值不足就先完善动作接口而不是增加 Agent 数量。

Agent 可写范围来自统一动作接口、编辑模型/writer 白名单及生命周期约束；EffectiveConfig 读回子集不能充当写权限清单，它提供的是值、来源与应用证据。

### 接续：独立 Geant4 工程导出

先输出可审阅的 C++/CMake 工程，携带所有必需的项目源码和配置资源、版本声明、许可/来源与 README；依赖 Geant4 SDK 是正常的，但不能依赖本工具安装目录、隐藏服务或只附 INI 冒充独立源码。可先以现有可信后端源码为基础导出，再为支持子集提供精简原生代码模板；生成规则、扩展点和不支持项明确列出，避免让 LLM 从零重写全部物理实现。

验收在干净 Windows/Linux 目录中完成 configure、build、run；脱离 GUI 后仍能修改探测器或源、重编译并看到可验证变化。比较导出前后的输入/几何/计分语义；固定环境的可复现检查与跨平台统计一致性分别定义，不要求跨编译器逐位一致。几何、源、计分、物理或资源不能完整导出的配置应拒绝或明确限定，不能静默降级。

### 最后：代码 Agent 与可恢复任务编排

只在独立工程/隔离目录中提出代码差异、构建、运行、分析、有限重试；保留可回滚提交和失败日志。源码及科学假设变化需要审阅，禁止通过篡改容差、删除测试、改变物理目标来制造通过。用户确认的是完整证据与产物。

框架决定：先稳定领域动作及状态契约，首个配置 Agent 用显式状态流程即可。需要长任务恢复、分支与人类介入时，优先评估 LangGraph 作为薄编排层；不把项目模型和 Geant4 运行器绑进 LangChain 的内部对象。LangGraph 的 checkpoint/interrupt 可以保存与恢复控制状态，但不会替我们保证进程幂等、物理正确或资源清理，仍需真实任务记录与回归。

## 参考与边界

- [Geant4 环境要求](https://geant4.web.cern.ch/documentation/dev/ig_html/InstallationGuide/gettingstarted.html)、[使用 Geant4 库构建应用](https://geant4.web.cern.ch/documentation/dev/ig_html/InstallationGuide/buildtools.html)：运行环境和编译开发环境应区分；CMake 可发现 Geant4 安装及可选能力。开发版文档不是我们的已测版本矩阵。
- [Qt QMainWindow](https://doc.qt.io/qt-6/qmainwindow.html)：docks 和 saveState/restoreState 提供现成布局机制；恢复只使用可信的本机布局数据。具体 PySide6/Qt 版本需在实施时核对。
- [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)、[interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)：支持持久状态和暂停恢复；恢复可能重入节点，因此有副作用的操作必须按任务身份核对，而非自动重跑。

这些资料支持可行性判断，不是当前项目的验收证据。
