## 2. 下一阶段 F2 怎样做

**用户应能在同一个受控后端进程内做三轮运行**，每轮开始前看到本轮将用的参数，结束后能追到实际输入、输出及重放材料。换几何、物理列表、线程或完整配置继续走新进程。L1 默认的新进程工作流仍有独立用途。

| 提交节点 | 实施与文件责任 | 该节点要拿出的证据 |
|---|---|---|
| 契约与最小实验 | 后端负责人先读 [main.cc](../../../main.cc) 的显式 `--ui --ui-session csh`、对应 Messenger/Manager 和[交互反例](../../../scripts/test_interactive_commands.py)。为候选粒子、能量、位置、方向、源形状、运行标记和逐轮输出选项列出 PreInit / Idle / 运行中状态表，登记命令、实际消费者、成功与拒绝语义 | 在同一真实进程运行 A/B/C 三轮，先选最小可证字段（如能量），一次仅改一项。登记 run ID、是否实际生效、提交来源、失败后的状态。输出目录、线程、几何、物理的拒绝实验各启独立进程，与三轮成功路径分开。现有 csh 捕获命令失败后应停止读入、非零退出，并证明其后的 beamOn 未执行。源形状、名称和输出开关以实测决定是否进入白名单 |
| 协议确认 | 将 `csh` 管道的命令边界、回执、超时、取消、崩溃和重连语义写成短提案。同列新增版本化协议的代价与触发条件。现有审计入口优先用于原型 | [开发接续计划 §6](../../开发接续计划.md) 保留了一次协议选择。给出三轮实验和推荐后，请用户就该选择拍板，再改生产入口。等待期间可继续准备回归、重放比较器和界面草图 |

| GUI 和业务接线 | DeepSeek 可负责“本轮已生效／下一轮待应用”的面板、中文提示和交互。复用[进程运行器](../../../gui/g4usim_gui/core/runner.py)与[K1 动作服务](../../../gui/g4usim_gui/core/experiment_workflow.py)，保持一个进程所有者和一条结果发布链。锁住运行期不安全的操作 | 从正常菜单进入，连续三轮 GUI → 后端 → 摘要 → 重放。覆盖拒绝、取消、会话断开、关窗、重新启动、旧后端及不完整结果。检查历史结果可读，下一轮草稿可辨认，焦点可达，正常退出后没有所属子进程 |
| 冻结、审查与集成 | 冻结实现与测试 SHA，独审状态门禁、随机重放、来源和进程清理，完成下文正式矩阵。保存修前失败和修后证据 | 交付三轮对照表、逐轮摘要与宏、回归报告及日志、代表性真实操作记录和独审结论。把通过的边界写进路线图与支持矩阵后再合入集成线 |

## 3. F2 期间可以平行处理什么

- **D 盘桌面修订补验**。由 GUI 验收者使用包含 `841c8f6b` 的源码。已有同机离屏结果：空项目切色处理中位数 7.67→0.61 秒，已载入六组结果时 7.37→0.65 秒；八项专项共 2,254 个断言入口。新增实窗观察覆盖 Windows 125%/150% 下的向导、浮动区、日志、图表和 VTK 文字，检查微软雅黑解析、数字 0–9、中文可读性、结果和草稿保持，再检查 Linux 无该字体时的中文回退。在同一项目记录切色至可交互的时间与测试环境，区分同步处理和绘制。与 F2 共享桌面时串行操作。原字体修订单独登记基线；现有界面的美术改造和新皮肤统一按 J3 实施。
- **WSLg 桌面限制**。此前 Windows 任务栏出现 Ubuntu 窗口但无法展开。L1 的 Linux 代表性操作通过独立 X11/xcb 桌面完成，固定回环夹具一次计划通过、零模拟事件，整任务到 300 秒后超时。若排查 WSLg，请登记 WSLg/Qt、显示通道、可见内容和一次真实交互，在问题通道上复测后再更新状态。这个问题可以独立排查。
- **E4 文档收尾**。文档负责人给当前规范条目逐项建立索引，区分历史计划和当前状态。以实际 CMake preset、GUI 启动方式和首个成功运行更新入门，链接巡检并让另一人在干净检出按步骤操作。与 F2 并行时，ROADMAP/STATUS 由一个负责人统一更新。
- **Q2、K2 准备**。可先整理参考数据出处、许可证、可交付资源和干净构建环境。只有一个接手者时优先完成 F2；F2 独占原 D 盘工作目录和索引。K2 若提前写代码，应另用 D 盘兄弟 worktree 和独立阶段分支；尚无独立检出时只做资料准备。两线也应避开同一 writer 和发布目录。

## 5. 每整阶段怎么验收、回信和合并

1. **指定人和文件。** D 盘接手者对本阶段端到端负责，可用 DeepSeek 担任协调、前端设计、实现和文案。复杂 Geant4 生命周期和线程代码交后端实现者，物理假设和最终证据交独立审查者。一个文件同时只有一个写者。若只有一个模型，先交可复现候选和测试，再请独立的 Codex 工作区审查。角色、信箱方向和模型选择分别见[协作协议](../README.md)及[分工规则](../MODEL-POLICY.md)。
2. **先基线后实现。** 每个阶段分支从当时已核对的交付 HEAD 创建，独立报告根、构建目录、输出和端口。候选有新测试文件时先纳入版本控制再冻结。双版构建分别绑定实际 Geant4 11.3.2 / 11.4.3 SDK，核对 `--capabilities`、源码指纹、EXE 和依赖，显式向 runner 指定该版 EXE 与 merge 工具、数据路径。Windows 预设名称查 [CMakePresets.json](../../../CMakePresets.json)，Linux 环境查[构建说明](../../Linux构建与验证.md)。
3. **专项命令可直接运行。** 以下 PowerShell 从 D 盘仓库根目录运行，演示桌面修订的自动专项。每步非零即停，正式报告保留逐例日志。文档用例替换为 `--profile static --case doc_links`。

   ```powershell
   $py = '.\gui\.venv\Scripts\python.exe'
   $ev = 'out/verification/theme-check-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
   & $py -B scripts/run_m0_tests.py --profile gui --case gui_theme_response --report-root $ev --require-tracked-sources --fail-on-skip
   if ($LASTEXITCODE -ne 0) { throw '见本次逐例日志' }
   & $py -B scripts/check_report_evidence.py --report-root $ev
   if ($LASTEXITCODE -ne 0) { throw '证据校验失败' }
   ```

4. **整项门禁。** 按影响面先过专项，再按[测试平台说明](../../测试平台说明.md)冻结正式构建和用例。本轮 F2 涉及前后端、结果及真实交互，覆盖 Windows static/gui、两版 backend/integration，Linux 两版适用矩阵、M0 双平台及 Windows/Linux 代表性真实窗口。发布与安装适用时核对 desktop-package / full-installation。各报告用 `--baseline` 指向同 profile、同探针且可比的原报告，同时检查逐例和总数、零 skip、日志摘要。CI 登记真实 SHA/run/job/attempt；截图、原始提示、凭据和未脱敏日志按原隐私规则留本机。UI 自动测试、原生观察和独立物理验证分栏。
5. **提交与交接。** 使用 `docs(F2)` 冻结契约、`feat(F2)` 或 `fix(F2)` 提交可测能力、`test(F2)` 归档冻结候选、`docs(F2)` 记录独审和集成。其他阶段替换代号。把执行回信放在 `docs/collab/outbox/YYYYMMDD-HHMM-deepseek-<topic>.md`，列起点/候选 SHA、改动路径、复现命令、实际/预期、失败原件、证据目录与待裁决事项。复核人用 `git show <阶段分支>:<回信相对路径>` 即可从 C 盘读到已提交的回信；审查结论通过对应提交交回。未提交文件在另一 worktree 不可见。
6. **合并顺序。** 对比阶段分支、D 盘保护基线和 `codex` 的提交图，独审通过后再正常合并或快进。D 盘含专属 GUI 改动，第一次将其带入集成线时一并审查这些差异和桌面补验。记录产品 SHA、证据 SHA、集成 SHA；只有普通推送确获授权并经远端核对后才报告远端已同步。保持另一个使用中的 worktree 由其所有者更新。

**遇到缺陷时的安排。** 能复现的错误若会使输入未生效却显示成功、串用其他 run 的结果、覆盖原件或重复启动任务，排在当前阶段验收之前，先留失败反例再修复。纯文案、非焦点布局和额外编辑能力分别登记影响范围，可随 E4、桌面补验或对应功能阶段处理。若参考数据缺失、受控协议尚待选择或独审未完成，回信列出受阻判据及仍可继续的独立任务，保留候选状态。
