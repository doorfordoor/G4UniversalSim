# J3 · DeepSeek 现有界面视觉改造与桌面皮肤任务书

**交付目标**：先在 B 晶格、K 软件、C 夜读三套现有外观中改进共用界面的视觉层次和区域区分度，使沿用旧皮肤的用户也能直接受益。再新增 **三套可选择、可记忆、可在真实 Qt 界面使用的皮肤**。DeepSeek 负责从视觉稿到代码、文案、性能与实窗举证，另一人独审。完成后用户应能一眼分清导航、当前编辑区、检查/结果区、运行日志和 AI 对话区，在不同光照与显示器上读清数值和状态。

## 先改现有界面：区域、层次与操作线索

**第一份交付是 B/K/C 的实装前后对照。** 选同一个工程和同一组窗口尺寸，在修改前记录配置编辑、3D/结果、运行日志和配置助手的实际界面。逐处标出相邻区域粘连、标题与表单同权重、按钮主次不明或状态难以辨认的问题，说明影响哪项操作。DeepSeek 先在默认 B 上做通“改参数 → 看预览 → 找日志 → 查结果”的路径，再把相同的区域线索应用到 K、C。布局归属可查[窗口外壳](../../../gui/g4usim_gui/window/shell.py)和[原生停靠区](../../../gui/g4usim_gui/window/workspace_layout.py)。

| 区域 | 用户应能辨认什么 | 设计与实现要点 |
|---|---|---|
| 导航、页头、中央编辑区 | 我在哪一页，修改哪个对象，哪个字段有键盘焦点 | 当前页用选中标记和短标题呼应；用字重与间距区分页标题、组标题、字段标签、说明。输入框、只读数值、校验错误各有清楚的轮廓或文字。将同组标签与输入靠近，拉开不同参数组的间距 |
| 配置与 3D/结果 | 左右并列或浮动后，能识别哪里改输入，哪里看几何或结果 | 编辑面、预览画布、结果视图分别保留有意义的标题与表面明暗，分隔条可见且容易定位。复用已有 dock 和图表；移动、停靠、缩窄后标题仍说明该区域的用途。边框和留白不挤掉表格首行、图例或轴标签 |
| 运行日志与配置助手 | 能分清后端输出、Agent 建议、待批准操作和执行结果 | 日志沿用通道和级别标签，助手用独立标题、任务状态和动作组。错误图标与排障文字并列，等待批准时说清会执行什么。页内主要操作有一个明确的视觉重心，次要动作降低强调 |
| 跨页面细节 | 相同状态、图标和控件在不同页面表达相同含义 | 统一对齐、控件间距、图标尺寸、边框和标题层级。区分悬停、已选中和键盘焦点；空结果、运行中、完成与失败各有可读提示。Windows 保持微软雅黑，已有物理量符号、单位、数据色标和 3D 外观覆盖继续按原定义显示 |

**单独验收旧外观。** 在 B/K/C 分别留存同工程、同页面、同缩放的前后画面与问题清单，逐项记录“改在哪里、实际改善了什么、仍有什么局限”。由未参与设计的人通过正常入口完成四件事：找到当前编辑对象和可改字段，切到对应 3D/结果，定位指定运行的日志，再找到助手中待批准的动作。逐项记录是否完成、是否误入别区、是否需要提示；遇到歧义就定位到具体控件再复验。先在既有“配置编辑、运行观察、结果分析”三个布局中检查各自可见的区域，再在移动/浮动布局、中英文、窄窗及键盘焦点下重复关键步骤。所有适用任务均须能独立完成；单名评审的记录只说明这些场景。本项与新增皮肤分别签收。

## 1. 三套皮肤分别解决什么问题

本机参考为 `E:\Downloads\Chrome\files (2).zip`，本轮核对到 A–N 共 14 份 HTML。参考其视觉层次，最终资产落在 Qt 主题系统。下表为首批工作名称和方向；DeepSeek 可在设计回信中说明更适合的名称和调整。

| 皮肤 | 面向任务 | 首版设计与必须现场看的细节 |
|---|---|---|
| **纸墨**（浅色） | 长时间读配置、诊断和运行报告 | 参考 A 的纸色与墨色。主编辑面最亮，报告边栏用低饱和灰绿色，标题和数值用深墨色。让只读来源、可编辑输入和当前焦点有三种清楚的外观；在两列长参数表和带误差条的图旁检查可读性 |
| **电路夜班**（深色） | 暗光下监视 3D、运行日志与任务 | 参考 D 的电路层次，重新配置深色背景及青绿强调；与 C 夜读并排验证差异。提高日志时间戳、图例和 VTK 轴文字可读性；每条严重诊断保留图标或文字，不能把普通运行状态照成报警色 |
| **高对比工作台**（浅色） | 投影演示、低对比显示器和键盘操作 | 用清晰的实线分界和强焦点轮廓区分导航、工作面及检查器；选中与键盘焦点可同时识别。检查失焦的选中行、禁用控件、菜单勾选，以及缩放后对话框的默认按钮 |

### 视觉设计交什么

先以同一内容画三套对照：有非法草稿的配置表、一条阻断诊断、一次已完成的运行、结果图及等待批准的 Agent。每套画出普通、悬停、焦点、选中、禁用、成功、警告、失败状态，给出中英文短标签和图标用法。保留数值、单位和错误详情；例如用户应能从“查看错误位置”“本轮已完成”“等待你批准”判断下一步。每套至少给一张整体界面和一张窄面板稿，在相同视口下比较。提交语义颜色表及设计理由，供开发复用和审查。对照稿只记为设计产物。

## 2. 从现有代码接入

1. **测旧版，建样例。** 在同机固定字体、缩放、Qt/VTK 版本和结果夹具，分别测空工程和载入六组结果。记录切换处理、处理完待绘制事件、重复选择同一有效色板三种时间。[现有专项测量](../../verification/gui-theme-response-20261102/README.md)为历史参照。同步验证 D 盘字体修订的原生显示，从而能区分已有缺陷和 J3 引入的回归。
2. **整理颜色与设置。** [主题实现](../../../gui/g4usim_gui/core/theme.py)已有 20 个颜色角色、QPalette、公共样式表与有效色板。先将稳定 ID、可翻译名称、所属浅/深组与颜色角色集中登记。[窗口菜单](../../../gui/g4usim_gui/window/shell.py)目前只枚举 B/K，深色固定 C；菜单、初次加载和实际应用均应读取同一登记表。为旧 `appearance/theme`、`appearance/light_palette` 写迁移和损坏值回退病例。浅、深各记上次选择；跟随系统时按系统明暗选对应组。首次使用仍可取 B/C 默认。偏好只入本机 QSettings。
3. **先做通一套。** 通过菜单选择纸墨，在主窗口、独立向导、浮动 dock、菜单、图表、日志与 3D 看到对应颜色，重启后恢复。再切回旧皮肤核对。如果当前选的是另一明暗组的皮肤，应让菜单说明“当前使用/下次使用”并用测试锁定行为。先过一套端到端再复制已审的颜色定义。
4. **补两套及自绘控件。** 给夜班、高对比工作台补全语义色和图标。检查 [Matplotlib 图表](../../../gui/g4usim_gui/widgets/plot_panel.py)、[VTK 预览](../../../gui/g4usim_gui/preview3d/pyvista_preview_widget.py)、Agent diff、历史列表及诊断定位。坐标轴、文本和边框可随皮肤调整，保留剂量色标、单位、数据系列含义、材料颜色与用户手调透明度。尽量通过公共样式/颜色角色刷新，记录确实需要局部绘制的控件。
5. **验证切换成本与状态。** 保留 `841c8f6b` 的优化：有效色板未变时跳过无用刷新，替换样式时避免中途处理事件；保留项目的焦点、选择和草稿。字体沿用[集中策略](../../../gui/g4usim_gui/core/fonts.py)，Windows 优先微软雅黑，Linux 检查实际中文后备字体，数字显示为 0–9。将皮肤切换与运行、Undo、生成包、F5 恢复及 K1 输入资格分开测试。

## 3. 如何验收

| 检查项 | 执行办法与通过条件 |
|---|---|
| 选择与持久化 | 每套新皮肤从应用菜单真实选中，关闭重启后恢复。验证初装、旧 B/K/C 设置、未知或已移除 ID、系统明暗切换与两组上次选择；勾选项、按钮文案与实际画面吻合 |
| 可读性与辨认 | 提交每套的实际前景/背景对照表。建议项目门槛：普通正文和可交互控件文字对其实际背景对比值至少 4.5:1，焦点与关键控件边界对相邻背景至少 3:1；透明层按混合后有效色计算。有特殊情况时在设计冻结前明确对象及替代识别方式。各状态有文字、图形或轮廓线索，窄 dock 里当前焦点仍可见 |
| 真实操作 | Windows 125% 和 150% 各切三套，在编辑器、结果页、日志和 Agent 之间自然导航，检查中英文长文案、向导、浮动 dock、图例及 VTK 标签；Linux 代表性实际桌面逐套切换并检查中文字体与深色状态。记录实际显示通道、DPR、正常退出和所属进程清理。WSLg RAIL 曾无法展开，用其他桌面完成的观察单列 |
| 状态不串改 | 准备一个含非法草稿的项目、一份可运行验证包、一个已载入结果及一个运行中任务，分别切换。核对草稿原文、Undo/Redo 栈效果、结果选择、显示覆盖、K1 有效性和任务 ID/计数；皮肤偏好不进项目 JSON 和实验包，不触发提交、生成或新运行 |
| 性能 | 候选与父版用同机、相同项目、同一测量边界；每个场景至少五次有效切换，报告中位数、最慢值及重复选择开销。旧修订两场景处理约 0.61/0.65 秒，处理至待绘制结束约 0.70/0.76 秒。建议首次冻结以同机现测父版中位数的 1.20 倍作为回归调查线，另锁定重复选择不重新刷整树；越线时加样复核、定位耗时并解释或修复，再决定签收。分别报告实窗和离屏计时 |
| 自动回归与收据 | 扩充 `gui_theme_response`、`gui_j1_appearance`、窗口与布局 smoke，新增 ID、迁移、重启、焦点和图表/VTK 反例；严格核验报告和逐例日志。覆盖涉及路径的 GUI 正式矩阵和实窗，记录可回退提交号。源码版本、可执行文件、截图观察、自动统计分别记账 |
