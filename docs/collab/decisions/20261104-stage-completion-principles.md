# 阶段收尾执行原则

用户明确授权与要求，2026-11-04起适用于J3及后续所有阶段。

- 禁止不断升级前置任务，使项目长期卡在同一阶段。阶段目标与验收清单开始后固定，不因工具完善欲望而增加门槛。
- 只有可复现且有影响证据的显著问题允许新增前置修复：核心功能不可用、结果或数据错误、用户数据受损、明确违反原定验收要求，或已有通道确实无法完成必需验收。
- 每个新增前置须写明反例、阻断的原验收项、最小修改范围和停止条件。达到条件立即回到原验收；不得顺势泛化工具或扩大测试工程。
- 普通工具瑕疵、增加覆盖、报告美化、未来兼容及额外优化记入后续待办，不阻塞阶段。已有证据可可靠映射时复用，不重复证明相同事实。
- 连续两轮未消除同一阻塞时，改变执行办法并推进其它可验项，禁止继续滚动派同类工具升级。只因真实权限或必须由用户执行的操作才请求协助。
- 作者交付后连续完成独审、必要复测、集成和下一项，不以已派工作为正常终点。保持单写者和原候选边界。
- 原定验收通过立即关闭阶段，同步最终报告、STATUS/ROADMAP、CURRENT-SUPERVISION及定时任务当前阶段，再实际启动下一阶段。不降低既定标准，不把缺证据当通过。
- Windows/Linux使用同一发布版本号，但分别构建、命名、打包与验收；不混用原生安装包。配置跨平台能力与本机依赖分别说明。

J3具体剩余范围见20261104-j3-closeout.md；本原则不新增产品验收项。
