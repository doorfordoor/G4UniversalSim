### 怎样排队

1. **首批 F2 与 J3。** 后端开发者做 F2 原型，DeepSeek 做 J3 设计、实现和真实窗口验证；独立审查者复核候选。如果只有 DeepSeek 一名开发者，先提交 F2 三轮实验及协议决策材料，等待决策期间优先完成 J3 设计和实现。先做完隔离分支上的当前提交再切换工作，不在同一目录混改两阶段。F2 的交互面板也由前端负责人负责，先固定协议和状态含义，再接线。
2. **让 Q2、F3 的测量先行。** Q2 冻结独立参考和适用域，F3 冻结工作负载和性能基线。Q2 之后做 H2、H3；F3 之后做 F7。E4 可随各阶段整理已证实的入口并独立收尾。若只有一条执行线且无新的用户优先级，按 F2/J3 → E4 → Q2 → H2 → H3 → F3 → F7 交付。
3. **K2 工程导出可以提前。** K1 和 I2 前置条件已具备。如果有独立源码所有者，K2 与科研线并行，先完成干净环境的独立构建与二次修改。L2 待 K2 验收后开启，沿用 L1 的任务、授权和恢复边界。是否引入 LangGraph 在 L2 用一个失败恢复病例比较之后决定。
4. **高级科研各自验收。** 默认 H4 → H5 → H6 → H8 → H7 → H9，M5 单独排期。如实际科研需求改变，先写清被提前项的参考数据、硬依赖与人员，再调顺序。既有里程碑 M0–M4 通过引用这些阶段的证据更新。

### 一个阶段从启动到交付

| 节点 | 负责人动作 | 何时交给下一位 |
|---|---|---|
