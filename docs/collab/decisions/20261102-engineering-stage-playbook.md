# 后续工程阶段实施指南

适用起点为 D 盘交接提交 `ca038dd9`。以下是供实施者使用的设计和验证步骤，各阶段实际状态以[路线图](../../ROADMAP.md)为准。分支、双版本构建、CI、独审、证据归档及双工作区交回方式沿用[D 盘交接计划](../inbox/20261102-2045-astra-d-workspace-execution.md)。下列提交名是建议节点。单个阶段内可连续工作。

## F2　受控的多轮运行会话

**从一次可解释的调整开始。** 操作者在一个进程中完成 A/B/C 三轮，例如同一单能源依次采用能量 A、B、A。事件数要小到便于对照原始行。用可识别初级粒子顶点或已审计内核应用的观测点，再比较 run ID、完成事件数和独立产物。固定输入下源能量回到 A 并不意味着第三轮事件记录应逐位等于第一轮，随机状态仍在前进。

1. 阅读 [csh 入口](../../../main.cc)、[真实交互反例](../../../scripts/test_interactive_commands.py)、[命令状态测试](../../../scripts/test_command_state_gating.py)和[随机命令语义测试](../../../scripts/test_random_command_semantics.py)。先从 `--ui --ui-session csh` 管道驱动同一个进程。对粒子、能量、方向、位置、形状、运行命名、逐轮输出逐项填表，每行登记命令、适用源模式、PreInit/Idle/事件中状态、返回与输出、对应实际消费者。观察只到缓存值的行保持待证。
2. 先交独立的成功记录和失败记录。真实后端拒令按现有合同终止 csh 输入、非零退出；每个拒绝样例开独立进程，并在拒令后追加 beamOn，查运行摘要证明后续事件未发生。UI 端对非法草稿可以在写入管道前提示，允许修改草稿再送出。几何、物理、线程、完整配置切换走新包、新进程。多源和延迟 GPS 的字段冲突分别测试。
3. 在 `docs(F2)` 提案列出两种方案的真实回执、错误归属和取消语义，并按[接续计划的协议决策](../../开发接续计划.md)交用户选择。优先评估复用 csh；若必须新增协议，列明版本协商、消息边界、旧后端回退及维护代价。等待选择时可准备比较器、UI 原型、反例和资源清单。
4. 决策后实现会话状态及逐轮收据。从[运行器](../../../gui/g4usim_gui/core/runner.py)、[动作服务](../../../gui/g4usim_gui/core/experiment_workflow.py)、[进度输出](../../../src/Actions/RunProgress.cc)找所有者。会话进入 Idle 后才接受已验证动作，提交下一轮时在后端确认前保持“待应用”。每轮绑定会话身份、run ID、请求/实际值、随机策略、命令来源、目录和终态。断连后只读核对身份，避免串接旧进程、重复提交或重复发布。生成可审阅的重放宏和比较清单，先验证单线程，再说明固定线程协议下可比较的事件集合。
5. DeepSeek 做主窗口的下一轮面板，显示本轮已生效值、下一轮草稿、拒绝原因和需重启动作。复用既有进度和历史。用真实菜单操作三轮，补验取消、关闭、进程故障、旧后端、重启与历史只读。皮肤切换期间检查每个状态的文字与焦点，同时核对无额外进程或重复运行。

**提交与退出判据。** `docs(F2)` 白名单实测与协议决定 → `feat(F2)` 后端和重放器 → `feat(F2)` GUI/异常路径 → `test(F2)` 三轮实窗、逐轮原件、跨平台矩阵与独审。重放须固定构建、数据、随机引擎/初态、线程及执行顺序。对有逐位要求的字段分别出差异表，核查超时、丢包、重入、零事件、拒令后是否仍有输出。失败或证据不足的字段不进入可操作白名单。

## E4　规范和中文入门收尾

**以新用户第一次运行反查文档。** 起点是[当前状态](../../../STATUS.md)、[支持矩阵](../../功能支持矩阵.md)、[快速使用说明](../../../gui/docs/中文快速使用说明.md)和[实际预设](../../../CMakePresets.json)。

1. 给每类事实指定维护位置。阶段完成度指向路线图，功能覆盖指向矩阵，用户操作进快速入门。对重复说法制表，注明当前事实、源码或测试依据、可信入口和拟修改路径。历史失败记录按日期保留。
2. 让一位新使用者从干净检出开始，按环境发现 → 选后端 → 空白或模板建模 → 检查 → 小样本运行 → 打开摘要 → 保存配置包执行。在 Windows 和 Linux 分开记录实际命令、所需前缀、版本与关键成功标志；区分源码入口、已安装工具和生成的配置包。
3. 核对缺少数据、Qt 或 SDK 时能从文档找到诊断入口；核对中文和英文状态用词可区分校验、创建进程、运行成功和物理验证。让第二人仅按修改后的文档复演，再跑[相对链接检查](../../../scripts/check_doc_links.py)。链接检查不验证网页信息、锚点内容和命令能否成功，需要实走。

**提交与退出判据。** `docs(E4)` 事实映射与规范归位 → `docs(E4)` 两平台入门和恢复说明 → 审阅收据。交付前后对照、两平台复演记录及链接报告。生成的 schema/矩阵段继续由现有生成器维护。独审抽查旧能力限制、免安装假设及无效构建预设。

## F3　性能测量与瓶颈修复

**先回答耗时去了哪里。** 现有[性能脚本](../../../scripts/measure_output_performance.py)已有 hits/events/mesh、CSV/ROOT/both、按轮交换候选顺序及 wall time、已登记文件字节和 Python 校验耗时；峰值内存与 CPU 采样需补独立测量。它适合作为出发点，GUI 主题响应另走皮肤工作线。

1. 为 hits-heavy 和 mesh-heavy 各选可重现夹具。冻结事件数、几何、物理、seed、线程、输出模式、数据盘和机器负载条件。基线与候选都记录后端身份、数据、依赖、命令、计时范围。先写稳定性与实用收益判据，再看候选差值。冷热缓存和异常慢轮分别记录。
2. 在同机交替运行基线和候选，多次测量并保留各轮原值。按初始化、事件输运、worker 写出、master 合并、离线校验拆分；测 wall time、进程 CPU 时间、峰值内存、产物数及字节。Windows working set 与 Linux RSS 分平台比较，保存采样方法、时间间隔、缺测区间。
3. 根据真实剖析选一个瓶颈，一次修改一项。分别核对事件和输出行数、单位、权重、统计汇总与失败传播。允许浮点容差的量先声明依据。压缩、缓冲、批量写出若可能推迟错误，加入磁盘/关闭失败用例。若收益不稳定，保留基线与撤回结论。tasking 路径单设实验，写明引擎、事件映射、统计判据和回退到 MT 的方法。

**提交与退出判据。** `test(F3)` 可复制基线与测量协议 → `perf(F3)` 单项候选和语义回归 → `test(F3)` 重复测量与独审。报告应让另一台机器用同样负载重做；样例速度、峰值内存、输出体积及验证时间分列，保留无收益或有倒退的负载。

## F7　二维扫描和受限并发

**先生成一张小网格，再让它可靠地跑完。** 复用[扫描模型](../../../gui/g4usim_gui/core/scan.py)中的 `ScanManifest`、`create_scan`、`load_manifest`、`collect`，从[串行运行器](../../../gui/g4usim_gui/core/scan_runner.py)的 `start/_next/stop` 和[真实后端回归](../../../gui/smoke_tests/smoke_scans_backend.py)进入。K1 与 F3 是前置条件。

1. 先把旧的一维 manifest 作为兼容样本冻结。设计二维轴名、单位、值序、point ID、基准快照、生成器版本和 seed 分配。以 2×3 参数组合验证实际六组输入，目录可搬移。拒绝同字段双轴、非法单位、无效组合和过大网格，显示预计作业数/总事件及磁盘需要。
2. 每个点用独立包、输出目录和 K1 证据。调度器只管理预算与队列，各执行进程由既有运行器拥有。为每点分配线程数，任意时刻活动点线程和不超过用户预算。检查停止等待队列、取消运行中点、迟到完成和异常关闭。重试沿用点身份并建立新的 attempt，保留旧失败及每次实际 seed/目录，防止旧完成信号覆盖新 attempt。
3. 接入场景生成器时先从一个已支持场景演示，复用其校验/render/generate 接口。二维图和 CSV 从同一结果集合派生，显示轴、单位、失败/缺失/取消点与统计适用性。点击一个格子能定位该点摘要和输入；缺失点保留空值。

**提交与退出判据。** `feat(F7)` manifest 和串行二维网格 → 预算与恢复 → DeepSeek 的二维图、错误和重试操作 → `test(F7)` 真实网格与独审。至少演示成功、一个失败点重试、用户取消、搬移重载及一维旧记录。故障注入后只重跑指定点，无重复发布，坐标与结果文件可独立重建。

## K2　独立可编译的 Geant4 工程导出

**以接收方拿到目录后的首个命令为设计起点。** 依赖 K1/I2。现有[配置包](../../../gui/g4usim_gui/core/experiment_bundle.py)、[运行包写入](../../../gui/g4usim_gui/writers/package_writer.py)和[SDK 打包](../../../packaging/build_sdk_package.py)提供资源闭包、输入生成与依赖验证基础。K2 须交付用户可维护的 C++、CMake 与资源。若提前与 F2 并行，指定独立工作树、构建目录和文件所有者。

1. 先定首版支持子集，例如单世界/目标、受支持材料、单束源和一个可核验的计分输出。逐项登记配置 → 生成源文件/数据 → Geant4 消费者 → 参考运行与可比字段。依赖 GDML、STL、外部表或受限许可证时，在生成前给出缺项、来源和可再分发策略。
2. 用一份最小工程手工跑通 `find_package(Geant4)`、构建、运行、编辑和再次构建。再抽取版本化模板。为材料/几何、源、物理和动作安排独立可读文件，入口与相对路径固定。生成时校验 C++ 标识、字面量转义、文件名碰撞、路径越界和资源哈希。复用已有 K1 的晚变化链接回归与失败清理规则。
3. 让 exporter 接受已验证快照，先生成临时目录、复核清单后一次发布。资源清单登记相对路径、内容哈希、许可证、SDK/数据版本和生成器版本，附平台构建步骤、示例命令及扩展位置。实际生成失败保留诊断，已有同名目录和用户已改源码须受到保护。
4. 在拿不到原仓库、工具安装目录及开发者缓存的 Windows/Linux 环境，用声明版本的 SDK 与数据构建。复制到含空格/非 ASCII 的新位置，运行相同小场景，核查实际几何/源/物理、事件数、计分与清单。然后人工修改一处 C++ 参数，重建、运行，证实输出发生可解释改变。缺 SDK、不可移植资源、无权限写入和半途失败分开测试。

**提交与退出判据。** `docs(K2)` 子集和许可 → `feat(K2)` 生成器及 CLI → DeepSeek 的预览/导出流程 → `test(K2)` 两平台独立消费。交付实际导出工程、源码清单、两环境命令/日志、修改前后差异和独审。不在工具内启动也能完成完整消费流程，才将该子集登记为可独立开发。

## L2　代码 Agent 与可恢复工作流

**先让一个受限的代码修改具有可核对的结果。** 前置 L1 和 K2。阅读[计划解析与权限边界](../../../gui/g4usim_gui/agent/actions.py)、[持久 journal](../../../gui/g4usim_gui/agent/session.py)、[控制器](../../../gui/g4usim_gui/agent/controller.py)与[原有 Agent 边界测试](../../../gui/smoke_tests/smoke_agent_boundaries.py)。沿用用户提供 API 或本地兼容模型的接入方式。固定协议夹具、真实模型生成、真实编译/执行及科学判断分层记录。

1. 以一份已验 K2 工程作输入，固定基准树 SHA、可写路径、允许工具和资源预算。模型先给出逐文件 diff 与理由。编译本身可以执行工程中定义的构建动作，因此 CMake 配置、构建和运行都应在同一受限环境进行。先验证隔离路径、网络/凭据访问、子进程及时间/磁盘限制能真实生效，再开放该级能力。
2. 规划 → 待审 diff → 已授权副本 → 构建 → 运行 → 证据分析 → 待用户确认发布。每一步在产生副作用前登记 operation ID、输入摘要、目标目录与预算。进程创建/结束和产物核验分别记账。崩溃后凭真实进程创建身份、输出与收据判断执行状态，身份未知时转人工处理；不同 diff、目标或预算需要新授权。
3. 从一处可定位的编译错误做有限重试。诊断提取器提供文件、行号、错误文本及已尝试修复，遮蔽凭据；修复只能修改授权路径。连续相同错误、超时、预算耗尽、权限升级或工作目录变化要形成可见终态。DeepSeek 做 diff 审阅、批准动作范围、日志与结果摘要、取消和导出界面。
4. 设立故障复现实验。覆盖首次成功、一次修复后成功、耗尽重试、模型返回越权路径、生成恶意构建动作、编译中断、运行后回执丢失、重复点击批准、用户拒绝发布。检查原项目可复原，外部文件完好，每一动作预算单次扣除，旧任务恢复不自动重发。实际云端、本地模型或本地协议夹具按实际身份列证。先用显式状态机走通；只有 LangGraph 等编排器能复用既有授权/journal、提供可演示的恢复收益时才引入，另作依赖和持久格式迁移决定。

**提交与退出判据。** `docs(L2)` 授权和威胁边界 → `feat(L2)` 隔离差异与构建 → 有界修复/恢复 → 可读审查与确认导出 → `test(L2)` 故障矩阵与独审。交付至少一个由真实模型提议且用户可审阅、在隔离工程内完成编译运行的例子，以及故障/恢复原件、受限项和调用预算。用户确认的文件与最后验证的树身份须一致。运行完成性与物理评价保持独立。
