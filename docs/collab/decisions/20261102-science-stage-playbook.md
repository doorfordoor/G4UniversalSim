# 科研与扩展阶段实施手册

适用于 D 盘接手者安排 Q2、H2–H9 和 M5。工作顺序沿用[统一路线图](../../ROADMAP.md)：Q2 → H2 → H3；高级科研按 H4 → H5 → H6 → H8 → H7 → H9 推进。M5 单独排期。每节的实验和功能均为拟实施内容。已有结果按[支持矩阵](../../功能支持矩阵.md)所列适用域引用。

## 所有科研阶段共用的四次交付

| 节点 | 负责人和交付物 | 何时可以进入下一步 |
|---|---|---|
| 定义与参考 | 方法负责人写一页规格，列粒子、材料、几何、能区、归一化对象、权重、单位、输出和适用边界。参考表逐行注明来源、版本及可用条件，附参考生成脚本或可重算的推导 | 独立复核者能指出每个观测量用什么独立量核验；模拟输入、统计量、容差、样本规模和停止条件已事先约定 |
| 最小通路 | 实现者先做一个可解释的小算例，从解析、校验到 worker 实际计数及 master 合并，写出机器可读结果。新能力默认关闭 | 开关关闭时旧用例仍成立；开启时可用实际观测检查效果；缺数据、非法值或不支持组合给出可定位的诊断 |
| 正反实验 | 不参与该实现的人员用另一种计算路径或外部参考对照。保存输入与资源哈希、SDK/数据版本、线程/种子、运行记录、原始量、统计方法和比较结果 | 报告区分算法自洽、外部对照、统计不充分和已确认偏差。若容差或样本方案变更，另立版本，保留按原方案得到的结果 |
| 完成交付 | 配置字段进 schema 生成流程，更新 CLI/GUI 支持边界、示例、科研判据和文档。再由前端负责人接结果展示和界面验证 | 在匹配的 Windows/Linux 和 Geant4 版本完成回归与独审；科学判据按声明的适用域签收。环境不足或缺独立参考的部分登记为待验 |

**前端交付约定。** DeepSeek 消费后端的量名、单位、适用域与证据状态，图例要分别显示真实零值、无数据、统计不足和范围外。主题切换须保留数据序列、图例身份、色标范围和当前选择。颜色之外应有线型、标记或文字辨识。新增皮肤遵循前端独立计划；科研比较始终使用数值输出。

## Q2　为现有计分建立可核查的科研基线

**从哪里开始。** 阅读 [DoseScorer](../../../src/Scoring/DoseScorer.cc)、[LETScorer](../../../src/Scoring/LETScorer.cc)、[FluenceScorer](../../../src/Scoring/FluenceScorer.cc)、[DisplacementScorer](../../../src/Scoring/DisplacementScorer.cc)、[事件统计实现](../../../src/Scoring/HistoryStatistics.cc)，对照[现有基准集](../../../scenarios/benchmarks/README.md)和[NIEL 表说明](../../../scenarios/semiconductor/niel/README.md)。先登记已知验证覆盖，再选择独立性或适用域尚有缺口的算例。

1. **做一张量与参考对照表。** Dose 项分开记录沉积能、扣除子体后的本体质量、输出单位和归一化对象。Fluence 项用已知路径和体积计算期望量。LET 项写清加权分子、分母和比值。DDD 项保存粒子、轨迹长度谱、NIEL 表身份及超出能表的长度。每项都要回答“若质量、体积或权重被错误重复相乘，该例是否会失败”。
2. **分两层验算。** 用简单均匀体、确定性输入和可重建的小样本检查统计与单位，再选有可追溯独立数据的材料和能点验证物理量。独立脚本从可核实的原始量重新计算估计值。用同一张 NIEL 表复算折积只验证折积实现，表本身的有效性须另有参考。
3. **独立审查不确定度。** 固定一组种子重复实验，提前确定比较方法和样本数。将事件内的多步贡献先合并，再估算跨事件波动；对零分母、N<2、稀疏 worker 和正常多线程合并分别做反例。零贡献事件仍属于已完成事件。LET 的比值误差需要分子分母的关联。
4. **最后检验已有 XS 偏置。** 同几何、源和截面定义，分别运行 analog 与有偏置的独立批次。核查实际 worker 的绑定和权重，再对加权透射或沉积作预先约定的比较。单列效率及总运行时间。保留独立均值差、统计误差、适用条件和异常种子。可复用[偏置 worker 回归](../../../scripts/test_biasing_worker_runtime.py)和[统计回归](../../../scripts/test_statistical_uncertainty.py)。

交付 Q2 参考清单、每个量的基准输入、比较器、容差依据与适用域表。某量欠缺独立数据时单列缺口，避免它被其它量的通过结果遮住。

## H2　体积和网格过滤、逐体积能谱

**切入点。** [ScoringMeshConfig](../../../src/Scoring/ScoringMeshConfig.cc) 已有粒子、动能及组合过滤的原生命令；部分过滤参数没有原生 getter。先检查既有覆盖，再确定体积 scorer 与能谱的新增部分，并沿用[已有网格测试](../../../scripts/test_scoring_mesh.py)。

1. 先定义过滤的是哪种粒子、哪个位置的动能、哪个体积身份。为能谱选择明确的填充时刻（例如首次入射或每步），约定区间开闭、溢出格、计数与权重。它们会决定同一条轨迹是否可能贡献多次。
2. 实现解析与统一校验后，在 volume 与 mesh 的实际计分链路应用规则。用同一配置生成可追溯的筛选说明。worker 各自填充，在 run 边界合并并核对总量；GUI 展示筛选条件、bin 单位和未覆盖部分。
3. 用单能直达束检查能峰和取样位置；再用互斥粒子、相邻能区及恰在边界的确定性输入。对可加计数或和量检查各分量含溢出格之和等于未筛选输出；对比值分别重组分子和分母。补空区间、非法单位、零命中、多体积同事件反例。

交付字段/单位契约、兼容原 A2 网格的差分测试，以及真实后端谱表。筛选对象注册收据与真实筛选效果各列一栏。

## H3　独立于质量几何的平行世界计分

**切入点。** 从[探测器构建](../../../src/Detector/DetectorConstruction.cc)、[物理装配](../../../src/Physics/PhysicsList.cc)及[原生网格观测](../../../src/Scoring/ScoringMeshConfig.cc)入手。先画出现有网格的 parallel-world process、质量几何和新计分几何三者的关系，避免给原有 mesh 重复注册。

1. 以一组命名薄层作首个算例，定义 world、位置/尺寸和 scorer 的稳定身份。明确路径冲突、超界和材料来源。剂量的质量取值若无法可靠确定，应拒绝对应请求。
2. 在初始化时构造计分世界及其物理连接，记录 master 与 worker 实际建立的计分对象。输出区分所涉 world，在不启用新计分时复跑既有质量几何。
3. 作三路比较：原均匀质量几何、启用虚拟薄层的同一质量几何、在质量世界中显式划出等材质等体积薄层的参考算例。核对总透射、分层沉积及质量口径。几何分步可能改变随机数消费，按事先约定的数值/统计规则验收。补重名、空单元、跨线程重复计数反例。

交付几何总览、world/单元身份表和三路结果。仅凭渲染截图不能判断输运是否受扰动。

## H4　importance 与 weight windows

**切入点。** [BiasingImportance](../../../src/Biasing/BiasingImportance.cc) 目前只有构造和析构。利用[现有偏置所有权](../../../src/Biasing/BiasingManager.cc)与 Q2 的 analog 装置，先选择可得到非零参考透射的屏蔽算例。

1. 将 importance 分区、粒子/能区、窗口上下限、边界归属、默认关闭和不支持组合分别写入契约。预先指定观测量、批次数、精度与耗时测量范围。
2. 两种方法分别完成解析、依赖检查、worker 安装和输出，再研究组合。记录实际分裂/轮盘相关计数、权重范围、极值和所属 run；全等重要度或等效关闭方案作控制。拒绝无法解释的区域、反向窗口及非有限参数。
3. 用独立批次与 analog 比较加权均值及误差；记录同机相同资源限制下的相对误差与耗时，以及预定义 FOM。若某方案更慢或误差上升，也输出实测值。汇报有效适用域、rare-event 样本充足性及失败配置。

交付两个可单独启用的算例、权重和极值反例、analog 对照与 FOM 表。保持 Q2 对既有 XS 算法的原报告身份。

## H5　光学过程、材料表面与探测计数

**切入点。** [PhysicsManager](../../../src/Physics/PhysicsManager.cc) 的构造器选择、[MaterialFactory](../../../src/Materials/MaterialFactory.cc) 和 [SensitiveDetector](../../../src/Hits/SensitiveDetector.cc) 是三个不同责任点。先区分现有[探测器响应场景](../../../scenarios/detector_response/README.md)中的沉积能观测和新增光子计数。

1. 固定最小材料、波段、折射率曲线、光产额、Birks 参数、表面方向和效率。给能量轴与长度单位设校验，用一对嵌套几何检验实际边界身份。
2. 分别接入闪烁、Cherenkov、光学传输与指定敏感面的计数。输出中区分产生、到达和探测三种数量，规定反射/重入是否重复计数，并保留父粒子和事件关联。
3. 在相应简化条件下分别检查单位沉积能的产生光子数、开/关 Birks 的变化、给定波段的 Frank–Tamm 参考及表面效率的极限情况。设置无光学配置、非法表轴和重复表面定义作为反例。在更复杂几何中分别报告传输与探测效率。

交付含输入表出处和单位的最小光学场景、各环节独立比较表，以及前端光子计数图例和适用条件。

## H6　活化时间窗与热中子输运

**切入点。** 查[物理构造器选择](../../../src/Physics/PhysicsManager.cc)、[数据集发现](../../../src/Core/Geant4DataLocator.cc)及[既有过程测试](../../../scripts/test_physics_a6.py)。实施前在两个支持版本上分别查询实际可用的核数据、过程、材料与温度条件。

1. 将活化和热散射分成独立配置。定义核素/亚稳态、照射/冷却/计数窗口、时间零点与归一化，以及热散射材料、温度和能谱口径。为缺库或不支持组合提供明确错误。
2. 活化先做已知初态的单核素，再做可解析的短衰变链，用版本化衰变常数与 Bateman 解独立生成时间窗期望值。保存生成、衰变与观测数量，分开比较窗内总衰变数和时点活度。
3. 热中子先建温度、边界和采样方式可控的体系。有平衡条件依据后才与相应热谱对照；通量谱、粒子数谱和泄漏谱分别标识。保留未达热平衡、有限几何和统计限制，并测试另一温度或材料的预期变化。

交付两套独立场景、数据版本/环境清单、时间窗及能谱原表。一个分项通过时只登记该分项。

## H8　规则体素和材料索引图

**切入点。** 查[数组模板](../../../src/Templates/ArrayTemplate.cc)、[放置构建](../../../src/Geometry/VolumeBuilder.cc)和[已有几何反例](../../../scripts/test_geometry_a5.py)。先定义支持的规则格，新增体模与已有数组/参数化放置分别编号。

1. 固定坐标原点、三轴顺序、体素中心、尺寸、线性索引、材料编号、输入格式与资源哈希。用不对称小阵列和角点标记验证方向。尺寸乘积、内存预算、表长和材料编号在分配前检查。
2. 实现初始化构建和运行时 copy number → 材料/体素身份的对应；输出稀疏数据时同时提供网格范围、零值和缺证据的解释。GUI 先给切片方向和选中体素坐标。
3. 均匀水体与等尺寸等材质体素水模采用相同束流，比总沉积和按同一空间分箱重算的深度剂量。再用异质边界验证材料未翻转，记录大型输入的峰值内存与失败路径。DICOM 导入保留为另行设计。

交付小型有方向标记的体模、均匀对照、深度剂量差异表及资源上限记录。

## H7　限定 region 的 Geant4-DNA

**切入点。** [PhysicsManager](../../../src/Physics/PhysicsManager.cc) 的 region/cuts 和[既有 MicroElec](../../../src/Physics/MicroElecPhysics.cc)能帮助查清 region 的创建时序和冲突；DNA 的模型名称、能区和安装数据须按实际 SDK 单独核实。

1. 选一种有定义参考的材料/粒子/能区和一个命名 region。分别列区内、区外的模型、切换条件、冲突及数据需求。先保留普通模式的对照配置。
2. 建立从配置到实际区域和模型的接线，保证其它区域按原配置输运。记录区域、粒子、能量、过程/模型的可观测身份；无法直接读取的字段注明证据来源。拒绝未建区域、超出支持材料、冲突配置。
3. 依匹配的官方示例做实现回归，另选适用的独立数据或解析量，以一致的材料、能区、单位和评分定义比较。检查区域内外、跨界两个方向和模型切换附近的结果。无法建立的独立验证登记具体缺口。

交付适用域表、示例同条件复现包、独立对照及区域边界用例；研究结论只覆盖通过比较的范围。

## H9　INI 定义的直方图与 ntuple

**切入点。** [AnalysisOutput](../../../src/Output/AnalysisOutput.cc) 负责 Geant4 分析对象及已有固定 ID，[OutputManager](../../../src/Output/OutputManager.cc) 管发布，[ROOT 回归](../../../scripts/test_root_output.py)与[直方图合并回归](../../../scripts/test_merge_histograms.py)保护旧文件。

1. 先列可选观测量及其来源（event/track/step）、单位、权重、支持类型和取值时机。定义 H1、H2、ntuple 的名字、列型、bin 边缘、下溢/上溢和命名冲突规则，明确固定内置 ID 保留范围。
2. 从一种 H1 贯通解析、worker book/fill、master 合并和 F1 清单；再分别接 H2 和 ntuple。以稳定 schema/version 描述文件。GUI 消费元信息生成轴和列名。
3. 从同一次小样本的原始记录独立重算 bin 内容、权重和、丢弃/溢出数以及元组逐行键。单/多线程按稳定事件键比较；检查配置关闭、零事件、重名、混型、非法边界及旧 reader。只有新旧输出在约定指标上证实等效后，再决定是否合并 writer。

交付字段字典、归档的原始小样本与独立重算器、旧 reader 兼容表和示例 INI。

## M5　可信 Python 后处理扩展的完整生命周期

**切入点。** 先运行[现有 registry 测试](../../../scripts/test_output_extensions.py)，阅读[registry](../../../scripts/output_extension_registry.py)、[CLI](../../../scripts/run_output_extension.py)和[输出扩展原型说明](../../输出扩展原型说明.md)。v1 会执行显式提供的可信 Python 模块，支持元数据校验、注册、列举和运行。接手者需要决定怎样发布、管理和退役这些扩展。

1. 固定 manifest 字段、ID/版本/API 兼容策略、来源/内容哈希、输入产物资格、可写输出目录和卸载语义。设计扩展清单浏览时如何只读展示元数据，避免为了看说明就执行模块。
2. 先用仓库外的最小可信样例串起安装、列出、显式运行、登记产物、升级和卸载。对已有扩展做兼容试验。失败时保留输入身份和错误报告。下载、自动发现或隔离执行若要开放，另行说明信任模型和权限。
3. 覆盖 API 不兼容、重复 ID、损坏输入、加载异常、执行超时（若支持）、半写产物、覆盖冲突和卸载后再调用。检查模块失败不把原运行改为成功/失败，不残留被认作有效的产物。GUI 的扩展页呈现来源和运行范围。

交付扩展作者示例、生命周期对照表、旧扩展兼容测试及用户安装/卸载说明。C++ 内核插件、运行中变更 scorer 和执行任意不可信代码均需单独立项。
