## 2. 七类任务：现状、缺口与达到方法

采用“任务级 L0–L4”，与项目阶段 L1 配置 Agent、L2 代码 Agent 无关：L0=现成模板少量修改；L1=GUI/配置/脚本，不改 C++；L2=新增组件不改核心；L3=必须改核心；L4=当前不支持。需要 Python 的 L1 仍有编程负担，另记“无需脚本”。支持等级必须写明最终交付量，不能用前处理 L1 代替完整科研任务 L4。

三层使用入口共享既有输入与结果契约：①任务模板/GUI；②INI、macro、CLI 与批量脚本；③编译时 Geant4 组件/受约束后处理扩展。AI 是可选助手，生成的结构化配置须能人工检查、保存和复演；基础任务在关闭 AI、无账户/外网协助时也须可完成。第二层不由本评审自动变成全新的 Python 绑定框架，第三层不自动变成动态插件市场。

界面逐步展示必要知识：材料/尺寸/束流、目标量、物理列表与适用域、质量/注量分母、统计不确定度、文件身份。常用路径不应要求理解 `G4RunManager`/`G4UserSteppingAction`/`G4VSensitiveDetector`；“自动选择”须展示依据、默认值和仍需用户确认的物理假设，不能隐藏模型限制。

借鉴的是可复用边界：[TOPAS 扩展文档](https://opentopas.readthedocs.io/en/main/extension-docs/intro.html)展示参数驱动和 C++ 扩展方式；[OpenGATE 首个模拟](https://opengate-python.readthedocs.io/en/master/user_guide/user_guide_first_simulation.html)与[几何对象](https://opengate-python.readthedocs.io/en/master/user_guide/user_guide_volumes.html)展示高层任务/体积组织。这些官方资料只支持设计参考，不证明本项目已有同等能力，也不要求复制它们的实现。

GU3 的最小可执行设计：

- **GU3-A 封装输入**：先选一份可合法保存/分发的真实 GDML SiP，冻结其来源、依赖 SHA、坐标单位、材料表、体积层级、敏感区与参考质量。分别验 GDML ON/OFF、缺文件/歧义名/非闭合或重叠拒绝、搬移后的来源、一次实际输运及逐体积结果。STEP/EDA 转换若确有需求，先定一种格式到 GDML/描述的单向适配，不把“支持 CAD”无限扩张。
- **GU3-B 半导体响应**：分开吸收剂量/照射归一化、器件电学损伤、SEE/SEU 三层。先选择明确粒子、能区、材料、尺寸与输出量；参考数据可追溯且单位/几何/物理配置可比，cut/步长收敛及容差在执行前固定。SEU 首个候选可用声明假设的敏感体积+收集效率/临界电荷模型，但必须按事件合并多 track、验证零/阈值边界、翻转截面分母/面积和置信区间，并与独立模型或实验比对；否则仅标经验模型，不能宣称器件预测已验证。没有足够输运记录时由 H9 有限补齐，不修改旧结果来补造信息。
- **GU3-C 扩展成本**：选一个非默认 scorer 与一个受支持后处理扩展，固定输入输出和同一验收用例，记录新增文件、核心修改文件、构建接线、测试和人工作业时间。目标扩展源码在组件目录、核心实现零修改；允许明确的外部注册/构建声明，不允许把核心变更改名算配置。AR2 的构造试件复用为工程证据，M5 再验版本兼容/生命周期；只以同一任务的前后记录判断成本变化，不预承诺百分比或运行提速。

## 6. 产品指标与真实用户验收方法

采用有效性、效率和满意度三个观察方向。[ISO 9241-11 官方摘要](https://www.iso.org/standard/63500.html)提供可用性概念框架，并明确不规定具体设计/评价方法；下面 **15 分钟、5 分钟、80% 是本项目初始产品目标，不是 ISO 统一门限或已获认证**。

|指标|操作定义与初始门限|记录/通过方法|
|---|---|---|
|首次简单模拟|已安装且数据就绪，从读 T01a 任务卡到结果可用且参与者完成解释的总墙钟≤15 分钟，后验判读正确|至少 80% 新手参加者达到；操作/查文档/计算等待均计入，独立评审员之后判读所用时间另计；安装时间单独公开，不能扣除计算等待来伪装达标|

试验执行安排：

1. **小规模发现问题**：建议三类人各 3 名，共 9 名；新手研究生、Geant4 开发者、领域科研人员，均非本产品开发者。用于找障碍和校准卡片/事件量，不用于宣称总体完成率。任务输入应保证正常计算可在小任务预算内完成，冻结后不为某次失败减事件数。
2. **正式有限验收**：初始建议 15 名独立参与者，三类各 5 名；产品/卡片/帮助材料在执行前冻结。新手的首次产品任务必须是 T01a，不参加先前产品 pilot/教学任务；T01b 使用其本人成功保存的 T01a 基准。T01a 失败导致后卡无法独立开始时，保留依赖blocked/救助记录并计入原分母，不能由开发者补建后称独立成功；其余卡平衡顺序。新手 5 人每卡至少 4 人成功是样本验收条件，但样本很小，不能外推“所有新用户成功率≥80%”。记录每人的每卡结果并给不确定性；总体推断另按精度与参与者内重复相关性设计样本量，不把 25 次任务当 25 个独立人。
3. **只给正常交付物**：安装说明、发布版文档、任务目标与正常软件功能；不提供逐步答案、开发者提示或隐藏操作脚本。AI 关闭的主试验与 AI 辅助试验分开。允许自行查正常文档，记录接触规则、查阅与求助；请求指导或被救助者该卡不计独立成功，原试次保留。预注册参与者作业cap（建议首卡30分钟、其它20分钟）；到点停止新增操作，未完成所需参与者动作则该卡失败，及时完成的提交可继续收取后端结果与独立判读。计算的最大等待/中止预算按固定任务另定，不删除超时/失败结果。cap不改变15/5分钟门限，也不把“已提交”当正确完成。
4. **正确性盲判**：观察员不辅导；独立评审按冻结标准核配置、实际产物、单位/分母、假设和解释，尽量以匿名产物判读。参与者知道自己使用何软件，故只能称“无指导测试/产物盲判”，不能称双盲。任何静默错误结果或错误物理解释被当作成功均阻断相关任务签收，必须修复/澄清后复验。
5. **原生 Geant4 比较**：在具备两种工具经验的参与者中，选择等价任务变体，按经验分层随机平衡先后顺序，避免把做第二遍的熟练收益算给产品。同硬件、Geant4/数据、物理、事件、量与容差；准备/配置/调试/计算分别记录，公开所用模板和训练。新手若不能原生编程，记真实未完成，不虚构无穷提速。该比较评估操作负担，不追加 F3 输运性能批次。
6. **修复与复验**：障碍按功能缺失、操作设计、架构耦合、科学模型、资料不清分类，回到明确责任阶段。新候选/新试次有独立身份；受训练的旧参与者只用于回归，不冒充首次使用者。若需调门限，必须先发布原因和新版方案，再用新数据评估，旧失败保持。

本轮没有参与者/用户测试数据。招募、正式输入/参考资料准备和真实试验是 GU4 等后续执行条件；这里已给出完成方法，不能用模型扮演用户或开发者操作代替实测。
