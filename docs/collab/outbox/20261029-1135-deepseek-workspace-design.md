# DeepSeek 工作区设计建议（待 Astra 取舍）

来源：用户授权 API，模型 deepseek-flash。输入为当前 Qt 架构事实与四份用户 HTML 的 CSS 色板；未发送密钥到日志或仓库，未做桌面视觉验收。

## Astra 采纳与纠偏

- 采纳 Qt 原生 dock、配置/运行/布局分离、布局恢复、B/K/C 三套起始色板及不重写物理逻辑的建议。上述色板来自 CSS 文本，未做实际画面验收。
- 不采纳把 Qt `saveState()` 二进制放进可分享项目 JSON；它只进入本机受控 UI 设置，实验包不携带机器布局。
- 不采纳“永不自动改配置、永不自动运行”的永久限制：这与用户目标相反。用户授权任务范围内通过受校验动作接口自动修改和运行，只有歧义或权限/科学范围变化需要停下确认。布局操作本身仍不得触发 run。
- `run_result` 证明规定的运行完成条件，不证明物理验证。物理验证需独立基准/实验与预定判据；不能以 AI 置信度或 Manager configured 子集替代。
- Manager configured 子集也不是 Agent 的写入白名单：自动修改边界由统一动作接口、编辑模型/writer 支持范围和生命周期校验决定；EffectiveConfig 只用于值、来源与应用证据的审查。
- “三步勿合并”仅作内部实施顺序；仍按用户偏好以一个完整工作区阶段交付。字体、密度与主题解耦，不固定 12px 字体，实际按系统字体和 DPI 验收。
- 文中的 `ui/...` 和 RunController 是概念性拟新增名称，不是现有仓库路径/API。实际文件范围依仓库 `g4usim_gui/core`、`widgets`、`window` 结构开工时确定。

以下为 DeepSeek 原建议，保留便于追踪，冲突处以上述裁决及 Astra 路线图为准。

## 设计评估：多主题可调整工作区

**必要性判断：值得做，但必须“最小化”。** 当前 220px 侧栏 + 九页 QStackedWidget 结构在页数增多后认知负担陡增，用户在高频操作（配置↔运行↔结果）间反复跳页；且后续要插入 AI 任务区，若不先建立可停靠工作区，AI 面板只能塞进第十个 page，交互会被死死绑住。因此工作区改造是 AI 区的前置投资，而非纯美化。但“多主题”本身价值中等——科研软件里真正提升效率的是布局自由度与状态可恢复性，主题只是降低长时间使用的视觉疲劳。**不要为了主题重写样式体系，先做布局，再叠加 2–3 套色板。**

**最小完整工作区阶段（分三步，勿合并）**

1. **停靠骨架**：将九页中真正需要并置的模块（配置编辑器、3D、结果/日志）转为 QDockWidget 面板，主区域保留 QStackedWidget 作为“中央视图”（3D/结果/文档）。面板移动/尺寸/隐藏/浮动用 QDockWidget 原生能力即可，不自定义拖拽协议。
2. **布局持久化**：预置 2–3 个布局（如“配置主导”“运行监视”“回顾分析”），用 `QMainWindow::saveState/restoreState` 存 QByteArray 到项目 JSON 的 `ui.layouts` 域，多屏时记录 screen 名称与 geometry 而非绝对坐标；恢复时若目标屏不存在，回退主屏并提示一次。
3. **恢复与重置**：启动时恢复上次布局；检测到 DPI 缩放变化或屏数变化时，保留面板可见性/尺寸比例但重置坐标到主屏；提供“一键重置”到默认布局，并区分“重置当前布局”与“清除全部已保存布局”。

**所有权划分（关键，防丢输入/重复 run）**

- **配置内容**：归项目模型（JSON + Manager），编辑器只读写模型；布局切换不得触发保存或校验。
- **运行状态**：归 RunController（QProcess 生命周期 + run 记录 writer）。面板隐藏/浮动/恢复**只影响可见性，不影响进程或状态机**；run 只能由显式“开始运行”触发，布局恢复代码中禁止任何 start 调用。
- **布局**：归 UI 状态，独立于项目语义；切换布局不提交编辑内容（编辑器以 dirty 标记提示，dirty 时切换布局给非模态警告，不阻塞）。恢复失败只降级 UI，不污染项目 JSON。

**主题推荐（最多 3 个，基于给定色板，桌面化改造）**

1. **B_晶格作默认**：白底 + `#0E7C86` 强调色，密集表格/树/数值面板清晰；正文用无衬线 `Noto Sans SC`，`line-height` 从 1.95 压到 **1.45–1.55**，字号 12–13px，行内高亮用 `#BFEFE9` 但降低饱和度一档避免噪声。
2. **K_软件作密集模式**：`#1971C2` 作选中/焦点、`#D0EBFF` 作 hover/选中底，适合长表单与多面板；同样压行距至 1.45。
3. **C_夜读作深色**：保留 `color-scheme:dark`，`#8CC8F0` 用于强调与链接，`#F0B850` 的 hl 透明度调到 ~0.25–0.3 用于“未保存/待验证”警示而非文本高亮；禁止把 `--lh` 用于正文，仅用于帮助文本。

**A_纸墨不推荐**：衬线正文 + 2.05 行距在密集科研软件中会显著降低信息密度，仅可作“文档/报告预览页”局部主题，不作全局主题。

**AI 区交互（留位即定原型）**

自然语言输入 → 生成**可审阅配置差异**（字段级 diff，标明来源、置信度、需确认项）→ 用户确认后**校验**（结构 + 物理量程 + 与 EffectiveConfig 一致性）→ 显式**运行** → **证据回报**（run_result 证据判定结果 + 关键产物链接）。三类状态必须分栏显示且命名不一：**操作成功**（diff 应用/校验通过）、**运行完成**（进程退出码/耗时/日志摘要）、**物理验证**（证据判定通过/失败/证据不足）。AI 区只产出 diff 与建议，**永不直接改配置、永不自动启动 run**；Manager configured 子集可作为 diff 的可写边界参考，超出即标“不可自动应用”。

**设计文件范围（拟新增，不假称已存在）**

- `ui/workspace/layout_manager.py`（拟新增）：预置布局、保存/恢复/重置、多屏与 DPI 降级。
- `ui/workspace/dock_registry.py`（拟新增）：面板 ID、可见性默认值、禁止隐藏的核心面板清单。
- `ui/theme/theme_tokens.py`（拟新增）：三套主题 token（含桌面化行距/字号覆盖），不照搬 CSS 变量名以外的排版值。
- `ui/ai/ai_diff_panel.py`（拟新增占位）：diff 视图 + 三态状态条。
- 修改 `MainWindow` 接 docking 与 layout_manager；项目 JSON writer 增加 `ui.layouts` 可选域（向后兼容，缺失即默认布局）。

**验收条件**

- 面板移动/浮动/隐藏后重启可恢复；目标屏拔除后回主屏且不丢面板可见性；DPI 变更后无重叠/不可见面板。
- 切换布局前后，编辑器 dirty 状态与文本不变；运行中切换/隐藏面板不中断 QProcess，不产生第二条 run 记录。
- 一键重置恢复默认且不清除项目配置；三主题切换不改变布局与运行状态。
- AI 占位区：diff 未确认前配置模型不变；无自动 run；三态状态文案独立可辨。

**应延后**：自定义拖拽/分屏平铺（先吃 QDockWidget 原生能力）；主题编辑器与用户自定义配色；布局云端/多项目共享；AI 区实际模型接入与自动应用配置；面板内嵌浏览器式文档视图。
