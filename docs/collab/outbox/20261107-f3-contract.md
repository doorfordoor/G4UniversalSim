## 3. 真实消费者、文件/对象事实与复用边界

### 3.1 hits 输出链（`hits-heavy` 的消费者）

每次 sensitive-detector hit：

1. `src/Hits/SensitiveDetector.cc` `ProcessHits()` → `ScoringManager::ScoreHit()`（`src/Scoring/ScoringManager.cc`）；
2. `ScoringManager::ScoreHit` → `src/Output/OutputManager.cc` 的 `WriteHit()`（约 468–503 行）；
3. `WriteHit()` → `src/Output/CsvWriter.cc` `WriteEscapedRow()`（约 209–230 行）逐行写 CSV；`WritesRoot()` 时同时 `AnalysisOutput::FillHit()` 写 worker ROOT ntuple；
4. 每事件另经 `WriteEventEdep()`（CSV）与 `FillEvent()`（ROOT）。

### 3.2 mesh 输出链（`mesh-heavy` 的消费者，稀疏且 master/worker 分工）

run 结束时（`src/Actions/RunAction.cc` `EndOfRunAction()`，约 200–245 行）：

1. master 在 Geant4 合并 worker scoring mesh 后才进入 EndOfRunAction；
2. **ROOT**：`role_ != Master`（worker）各自调用 `OutputManager::FillScoringMeshesRoot(runID, run->GetNumberOfEvent())`（`src/Output/OutputManager.cc:254` 起）；worker 只发布自己持有的部分量/部分 cell 行；master 不写 ROOT；
3. **CSV**：`role_ != Worker`（master）调用 `WriteScoringMeshesCsv(runID, run->GetNumberOfEvent())`（`:263` 起），一次写合并后的全部行；
4. 两者都经 `ScoringMeshExport::CollectCells()`（`src/Scoring/ScoringMeshExport.cc:74–124`）：**只遍历 `mesh->GetScoreMap()` 中现存量、再遍历 `score->GetMap()` 现存 key**，不遍历 24³ 全部单元。零贡献 cell 不会被发布。因此行数是稀疏业务行数，**不是固定的 41472 行**；不得为了凑数伪造零行。
5. 行的业务键是 `(mesh, quantity, i0, i1, i2)`，`i0/i1/i2` 必须落在声明的 `bins` 内，`quantity` 必须属于实际三个量（`energyDeposit`/`doseDeposit`/`cellFlux` 对应的输出名）。

### 3.3 计时边界（修正首稿）

- `src/Actions/RunAction.cc:89` `runTimer_.Start()`（master BeginOfRun，run 开始校验后）；
- `RunAction.cc:200–227`：写 event/hits、写 worker 直方图、Flush、**ROOT mesh（worker）/CSV mesh（master）导出**；
- `RunAction.cc:234` `runTimer_.Stop()` 在 mesh CSV 导出**之后**、`WriteScorerStatisticsCsv()`（`:238`，写 `run_wall_time_s`/`fom_per_s`）、ROOT 最终关闭/合并、metadata、最终摘要与进程退出**之前**；
- 结论：`run_wall_time_s` 覆盖 BeginOfRun→mesh CSV 导出结束，**不含**统计 CSV、ROOT 关闭/合并、metadata/摘要与进程退出；`total_elapsed_s`（进程级）才是覆盖启动、初始化、运行、全部收尾的主指标。两者都必须报告，不得互相替代。

## 4. 两个负载的冻结定义与负载资格

两个负载都由 `scripts/measure_output_performance.py` 生成配置，禁止手工另写一套。

### 4.1 `hits-heavy`

- 几何：`config/geometry/hit_smoke_box.ini`（见 §3.4），模板 `simple_box`；
- 物理：`em = option4`，`default_cut = 10 um`；
- 源：`e-`，2 MeV，点源 `(0,0,-9) mm`，方向 `(0,0,1)`；
- 运行：`threads = 2`，`seed = 4242`，`events = 1000`；
- 表达式：`hits = true`、`event_edep = true`、`edep = true`、`auto_create_default_scorers = true`；
- 格式：`csv` 与 `root` 各为独立样本（`both` 只作可选诊断，不入正式矩阵）。

负载资格（每个格式分别判定，任一不满足即停止）：

**csv 样本**
1. run 成功：exit 0；`run_metadata.json` 的 `status=completed`、`output_failure_status=none`、`run_count=1`、`planned_events=completed_events=1000`；
2. 全部 worker 的 `hits_t*.csv` 合并后数据行数 ≥ 1000；
3. 合并 `event_edep_t*.csv` 后恰好 1000 行，eventID 集合恰为 `0..999`（无重复、无越界）；
4. 全部 hits CSV 的注册字节数 ≥ 全部注册字节的 90%；`event_edep` 行数按合并后计，不按 `_t0`。

**root 样本**
1. run 成功条件同上；
2. `*.root` 存在且由 worker 写；用 uproot 读取 hit/event ntuple，合并全部 worker 行后 hit 行数 ≥ 1000、eventID 集合恰为 `0..999`；
3. 不要求 hits/event CSV 存在，不得因此判失败；ROOT 文件注册字节 ≥ 全部注册字节的 90%（`*.root` 通常远大于 summary/metadata）。

### 4.2 `mesh-heavy`

- 几何/物理/源/线程/seed/事件数：同 `hits-heavy`；
- 表达式：`hits = false`、`event_edep = false`、`edep = true`、`auto_create_default_scorers = true`；
- `/score/` 宏（脚本既有写法）：`/score/create/boxMesh benchmarkMesh`；`/score/mesh/boxSize 10 10 10 mm`；`/score/mesh/nBin 24 24 24`；`/score/quantity/energyDeposit edep MeV`；`/score/quantity/doseDeposit dose Gy`；`/score/quantity/cellFlux flux`；`/score/close`；
- 格式：`csv` 与 `root` 各为独立样本。

负载资格（任一不满足即停止）：

**共同**
1. run 成功条件同 §4.1；
2. 网格声明与 summary 一致：`scoring_mesh_count=1`、`bins=24,24,24`、quantity 集合为实际三个量；
3. 不要求 hits/event CSV 存在；若存在任一 hits/event CSV 行 ≥1，则该样本不合格（网格负载不应走 hit 发布）。

**csv 样本**
4. `scoring_mesh.csv` 存在；数据行数 = 实际非空 `(quantity, i0, i1, i2)` 业务键数，**不要求 41472**；行数可为 1..41472 之间（允许少量非零 cell），每个键唯一；所有 `i0/i1/i2` 在 `0..23` 内；每个 quantity 的行数 ≤ 13824；

**root 样本**
6. 每 worker 一个 `*.root`；读取 mesh 对象（或 summary 描述的 mesh ntuple）后按业务键合并；合并后键数 = 非空键数，键唯一，索引在范围内；每 worker 行是部分量/部分 cell；master 不写 mesh ROOT；
7. 不要求 `scoring_mesh.csv` 存在。

**PID/内存观测（F3-2 允许补足的最小接线，本任务不实现）**

计时样本不采样内存；内存阶段单独执行，每个 (binary, 负载, 格式) 3 次，每次：

1. 记录本次启动的 Python 进程 PID 与命令；用 `Get-CimInstance Win32_Process` 沿 `ParentProcessId` 链找到 **本次树内**的 `G4UniversalSim.exe`（用 exe 路径 + SHA-256 校验，不能只按进程名），得到唯一 PID；
2. 对该 PID 每 100 ms 读取 `WorkingSet64`（并在结束时读 `PeakWorkingSet64`），每次调用独立清零；同名其它进程一律不纳入；
3. 记录：`samples`、实际采样间隔（均值/最小/最大）、观察到的子进程 PID/启动时间/路径/SHA、终止时刻；若采样期间未观察到合格子进程或 `samples<5` → 该样本无效；
4. 不得用“同名进程最大值”或“多个对象求和”作单次峰值；内存阶段与计时阶段不得并发；
5. 接线实现放在 `out/collab/20261107-f3-preregister` 之外的证据目录（例如 `out/collab/20261107-f3-baseline/<utc-uuid>/observe_memory.ps1`），不修改 `scripts/measure_output_performance.py`；若确需修改该脚本，必须先提交 diff+SHA 给主审并在冻结前获准；测量前由主审审阅最终观测实现与 SHA。

## 8. 科学等价判据（可执行、防错误抵消、不得以性能换科学差异）

### 8.1 不变量集合与比较对象

对每个 (负载, 格式) 的每个样本，比较：

1. **事件契约**：`status=completed`、`run_count=1`、`planned_events=completed_events=1000`；CSV：合并全部 worker `event_edep_t*.csv` 后 eventID 集合 = `0..999`；ROOT：从 ntuple 读取事件集合 = `0..999`；
2. **hits（hits 负载，CSV）**：合并全部 worker `hits_t*.csv` 后，按行构造业务元组
   `(eventID, trackID, parentID, particleName, volumeName, processName, edep, ndep, stepLength, x0,y0,z0, x1,y1,z1, px,py,pz, kineticEnergy, weight, LETcalc, LETstep)`
   （只取文件头实际存在的列；`runID` 不参与，行顺序不参与；浮点列按 12 位有效数字字符串归一）；
   比较为**多重集相等**：每个元组的重复次数必须一致；另比较每 event 行数、每 `(particle,volume,process)` 行数**精确相等**。逐列总和只能作诊断，**不能**作为通过依据（两个不同行互换坐标/方向时逐列总和会漏检）。
3. **hits（hits 负载，ROOT）**：合并全部 worker 的 hit ntuple 行，按同一业务元组（以 ROOT 存在的分支集合为准）做多重集比较；不得对 `eventID/trackID/parentID` 求和；`threadID` 与行顺序剔除后比较。
4. **event_edep**：CSV 合并后按 eventID 的原始/加权 edep 值比较（12 位有效数字）；ROOT 读取 event ntuple 后按 eventID 比较；不累加 eventID。
5. **mesh**：CSV（master，稀疏）与 ROOT（worker，稀疏、部分量）各自按 `(mesh, quantity, i0, i1, i2)` 合并为映射：跨 worker 的 `sum`、`sum_sq`、`entries` 相加；`n_events` 不逐 cell 累加，也不在 worker 间相加——按 run 级 N 一次（取 `run_0_completed_events`）；缺键按零（不伪造行）；比较两映射的键集合与三项数值；`sum_sq` 与 `entries` 也要比较，不能只看 `sum`。
6. **scorer_statistics**：`sum`、`sum_sq`、`n_events`、`entries`、`value`、`mean_per_event`、`std_error`、`rel_error`（不比较 `run_wall_time_s`/`fom_per_s`）；master 文件，按 run 取。
7. **直方图（CSV 样本）**：合并全部 worker 的 `hist_*_t*.csv`：同 bin 的计数/求和相加、entries 相加后比较；不比较 per-thread 文件形状以外的元数据。
8. **ROOT 直方图（root 样本）**：合并全部 worker 直方图后比较 bin 内容（不比较内部计数器指针/名字以外结构）；`uproot` 读取、按 bin 求和。
9. **summary 科学字段**：`run_summary.txt` 与 `run_metadata.json` 中除 §8.3 可变字段外全部比较（含几何/物理/源/scoring 事实、事件数、n_events、`scoring_mesh_*` 声明、单位等）。
10. **跨格式互校（可选，仅 `both`）**：同一 run 的 CSV 与 ROOT 用 `scripts/compare_root_csv.py`（rel_tol 1e-9）；纯 csv/root 样本不得调用该工具，也不要求其存在。

### 8.2 判据（结果前写定）

- `decimal12_half_unit(x)` 的定义：把被比较的打印值当作文本处理——若文本含小数为 d 位、十进制指数 e（科学计数法价 `m×10^e`），半单位 `h = 0.5×10^(e-d)`；若文本为不带小数/指数的整数，`h = 0.5`；若文本为 `0`/`0.0`/`-0`，按其打印小数位 d 取 `h = 0.5×10^(-d)`；不得先把值格式化成 12 位再定义半单位。
- 基线包络：对每个浮点字段 `f`，`E(f) = max_r |x_r − median(x)|`（5 个基线轮）；
- F3-3 判定：浮点字段要求
  `|median_new − median_base| ≤ max(3·E(f), decimal12_half_unit(median_base_text), 1e-9·|median_base|)`，
  且相对硬上限 `|Δ|/|median_base| ≤ 1e-6`（仅当 `|median_base| > 0`）；
- `base=0` 分支：相对项不适用；要求 `|Δ| ≤ max(3·E_abs, decimal12_half_unit("0"))` 且 `E_abs` 为绝对值包络；若 baseline 全部轮为 0 而候选出现非零，必须同时满足上述绝对界，并在报告中列出该字段；不得用除零或放宽绝对容差掩盖量级错误；
- 近零但非零：若 `|median_base| < 1e-12`，跳过相对硬上限但必须满足同一绝对/包络界，并逐条列出；不得对近零字段使用比其它字段更宽松的固定绝对阈值（如 1e-6 绝对）；
- 整数/计数类字段（行数、entries、n_events、eventID 集合大小、每 cell 条目数等）必须**完全相等**；基线 5 轮中若出现不一致 → 标为“非确定”，立即停止 F3-3 并报告（不允许靠放宽判据掩盖）；
- 任一 (负载, 格式) 的科学等价 fail → F3-3 不通过，不再比较资源收益；
- 多字段/多重集比较由 F3-2 新增的只读分析脚本（证据目录内，先经主审看过）实现；分析脚本必须按本节规则输出逐字段 pass/fail 与聚合结论，不得使用“逐列总和相等”替代多重集。

### 8.3 可变字段（允许不同，不作为放宽结果依据）

`total_elapsed_s`、`run_wall_time_s`、`fom_per_s`、`python_verify_seconds`；`summary_generated_at`、`execution_id`、输出/输入路径字段（`output_dir*`、`main_config`、`macro_file*`、`effective_*_origin_*` 的文件相关部分）；文件原始 SHA-256（CSV worker 划分/ROOT 合并顺序/元数据导致，必须记录供复核但不是相等判据）；worker 文件数量/命名中的线程后缀、`threadID` 列、ROOT 行顺序与元数据块；日志与 summary 中的时间/路径文本。

### 8.4 禁止事项

- 不得关闭输出开关、改 seed/线程/事件数/cut/物理列表/几何、改统计定义（sum/sum_sq/n_events/estimator）、删行/稀释事件来换性能；

- 不得用“逐列总和”或“只比能量”替代 §8.1 的多重集/逐桶比较；

- 不得对 eventID/trackID/parentID 求和或把 mesh 每 cell 的 n_events 相加。

## 9. 资源判据（单一目标 + 回归守卫）

### 9.1 基线噪声门（F3-2 结束判定）

对每个 (负载, 格式)：`MAD = median(|x − median(x)|) / median(x)`，要求 `MAD ≤ 5%`。任一超限 → F3-2 `inconclusive`，停止，不进入 F3-3；不得加轮/换机器追通过。

### 9.2 F3-3 通过条件（目标与守卫分离）

**目标（§6.3 选定的唯一 (负载, 格式)，计时按 `csv` 或 `root`）**
1. `median(total_elapsed_s, candidate) ≤ 0.95 × median(baseline)`（≥5% 端到端改善）；
2. 5 个配对轮中至少 4 个候选更快（配对按 `(repeat)` 同输入）；
3. 目标格式的峰值 RSS：`median(candidate) ≤ 1.10 × median(baseline)`；
4. 输出契约：每样本 `registered_files` 与 baseline 相同；`registered_bytes` 相对变化 ≤ 0.5%；
5. 科学等价（§8）在目标上 pass。

**回归守卫（其余 3 个 (负载, 格式)）**
1. `median(total_elapsed_s, candidate) ≤ 1.05 × median(baseline)`（不超过 5% 时间回归）；
2. 峰值 RSS ≤ 1.10×；
3. `registered_files` 相同、`registered_bytes` ≤ 0.5%；
4. 科学等价 pass。

**辅助量**：`run_wall_time_s` 两个二进制都报告，但不设独立通过门槛（解释用；若目标 run_wall 明显劣化，需在报告中说明原因）。

### 9.3 判定

- 目标与全部 3 个守卫都满足 → `pass`；
- 科学等价 fail、身份/环境/输入不一致、目标未达 5% 或配对不足、守卫时间回归 >5% → `fail`（不得用其它收益补偿）；
- 基线噪声超限、有效样本不足、环境漂移 → `inconclusive`；
- 不设置本合同之外的“最小有意义差异”。
