## 2. 失败事实

- Job：`I2 native runtime and SDK installation` / `ubuntu-24.04 / Geant4 11.4.3 installation`，run `126681328482`。
- `packaging/ci_delivery.py` 的 `source-and-data` 预检失败：
  - `need 6810606082 additional bytes, available 4751527936`
  - 缺口 = `6810606082 - 4751527936 = 2059078146` 字节（约 1.92 GiB）。
- 预检公式（`packaging/ci_delivery.py:307`）：`data_size * 3 + 256 MiB`，反推数据量
  `data_size = (6810606082 - 268435456) / 3 = 2180723542` 字节（约 2.03 GiB）。
- 证据来源：`docs/collab/CURRENT-SUPERVISION.md:22` 与 `out/collab/e4-independent/install-error-excerpt.txt`。原失败日志保留，不覆盖。

## 3. 方案

在托管 Linux 任务的安装验收之前新增一步：

```yaml
- name: Free unused hosted Android SDK before installation acceptance
  if: runner.os == 'Linux' && runner.environment == 'github-hosted'
```

行为：

1. 固定目录 `/usr/local/lib/android/sdk`（GitHub 托管 Ubuntu 镜像预装的 Android SDK；本项目构建/验收不使用）。
2. `[ -d "${sdk_root}" ] && [ ! -L "${sdk_root}" ]` 守卫后 `sudo rm -rf "${sdk_root}"`；不枚举、不删除其它工具，不做 `apt purge`。
3. `removed=true` 表示确实删除了该目录；`removed=false` 表示镜像布局变化后目录不存在（安全 no-op），用于区分“未删除”与“删除后释放为 0”。
4. `df -B1 --output=avail "$RUNNER_TEMP"` 在删除前后各测一次：`$RUNNER_TEMP` 是安装工作区所在的文件系统（而不是无关的根挂载假设）。
5. 持久记录写入 `$GITHUB_STEP_SUMMARY`（job UI 可读，随 run 保留），字段：
   - `filesystem_probe_path: <实际 $RUNNER_TEMP 路径> (installation workspace)`
   - `before_available_bytes` / `after_available_bytes` / `freed_bytes`
   - `removed_fixed_directory` / `removed`
6. 新增步骤位于 Linux 依赖安装之后、`Install isolated packaging dependencies` 之前，即 Geant4 SDK 安装、后端构建、Linux 安装验收之前；缓存/路径清理不作为步骤前置条件。

未采用的做法：不删除 pip 缓存或用户缓存（避免破坏后续 pip 安装）；不删除整个 `/usr/local/lib/android` 之外的目录；不覆盖/降低 `packaging/ci_delivery.py` 的门槛；不需要 JSON 收据文件（step summary 即持久记录，符合“如增加 JSON 收据须纳入原 Linux artifact 或直接用 step summary”的要求）。

## 4. 为什么能解决阻塞

- 缺口约 2.06 GB，而托管 Ubuntu 镜像预装 Android SDK 占用数 GB（实际释放量以运行期 step summary 的 `freed_bytes` 为准）。
- 删除仅针对固定目录且只在 GitHub 托管 Linux 上执行；自托管 runner 与 Windows 任务不进入该步骤。
- 释放后的 `before/after/freed` 字节由本步骤记录，后续 `source-and-data` 预检仍按原公式和原门槛执行：若释放不足，job 仍以原始错误失败并留下真实数字，不会伪造通过。

## 5. 保留不变的项

- `packaging/ci_delivery.py` 未修改（`source-and-data`、`outer-release`、`explicit-outer-zip`、`runtime-sdk-installation` 门槛与 256 MiB 边界保持原样）。
- Geant4 安装前缀/数据集、编译器与系统依赖、后端与前端构建、源码、产物、安装/运行收据、artifact 上传逻辑（`full-installation-${{ runner.os }}`，`retention-days: 7`）均未改动。

## 8. 未验证与限制

- 本机没有 Ubuntu 云 runner，无法实测删除释放量与完整 job；本回执只交付可审查候选，云运行由主审触发。
- `removed=true` 的释放量取决于 GitHub 镜像当前预装的 Android SDK 大小；本回执不承诺固定字节数。
- 若托管镜像后续移除该预装目录，本步骤为安全 no-op（`removed=false`），不会制造假成功。
- 磁盘门槛未调整；若实际释放量不足，仍需另立最小方案（本任务不扩范围）。
