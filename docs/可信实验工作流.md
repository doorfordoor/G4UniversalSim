## 无窗口命令入口

从安装了 GUI Python 包的环境运行以下命令。源码检出需要把仓库的 `gui` 目录加入 `PYTHONPATH`。依赖统一安装自 `gui/requirements.txt`，CLI 使用 `QCoreApplication`，不要求创建窗口。

```text
python -m g4usim_gui.experiment_cli --project project.json inspect
python -m g4usim_gui.experiment_cli --project project.json validate --level fields
python -m g4usim_gui.experiment_cli --project project.json --executable BACKEND validate --level initialization
python -m g4usim_gui.experiment_cli --project project.json apply --snapshot candidate.json --save-project revised.json
python -m g4usim_gui.experiment_cli --project revised.json --runs-root runs generate
python -m g4usim_gui.experiment_cli --project revised.json --executable BACKEND --runs-root runs --records records run
python -m g4usim_gui.experiment_cli --project revised.json --records records evaluate --run-id RUN_ID --comparisons comparisons.json
python -m g4usim_gui.experiment_cli --project revised.json --executable BACKEND evaluate --run-first --comparisons comparisons.json
python -m g4usim_gui.experiment_cli --project revised.json export --destination portable-bundle
python -m g4usim_gui.experiment_cli --bundle portable-bundle --executable BACKEND run
```

全局参数放在动作名之前。`--project` 和 `--bundle` 必须二选一。`--executable`、`--runs-root` 覆盖本次选定的运行环境；`--records PATH` 是服务记录目录，不是单个 JSON 文件。默认记录目录为 runs root 下的 `experiment-records`；项目未指定 runs root 时，使用当前目录下的 `runs`。每个服务动作的记录由统一服务按独立身份持久保存。

`--timeout SECONDS` 默认 300 秒。收到中断信号或超过时限后，CLI 在 Qt 事件循环中请求服务取消，默认 5 秒后升级为强制取消和停止其持有的进程，再有界等待。`--stop-timeout SECONDS` 可调整单阶段等待上限。取消、超时以及清理未取得服务终态均返回失败；迟到的成功记录不能覆盖本次超时。

后台工作返回时，若本次操作已取消，公开记录使用 `status=cancelled`、`reason=experiment.cancelled`；未取消但输入身份已变化时才使用 `status=stale`、`reason=experiment.inputs_changed`。这是原因码纠正，记录结构和取消优先级不变；既有历史记录不回写。取消请求本身不证明后端在事件中途终止，实际退出和完成事件仍分别按观测证据记录。

## 操作与证据

| 操作 | 含义与边界 |
| --- | --- |
| `inspect` | 后端 Configure 与 macro preflight；不代表初始化或事件完成。 |
| `validate --level fields` | 字段及依赖校验；不代表后端初始化。 |
| `validate --level initialization` | 后端初始化及几何检查，由服务执行并判定。 |
| `apply` | 通过统一服务校验并经 F5 事务接受完整候选快照。 |
| `generate` | 通过已有 writer 生成运行包；不代表模拟成功。 |
| `run` | 通过已有 runner 执行，成功须由服务核对 run result 与来源证据。 |
| `evaluate` | 对明确 run 与显式参考、单位、容差及统计方法进行比较。 |
| `export` | 原子发布资源闭包、manifest、历史记录与重放入口；不包含后端二进制。 |

外部输入的独立 `inspect` 直接读取原文件与原工作目录，保留后端原始来源行号和诊断；它只记录声明的主配置/macro字节，递归输入闭包与环境未观测。不能据此取得初始化、事件完成、物理比较或可移植导出资格。真正运行及初始化前的内部 Inspect 使用本次隔离输入树。

导出的历史记录保留实际构建信息、随机设置、完成事件及输入观测边界；`initial_engine_seed=unknown` 等未知值保持未知。机器私有来源路径按明确去敏规则省略或以摘要标识，不用配置中的 seed 替代未观测的引擎事实。历史记录的完整保存也不会令其自动成为当前验证。

`apply --snapshot` 接受 `g4usim_edit_snapshot_v1` 完整快照，包含 `schema`、`version`、`project`、`state`，与 [F5 快照](配置撤销与恢复.md) 编解码契约一致。重复字段、未知字段、不完整字段、非法类型及非有限数值由现有严格解析器拒绝。CLI 不提供任意属性路径、脚本或补丁执行入口；不直接修改 session 来绕过核心 `apply`。只有服务接受后才把当前快照保存到明确指定的 `--save-project`。保存失败单独返回非零；不会据此宣称项目文件已经发布。

比较输入是 JSON 数组，例如：

```json
[
  {
    "artifact": "event_edep_t0.csv",
    "column": "raw_edep_MeV",
    "quantity": "energy_deposition",
    "unit": "MeV",
    "reference": 0.5,
    "reference_unit": "MeV",
    "absolute_tolerance": 0.01,
    "relative_tolerance": 0.05,
    "source": "用户选定并核实的参考来源",
    "statistical_method": "mean_standard_error",
    "sigma_multiplier": 3.0,
    "weighted": false,
    "normalization": "per_event",
    "run": 0,
    "object": "sensitive_total",
    "reference_file": "reference.json"
  }
]
```

数值仅演示格式，不是本项目物理基准。当前服务只开放完整逐事件敏感体总沉积能的 `mean_standard_error`，单位 MeV、`per_event` 归一化；加权时使用 `weighted_edep_MeV` 列。服务从登记 CSV 计算均值与标准误，不接受外部传入的通过结论；单事件无法给出该统计误差。其他估计器当前拒绝。

`reference_file` 指向 `g4usim_physical_reference_v1` JSON，须包含与比较一致的 `value`、`quantity`、`unit`、`weighted`、`normalization`、`object`、`run`、`source`，还须明确 `conditions` 与 `source_kind`（`user_supplied` 或 `analytic`）。服务绑定实际参考文件 SHA；可选 `reference_sha256` 用于额外约束，不能用文件名替代出处或独立基准。

历史记录用于追溯。重新启动 CLI、加载项目或导入 bundle 不会把旧验证自动升级为本机当前可信。显式 `evaluate --run-id` 可选择先前会话的运行，但服务必须重新核对当前配置与执行身份、实际输出目录、F1 文件登记和摘要、参考文件及比较规则；旧记录不能绕过这些检查。通过后新增本次比较记录，旧运行记录仍保持历史或陈旧标记，不会自动复活为当前执行通过。使用 `evaluate --run-first` 可明确授权先完成本次新运行，再在同一服务会话中比较；仍只输出一份最终动作 JSON，并持久保留运行与比较两份记录。撤销也不能自动恢复旧信任。

## JSON 输出与退出状态

GUI 顶栏、结果及进度关联实际启动的记录身份。后台核验未结束时显示“核验中”；配置修改、撤销、恢复或资源变化后，原结果显示为“上次运行（配置已变更）”。旧日志、退出码和完成计数仍可追溯，但不再代表当前配置。身份无法关联时明确显示当前输入未验证。取消或失败不会重新启用旧成功资格；后端结束与服务记录完成是不同的时点。

每次动作只向 stdout 写入一行 UTF-8 JSON：

```json
{"schema":"g4usim_experiment_cli_v1","command":"run","ok":false,"record":null,"error":{"code":"示例错误码","message":"诊断原文"}}
```

服务记录保留在 `record`；解析或启动失败时可为 null。`ValidationReport` 经自身 `to_dict()` 转换，未知对象拒绝序列化。诊断与依赖输出重定向到 stderr，后端日志仍由 runner 管理。`--help` 使用标准命令行帮助文本。

| 退出码 | 含义 |
| --- | --- |
| 0 | 收到服务终态 `passed`，所需保存动作亦成功。 |
| 1 | 服务报告 failed、stale 或 unobserved。 |
| 2 | 参数、文件、输入或依赖错误。 |
| 3 | 未预期错误或接口不一致。 |
| 124 | 本次动作超时。 |
| 130 | 本次动作取消或收到中断。 |

CLI 不调用 shell，也不另建模拟进程控制器。后端退出 0、没有摘要、只有旧摘要、零事件或部分事件不能被 CLI 提升为成功；这些事实交由同一服务与 runner 评估。

## 配置包搬移与重放

加载先调用资源模块的 `load_bundle()`，验证 manifest 成员、SHA256 与路径闭包；导入历史保留陈旧标记。重放使用已核验的 `replay_inputs`，以当前包目录作为工作目录，在统一服务的 external 输入入口运行，避免重新生成编辑配置后丢失相对资源。运行输出和新记录写入本机 runs root，不把包内历史当作新执行证据。搬移后仍须重新选择后端：

GUI 加载同时重定位项目模型及与其指向相同资源的编辑草稿，之后可正常收集、修改、撤销及另存到其他目录。空白或非法草稿不会被“修复”为有效配置；仍须由字段校验明确拒绝。加载包不自动执行模拟，也不会恢复旧验证资格。

```text
python -m g4usim_gui.experiment_cli --bundle PATH --executable EXE run
```

未知资源、篡改、缺失、链接或逃逸路径遵守资源模块的拒绝规则；分发权限未知不等于获得授权。`export --resource-policy policy.json` 仅把显式策略交给核心服务。

本地 generated 模式中，用户明确选择 geometry source-copy，且唯一障碍为未知语法时，核心提供保留旧行为的兼容运行路径：仍由已有 writer 生成独立输入，由 F1 严格核对计划输入和实际读取证据。该路径不宣称递归闭包完整或可分发。缺失资源、链接、逃逸或其他错误不能借此 fallback；export 仍严格拒绝未知语法。source-copy 同意本身不等于编辑器或物理校验通过。

## 专项验证

### Windows 深目录启动

后端新增可选 `--working-directory <绝对目录>`，在 Manager 构造、数据发现和任何配置读取之前切换一次。缺值、空值、重复、相对路径、缺失目录和普通文件均立即失败，不在启动目录生成另一份摘要。能力协议用 `launch.working_directory = true` 声明支持。原有短目录调用不添加参数，保持旧后端兼容；旧后端无法接受深目录启动参数时明确报不支持，不在错误目录重试。

Windows 的环境探测、Inspect 和既有 runner 共用纯启动计划：按 UTF-16 单元识别过长工作目录，从同一路径的短祖先创建子进程，再由后端恢复真实实验目录。启动目录和真实目录分别记录，所有资源解析、F4 位置及 F1 输入身份继续使用真实目录。GUI/CLI 宿主不调用全局 chdir，不复制第二份输入、不创建短路径链接或盘符映射。

MSVC 后端嵌入 `longPathAware` 和 UTF-8 进程代码页 manifest；配置原文属于 CMake 源码指纹。当前支持依赖现代 Windows（UTF-8 manifest 自 Windows 10 1903 起）及系统长路径策略已启用，程序不更改该策略。切入深目录后任意第三方子进程仍可能受系统限制，本修复不扩大外部 macro IO 或资源闭包支持。[微软路径限制](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)、[进程代码页](https://learn.microsoft.com/en-us/windows/apps/design/globalizing/use-utf8-code-page)。

专项 `scripts/test_backend_working_directory.py` 保留真实深目录输入、启动祖先的同名错误输入、无效参数、真实初始化/事件与 F1 证据，并对相对数据目录做正反检查；其中空数据目录仅检验发现语义，真实模拟使用实际安装的数据集。专项不替代整阶段冻结矩阵与实窗验收。

```text
python scripts/test_k1_cli.py
python scripts/test_k1_cli.py --backend EXE
python scripts/test_k1_cli.py --backend
python scripts/test_k1_cli.py --backend EXE --evidence-root evidence
```

真实后端专项按“显式 `--evidence-root` → `G4USIM_TEST_EVIDENCE_DIR` → `out/verification/k1-cli`”选择证据根，每轮新建唯一目录，成功和失败都保留。目录包含原始输入、每次 CLI 的 stdout／stderr／JSON／退出收据、服务记录、真实摘要与 runner 日志，不再随临时目录删除。未运行完成、超时或路径不存在仍保留失败收据，不作为通过。

static 专项需要 `gui/requirements.txt` 中的 PySide6/QtCore，由主负责人在统一登记中声明依赖；本专项不改统一测试登记。默认测试命令路由、严格输入、JSON 单行输出及真实 Qt 事件循环中的合成服务完成/取消/超时，另用真实 runner 管理 Python 测试进程，检查退出零但无摘要及有界停止，并核对搬移包输入与陈旧历史；不声称运行 Geant4。`--backend` 不带值时读取 `G4USIM_EXE`；显式请求后缺依赖或路径错误必须失败，不以 skip 冒充 pass。可选后端专项覆盖真实 Inspect、两层 validate、三事件运行、搬移包重放、篡改拒绝和零事件拒绝。实际结果与尚未验证边界见任务交付报告；不把专项等同整项 K1 验收或物理比较验证。

## 命令预览与进行中状态

生成或运行成功且记录未陈旧时，运行页更新命令预览。有有效启动收据时使用实际启动参数；否则只保留记录中的计划命令，不能据此确认启动。逻辑工作目录按收据或计划输入树显示，Windows深目录启动的进程创建目录不同时单独列出，缺失目录事实显示未知。编辑工作区不会因为显示运行记录而改变。服务对某一动作或层报告pending时，该项显示“进行中”；重新核验时原通过层可暂时进入这一状态，其他层保留各自事实。进行中不代表已经通过。
