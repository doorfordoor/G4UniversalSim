# 配置兼容与迁移（E6）

E6 补齐已有配置的字段定义和版本兼容。格式检查通过只说明文件可按相应规则解释；之后仍须检查输入、构建几何并运行仿真，才有对应的后端证据。当前实施和验收状态以 [ROADMAP](ROADMAP.md) 为准。

## 四种版本分别表示什么

| 文件/协议 | 当前版本 | 缺版本或旧版本 | 未来或非法版本 |
| --- | --- | --- | --- |
| 主 INI | `[general] schema_version = 1` | 缺失按原来的版本 1 行为处理 | 只接受精确的 `1`，其余在主配置发布前拒绝并指出文件及行号 |
| 几何 INI | `[global] version = 2` | 缺失/1 保持原兼容警告；2 使用严格诊断 | 拒绝，不自动降级 |
| GUI 项目 JSON | `G4UniversalSimProject`，`version: 6` | 缺失按 1；1–6 经已知兼容规则读取为当前模型 | 拒绝，不过滤未知字段来冒充成功 |
| 有效配置快照 | `g4usim_effective_config_v1` | 按原快照协议加载 | 与上述三个输入版本无关，见 [EffectiveConfig](EffectiveConfig.md) |

GUI 新生成的主 INI 明确写入 `[general] schema_version = 1`；旧文件缺标记时仍兼容读取，不自动改写。版本标记不改变默认物理、配置优先级或重复声明规则。重复 section/key 仍后值生效并告警，版本也按胜出的声明判断；例如先写 2 后写 1 会按 1 读取并保留重复诊断。独立几何文件使用自己的加载边界，未知 `[general]` 仍按几何版本规则处理，不能误触发主 INI 校验。

有效配置新增 `/configuration/main_ini_schema_version`，记录类型化版本和真实来源。缺版本不伪造显式请求；此字段是输入格式检查结果，不是 Geant4 内核应用收据。既有 JSON 协议不改名。

## 使用迁移副本

GUI 的文件菜单提供“配置迁移副本…”。选择项目、主 INI 或几何文件后，先查看输入/输出版本、改动、诊断和输出文本，再选择新文件。取消或失败不切换当前项目；项目副本写成后，只有显式点击“打开新项目副本”才加载它。

- **主 INI**：缺版本时补上标记；已有合法标记保持原字节。保留注释、顺序、未知字段、数值和重复声明。副本必须与源在同一目录，避免能谱、场图、NIEL 等相对主 INI 路径改变；进程工作目录规则也保持原状。跨目录可移植实验包属于 K1。
- **几何**：将缺省/1 规范为 2，保留源级内容；未知字段、重复声明、忽略字段、未来版本和歧义拒绝。legacy metadata 只有在用户提供明确映射时才改成 `metadata.<名称>`；不把疑似拼写错误自动解释为元数据。STL/GDML/副本表相对路径转换为原资源的绝对路径，迁移副本不会偷偷指向另一个同名文件；这不打包外部资源。
- **项目**：按既有扁平字段及缺失编辑器的兼容规则输出 v6，明确归一已知几何别名及旧 preview 数据；未知嵌套字段、冲突别名、重复 JSON key、非有限数值拒绝。显式编辑器中的空字段或非法值不能触发整个编辑器重置；原设置保留供修正，或在无法表示时明确拒绝。源位置只提供 `position_mode` 或 `position_type` 时派生另一个；同时提供但不一致时报告冲突。内存模型版本与序列化版本一致，迁移计划另记输入版本。

打开项目时，GUI 在更新当前项目和页面前检查实际整数控件的表示范围；越界值明确拒绝，不限幅后冒充原配置。此范围仅约束当前 GUI，不改变后端 INI/CLI 的支持范围。空选项显示为空，未知选项保留供审查；无效物理量仍由原有校验提示，不靠迁移换成默认实验。上述预检保证已覆盖的解析、兼容和参数投影错误不污染当前状态，不意味着任意系统或 Qt 异常都能回滚。

兼容差异：旧 GUI 对 `runSettings.threads = 0` 会隐式回退为项目线程数；现在明确拒绝，打开前须把该字段设为所需的正线程数。其他超出实际控件范围的整数也不再限幅。因此不能将本次 GUI 导入称为接受集合完全不变；原始文件不会被自动修写，主 INI 与命令行行为不受此限制影响。

新副本发布前重新核对源 SHA-256；已有目标、同文件、硬链接/符号链接别名均不能被覆盖。同目录临时文件写完、flush/fsync 后以独占硬链接发布；不支持该操作的文件系统会明确失败。发布完成后的临时链接清理失败显示警告，不把已写好的副本说成失败，也不删除目标。普通项目保存仍保留原来的原子替换语义。

## 从运行包恢复和复制

历史页的快照入口与普通项目打开分开校验。对于标准运行包，它读取同包内当前材料、几何文件，以及快照记录的运行和源/物理/计分编辑参数；旧 selected/sourcePath 和旧 dirty 编辑缓存不能覆盖这些输入。材料快照只记组分数量，不能据此恢复配方；配方来自包内实际材料 INI。未知或损坏的包信息、缺资源、路径歧义在发布到页面前拒绝，普通项目打开仍拒绝运行包专用字段。

恢复后进入待重新检查、生成的状态，清除当前宏和输出路径。未输出的编辑草稿、手工修改后的 main/macro 和运行期最终配置不在恢复范围内；历史成功状态不会成为新运行证据。旧格式没有材料/几何内容哈希，当前读取的文件也不能据此认定与历史运行时完全相同。完全不含包信息的旧项目快照仍按普通项目兼容规则读取，并明确提示原资源尚未验证。

“复制运行包”只支持当前标准 GUI 生成的完整输入集合。复制时仅重定位确认过的材料、几何与输出三个主 INI 路径及对应包信息，源包不改，新 logs/output 为空。额外文件、外部资源依赖、歧义声明或非标准宏会明确拒绝；任意资源闭包、跨机器可移植导出属于 K1。旧报告的复制不代表新模拟已经执行，仍需 Inspect 和实际运行。

复制后启动使用副本当前主 INI 中的线程数、随机种子和运行名称，避免被另一个当前项目的值覆盖。种子缺省时不追加旧种子，显式 0 则保留。用户已选择的后端可执行文件保持不变；如副本已写成但 GUI 无法载入，提示会给出副本位置并说明尚未运行，原当前项目保持原状。

## 字段覆盖和诊断

统一 schema 增加全局/局部场、偏置开关、legacy XS 偏置、逐 particle/process XS 偏置及主版本标记，共 394 个字段定义。生成文件只能由 `scripts/generate_config_schema.py` 更新。场与偏置仍由各自解析器执行上下文/运行校验，见 [schema 说明](配置schema说明.md)。

迁移不会改变局部场最近祖先规则、偏置 dormant 配置短路、process 大小写、单位/精度、模块三态或 worker 生命周期。标量验证与后端保持 ASCII 空白规则，不用 Unicode 空白把非法版本、数值或布尔值变成合法值。

后端几何诊断的排序和去重使用同一完整身份。GUI 以来源、位置、错误类型和级别识别同一问题，显示文案变化不会制造新问题；不同来源问题也不能因为文字相同而被合并。重复读取、校验和项目重载不得累加同一源诊断。

## 验证边界

几何迁移预览检查字段识别、重复声明、明确映射和路径，不替代完整几何、材料和编译能力检查；请继续执行后端的 Inspect inputs 与实际运行。项目迁移也不清除原有 source errors 或 round-trip blockers。simple/layered/hierarchical 的现有编辑子集继续往返；A5/场/偏置等未开放的编辑能力保持原边界，J2 单独推进。

正式回归包括 `test_main_config_version.py`、`test_main_ini_migration.py`、`test_field_biasing_schema.py`、`test_config_migration.py`、`test_config_migration_backend.py`、`test_geometry_diagnostic_identity.py` 与 `smoke_config_migration_ui.py`。阶段全量、平台及可见窗口证据在最终验收报告中登记，不能从本文或单项通过推断整阶段完成。
