# G4UniversalSim 几何模式与界面命名规范

版本日期：2026-09-21。

本文规定几何构建能力在后端接口、GUI 产品入口和用户文档中的分层方式。目标是减少重复模式和技术名词暴露，同时保持旧配置、macro 和项目文件兼容。

本文只定义产品分类和迁移规则，不改变当前后端支持事实。实际支持等级仍以代码、测试和 `docs/功能支持矩阵.md` 为准。

## 1. 核心原则

### 1.1 产品模式与后端模板分离

- 后端模板名是稳定机器接口，例如 `layered_device`、`hierarchical`。
- GUI 显示名是可翻译的产品文案，不得直接把机器 token 当作最终用户标签。
- 配置、macro、项目 JSON、run package 和摘要保存稳定机器值，不保存翻译后的显示文本。
- 切换语言只改变显示名，不改变当前选择、生成配置或项目文件。

### 1.2 主入口少而清晰

GUI 顶层只保留能代表不同工作流、且用户容易区分的模式。特定领域快捷构造应作为“预设”或“向导”，而不是永久增加顶层模板类型。

### 1.3 后端兼容不等于 GUI 主推

后端已有模板不能仅因“可运行”就继续占据 GUI 主选择器。可以保留解析和运行兼容，同时在 GUI 中降级为：

- 内置预设；
- 高级/兼容入口；
- 只读导入；
- 规划中且禁用的入口。

### 1.4 不静默迁移

- 旧配置和旧项目必须继续按原 token 读取。
- GUI 不得在打开、保存或生成 package 时自动把一种模板改写为另一种。
- 若提供“转换为通用层级几何”，必须显示转换预览、可能损失、目标文件，并由用户显式确认。
- 原文件不得被覆盖；转换结果写入新文件或新 run package。

## 2. 面向用户的三类几何工作流

### 2.1 快速分层模型

| 属性 | 规定 |
| --- | --- |
| GUI 中文名 | `快速分层模型` |
| GUI 英文名 | `Layered Model` |
| 后端 token | `layered_device` |
| 适用场景 | 薄膜、探测器层、屏蔽层、沿单轴堆叠结构。 |
| 当前边界 | 当前后端只支持沿 z 轴和盒状层；不应暗示任意轴或任意 solid。 |
| GUI 状态 | 主入口，可编辑、可生成，但只开放后端已验证字段。 |

这是普通用户的首选简单模式。名称避免使用实现类名 `LayeredDeviceTemplate`，也避免让用户先理解 INI section 结构。

### 2.2 通用层级模型

| 属性 | 规定 |
| --- | --- |
| GUI 中文名 | `通用层级模型` |
| GUI 英文名 | `Hierarchical Model` |
| 后端 token | `hierarchical` |
| 适用场景 | 多体积父子关系、位置、旋转、多种 solid、region、sensitive、bias 和布尔运算。 |
| 当前边界 | GUI 只可编辑其无损支持子集；其他后端字段按只读、blocker 或显式 source-copy 处理。 |
| GUI 状态 | 主入口；布尔运算是本模式中的高级功能，不再作为独立顶层模式。 |

`boolean_hierarchical`、`hierarchical_boolean` 和 `boolean` 只能作为旧 GUI/项目兼容别名或内部编辑状态。生成给后端的 canonical template 应为 `hierarchical`，布尔操作由几何文件中的 `[volume.<target>.boolean.<index>]` 表达。

### 2.3 外部几何导入

| 属性 | 规定 |
| --- | --- |
| GUI 中文名 | `外部几何导入` |
| GUI 英文名 | `External Geometry Import` |
| 未来后端 token | `gdml`，以及经单独设计后的 STL/CAD token。 |
| 适用场景 | 使用外部工具创建并导出的几何。 |
| 当前边界 | GDML 后端当前 fail-fast；STL/CAD 尚无运行时实现。 |
| GUI 状态 | 可展示为“规划中/不可运行”，默认禁用，不得生成可运行 package。 |

“外部几何导入”不得与项目运行来源的 `external` 模式混淆。界面和代码命名中分别使用 `geometry import` 与 `run input mode`。

## 3. 现有模板的产品归类

| 后端模板/token | 后端事实 | GUI 产品归类 | 长期处理 |
| --- | --- | --- | --- |
| `layered_device` / `layered` | 可运行，当前为 z 轴盒状层 | `快速分层模型`主入口 | 保留 canonical `layered_device`；alias 只用于兼容读取。 |
| `hierarchical` | 通用层级后端主路径 | `通用层级模型`主入口 | 作为长期 canonical 通用几何格式。 |
| `simple_box` / `simple` | 可运行的 world + target 最小模板 | 教学/测试预设 | 不再作为默认顶层产品模式；保留后端和旧配置兼容。可由通用层级模型的“单靶体预设”替代。 |
| `array` | 可运行但主要是盒状规则阵列 | 通用层级模型的“规则阵列预设” | 暂不删除后端；未来预设生成显式 hierarchical volumes 或受控参数化几何。 |
| `shielding` | 可运行但本质是 z 轴盒状层加可选 detector | 快速分层模型的“屏蔽体预设” | 暂不删除后端；逐步收敛到 layered/hierarchical 生成器。 |
| `boolean_hierarchical`、`hierarchical_boolean`、`boolean` | 不是 `TemplateFactory` 的正式后端模板 | 通用层级编辑器内部/旧项目兼容 | 从顶层选择器移除；canonical 后端 token 使用 `hierarchical`。 |
| `gdml` | 后端明确拒绝 | `外部几何导入`中的规划项 | 保留 fail-fast，真实实现进入 M1 后再开放。 |
| STL/CAD | 未实现 | `外部几何导入`中的规划项 | 不增加可运行 token，不以预览或文件选择器宣称支持。 |

## 4. GUI 命名和数据绑定规范

### 4.1 ComboBox 数据模型

几何模式选择器必须使用显示文本与机器值分离的数据项：

```python
combo.addItem(ui_text("Layered Model"), "layered_device")
combo.addItem(ui_text("Hierarchical Model"), "hierarchical")
combo.addItem(ui_text("External Geometry Import (Planned)"), "external_geometry_import")
```

读取与写入规则：

- 使用 `currentData()` 得到机器值。
- 使用 `findData()` 恢复项目选择。
- 不得使用 `currentText()` 写入 `geometry.template`。
- 不得使用翻译后的文本比较业务逻辑。
- 切换语言时原位更新 item text，并保持 item data 和当前选择不变。

### 4.2 推荐显示文案

| 机器值或产品 ID | 中文 | English | 状态后缀 |
| --- | --- | --- | --- |
| `layered_device` | 快速分层模型 | Layered Model | 无；在帮助文本中说明 z 轴/盒状限制。 |
| `hierarchical` | 通用层级模型 | Hierarchical Model | 无或“高级”。 |
| `external_geometry_import` | 外部几何导入 | External Geometry Import | `（规划中）` / `(Planned)`。 |
| `simple_box` | 单靶体预设 | Single Target Preset | `（兼容）` / `(Legacy)`，只在高级/导入上下文显示。 |
| `array` | 规则阵列预设 | Regular Array Preset | `（兼容）` / `(Legacy)`。 |
| `shielding` | 屏蔽体预设 | Shielding Preset | `（兼容）` / `(Legacy)`。 |

状态不能只用颜色表达；必须有文字或图标。原始 token 可以在高级信息、tooltip 或生成预览中显示，便于排错。

### 4.3 模式、预设与功能的区别

- 模式决定编辑器的数据结构和主要工作流。
- 预设只负责创建某个模式下的初始模型，之后仍使用目标模式保存。
- 布尔运算、规则阵列、屏蔽层和单靶体是功能或预设，不是新的顶层模式。
- 文件格式 GDML/STL 是导入来源，不应与原生构建模式平铺成同级可运行选项，除非后端真正实现并验证。

## 5. 兼容与剪枝流程

### 阶段 A：界面收敛，不删后端

1. GUI 顶层选择器只显示三类工作流。
2. `simple_box`、`array`、`shielding` 移入“预设/兼容导入”区域。
3. boolean 别名从顶层列表移除，合并进 hierarchical 高级功能。
4. GDML/STL 保留规划入口但禁用生成和运行。
5. 旧项目加载时仍能识别所有旧 token，并显示兼容状态。

### 阶段 B：建立显式转换器

1. 为 `simple_box → hierarchical` 建立无损转换和 round-trip 测试。
2. 为 `shielding → layered_device` 或 `hierarchical` 定义明确目标，并验证 detector、region、sensitive 和位置语义。
3. 为 `array → hierarchical` 评估展开体积数量、copy number 和性能；大阵列未来可迁移到真实 parameterised/replica 能力。
4. 转换必须输出新文件、迁移报告和旧 token 来源。

### 阶段 C：评估后端弃用

只有满足以下条件后才能考虑弃用某个后端模板：

- 所有字段都有等价 canonical 表达；
- 存在自动迁移器和兼容测试；
- 示例、GUI、文档和用户项目迁移路径齐备；
- 至少经过一个明确的弃用周期；
- 删除不会破坏 macro、配置或项目 JSON 的既有接口。

在此之前，所谓“剪枝”只指 GUI 信息架构收敛和重复实现减少，不指删除后端兼容路径。

## 6. 新模式准入规则

以后新增几何模式必须同时满足：

1. 不能由现有模式加一个预设或功能开关清晰表达。
2. 后端有独立且真实的构建语义，不是简单配置别名。
3. 有稳定机器 token、schema/version 和兼容策略。
4. 完成解析、校验、Geant4 对象创建、生命周期和错误路径。
5. 有后端 smoke、必要的 overlap/MT 测试和示例。
6. GUI 明确标出可编辑、只读预览或不可用状态。
7. 中文/英文显示名、帮助文本和诊断已进入集中翻译层。

不满足这些条件时，应实现为预设、功能、只读导入或仅规划项。

## 7. 当前实施顺序

1. 先完成并原子提交 M0-3B2B2，避免继续扩大当前混合 diff。
2. 整理 GUI 演示期修改时，引入显示名/机器值分离基础，但不删除旧模板兼容。
3. 在 M0-3C0A 复审后实施 GUI 顶层模式收敛和旧项目加载测试。
4. 在 M0-3B3 中实现预设转换、完整 round-trip、诊断去重和 canonical hierarchical 输出。
5. 在 M1 中实现真正 GDML/外部几何后，再解除“规划中”状态。

## 8. 本轮非目标

- 不删除 `SimpleBoxTemplate`、`ArrayTemplate` 或 `ShieldingTemplate`。
- 不改变现有配置 token 或默认后端解析行为。
- 不把 GDML/STL 标记为部分或完整支持。
- 不自动迁移或覆盖用户几何文件。
- 不因 GUI 名称变得易读而改变功能支持等级。
