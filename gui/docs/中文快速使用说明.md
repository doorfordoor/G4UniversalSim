# G4UniversalSim GUI 中文快速使用说明

整理日期：2026-07-03。本文件说明 `gui/` 下的 PySide6 外部运行器。它不会把 Geant4 嵌入 Qt 窗口，也不是 Geant4 OpenGL/Qt 可视化界面；它通过 `QProcess` 调用已有的 `G4UniversalSim.exe`，负责生成运行包、启动进程、收集日志、预览输出和管理运行历史。

## 1. 安装和启动

从仓库根目录进入 GUI 目录：

```powershell
cd gui
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

3D 预览是可选能力：

```powershell
pip install -r requirements-3d.txt
```

如果没有安装 PyVista/VTK，GUI 仍可启动，3D Preview 页会显示文本 fallback。设置 `QT_QPA_PLATFORM=offscreen` 时默认也会使用 fallback，除非显式设置 `G4USIM_ENABLE_OFFSCREEN_PYVISTA=1`。

## 2. GUI 的基本工作流

1. 在 Project 页选择 `G4UniversalSim.exe`。
2. 选择 workspace root，通常是仓库根目录。
3. 选择已有 `main.ini` 和 macro，或转到 Config Builder 生成新的运行包。
4. 设置 output directory、threads、seed 和 run name。
5. 点击 Build command 查看实际命令。
6. 点击 Run 启动外部进程。
7. 在 Run 页查看 stdout/stderr。
8. 在 Output 页刷新并查看输出文件。
9. 在 Run History 页加载、复制或重新运行历史包。

GUI 构造的命令遵循当前 CLI：

```text
G4UniversalSim.exe --config <configPath> --macro <macroPath> --output <outputDir> --threads <N> --seed <N> --run-name <name>
```

如果 seed 为空，GUI 不传 `--seed`。当前 GUI 要求 macro 路径存在。

## 3. 项目页

项目页保存的是 GUI 状态，不是后端仿真的输入格式。保存的 JSON 使用 `G4UniversalSimProject` schema，当前 version 为 5。

主要字段：

- executable：后端可执行文件。
- workspaceRoot：运行进程的工作目录。
- configPath：传给 `--config` 的主配置文件。
- macroPath：传给 `--macro` 的 macro。
- outputDir：传给 `--output` 的输出目录。
- runsRoot：Config Builder 生成运行包的位置。
- threads、seed、runName：对应 CLI 参数。

Recent Projects 只记录最近打开的项目 JSON 路径。

## 4. 配置生成页

配置生成页用来生成一次可复现的 run package。它不会覆盖原始 `materials.ini` 或 `geometry.ini`。若在编辑器里修改了材料或几何，修改内容只写入新生成的包。

生成包布局：

```text
<runsRoot>/<timestamp>_<run_name>/
  config/
    main.ini
    materials/material.ini
    geometry/geometry.ini
  macros/run.mac
  logs/
  output/
  project_snapshot.json
  validation_report.txt
```

生成后 Project 页会自动指向包内的 `config/main.ini`、`macros/run.mac` 和 `output/`。

### 材料

Materials Editor 支持：

- NIST alias 行。
- `mass_fraction` 材料。
- `atom_count` 材料。
- `volume_fraction` 材料。
- 添加、复制、删除、启用/禁用和验证行。

重要限制：

- `volume_fraction` 的组分必须是材料，不能直接用裸元素。
- 分数类组分必须加和为 1.0。
- 编辑结果只写到生成包的 `config/materials/material.ini`。
- 材料文件采用后端闭合 schema；未知 section、未知 key、空名称后缀和 implicit global 字段会在校验/后端启动时阻止运行。旧 run package 的 `[material.<name>] type = material` 已弃用但仍可读取，新生成包不再包含该字段；空值、其他值或其他 section 中的 `type` 会被拒绝。`temperature`、`pressure` 当前不可用，错误时请使用 density、state 和 composition。
- 从源材料文件读取到的 schema 错误会持续显示；编辑或重复校验不会把它们视为已修复。请先修正并重新加载源文件，之后才能生成材料预览和 run package。

### 几何

Geometry Editor 当前可生成：

- `simple_box`
- `layered_device`
- `hierarchical`
- `hierarchical_boolean` / `boolean_hierarchical` / `boolean`

主要标签页：

- Simple Box：编辑 `[world]` 和 `[target]`。
- Layered Device：编辑沿 z 轴堆叠的层。
- Hierarchical Volumes：编辑 `[world]` 和 `[volume.*]`。
- Boolean Operations：编辑 `[volume.<target>.boolean.<index>]`。
- Preview / Unsupported Template：查看不支持编辑的源文件摘要。

GUI 的几何校验和后端能力不完全相同。后端已经支持 `trd` 和 `trap`，但当前 GUI 层级/布尔编辑器的校验白名单主要面向 `box`、`tubs`、`sphere`、`orb`、`cone`，稳定预览以 `box` 和 `tubs` 为主。如果要使用 GUI 尚未放开的后端形状，可以手写几何配置并通过 Project 页运行。

`array`、`shielding`、`gdml` 和 STL 不作为 GUI 可编辑目标。`gdml` 在后端也仍是占位，不可作为真实 GDML 导入使用。

### 布尔操作

布尔工具是 solid operand，不是普通体积。它们没有材料、敏感探测器、bias 或 region 状态。目标体积保留这些属性。

GUI writer 会按目标体积重新编号启用的布尔操作，从 0 开始连续输出。

### 几何源文件的无损保护

M0-3B2B1 起，Geometry Editor 会保留源解析错误和警告；重复校验、编辑或三维预览不会把源问题当作已修复。若源文件包含当前编辑模型无法无损保存的 `cut.*`、`vis.*`、`auto_stack`、显式 position/rotation、shape-specific 属性、userProperties 或 boolean tool properties，界面会显示 round-trip blocker，并禁止生成 editable geometry/package。

M0-3B2B2 起，几何来源 warning 会保留文件、行号、原始 section/key/value 和迁移建议。hierarchical/layered 的旧式无前缀属性会显示为 legacy metadata 并保留；`metadata.<非空名称>` 是只保存的 canonical metadata，不参与运行。array/shielding 仍为 preview-only，严格 `version=2`、自动迁移和完整 round-trip 留待后续阶段。

可以显式选择“复制原始 geometry source”模式。该模式逐字节复制源文件，不经过编辑器 writer，报告会注明 Geometry Editor validation 已绕过。metadata 编辑框只接受 `metadata.<非空名称> = value`；`name`、`placement`、`cut.*`、`vis.*`、`copyNo`、`shape`、`material` 等 runtime 字段和旧式无前缀未知字段不能通过 metadata 写出。旧字段本阶段不会自动改名或删除，严格迁移留给 M0-3B3。

### 三维预览

三维预览是近似配置预览，不是 Geant4 navigator、overlap check 或真实 CSG 可视化。

当前用于辅助检查：

- primitive box、tubs/cylinder、sphere/orb、cone。
- 部分布尔工具的近似显示。
- source surface/ray 预览。
- sensitive/bias 标签。

最终几何是否可运行，以 C++ 后端 `/run/initialize` 为准。

### 运行配置

Run Config 分为 Source、Physics 和 Scoring。

Source 可生成的后端安全组合：

- point + fixed direction
- point + isotropic
- plane circle + fixed direction
- plane circle + isotropic

rectangle、annulus、cone、cosine、focused 等源模式可用于预览或保留模型字段，但当前 GUI 会阻止生成到 `main.ini`。

Physics 当前生成 reference 模式，常用 `FTFP_BERT_EMZ` 和 `default_cut`。打开 biasing physics 只代表启用物理钩子，GUI 尚没有 biasing 规则编辑器。

Scoring 当前生成 hits、event_edep、edep 直方图和 edep 汇总设置。GUI 禁用 LET/Dose/Fluence 生成，因为后端这些能力还不是完整用户级功能。

## 5. 生成并运行

推荐先点击 Validate。没有 error 时再点 Generate Package 或 Generate and Run。

生成包可脱离 GUI 复现：

```powershell
G4UniversalSim.exe --config <package>\config\main.ini --macro <package>\macros\run.mac --output <package>\output --threads 1
```

生成的 `run.mac` 基本结构是：

```text
/control/verbose 1
/run/verbose 1
/event/verbose 0
/tracking/verbose 0
/run/initialize
/run/beamOn <N>
```

如果启用 dry run 或 beamOn 数为 0，则不会写 `/run/beamOn`。

## 6. 运行页

运行页负责启动和管理外部进程：

- Build command：预览 program、arguments、working directory 和 human-readable 命令。
- Run：启动 `QProcess`。
- Stop：请求正常终止。
- Kill：强制结束仍未退出的进程。
- Save Logs：刷新 stdout/stderr 日志文件。

运行时日志会写到：

- 包运行：`<package>/logs/stdout.log` 和 `stderr.log`。
- 非包运行：`<outputDir>/logs/stdout.log` 和 `stderr.log`。

GUI 还会写 `run_status.json`，记录 state、startedAt、finishedAt、exitCode、command 和 workingDirectory。这个文件只服务 GUI，不是后端输入。

## 7. 输出页

输出页支持普通输出目录和 GUI 生成包。

标签页：

- Overview：显示包路径、输出目录、文件统计、线程 CSV 数量和 merge 状态。
- Preview：预览小型文本、配置、macro、JSON、CSV 文件。
- Run Summary：结构化查看 `run_summary.txt`。
- CSV Preview：用 Python 标准 `csv` 解析预览 CSV，避免一次加载超大文件。
- Merge：调用合并工具。
- Logs：查看 `stdout.log`、`stderr.log` 和 `validation_report.txt`。

可识别输出包括：

- `hits_t*.csv`
- `event_edep_t*.csv`
- `hist_edep_raw_t*.csv`
- `hist_edep_weighted_t*.csv`
- `hits_merged.csv`
- `event_edep_merged.csv`
- `hist_edep_raw_merged.csv`
- `hist_edep_weighted_merged.csv`
- `run_summary.txt`
- `stdout.log`
- `stderr.log`
- `validation_report.txt`
- `project_snapshot.json`

## 8. 合并

后端不会自动合并多线程输出。GUI 的 Merge 页只是调用已有工具：

```powershell
python scripts/merge_outputs.py --input <outputDir> --pattern "hits_t*.csv" --output <outputDir>/hits_merged.csv
python scripts/merge_outputs.py --input <outputDir> --pattern "event_edep_t*.csv" --output <outputDir>/event_edep_merged.csv
mergeHistograms.exe --input <outputDir> --pattern hist_edep_raw_t*.csv --output <outputDir>/hist_edep_raw_merged.csv
mergeHistograms.exe --input <outputDir> --pattern hist_edep_weighted_t*.csv --output <outputDir>/hist_edep_weighted_merged.csv
```

`merge_outputs.py` 位于仓库 `scripts/`。`mergeHistograms.exe` 会在常见 build 目录中查找。若目标 merged 文件已存在，GUI 不会自动覆盖。

## 9. 运行历史

运行历史页扫描 runs root。目录满足以下任一条件会被识别为运行包：

- 存在 `project_snapshot.json`。
- 存在 `config/main.ini` 和 `macros/run.mac`。
- 同时存在 `output/` 和 `logs/`。

功能：

- 查看包状态、exit code、几何模板、线程数、beamOn 数和输出文件统计。
- 加载历史 `project_snapshot.json` 到当前 Project。
- 打开历史包输出。
- 复制包。
- 复制并重新运行。

复制包只复制 `config/`、`macros/`、`project_snapshot.json` 和 `validation_report.txt`，会创建新的空 `logs/` 和 `output/`，不会复制旧 CSV 或旧日志。

## 10. 当前限制

- GUI 不嵌入 Geant4 可视化。
- 不加载大型 CSV 全量内容。
- 不提供直方图绘图。
- 不提供参数扫描 UI。
- 不提供 biasing 规则编辑器。
- `array`、`shielding`、GDML、STL 不作为 GUI 可编辑目标。
- 3D Preview 是近似预览，不替代 Geant4 初始化、tracking 或 overlap 检查。
- GUI 不硬删除历史包。
- 暂未打包成独立桌面程序。

## 11. 常见问题

### 运行前验证失败

先检查 executable、macro、config、workspace root 和 outputDir 是否存在。outputDir 可以不存在，但它的上级目录必须存在。

### 生成包后原始配置没有变化

这是预期行为。GUI 不覆盖原始材料和几何文件，所有编辑结果写入新包。

### 三维预览空白或只有文本

可能没有安装 `requirements-3d.txt`，或当前 Qt/VTK/OpenGL 环境不可用。文本 fallback 不影响生成包和运行。

### 多线程输出没有合并文件

这是预期行为。到 Output 页的 Merge 标签运行合并任务。

### GUI 生成的几何和手写几何能力不同

以 C++ 后端为最终运行准则。GUI 只是安全编辑器，校验规则有意比后端保守。
