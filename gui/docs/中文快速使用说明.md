# G4UniversalSim GUI 中文快速使用说明

整理日期：2026-08-06。本文件说明 `gui/` 下的 PySide6 外部运行器。它不会把 Geant4 嵌入 Qt 窗口，也不是 Geant4 OpenGL/Qt 可视化界面；它通过 `QProcess` 调用已有的 `G4UniversalSim.exe`，负责生成运行包、启动进程、收集日志、预览输出和管理运行历史。

## 1. 安装和启动

从仓库根目录进入 GUI 目录：

```powershell
cd gui
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

3D 预览是可选能力：

```powershell
pip install -r requirements-3d.txt
```

如果没有安装 PyVista/VTK，GUI 仍可启动，3D Preview 页会显示文本 fallback。设置 `QT_QPA_PLATFORM=offscreen` 时默认也会使用 fallback，除非显式设置 `G4USIM_ENABLE_OFFSCREEN_PYVISTA=1`。

### 1.1 语言和主题

主窗口右上角提供“语言”和“主题”菜单：

- 语言支持中文和 English，切换后立即更新主框架、核心页面静态控件和关键运行状态。
- 首次启动时，中文系统默认使用中文，其他系统默认使用英文；用户选择会通过 `QSettings` 持久化。
- 浅色、深色和跟随系统主题可以独立于语言切换并持久化。
- Geant4 命令、INI section/key、文件名、材料名、几何模板 token 和后端原始诊断保持原文，避免翻译改变接口或排错语义。

### 1.2 开始页和示例库

启动后首先显示侧栏的**开始**页：**新建仿真...** 打开新建仿真向导，**打开项目...** 读取项目 JSON，“最近的项目”列出保存过且仍存在的项目。下方“示例”给出五个带缩略图的示例卡片：质子布拉格峰、屏蔽板、硅中的朗道分布、NaI γ 能谱和质子能量扫描。点击卡片或“打开示例”后：

- 示例的设置像向导一样写入当前项目，配置页的几何、源、物理、计分和运行参数被替换，可直接修改；
- 附带的 Geant4 结果（`examples/gallery/<示例>/`）在“结果 / 图表”中立即显示，能量扫描示例在“参数扫描”页显示结果表和曲线；
- 附带结果只读：在配置页按“生成并运行”会在运行目录中重新计算，扫描示例需要用“新建扫描”重新生成运行包后才能运行。

附带结果是单一种子、有限事件数的小样本，用于演示读图，不是物理基准；γ 能谱不含探测器分辨率。示例说明与重新生成方法见 `examples/gallery/README.md`。

界面右上角的两个图标按钮分别是主题和语言；“项目”标签与运行状态标签（圆点 + 文字，运行中、成功、失败用颜色区分但始终有文字）显示在旁边。侧栏底部显示 GUI 版本。

## 2. GUI 的基本工作流

**新建仿真向导（路线图 C2）：**菜单 **File → New Simulation...**（Ctrl+N）按“场景 → 材料和几何 → 源 → 物理/输出/运行”四步引导：场景可选单一靶、体模深度剂量（体模分为若干敏感薄片，各片剂量即深度剂量曲线）、屏蔽平板（屏蔽层后 1 mm 处的敏感探测器）、硅探测器和 γ 谱仪（闪烁体圆柱 + 各向同性点源）；材料只提供 Geant4 NIST 材料，源为沿 +z 的笔形束、矩形宽束或各向同性点源，位于靶前 10 mm；最后一页显示摘要，参数无效时无法完成。完成后向导把结果原位写入当前项目（generated 模式）：Configuration 页的几何、源、物理、计分和运行参数都被替换，可继续用完整编辑器（高级模式）修改；勾选“完成后生成运行包并运行”时立即走与编辑器相同的校验、生成包和运行流程。运行后在 Results / **Plots** 查看结果。向导不修改材料文件，不生成后端支持但 GUI 不能编辑的字段（例如 replica、打分网格、高级源）。

1. 在 Project 页选择 `G4UniversalSim.exe`。
2. 选择 workspace root，通常是仓库根目录。
3. 新项目默认选择“由配置页生成”；在 Configuration 页完成配置后，点击 Run 会自动校验并生成新的运行包。只有需要复用手写文件时才切换为“使用外部文件”。
4. 设置 output directory、threads、seed 和 run name。
5. 点击 Build command 查看实际命令。
6. 点击 Run 启动外部进程。
7. 在 Run 页查看 stdout/stderr。
8. 在 Output 页刷新并查看输出文件。
9. 在 Run History 页加载、复制或重新运行历史包。

GUI 构造的命令遵循当前 CLI：

```text
G4UniversalSim.exe --config <configPath> --macro <macroPath> --output <outputDir> --threads <N> --seed <N> --run-name <name>
```

如果 seed 为空，GUI 不传 `--seed`。只有路径非空时才会加入 `--config` 或 `--macro`；外部文件模式允许 config-only、macro-only 或两者同时提供。

### 2.1 参数扫描与批量运行（路线图 C3）

侧栏 **Parameter Scans**（参数扫描）页让当前配置页（generated 模式）中的一个设置取多个值，每个取值生成一个普通运行包，全部放在 runs root 下的 `<时间>_scan_<名称>/` 目录中，并写出清单 `scan.json`（`G4UniversalSimScan` v1）。点击 **Use current configuration** 读取配置页，选择参数：`source.energy`（带单位的能量）、`source.particle`、`physics.reference`、`run.seed`、`run.beam_on`、`geometry.<体积>.material`，以及 box 体积的 `geometry.<体积>.thickness`（只改 z 尺寸，x/y 与位置不变，叠层时请自行确认不重叠）。取值写成 `50, 100, 150 MeV`（末尾单位作用于没有单位的数字）、`lin(10, 200, 5) MeV` 或 `log(1, 1000, 4) MeV`，最多 200 个点。**Create scan** 先逐点用配置页同样的校验检查，任何一点不合格都不会写出文件。**Run pending points** 依次运行尚未成功的点（**Run all points** 全部重跑），每个点与普通 Run 一样由运行器写日志和 `run_status.json` 并按运行摘要判定状态，某点失败不影响后续点，**Stop scan** 终止当前点并跳过其余点；每个点使用清单中自己的随机种子。结果表列出每个点的状态、完成事件数和所选物理量（来自该点合并的 `scorer_statistics.csv`）及其相对统计误差，右侧图给出该量随参数的变化（误差棒为统计误差，可选 **Per primary** 除以完成事件数）；**Export results...** 导出 CSV，**Open scan...** 重新打开 `scan.json`。扫描不改变配置页本身。

## 3. 项目页

项目页保存的是 GUI 状态，不是后端仿真的输入格式。保存的 JSON 使用 `G4UniversalSimProject` schema，当前 version 为 6。

主要字段：

- executable：后端可执行文件。
- runInputMode：稳定机器值 `generated` 或 `external`。界面分别显示“由配置页生成”和“使用外部文件”。
- workspaceRoot：运行进程的工作目录。
- configPath：传给 `--config` 的主配置文件。
- macroPath：传给 `--macro` 的 macro。
- outputDir：传给 `--output` 的输出目录。
- runsRoot：Config Builder 生成运行包的位置。
- threads、seed、runName：对应 CLI 参数。

Recent Projects 只记录最近打开的项目 JSON 路径。

新项目的 `configPath` 和 `macroPath` 默认为空。在 `generated` 模式下，这两个输入框只显示最近一次实际生成结果，配置变化后旧包会标记为失效，Run 会重新生成；不会回退到仓库根目录的默认 `main.ini` 或测试 macro。在 `external` 模式下，路径变化会立即刷新 Run Console 命令。旧项目没有 `runInputMode` 时，只要原来有 `configPath` 或 `macroPath` 就迁移为 `external`，否则迁移为 `generated`。

2026-10-03 工作区已验证上述运行来源流程，尚未提交。真正启动 generated 输入需要已生成的 `main.ini` 和 `run.mac`；外部输入必须指向文件，目录不能作为配置或 macro。已有进程运行时，重复 Run 不会创建新包。项目名称、可执行文件或工作目录变化也会使生成包失效。generated 模式的实际输出位于新 package 的 `output/`，由运行包统一管理。

Run Console 提供 Inspect inputs（检查运行输入）和 Run plan（运行前清单）。它通过后端 `--inspect-run` 同时读取主配置与显式 CLI 参数，并识别主配置中指定的 macro，因此支持 config-only、macro-only 和联合输入。清单显示 macro 执行前的启动值、来源、材料/几何文件与展开命令；会改变配置的 macro 命令有分类标记，缺少 `beamOn` 会提示。外部模式点击 Run 时先异步查询，成功后才启动；冲突、动态 macro、输入变化或查询失败均不会启动。需重新构建或选择带 `--inspect-run` 的新版后端；旧后端会显示接口错误。清单表示运行计划，实际成功仍需核对运行摘要，当前 C4 尚在后续队列。

## 4. 配置生成页

配置生成页用来生成一次可复现的 run package。它不会覆盖原始 `materials.ini` 或 `geometry.ini`。若在编辑器里修改了材料或几何，修改内容只写入新生成的包。

生成包布局：

```text
<runsRoot>/<timestamp>_<run_name>/
  config/
    main.ini
    materials/material.ini
    geometry/geometry.ini
  macros/run.mac
  logs/
  output/
  project_snapshot.json
  validation_report.txt
```

生成后 Project 页会自动指向包内的 `config/main.ini`、`macros/run.mac` 和 `output/`。材料/几何路径或编辑内容、Source/Physics/Scoring、beamOn、dry-run、threads、seed、run name、output 或 runs root 变化后，Run Console 会显示“配置已修改，运行时将重新生成 package”，但不会在每次键盘输入时写文件。

### 材料

Materials Editor 支持：

- NIST alias 行。
- `mass_fraction` 材料。
- `atom_count` 材料。
- `volume_fraction` 材料。
- 添加、复制、删除、启用/禁用和验证行。

重要限制：

- `volume_fraction` 的组分必须是材料，不能直接用裸元素。
- 分数类组分必须加和为 1.0。
- 编辑结果只写到生成包的 `config/materials/material.ini`。
- 材料文件采用后端闭合 schema；未知 section、未知 key、空名称后缀和 implicit global 字段会在校验/后端启动时阻止运行。旧 run package 的 `[material.<name>] type = material` 已弃用但仍可读取，新生成包不再包含该字段；空值、其他值或其他 section 中的 `type` 会被拒绝。`temperature`、`pressure` 当前不可用，错误时请使用 density、state 和 composition。
- 从源材料文件读取到的 schema 错误会持续显示；编辑或重复校验不会把它们视为已修复。请先修正并重新加载源文件，之后才能生成材料预览和 run package。

### 几何

几何模式选择器使用本地化显示名，但项目 JSON、INI 和 run package 始终保存稳定机器值：

- “快速分层模型 / Layered Model”对应 `layered_device`，用于沿 z 轴堆叠的盒状层。
- “通用层级模型 / Hierarchical Model”对应 `hierarchical`，布尔运算是其中的高级功能，不再作为独立顶层模式。
- “外部几何导入 / External Geometry Import”当前标记为“规划中”并禁止选择；GDML 后端仍会 fail-fast；STL（`shape = tessellated`）、新增形状和 replica/parameterised 放置可在手写几何 INI 中使用（路线图 A5，GUI 编辑器不能编辑这些体积）。3D 预览页默认显示 Geant4 实际构建的几何（路线图 G1）：打开该页时后端只执行 `/run/initialize` 并导出几何（约 3 秒），无需先生成运行包；勾选“自动显示 Geant4 几何”时，每次修改后稍候自动重建，未改变的几何直接从缓存显示。构建期间先显示编辑器草图（近似，按“刷新预览”也可随时查看），完成后替换为后端几何；编辑过的几何或材料有错误时不会运行后端，而在下方列出编辑器错误，后端拒绝时显示后端给出的原因。external 模式使用项目主 INI。“显示后端几何”按钮可手动刷新。此视图只显示几何，不做重叠检查。

新项目不再把 `simple_box`、`array`、`shielding` 或 boolean alias 作为顶层模式提供。打开旧项目时，GUI 会按原机器 token 动态显示兼容项，不会静默迁移或改写原文件；`simple_box` 仍可兼容编辑，`array` 和 `shielding` 仍为只读预览。

主要标签页：

- Simple Box：兼容编辑旧 `simple_box` 项目的 `[world]` 和 `[target]`。
- Layered Device：编辑“快速分层模型”的沿 z 轴堆叠层。
- Hierarchical Volumes：编辑 `[world]` 和 `[volume.*]`。
- Boolean Operations：编辑 `[volume.<target>.boolean.<index>]`。
- Preview / Unsupported Template：查看不支持编辑的源文件摘要。

GUI 的几何校验和后端能力不完全相同。后端支持 `trd` 和 `trap`；当前工作区的 hierarchical 普通体积编辑器已开放 `trd` 的 `dx1/dx2/dy1/dy2/dz` 五个表格字段，并通过 writer、生成包和真实后端回归。布尔工具的 `trd` 和 `trap` 等其他后端形状尚未由 GUI writer 全面开放；三维预览仍是近似显示。如果要使用 GUI 尚未放开的后端形状，可手写几何配置并通过 Project 页运行。

`array`、`shielding`、`gdml` 和 STL 不作为 GUI 可编辑目标。`array`、`shielding` 只在旧项目兼容加载时出现；`gdml` 在后端也仍是占位，不可作为真实 GDML 导入使用。

### 布尔操作

布尔工具是 solid operand，不是普通体积。它们没有材料、敏感探测器、bias 或 region 状态。目标体积保留这些属性。

GUI writer 会按目标体积重新编号启用的布尔操作，从 0 开始连续输出。

### 几何源文件的无损保护

M0-3B2B1 起，Geometry Editor 会保留源解析错误和警告；重复校验、编辑或三维预览不会把源问题当作已修复。当前工作区的 B3 子链路可保留 hierarchical 普通体积及 layered 层上后端支持的四种 `vis.*` 与四种 `cut.*`，编辑其他字段后 writer 仍写回原值；它们暂未提供独立的可视化编辑控件。layered 的 `auto_stack`、position 和 rotation 已可编辑并往返，canonical metadata 保留原 key；未知 `vis.*`/`cut.*`、显式 placement、其他 shape-specific 属性、userProperties 或 boolean tool properties 仍显示 round-trip blocker，并禁止生成 editable geometry/package。

空的未知 section、未列入 `[layers]/names` 的 `[layer.*]`，以及重复 section/key 也会阻断可编辑生成；请先在源文件中消歧并重新加载。显式 source-copy 可保留原文，但不表示编辑器或严格后端已接受这些声明。

M0-3B2B2 起，几何来源 warning 会保留文件、行号、原始 section/key/value 和迁移建议。hierarchical/layered 的旧式无前缀属性会显示为 legacy metadata 并保留；`metadata.<非空名称>` 是只保存的 canonical metadata，不参与运行。B3 工作区后端可对 `[global] version = 2` 启用严格字段诊断；GUI 已能在当前可编辑子集中保留并写回该版本标记，项目快照也保留版本。其他无法无损保存的字段仍显示 round-trip blocker，用户可显式 source-copy 保留原文。array/shielding 仍为 preview-only，自动迁移和完整 round-trip 尚未完成。

当前工作区的 GUI 工作区计数避免重复累加几何源解析消息；生成前校验对同一份已加载源文件只报告一次源解析错误。若编辑期间源文件在磁盘上改变，须重新加载后才可生成包。材料源 warning 与编辑器语义 warning 分别保留；这仍不是跨 parser、编辑器、后端的完整诊断去重。

可以显式选择“复制原始 geometry source”模式。该模式逐字节复制源文件，不经过编辑器 writer，报告会注明 Geometry Editor validation 已绕过。metadata 编辑框只接受 `metadata.<非空名称> = value`；`name`、`placement`、`cut.*`、`vis.*`、`copyNo`、`shape`、`material` 等 runtime 字段和旧式无前缀未知字段不能通过 metadata 写出。旧字段本阶段不会自动改名或删除，严格迁移留给 M0-3B3。

### 三维预览

三维预览是近似配置预览，不是 Geant4 navigator、overlap check 或真实 CSG 可视化。

首次启动时，默认几何模板为 `hierarchical`，默认源文件为仓库中的 `test/geometry/hierarchical_test.ini`。该示例包含层级体积、带内半径的 `tubs` 和 `trd`，适合检查预览效果。当前工作区版本已对该源文件完成普通体积字段往返，原先的 `trd` 五参数 blocker 已消除；真实 GUI 生成包完成 3/3 事件。它仍须通过每次生成前的校验，且不能自动启用 source-copy；旧 `test/main_hierarchical.ini` 的 biasing 配置不能因此视为有效默认运行。

如需无界面验证该复杂几何，请运行 `test/macros/run_hierarchical_batch.mac`；它不包含 Qt/OpenGL 命令，并在真实后端完成 3 个事件。`test/macros/vis.mac` 只供显式 UI 可视化。默认 GUI 复杂几何源的普通体积字段已通过往返测试，不需要 source-copy；其他含未知字段或未开放形状的源文件仍必须保持 blocker，不能自动启用 source-copy 绕过校验。

当前用于辅助检查：

- primitive box、tubs/cylinder、sphere/orb、cone，以及 `trd` 的近似预览；`trd` 普通体积五参数可在层级表格编辑，预览仍不等于 Geant4 真值。
- 全角度 `tubs` 会保留内半径并显示为空心体；部分角度 `tubs` 当前仍按完整圆周近似显示并给出提示。
- 部分布尔工具的近似显示。
- source surface/ray 预览。
- sensitive/bias 标签。

最终几何是否可运行，以 C++ 后端 `/run/initialize` 为准。

### 运行配置

Run Config 分为 Source、Physics 和 Scoring。

Source 可生成的后端安全组合：

Source 编辑器的 `Position` 对 point 写入 `[source]/position`；对 plane circle/rectangle 写入 `[source]/center`，按 x、y、z 三个带长度单位的分量设置中心。circle 使用 `radius`，rectangle 使用 `halfx`、`halfy` 两个正半宽。两种平面源均位于 XY 平面；矩形不支持旋转源平面。旧宏命令 `planeBeam` 仍只支持零 x/y 中心。

- point + fixed direction
- point + isotropic
- plane circle + fixed direction
- plane circle + isotropic
- plane rectangle + fixed direction（实验性）
- plane rectangle + isotropic（实验性）

annulus、cone、cosine、focused 等源模式仍仅供预览或保留模型字段，GUI 会阻止生成到 `main.ini`。rectangle 目前仅开放上述 XY 平面子集。

Physics 当前生成 reference 模式，常用 `FTFP_BERT_EMZ` 和 `default_cut`。GUI 尚没有 biasing 规则编辑器；仅勾选物理钩子无法形成有效偏置，`generated` 模式会阻止生成。需要 process-level biasing 时请在 batch 模式使用 `external` 配置或 macro；后端当前拒绝 `--ui` 与启用偏置的配置或修改偏置的 macro 组合。核对运行摘要中的目标匹配状态时请注意，`validated` 不代表已经观察到实际偏置或完成物理验证。

Scoring 当前生成 hits、event_edep、edep 直方图和 edep 汇总设置，并可勾选“启用敏感体吸收剂量 Dose (Gy，原型)”与“启用径迹长度 Fluence (mm^-2，原型)”；默认均关闭。开启任一项须保持 `auto_create_default_scorers=true`，生成包在 `[scoring]` 分别写出 `dose = true`、`fluence = true`。LET 仍不支持生成。

完成真实 Geant4 运行后，打开 Results 页的 **Dose (Gy)** 标签，查看逐 `runID` 与 physical touchable 的原始/加权 Edep、质量及 Gy 值。后端生成 `dose_volume_summary_tN[_rR].csv`，GUI 将已发现的 worker 沉积能量求和，体积质量只使用一份，再计算剂量。若文件损坏则跳过并显示警告；若缺少 worker 文件，页面无法保证结果覆盖全部线程。该功能目前只统计已配置敏感体，结果未按源强、注量、时间或事件数归一化，尚未通过独立物理 benchmark；请勿当作经标定的真实照射剂量。

Results 页的 **Fluence (mm^-2)** 标签读取 `fluence_volume_summary_tN[_rR].csv`，按每个 run 和 physical touchable 累加 worker 的 raw/weighted step length，敏感体体积只取一份，除以体积后显示 mm^-2。零 Edep 的有效输运步也参与；当前仅适用于无 daughter 的敏感 solid。坏文件会跳过并提示，缺失 worker 不能当作零。该原型没有源强、时间或事件数归一化，不代表 surface-crossing fluence，也未经过独立物理 benchmark。

## 5. 生成并运行

`generated` 是新项目的默认运行来源。点击 Run 时，GUI 会同步 Project 页和 Configuration 页、执行完整校验、生成新 package，再用包内 `config/main.ini`、`macros/run.mac` 和 `output/` 启动。也可以先点击 Validate，或手动点击 Generate Package / Generate and Run。

若几何源存在 round-trip blocker，Run 不会自动启用 source-copy。必须由用户显式勾选“复制原始 geometry source”，之后才会逐字节复制源文件；该模式只保证原文保留，不表示 Geometry Editor 已验证这些字段。

生成包可脱离 GUI 复现：

```powershell
G4UniversalSim.exe --config <package>\config\main.ini --macro <package>\macros\run.mac --output <package>\output --threads 1
```

生成的 `run.mac` 基本结构是：

```text
/control/verbose 1
/run/verbose 1
/event/verbose 0
/tracking/verbose 0
/run/initialize
/run/beamOn <N>
```

如果启用 dry run 或 beamOn 数为 0，则不会写 `/run/beamOn`。

## 6. 运行页

运行页负责启动和管理外部进程：

- Build command：预览 program、arguments、working directory 和 human-readable 命令。generated package 失效时只显示重新生成提示，不把旧命令伪装成有效命令。
- Run：generated 模式先重新生成 package，external 模式直接校验所选路径，然后启动 `QProcess`。
- Stop：请求正常终止。
- Kill：强制结束仍未退出的进程。
- Save Logs：刷新 stdout/stderr 日志文件。

运行时日志会写到：

- 包运行：`<package>/logs/stdout.log` 和 `stderr.log`。
- 非包运行：`<outputDir>/logs/stdout.log` 和 `stderr.log`。

GUI 还会写 `run_status.json`，记录 state、startedAt、finishedAt、exitCode、command 和 workingDirectory。这个文件只服务 GUI，不是后端输入。

## 7. 输出页

输出页支持普通输出目录和 GUI 生成包。

**图表（路线图 C1）：**Results / **Plots**（图表）标签自动列出当前输出目录中可绘制的数据集：合并的 `scorer_statistics[_rR].csv` 中每个 scorer/量（各敏感 touchable 的柱状图与 A3 统计误差棒）、原生打分网格（`scoring_mesh[_rR].csv`，或 ROOT 输出中的 `mesh` ntuple；**View** 可选沿某轴的分布（对另两轴求和，误差按各格独立做平方和开方）或二维图，box 网格的坐标单位为 mm，取自 `run_metadata.json`）、Edep 直方图（各 worker 求和，泊松误差）、逐事件沉积谱（`event_edep`）和相空间能谱（按粒子、对数分箱、sqrt(Σw²) 误差）。可勾选 X/Y 对数、**Per primary**（每个初级粒子：除以 `run_summary.txt` 中该 run 完成的事件数，使事件数不同的 run 可比较）、**Overlay all runs**（叠加同一目录的各 run），或用 **Compare with output...** 叠加其他输出目录中同名的数据集（二维图只显示主数据集）。**Export image...** 导出 PNG/SVG/PDF，**Export plotted data...** 导出图中数值的 CSV。图表只显示后端写出的数值，不做物理修正；需要 `matplotlib`（见 `gui/requirements.txt`），缺少时该标签显示原因。

**JSON 导出（M3/M5 实验性原型）：**选择已有模拟输出目录，打开 Results / **JSON Exports (M5 prototype)**，点击 **Export Dose JSON...** 或 **Export Fluence JSON...**，为新文件选择 `.json` 保存路径。页面用独立 `QProcess` 异步执行 `dose_json` 或 `fluence_json`，显示进程输出、成功路径及 `warnings`；运行时禁止重复启动，可点击 **Cancel export**，已有目标文件不会覆盖。导出完成后刷新文件列表。导出只聚合目录中**已发现**的 worker CSV，不能证明源模拟已经完成、所有 worker 文件齐全或物理数值已经标定；请先核对 `run_summary.txt` 的状态、事件数、输出文件清单和 JSON 警告。Dose/Fluence 尚无独立物理 benchmark；可信 Python 后处理接口详情见 `docs/输出扩展原型说明.md`。

## 8. 合并

后端不会自动合并多线程输出。GUI 的 Merge 页只是调用已有工具：

```powershell
python scripts/merge_outputs.py --input <outputDir> --pattern "hits_t*.csv" --output <outputDir>/hits_merged.csv
python scripts/merge_outputs.py --input <outputDir> --pattern "event_edep_t*.csv" --output <outputDir>/event_edep_merged.csv
mergeHistograms.exe --input <outputDir> --pattern hist_edep_raw_t*.csv --output <outputDir>/hist_edep_raw_merged.csv
mergeHistograms.exe --input <outputDir> --pattern hist_edep_weighted_t*.csv --output <outputDir>/hist_edep_weighted_merged.csv
```

`merge_outputs.py` 位于仓库 `scripts/`，仅按稳定文件顺序拼接同表头 CSV 的数据行，不会对同一事件或命中做聚合。它先校验全部输入的表头和列数，再生成结果；空文件、重复输入、目标与输入相同或已有目标文件均会报错，失败不会留下部分合并结果。`mergeHistograms.exe` 会在常见 build 目录中查找；当前工作区候选可读取后端带 `_MeV` 的五列表头及旧五列/三列。仅全部输入为 v3 时，合并结果的 bin 边界列标注 `_MeV`；其他组合保留不带单位的兼容表头。bin 边界不兼容时拒绝合并。合并是数据后处理，不表示物理结果已经验证。

多次 `/run/beamOn` 的首轮沿用 `_tN` 文件名，后续 run 使用 `_tN_rR`；Merge 的 `*_t*.csv` 模式会收集两种文件。hits/event CSV v3 继续以 `runID` 开头，能量/长度列在表头标注单位且不再输出无计算链的 LET 占位列；v2 消费者需按字段名迁移，v1 不具备可靠的多 run 重建能力。字段和单位详见仓库 `docs/输出数据契约.md`。

## 9. 运行历史

运行历史页扫描 runs root。目录满足以下任一条件会被识别为运行包：

- 存在 `project_snapshot.json`。
- 存在 `config/main.ini` 和 `macros/run.mac`。
- 同时存在 `output/` 和 `logs/`。

功能：

- 查看包状态、exit code、几何模板、线程数、beamOn 数和输出文件统计。
- 加载历史 `project_snapshot.json` 到当前 Project。
- 打开历史包输出。
- 复制包。
- 复制并重新运行。

复制包只复制 `config/`、`macros/`、`project_snapshot.json` 和 `validation_report.txt`，会创建新的空 `logs/` 和 `output/`，不会复制旧 CSV 或旧日志。

## 11. 常见问题

### 运行前验证失败

先检查 executable、macro、config、workspace root 和 outputDir 是否存在。outputDir 可以不存在，但它的上级目录必须存在。

### 生成包后原始配置没有变化

这是预期行为。GUI 不覆盖原始材料和几何文件，所有编辑结果写入新包。

### 三维预览空白或只有文本

可能没有安装 `requirements-3d.txt`，或当前 Qt/VTK/OpenGL 环境不可用。文本 fallback 不影响生成包和运行。

### 多线程输出没有合并文件

这是预期行为。到 Output 页的 Merge 标签运行合并任务。

### GUI 生成的几何和手写几何能力不同

以 C++ 后端为最终运行准则。GUI 只是安全编辑器，校验规则有意比后端保守。
# 运行结果判定（M0-3C4 工作区候选）

运行页会同时显示进程退出码和模拟结果。退出码为 0 不等于模拟成功：只有本次新生成的 `run_summary.txt` 证实后端和 macro 完成、至少执行一个 run、每轮计划事件全部完成且逐轮合计与摘要总数一致时才显示“模拟成功”。仅配置检查（dry-run）、交互会话结束但未运行、正常退出但无 run 会单独标记；停止、强制结束、摘要缺失或旧摘要不会被历史页误判为成功。历史页对旧版状态文件缺少摘要新鲜度证据的条目保守显示“结果未证实”。
