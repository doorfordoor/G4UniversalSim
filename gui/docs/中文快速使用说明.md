# G4UniversalSim GUI 中文快速使用说明

本文档说明当前 PySide6 GUI 的最小使用流程。GUI 是外部 Runner，不嵌入 Geant4、`G4RunManager`、OpenGL 或 Geant4 Qt 可视化；它通过 `QProcess` 启动已经编译好的 `G4UniversalSim.exe`，并负责生成运行包、查看输出、合并结果和管理历史运行。

## 1. 启动 GUI

在项目根目录下执行：

```powershell
cd gui
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

开发 smoke 检查：

```powershell
python -m compileall gui
python gui/smoke_tests/smoke_project_io.py
python gui/smoke_tests/smoke_parsers.py
python gui/smoke_tests/smoke_materials_editor.py
python gui/smoke_tests/smoke_run_config_editors.py
python gui/smoke_tests/smoke_geometry_editor.py
python gui/smoke_tests/smoke_output_tools.py
python gui/smoke_tests/smoke_history.py
```

## 2. Project 页

Project 页用于选择外部可执行程序和已有输入文件。

必填项：

- `Executable`：例如 `D:/Geant4/G4UniversalSim/build_vs2026/Release/G4UniversalSim.exe`
- `Macro`：例如 `D:/Geant4/G4UniversalSim/macros/test_simple_min.mac`
- `Output directory`：输出目录

可选项：

- `Config`：例如 `config/main.ini`。如果 macro 自举完整配置，可以留空。
- `Workspace root`：通常是项目根目录。
- `Threads`：线程数，必须为正整数。
- `Seed`：随机数种子，留空则不传 `--seed`。
- `Run name`：传给主程序的运行名。

GUI 生成的命令格式为：

```text
G4UniversalSim.exe --config <configPath> --macro <macroPath> --output <outputDir> --threads <N> --seed <N>
```

## 3. Config Builder 页

Config Builder 用于从已有材料和几何 ini 生成一个独立运行包。

典型流程：

1. 选择 workspace root、runs root、materials config、geometry config。
2. 选择 geometry template。
3. 设置 run name、threads、beamOn 数量。
4. 在 Materials、Geometry、Run Config 页编辑配置。
5. 点击 `Validate`。
6. 没有 error 时点击 `Generate Package` 或 `Generate and Run`。

生成目录结构：

```text
runs/<timestamp>_<run_name>/
  config/main.ini
  config/materials/material.ini
  config/geometry/geometry.ini
  macros/run.mac
  logs/
  output/
  validation_report.txt
  project_snapshot.json
```

生成后，Project 页会自动切换到该 package 的 `config/main.ini`、`macros/run.mac` 和 `output/`。

## 4. Materials Editor MVP

Config Builder 右侧 `Materials` 页是第一版材料编辑器。

支持：

- 从当前 `materials.ini` 加载材料。
- 新增 NIST alias。
- 新增 `mass_fraction`、`volume_fraction`、`atom_count` 材料。
- 复制、删除材料行。
- 修改 name、mode、density、enabled、components。
- 校验重复名称、缺失密度、fraction sum、atom_count 整数等常见问题。
- 在 `Raw Files -> Generated materials preview` 查看将写入 package 的 `materials.ini`。

不会做：

- 不覆盖原始 `materials.ini`。
- 不写回用户选择的 source 文件。
- 不查询完整 NIST 数据库。
- 不做完整化学式解析。

只有当 Materials Editor dirty 时，`Generate Package` 才会把 GUI 生成的材料写入：

```text
<package>/config/materials/material.ini
```

否则继续复制原始材料文件。

## 5. Geometry Editor MVP

Round 7K 后，Config Builder 右侧 `Geometry` 页支持两种可编辑模板：

- `simple_box`
- `layered_device`

其它模板仍为 preview-only：

- `hierarchical`
- boolean geometry
- `array`
- `shielding`
- GDML/STL

原始 `geometry.ini` 永远不会被覆盖。只有当 Geometry Editor dirty 且模板为 `simple_box` 或 `layered_device` 时，package writer 才会生成：

```text
<package>/config/geometry/geometry.ini
```

否则继续复制原始几何文件。

Round 7K-check 增加了后端验证脚本：

```powershell
python gui/smoke_tests/smoke_geometry_backend_package.py
```

如果不设置 `G4USIM_EXE`，脚本只检查 GUI writer / package 生成逻辑。如果要让脚本调用真实 C++ 后端：

```powershell
$env:G4USIM_EXE="D:\Geant4\G4UniversalSim\build_vs2026\Release\G4UniversalSim.exe"
python gui/smoke_tests/smoke_geometry_backend_package.py
```

该脚本会生成 Simple Box 和 Layered Device 两个 package，检查：

- generated `geometry.ini` 的 section/key；
- generated `main.ini` 是否指向 package 内的 `config/geometry/geometry.ini`；
- `validation_report.txt` 是否包含 `geometry_source_mode = generated by Geometry Editor`；
- 如果设置了 `G4USIM_EXE`，则实际执行 `/run/initialize` 和 `/run/beamOn`。

当前本地后端验证结果：Simple Box 和 Layered Device 单线程 package 均可成功运行并生成 `run_summary.txt`、`event_edep_t0.csv`、`hist_edep_raw_t0.csv`、`hist_edep_weighted_t0.csv`。`--threads 2` 回归运行没有 fatal error，但当前 exe 只输出 `t0` 文件，说明该环境可能是顺序 Geant4 构建，或当前后端未产生 per-worker 输出。

### 5.1 Simple Box

生成格式严格对应 C++ `SimpleBoxTemplate`：

```ini
[world]
size = 10 cm, 10 cm, 10 cm
material = G4_AIR

[target]
name = Target
shape = box
size = 1 cm, 1 cm, 1 mm
material = G4_Si
position = 0 mm, 0 mm, 0 mm
rotation = 0 deg, 0 deg, 0 deg
sensitive = true
bias = false
region = SV
```

可编辑字段：

- world size/material
- target name/shape/size/material
- target position/rotation
- target sensitive/bias
- target region

当前 Simple Box 编辑器只生成 `shape = box`。如果需要更复杂形状，请使用源 geometry preview 或等待后续 hierarchical editor。

### 5.2 Layered Device

生成格式严格对应 C++ `LayeredDeviceTemplate`：

```ini
[world]
size = 20 cm, 20 cm, 20 cm
material = G4_AIR

[layers]
count = 3
names = Substrate, Oxide, Metal
auto_stack = true
axis = z
gap = 0 um

[layer.Substrate]
thickness = 500 um
xy = 10 mm, 10 mm
material = G4_Si
sensitive = false
bias = false
region = SubstrateRegion
```

可编辑字段：

- world size/material
- stacking axis，目前只能是 `z`
- gap
- z_start，可选
- layer enabled/name/material/thickness/xy/sensitive/bias/region/copyNo
- add/duplicate/delete/up/down layer

校验规则包括：

- 至少一个 enabled layer。
- layer name 不能为空且不能重复。
- thickness 必须包含长度和单位。
- xy 必须包含两个长度。
- copyNo 如填写必须是整数。
- material 必须在编辑材料或常见 NIST quick list 中找到；未知 `G4_` 名称会给 warning，自定义未知材料会给 error。
- 如果几何标记 sensitive 但 scoring hits 关闭，会给 warning。
- 如果几何标记 bias 但 physics biasing hook 关闭，会给 warning。

### 5.3 Preview / Unsupported Template

`Preview / Unsupported Template` 子页继续显示 parser 静态解析出的普通 volume。

`Boolean Ops` 主 tab 继续显示 `volume.<name>.boolean.<index>` 等布尔操作预览，但 Round 7K 不编辑布尔几何。

## 6. Run Config 页

`Run Config` 页包含：

- `Source`
- `Physics`
- `Scoring`

这些编辑器会驱动生成的 `main.ini`。在 `Raw Files -> Generated main.ini preview` 可查看最终写入 package 的主配置。

### 6.1 Source

当前支持：

- preset
- particle
- energy
- position_type，目前生成 `point`
- position
- direction
- angular_mode，仅作 GUI 状态提示

### 6.2 Physics

当前支持：

- mode，目前 GUI 主要生成 `reference`
- reference list
- default cut
- enable biasing physics hook

注意：`enable biasing physics` 只打开 physics hook，不等于配置 biasing rule。

### 6.3 Scoring

当前支持：

- enable scoring
- hits
- event_edep
- edep scorer
- raw histogram
- weighted histogram
- bins/min/max
- volume summary
- particle summary
- auto-create default scorers

LET / Dose / Fluence 在当前 GUI 中不作为普通编辑项开放，因为后端仍是 stub/实验性能力。

## 6.5 3D Preview 页

Round 7K-P 后，Config Builder 右侧增加 `3D Preview` 页。

它用于预览当前 GUI 模型中的几何和源方向：

- `simple_box`：world wireframe、target box、source arrow、sensitive/bias 标识。
- `layered_device`：world wireframe、enabled layers 的 z 向堆叠、source arrow、sensitive/bias 标识。
- unsupported template：显示文本摘要和 warning。

3D Preview 是配置级近似预览，不是 Geant4 真正可视化：

- 不嵌入 Geant4 RunManager。
- 不调用 Geant4 Qt/Vis。
- 不执行 Geant4 navigator。
- 不检查 overlap。
- 不替代 `/run/initialize`。
- 不渲染 GDML/STL。
- 不做真实 Boolean CSG。
- 不做 3D picking 编辑。

### 可选 3D 依赖

默认 GUI 不强制安装 3D 依赖。没有安装时，`3D Preview` 页会显示文本 fallback 和安装提示。

如果设置了 `QT_QPA_PLATFORM=offscreen`，GUI 默认也会使用文本 fallback；这是为了避开 Windows 上 VTK/OpenGL 在无显示后端创建 render window 时可能发生的底层崩溃。真正的 PyVistaQt 视觉检查建议在普通桌面 Qt 会话中完成；只有确认 offscreen OpenGL 可用时，才设置 `G4USIM_ENABLE_OFFSCREEN_PYVISTA=1` 强制测试。

可选安装：

```powershell
cd gui
pip install -r requirements-3d.txt
```

`requirements-3d.txt` 包含：

```text
pyvista
pyvistaqt
vtk
```

### 使用方式

1. 在 Geometry 页编辑 Simple Box 或 Layered Device。
2. 在 Run Config -> Source 中设置 source position / direction。
3. 切到 `3D Preview`。
4. 点击 `Refresh Preview`。
5. 可用 `Show Source` 和 `Show Labels` 控制箭头与标签。
6. 如果 PyVista 可用，可使用 `Reset Camera` 重置视角。

### Source arrow 含义

箭头从 `SourceEditableModel.position` 出发，方向来自 `SourceEditableModel.direction`。方向会归一化后用于显示；如果方向为 `0,0,0` 或解析失败，Preview 会给 warning，但不会影响 Validate / Generate / Run。

### 验证命令

```powershell
python gui/smoke_tests/smoke_preview3d.py
```

该 smoke 会验证：

- mm/cm/um/m/deg 单位解析；
- `0,0,-5 mm` 形式的位置解析；
- source direction 解析；
- Simple Box PreviewScene；
- Layered Device PreviewScene；
- fallback widget；
- Config Builder offscreen 中存在 `3D Preview` tab。

## 7. Run 页

Run 页用于启动和监控外部仿真进程。

- `Build command`：预览将要执行的程序、参数和工作目录。
- `Run`：启动外部 `G4UniversalSim.exe`。
- `Stop`：请求进程正常退出。
- `Kill`：强制终止进程。
- `Save logs`：刷新当前 stdout/stderr 日志。

GUI 会写入：

```text
<package>/logs/stdout.log
<package>/logs/stderr.log
<package>/logs/run_status.json
```

如果不是 package 结构，则写入：

```text
<outputDir>/logs/
```

## 8. Output 页

Output 页用于浏览运行输出。

支持：

- `run_summary.txt`
- `hits_t*.csv`
- `event_edep_t*.csv`
- `hist_edep_raw_t*.csv`
- `hist_edep_weighted_t*.csv`
- `stdout.log`
- `stderr.log`
- `validation_report.txt`
- `project_snapshot.json`

CSV 预览会限制行数，不会完整加载大文件。

Merge 页会调用项目已有工具：

```powershell
python scripts/merge_outputs.py --input <outputDir> --pattern "hits_t*.csv" --output <outputDir>/hits_merged.csv
python scripts/merge_outputs.py --input <outputDir> --pattern "event_edep_t*.csv" --output <outputDir>/event_edep_merged.csv
mergeHistograms.exe --input <outputDir> --pattern hist_edep_raw_t*.csv --output <outputDir>/hist_edep_raw_merged.csv
mergeHistograms.exe --input <outputDir> --pattern hist_edep_weighted_t*.csv --output <outputDir>/hist_edep_weighted_merged.csv
```

如果目标 merged 文件已存在，对应 merge 任务会显示为不可用，避免覆盖旧结果。

## 9. Run History 页

Run History 扫描 runs root 下的历史 package。

可用操作：

- `Load Snapshot into Project`：读取历史 `project_snapshot.json`，恢复 GUI 状态。
- `Open Output`：切到 Output 页查看该 package。
- `Duplicate Package`：复制 config、macros、snapshot、validation report，并创建新的空 logs/output。
- `Duplicate and Rerun`：复制后立即用新 package 运行。

Duplicate 不复制旧输出 CSV 和日志，避免新旧结果混在一起。

## 10. 当前边界

当前 GUI 已可用于：

- 选择可执行程序、配置、macro 和输出目录。
- 编辑 Materials、Simple Box / Layered Device Geometry、Source、Physics、Scoring。
- 生成最小可运行 package。
- 运行外部仿真。
- 查看 stdout/stderr、summary、CSV。
- 合并 per-thread 输出。
- 管理历史 package。

当前 GUI 暂不实现：

- hierarchical/boolean/array/shielding/GDML/STL 几何编辑器。
- Biasing rule 图形编辑器。
- Geant4 可视化嵌入。
- 大型 CSV 全量加载。
- 曲线绘图。
- 参数扫描 UI。
- GUI 打包成独立 exe。

Round 7L 如果继续推进，建议做 hierarchical/boolean geometry editor；否则 Round 8 可转向打包、安装路径检查和真实 Windows 手动 QA。

## Round 7L 更新：Hierarchical / Boolean Geometry Editor

当前 GUI 已支持编辑并生成以下几何模式：

- `simple_box`
- `layered_device`
- `hierarchical`
- `boolean_hierarchical` / hierarchical boolean

`array`、`shielding`、GDML/STL 仍为 preview-only，不会由 GUI 生成新的几何文件。

### Hierarchical Volumes 页

该页编辑 C++ 后端当前支持的通用层级几何语法：

```ini
[world]
shape = box
size = 10 cm,10 cm,10 cm
material = G4_AIR

[volume.Detector]
parent = world
shape = box
size = 1 cm,1 cm,1 cm
material = G4_Si
position = 0 mm,0 mm,0 mm
sensitive = true
region = SV
```

表格字段含义：

- `enabled`：是否输出。`false` 的行保留在 GUI 中，但不会写入 generated `geometry.ini`。
- `name`：volume 名称。根节点应命名为 `world`。
- `parent`：父 volume。非 world volume 必须有 parent。
- `shape`：稳定编辑 `box`、`tubs`；后端还支持 `sphere/orb/cone`，GUI 会给近似预览 warning。
- `material`：普通 volume 的材料。
- `position` / `rotation`：三分量位置和旋转。
- `size/parameters`：`box` 使用 `size`；`tubs` 使用 `parameters`。
- `sensitive` / `bias` / `region`：写入普通 volume。

Validation 会检查 world 是否存在、重复 volume name、parent 是否存在、parent cycle、材料引用、shape 和 size/parameters。

### Boolean Operations 页

该页编辑 C++ 后端当前支持的 sequential boolean solid 语法：

```ini
[volume.Target.boolean.0]
operation = subtraction
shape = tubs
parameters = 0 mm,1.5 mm,5 mm,0 deg,360 deg
position = 0 mm,0 mm,0 mm
rotation = 0 deg,0 deg,0 deg
name = center_hole
```

重要语义：

- Boolean tool 是 solid operand，不是普通 volume。
- Boolean tool 不拥有 `material`、`sensitive`、`bias`、`region` 或 cuts。
- Boolean target volume 继承 target 自己的 material/sensitive/bias/region/cuts/visual。
- Enabled boolean ops 会按 target 从 `0` 连续重排后输出。
- 顺序语义为 `(((base op0 tool0) op1 tool1) ...)`。

支持的 operation：

- `subtraction`
- `union`
- `intersection`

3D Preview 对 boolean 只显示 target base volume 和半透明/线框 tool cutter，不做真实 CSG。最终几何以 Geant4 后端 `/run/initialize` 为准。

